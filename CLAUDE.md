# Catalog — правила для Claude Code

Контекст проекта (стек, структура, запуск, ADR) — [`AGENTS.md`](AGENTS.md).

Ниже — инварианты, которые обязаны выполняться в **любой** сессии.

## Пайплайн разработки по планам

Пайплайн живёт в плагине `shift@belch` (маркетплейс `belch` → `~/AIProjects/shift`),
а не в этом репозитории. Проектных копий ролей, workflow и хука здесь нет и быть не
должно: проектные агенты перекрывают агентов плагина молча, и репозиторий тихо
работает на устаревших промптах.

Запуск смены — `/shift:run <RUN_NAME>`; выгрузка задач Plane в планы —
`/shift:plane-todo-loop`.

Всё проектное, что нужно ролям — префикс тикетов, каталог планов, команды проверок,
пути UI, ADR, доп-критерии DoD, координаты трекера — объявлено в
[`.claude/pipeline.md`](.claude/pipeline.md). Меняется поведение пайплайна на
Catalog — правится **этот** файл, а не промпты плагина.

## Команды проверок

Гонять **по всему коду**, не только по диффу.

Backend — из `backend/`:

```bash
ruff check .
pytest
```

Frontend — из `frontend/`:

```bash
pnpm run build
pnpm run lint
pnpm run typecheck
pnpm run test
```

`pnpm run test` (`vitest run`) — такая же обязательная проверка, как остальные
три. Не прогнанная проверка не считается зелёной.

Канонический список для пайплайна — таблица в разделе **Команды проверок**
контракта [`.claude/pipeline.md`](.claude/pipeline.md); расхождение между ней и
этим списком — баг, править надо оба места.

## Definition of Done шага

DoD шага пайплайна = критерии приёмки из файла плана
(`docs/plan/<RUN_NAME>/NN-CATALOG-*.md`)
+ все шесть команд выше зелёные
+ доп-критерии из контракта
+ нет Critical/Medium замечаний ревьюера.

Для UI-шага (маркер `- **Тип шага:** ui` в плане) дополнительно: нет
Critical/Medium замечаний UI-ревьюера + выполнены критерии визуальной приёмки из
дизайн-спеки `docs/plan/<RUN_NAME>/<stem плана>.design.md`.

**История.** С 2026-08-20 по 2026-08-21 ревью было переведено в совещательный
режим (вердикт не блокировал коммит) — см. `chore/advisory-review`. За одну
смену это дало 40 незакрытых замечаний, включая Critical: фронтенд молча
выбрасывал коллекционные выходы, а тесты этого не видели, потому что обходили
нормализацию. Разбор потребовал отдельного прогона доработки на три цикла.
Гейт возвращён; повторять эксперимент без веской причины не стоит. Отсюда же
доп-критерий DoD в контракте про тест на продовом пути данных.

## Секреты

- Ключи и токены — только через `.env` / переменные окружения
  (`${env:VAR}` в MCP-конфигах).
- Никогда не хардкодить их в коде, в промптах агентов и в файлах состояния.
- Никогда не коммитить `.env*` (кроме `.env.example`), `.claude/state/*`,
  `.claude/steps-results/*`, `.cursor/state/*`, `.kilo/plans/*`.
