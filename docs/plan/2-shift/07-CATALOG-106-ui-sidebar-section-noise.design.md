# CATALOG-106 — Дизайн UI

- **Источник:** `docs/plan/2-shift/07-CATALOG-106-ui-sidebar-section-noise.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

После CATALOG-105 заголовки секций стали тихими eyebrow-надписями (11px / 600 / uppercase / `--ink-faint`), но рядом с ними по-прежнему стоят громкие серые пилюли `btn-secondary` — «+ Новый чат», «Обновить», «Обновить», «Обновить». Сейчас это самый шумный слой сайдбара: четыре кнопки-плашки кричат громче и заголовков, и содержимого списков, хотя нужны они изредка. Плюс при скролле длинного списка сессий заголовок уезжает вверх, и непонятно, в какой секции находишься.

Целевая картина в покое: сайдбар — три тихих ярлыка с числами и содержимое под ними. Никаких кнопок, пока пользователь не потянулся к секции.

Сценарий:

1. Пользователь смотрит на сайдбар в покое: «СЕССИИ 12», «ДОКУМЕНТЫ 4», «СКИЛЛЫ 3». Счётчик отвечает на вопрос «сколько там?» даже у свёрнутой секции — раскрывать ради подсчёта не нужно.
2. Пользователь наводит мышь на строку заголовка: строка подсвечивается (`--sidebar-brand-hover`, как и раньше), и в её правой части проявляются icon-кнопки — «+» и «обновить» у Сессий, «обновить» у Документов и Скиллов. Ширина заголовка при этом не меняется: место под кнопки зарезервировано всегда, меняется только прозрачность.
3. Пользователь уводит курсор — кнопки гаснут за 120 мс, строка возвращается в тихое состояние.
4. Пользователь идёт по Tab: попав на кнопку заголовка, он сразу видит проявившиеся кнопки секции (`focus-within` у всей строки) и может дотабать до них. Скрытые кнопки остаются в DOM и в дереве доступности — они не «пропадают» для скринридера и клавиатуры.
5. На тач-устройстве (`hover: none`) hover-механики нет — кнопки видны всегда, ничего не нужно «наводить».
6. Пользователь скроллит длинный список сессий: заголовок секции прилипает к верху области скролла на непрозрачной подложке `--sidebar`, содержимое уезжает под него, а не сквозь него. Дойдя до конца секции, заголовок выталкивается следующей секцией.

Побочный эффект шага: кнопки в заголовках перестают быть текстовыми и становятся icon-кнопками одного общего класса с рескан-кнопкой футера — это и есть требование ТЗ п.3 («общий класс icon-кнопок: рескан в футере и кнопки заголовков»). Текстовая пилюля в eyebrow-строке 11px невозможна как «тихий» элемент: она вдвое выше надписи, у неё своя заливка и она резервирует ~80px, которые в скрытом состоянии просто съедают ширину заголовка. Иконка резервирует 28px и в покое не видна.

Вне scope: содержимое панелей (`SessionsPanel` / `DocumentList` / `SkillsPanel`), крупная кнопка «Новый чат» над секциями (остаётся всегда видимой — именно она страхует спрятанный «+»), поиск, футер сверх общего icon-класса.

### Почему `disabled` во время загрузки снимается

Сейчас кнопки обновления гаснут в `disabled` на время запроса. С hover-видимостью это ломает клавиатуру: браузер снимает фокус с элемента, который стал `disabled`, → пропадает `focus-within` → вся группа кнопок исчезает у пользователя из-под рук прямо в момент нажатия Enter. Поэтому у кнопок обновления остаётся только `disabled={!hasWorkspace}`, а состояние запроса передаётся `SpinnerIcon` + `aria-busy`. Повторный клик — это повторный GET, побочных эффектов нет. У «Новый чат» условие сохраняется как есть (`!hasWorkspace || sessions.loading`): это мутирующее действие, и держать фокус на нём важнее нельзя.

## Layout и состояния

### Видимость actions

```
.catalog-section-header__actions
    display: flex; flex: none; align-items: center; gap: 4px;

@media (hover: hover)
  .catalog-section-header__actions
      opacity: 0; transition: opacity 120ms ease;
  .catalog-section-header:hover > .catalog-section-header__actions,
  .catalog-section-header:focus-within > .catalog-section-header__actions
      opacity: 1;

@media (hover: hover) and (prefers-reduced-motion: reduce)
  .catalog-section-header__actions { transition: none; }
```

Ключевые требования:

- Скрытие только через `opacity`. `display: none`, `visibility: hidden`, `width: 0` и рендер по условию в JSX **запрещены** — они убирают кнопки из потока (прыжок ширины заголовка) и/или из дерева доступности.
- Скрытие живёт **внутри** `@media (hover: hover)`, а не как базовое правило с откатом в `@media (hover: none)`. На тач-устройстве кнопки видны с первого кадра, без риска «мигания» из-за порядка правил.
- Триггер — `.catalog-section-header` целиком: наведение и фокус на кнопке-заголовке тоже проявляют actions.
- `pointer-events` не трогаем: невидимой кнопка бывает только когда курсора над строкой нет, значит кликнуть «вслепую» по ней невозможно.

### Счётчик

Бейдж рендерится, только когда `count` — число и `count > 0`. Ноль не показываем: пустая секция и так пуста при раскрытии, а «0» в трёх заголовках на свежем воркспейсе — ровно тот шум, который шаг убирает. Класс — `badge-neutral` (по ТЗ) плюс `tabular-nums`, чтобы ширина бейджа не дёргалась при смене цифр.

### Общий класс icon-кнопок

```
.catalog-sidebar__icon-button
    display: inline-flex; flex: none; align-items: center; justify-content: center;
    border-radius: var(--radius-control);
    color: var(--ink-faint);
    transition: background-color 120ms ease, color 120ms ease;
.catalog-sidebar__icon-button:hover   { background: var(--sidebar-selected); color: var(--ink); }
.catalog-sidebar__icon-button:focus-visible { outline: none; box-shadow: 0 0 0 2px var(--brand); }
.catalog-sidebar__icon-button:disabled { cursor: not-allowed; opacity: .5; }
.catalog-sidebar__icon-button:disabled:hover { background: transparent; color: var(--ink-faint); }

@media (prefers-reduced-motion: reduce)
  .catalog-sidebar__icon-button { transition: none; }
```

- **Размер класс не задаёт.** Размер приходит утилитой на месте использования: `size-7` (28px) в заголовках, `size-8` (32px) в футере. Причина техническая: правила `.catalog-*` в `index.css` идут после `@tailwind utilities` по исходному порядку, поэтому `width`/`height` из класса перебили бы `size-8` в футере. Заодно 104-й размер рескан-кнопки остаётся нетронутым.
- **Фон hover — `--sidebar-selected` (#ececec), а не `--sidebar-brand-hover` (#f0f0f0).** Это осознанное отклонение от CATALOG-104. Строка заголовка на hover сама залита #f0f0f0; кнопка с тем же #f0f0f0 внутри неё не даёт никакой обратной связи — палец «теряет» цель. #ececec — существующий токен (им залита выбранная строка списка), новых цветов не появляется. В футере, где подложка #f8f8f8, разница неощутима.
- **Цвет — `--ink-faint`, hover `--ink`.** Второе отклонение от CATALOG-104, где рескан наследовал `--ink` (#2e3236). Иконка вспомогательна: в футере громким должно быть имя папки (14px/600/`--ink`), в заголовке — надпись; глиф `--ink-faint` (#5f6368 на #f8f8f8, ≈5.9:1) остаётся отчётливым, но не спорит с ними. Hover возвращает `--ink` — движение вверх по контрасту при наведении.
- Фокус-кольцо — `box-shadow: 0 0 0 2px var(--brand)`, как у существующего `.icon-button`, а не Tailwind-`ring`: класс написан на чистом CSS рядом с остальными правилами сайдбара.
- Класс новый; существующие `.icon-button` (панель артефактов, 30px, свои токены) и `.btn-icon-ghost` не переиспользуются и не меняются: у обоих hover-фон из «белой» палитры main (`--icon-button-hover` / `--surface-hover` = #f1f1f1 / #f0f0f0), который в сайдбаре сливается с подсветкой строки.

### Sticky-заголовок

К `.catalog-section-header` добавляются:

```
position: sticky; top: 0; z-index: 1; background: var(--sidebar);
```

Существующие свойства (`display:flex`, `justify-content: space-between`, `gap: 8px`, `min-height: 32px`, `padding: 0 8px`, `border-radius: var(--radius-control)`) и правило `:hover { background: var(--sidebar-brand-hover) }` сохраняются без изменений.

Как это работает и почему так:

- Скроллпорт — `.catalog-sidebar__sections` (`overflow-y: auto` из CATALOG-104). Контейнер без padding, поэтому `top: 0` прижимает заголовок ровно к верхней кромке области скролла.
- Containing block каждого заголовка — корень его секции (`div.flex.flex-col.gap-2`). Значит заголовок липнет только пока его собственная секция в кадре, и выталкивается нижней кромкой своей секции. Наложений между заголовками разных секций и на чужие разделители не бывает.
- `z-index: 1` нужен не против разделителей (они в потоке и уже перекрываются фоном позиционированного заголовка), а против содержимого списков: у строк есть собственные фоны (`aria-current` → `--sidebar-selected`, hover), и без явного z-index порядок отрисовки на границе «позиционированный элемент против фонов потомков» становится неочевидным. Единица достаточна: конкурентов в этом стекинг-контексте нет, разделители остаются без `z-index`.
- Фон обязан быть непрозрачным и равным `--sidebar` — тем же, что у самого сайдбара, поэтому в покое (когда ничего не скроллится) визуально ничего не меняется.
- Скругление 8px оставляем: сквозь угловые «треугольники» (x < 8px и x > w−8px) виден фон `aside` того же цвета `--sidebar`, а содержимое секций отбито `padding: 1px 8px 7px` у `[role="region"]` и разделитель отбит `margin: 0 8px` — под уголки ничего не попадает.
- Корню секции и контейнеру секций **нельзя** добавлять `overflow`, `contain`, `transform` или `filter` — любое из них ломает sticky.

## Взаимодействия

- **Наведение на строку заголовка** — проявление actions за 120 мс. Только `opacity`; ни размеры, ни позиция, ни цвет надписи не меняются, поэтому «дрожания» соседних элементов нет.
- **Клик по заголовку** — прежний `onToggle`. Кнопки actions — сёстры кнопки-заголовка (вложенных `<button>` нет), клик по ним секцию не сворачивает и не раскрывает.
- **Клик по «+»** — `handleNewChat`, как сейчас. Если секция «Сессии» свёрнута, поведение не меняется (шаг не добавляет авто-раскрытия).
- **Клик по «обновить»** — `X.refresh()`. Иконка меняется на спиннер, кнопка остаётся активной и сфокусированной.
- **Клавиатура.** Число и порядок табстопов те же: заголовок → его кнопки → содержимое секции. Первый же Tab на заголовок делает кнопки видимыми, так что «фокус на невидимом элементе» невозможен.
- **Скролл колесом над прилипшим заголовком** — обычный скролл контейнера; заголовок не перехватывает событие (у него нет своего `overflow`).
- **Hover прилипшего заголовка** — подложка `--sidebar-brand-hover` поверх уезжающего содержимого; просветов нет, так как фон непрозрачный.
- **Крайний случай: очень большое число в бейдже.** Ширина бейджа растёт вправо, кнопка-заголовок `flex: 1`, actions `flex: none` — сначала сжимается свободное место, кнопки не выдавливаются за край.
- **Крайний случай: `hover: hover` + тач одновременно (тач-ноутбук).** Кнопки скрыты; тап по строке заголовка сворачивает секцию, но эмулированный hover проявляет группу — второй тап попадает по кнопке. Отдельного лечения не предусматриваем.
- **Крайний случай: обновление во время hover, курсор ушёл.** Группа гаснет вместе со спиннером. `:has()`-костыли, удерживающие видимость по `aria-busy`, вводить не нужно — они добавляют хрупкость ради секундного состояния.

## Стиль и токены

Только существующие переменные и утилиты; новых токенов нет.

- Тайминги: 120 мс `ease` и для проявления actions, и для hover icon-кнопки — сайдбар отвечает одинаково быстро в обоих случаях. Обе анимации отключаются под `prefers-reduced-motion: reduce` (как уже сделано у `.catalog-message-commands` через `motion-reduce:transition-none`).
- Бейдж: `badge-neutral` = `bg-surface-sunken` (#e0e0e0) + `text-[10px]` + `text-ink-faint`. Контраст #5f6368 на #e0e0e0 ≈ 4.6:1 — выше 4.5:1. Кегль 10px против 11px заголовка: число тише надписи, но читается; `gap: 6px` кнопки-заголовка отбивает его от слова.
- Icon-кнопки: 28px в заголовке при высоте строки 32px — по 2px воздуха сверху и снизу, квадрат hover не упирается в кромки строки. Глиф 16px в 28px и 18px в 32px — одинаковая пропорция ~0.57.
- Радиусы: `--radius-control` (8px) и у строки заголовка, и у icon-кнопки — вложенные скругления одного семейства.
- Палитра сайдбара после шага: подложка строки #f0f0f0 → подложка кнопки #ececec → выбранная строка списка #ececec. Никаких «белых» hover-цветов main (#f1f1f1 / #f0f0f0 из `--icon-button-hover` / `--surface-hover`) в сайдбаре не появляется.
- Шкала громкости из CATALOG-105 сохраняется: футер (14px/600/`--ink`) → списки (14px/400–500) → заголовки (11px/600/`--ink-faint`) → бейджи и иконки (10–16px, `--ink-faint`). Кнопки в покое из шкалы выпадают вовсе — их не видно.

## Доступность (a11y)

- Скрытие через `opacity` оставляет кнопки в дереве доступности и в порядке табуляции — скринридер и клавиатура видят их всегда, независимо от `hover`. `aria-hidden` на группе actions ставить нельзя.
- `focus-within` на строке заголовка — обязательное условие: без него зрячий клавиатурный пользователь получил бы фокус на невидимой кнопке.
- Каждая icon-кнопка имеет `aria-label` **и** `title` (подсказка мышью + имя для SR). Метки уникальны: «Новый чат» (метки «Обновить …» отменены CATALOG-109).
- Кнопки обновления несут `aria-busy` вместо `disabled` на время запроса — фокус не теряется при нажатии с клавиатуры. `SpinnerIcon` уже уважает `motion-reduce`.
- Счётчик входит в доступное имя кнопки-заголовка: «Сессии 12». Это осмысленно, поэтому `aria-hidden` на бейдже не ставим; `aria-expanded` / `aria-controls` не меняются.
- Тач-цель icon-кнопки 28px — ниже 44px, но сайдбар доступен только с ≥1024px, где основной ввод — мышь; в футере тач-цель остаётся 32px, как в CATALOG-104.
- Фокус-кольцо icon-кнопки (`0 0 0 2px var(--brand)`) внешнее и умещается: кнопка отбита от правой кромки сайдбара на 8px (`padding: 0 8px` строки заголовка, `padding-right: 8px` футера).
- Sticky не создаёт ловушек фокуса: заголовок не перекрывает элементы, к которым ведёт Tab, — при фокусе внутри секции браузер доскроллит с учётом прилипшего блока (`scroll-margin` не требуется, высота заголовка 32px и он всегда выше своего содержимого в потоке).
- Контрасты: `--ink-faint` на `--sidebar` ≈5.9:1, на `--sidebar-brand-hover` ≈5.4:1, на `--sidebar-selected` ≈5.2:1 — все выше 4.5:1.

## Контракты данных

Новых API, WS-сообщений и типов нет. Счётчики берутся из уже загруженных списков:
