## Цель и пользовательский путь

Скил объявляет **режим входа** — сколько документов он принимает: `1 документ`, `2 документа` или `список`. Режим задаётся автором один раз при сохранении скила и потом определяет, каким контролом пользователь выбирает документы при запуске.

Два сценария:

1. **Настройка скила (автор).** Пользователь открывает модалку настройки (draft, до коммита) → рядом с провайдером/моделью/рассуждениями видит новый выбор «Вход» с тремя вариантами → выбирает нужный → «Сохранить». Режим уходит в `configure` и фиксируется в скиле.
2. **Запуск скила (исполнитель).** В панели скилов у committed-скила вместо универсального чек-листа документов показывается контрол, соответствующий сохранённому режиму:
   - `1 документ` → один combobox (single);
   - `2 документа` → два combobox (первый и второй документ);
   - `список` → combobox с множественным выбором (multi-select).
   Кнопки «В док» / «На экран» активны только когда выбор валиден для режима.

## Дерево компонентов и файлы

- **`frontend/src/components/DocumentCombobox.tsx`** — новый переиспользуемый combobox для выбора документа(ов). Один компонент с двумя режимами через проп `multiple`:
  - single: триггер-кнопка показывает выбранный `title` (или плейсхолдер) → выпадающая панель со списком опций → клик по опции выбирает и закрывает панель.
  - multi: триггер показывает «N выбрано» → панель с чекбоксами, остаётся открытой при выборе; клик вне панели закрывает.
  Используется и в панели скилов (single/two/list), и как строительный блок для режима «2 документа» (два независимых экземпляра).
- **`frontend/src/components/SkillSettingsModal.tsx`** (изменяется) — добавить блок выбора режима входа; прокинуть значение в `configureSkill`.
- **`frontend/src/components/SkillsPanel.tsx`** (изменяется) — заменить единый чек-лист (`SkillsPanel.tsx:104-140`) на рендер контрола по режиму скила; локальное состояние выбора хранить в форме, пригодной для всех режимов.
- **`frontend/src/api.ts`** (изменяется, контракт данных) — `SkillOut.input_arity`, `configureSkill(..., { input_arity })`; `SkillPreview.input_arity` уже есть (`api.ts:73`).

Модель режима (согласовано с code-планом `CATALOG-4-code-...`): поле `input_arity: number | null`, где `1` = один документ, `2` = два документа, `null` = список. UI работает только с этими тремя значениями.

## Layout и состояния

### Модалка настройки (`SkillSettingsModal`)

Новый блок «Вход» ставится **первым** в списке полей (над «Провайдер»), т.к. это семантика самого скила, а не рантайм-параметр. Реализация — сегментированный радиогруппой набор из трёх опций в одну строку (радио-кнопки, стилизованные как кнопки-таблетки), либо `<select>` тем же классом `fieldCls`, если ширины не хватает. Предпочтителен радиогруппой ряд из трёх кнопок:

```
Вход
[ 1 документ ] [ 2 документа ] [ Список ]
```

- Начальное значение: из `preview.input_arity` (`1` / `2` / `null`); если поле пустое — дефолт `1 документ` (соответствует прежнему поведению single-doc).
- Активная опция подсвечена (`bg-indigo-600 text-white`), остальные — `bg-slate-800 text-slate-300`.
- Значение уходит в `configureSkill(skillId, { model, provider, reasoning, input_arity })`.
- Состояния модалки не меняются (loading моделей/провайдеров, `saving`, `error`) — блок «Вход» доступен всегда, локальных ошибок не имеет.

### Панель скилов (`SkillsPanel`, committed-скил)

Заголовок контрола выбора зависит от режима. Все три варианта заменяют текущий `<ul>`-чек-лист:

| Режим | Контрол | Заголовок/подпись |
|---|---|---|
| `1` | один `DocumentCombobox` (single) | «Документ» |
| `2` | два `DocumentCombobox` (single) в столбик | «Документ 1», «Документ 2» |
| `null` (список) | один `DocumentCombobox` (multiple) | «Документы» |

Состояния:
- **empty (нет документов):** вместо контрола — текст «нет документов» (как сейчас, `SkillsPanel.tsx:102`); кнопки apply скрыты/недоступны.
- **default (есть документы, ничего не выбрано):** триггер(ы) показывают плейсхолдер («Выберите документ» / «Выберите документы»); кнопки apply `disabled`.
- **partial (режим 2, выбран только один):** кнопки `disabled`; под контролами — подсказка «Выберите два разных документа».
- **invalid (режим 2, оба совпадают):** кнопки `disabled`; подсказка «Документы должны отличаться».
- **valid:** кнопки активны; на «В док»/«На экран» — счётчик как сейчас (`… (N)` при N>1).
- Ошибки apply (сетевые) обрабатываются выше по стеку (RunView/App), в контроле не показываются.

Дефолт выбора: для режима `1` предзаполнять текущим открытым документом (`defaultDocId`), сохраняя удобство «один клик» из текущего кода (`SkillsPanel.tsx:17-23`). Для режимов `2` и `список` — не предзаполнять (выбор осознанный).

## Взаимодействия

**DocumentCombobox (single):**
- Клик по триггеру — открывает/закрывает панель.
- Клик по опции — выбирает документ, закрывает панель, вызывает `onChange(docId)`.
- Клик вне компонента или `Escape` — закрывает панель без изменения.
- Опционально (в скоупе, если тривиально): поле поиска в шапке панели фильтрует опции по `title` (регистронезависимо). Combobox по ТЗ подразумевает фильтрацию, но при большом усложнении допустимо оставить простой список — критерии приёмки это не требуют жёстко.

**DocumentCombobox (multiple):**
- Клик по триггеру — открывает/закрывает панель.
- Клик по опции/чекбоксу — тогглит документ в выборке, панель **не** закрывается, `onChange(nextIds)`.
- Триггер показывает «N выбрано» (или плейсхолдер при N=0).
- Клик вне / `Escape` — закрывает панель.

**Режим «2 документа»:**
- Два single-combobox. Значение первого — `docIds[0]`, второго — `docIds[1]`.
- Валидность: оба выбраны и различны. При совпадении — подсказка и `disabled` кнопок (см. состояния).

**Кнопки apply:**
- `onApply(skillId, docIds, 'persist' | 'preview')` — сигнатура не меняется; `docIds` формируется по режиму (single → `[id]`, two → `[id1, id2]`, list → `[...ids]`).
- `disabled`, пока `isValid(mode, docIds)` не выполнено. Правила: single — ровно 1; two — ровно 2 различных; list — ≥1.

Крайние случаи:
- Документ, ранее выбранный, удалён из списка → компонент отбрасывает отсутствующие id из выборки при следующем рендере (не показывать «битые» выборы), кнопки пересчитывают валидность.
- Смена режима скила (переконфигурирование) → текущий локальный выбор для этого скила сбрасывается, чтобы не переносить, например, 5 выбранных документов в режим `1`.

## Стиль и токены

Держимся текущей тёмной палитры и утилит Tailwind v3 (ADR 0011), консистентно с `SkillSettingsModal`/`SkillsPanel`/`ModelSelector`:

- Триггер combobox: `w-full rounded bg-slate-800 px-2 py-1 text-[11px] text-slate-100 text-left flex items-center justify-between` + иконка-шеврон справа (`▾`, `text-slate-400`).
- Плейсхолдер: `text-slate-500`.
- Панель (popover): `absolute z-10 mt-1 w-full rounded border border-slate-700 bg-slate-900 shadow-xl max-h-48 overflow-y-auto`. Контейнер строки скила — `relative`, чтобы позиционировать панель.
- Опция: `flex items-center gap-1.5 px-2 py-1 text-[11px] text-slate-300 hover:bg-slate-800 cursor-pointer`; выбранная в single — `bg-indigo-600/20 text-white`; чекбокс в multi — `accent-indigo-500 h-3 w-3` (как в текущем чек-листе).
- Радиогруппой ряд в модалке: таблетки `rounded px-2 py-1 text-[11px]`, активная `bg-indigo-600 text-white`, неактивная `bg-slate-800 text-slate-300 hover:bg-slate-700`; подпись поля — `text-[11px] text-slate-400` (как остальные лейблы модалки).
- Кнопки apply — без изменений (`bg-indigo-600` / `bg-slate-700`, `text-[11px]`, `disabled:opacity-50`).
- Подсказки валидности — `text-[10px] text-amber-400`.

## Доступность (a11y)

- Триггер combobox: `role="combobox"` (или `<button>` с) `aria-haspopup="listbox"`, `aria-expanded`, `aria-label` («Документ» / «Документы» / «Документ 1» / «Документ 2»).
- Панель опций: `role="listbox"`; опции `role="option"` с `aria-selected`. В multi-режиме чекбоксы имеют доступные подписи (`<label>` оборачивает input, как в текущем коде).
- Клавиатура (минимум для среза): `Enter`/`Space` открывают панель; `Escape` закрывает и возвращает фокус на триггер; `Tab` уводит фокус и закрывает панель. Стрелочная навигация по опциям — желательна, но не обязательна для приёмки.
- Радиогруппой ряд в модалке: `role="radiogroup"` c `aria-label="Вход"`; каждая таблетка — радио, переключается стрелками/`Space`.
- Контраст: активные состояния на `indigo-600`, текст `text-slate-100/300` на тёмном фоне — соответствует остальному UI.
- Заголовки контролов — реальные текстовые лейблы, связанные с контролом (не только placeholder).

## Контракты данных (если нужны)

Зависит от code-плана `CATALOG-4-code-skill-input-arity-param.md` (должен быть влит раньше):

- `SkillOut.input_arity: number | null` — приходит из `GET /skills`; используется в `SkillsPanel` для выбора контрола.
- `SkillPreview.input_arity: number | null` (`api.ts:73`) — сид для радиогруппы в модалке.
- `configureSkill(skillId, { model, provider, reasoning, input_arity })` — `PATCH /skills/{id}/configure` принимает `input_arity`.
- `applySkill(skillId, docIds, mode)` / `onApply` — сигнатуры не меняются; меняется только состав `docIds` по режиму.

Семантика: `1` → single, `2` → two, `null` → list. UI не отправляет иных значений `input_arity`.

- [ ] Combobox открывается/закрывается по клику и закрывается по `Escape`/клику вне; single закрывается при выборе, multi — остаётся открытым.
- [ ] Кнопки «В док»/«На экран» `disabled`, пока выбор невалиден: single — не ровно 1; two — не два различных документа; list — 0 выбранных.

- [ ] Стиль контролов консистентен с существующим тёмным UI (палитра slate/indigo, размеры текста `text-[11px]`/`text-[10px]`).
