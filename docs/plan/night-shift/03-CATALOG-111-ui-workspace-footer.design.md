# CATALOG-111 — Дизайн UI

- **Источник:** `docs/plan/night-shift/03-CATALOG-111-ui-workspace-footer.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Футер сайдбара сегодня кричит громче, чем должен: полужирный текст, шеврон `⌄`, hover во всю ширину сайдбара с прямыми углами и высота 40+px. Он выглядит как отдельная панель, приклеенная снизу, а не как часть сайдбара — потому что единственный элемент с отрицательными маржинами и `border-radius: 0` во всём сайдбаре.

Целевая картина: **тихая статусная строка**, которая по геометрии — родная сестра кнопки «Новый чат» сверху (тот же инсет, тот же радиус, тот же hover-токен), а по громкости — тише списков секций.

Сценарий:

1. Пользователь открывает приложение и скользит взглядом по сайдбару сверху вниз: поиск → «Новый чат» → секции → тонкая линия → строка с иконкой папки и её именем. Строка не притягивает взгляд: обычный размер, средний вес, никаких стрелок.
2. Наводит курсор — под строкой мягко проявляется скруглённая подложка ровно той же формы и ширины, что у «Нового чата». Это читается как «здесь можно нажать», без обещания выпадающего меню (шеврона нет — открывается модальный пикер, а не dropdown).
3. Нажимает — открывается пикер воркспейса.
4. Нажимает иконку справа — идёт рескан **текущей папки**: об этом теперь прямо говорит подсказка «Пересканировать папку», а не безобъектное «Пересканировать».
5. Папка не открыта — строка на месте, той же высоты и ширины, с приглушённым «Папка не открыта»; иконки рескана нет, но её место сохранено, поэтому при открытии папки ничего не сдвигается.

Вне scope: содержимое пикера, `RescanReportModal`, шапка приложения, скролл-каркас сайдбара (закреплён в CATALOG-104), сама иконка папки (CATALOG-110 — уже в футере).

## Layout и состояния

### Геометрия: футер садится в сетку сайдбара

Сайдбар — `aside.p-3` (12px). Все «сидящие в сетке» элементы дополнительно отступают 8px внутрь: `.catalog-search` и `.catalog-new-chat` (`margin: 0 8px`), разделители секций (`.catalog-sidebar__sections > * + *::before { margin: 0 8px }`), списки (`[role="region"] { padding: 1px 8px 7px }`). Итог — общая левая кромка **20px** от края сайдбара.

Футер сейчас единственный, кто из этой сетки выпадает (`margin: 0 -12px -12px`). Приводим его к общему инсету:

```css
.catalog-sidebar__footer {
  display: flex; flex: none; align-items: center; gap: 4px;
  margin: 0 8px; padding-top: 8px;
  border-top: 1px solid var(--sidebar-line);
}
```

Что даёт каждая правка:

- `margin: 0 8px` вместо `0 -12px -12px` — футер по ширине совпадает с «Новым чатом» пиксель в пиксель, а `border-top` автоматически встаёт в один ряд с разделителями между секциями (те тоже инсет 8px). Отдельный псевдоэлемент под линию не нужен.
- Нижний `-12px` уходит: под футером остаётся 12px паддинга `aside`, зеркально верхним 12px над поиском. Футер по-прежнему прижат вниз за счёт `flex: 1` у `.catalog-sidebar__sections` (механизм из CATALOG-104 не трогаем).
- `padding-right: 8px` уходит: правый край строки теперь задаёт сам инсет футера, а зазор между пикером и рескана — `gap: 4px` (тот же шаг, что у `.catalog-section-header__actions`).
- `flex: none` и `border-top` сохраняются как есть.

### Строка футера

```
│←12px aside─┼─8px─┤
             ┌──────────────────────────────────────┐ ← border-top (в ряд с разделителями секций)
             │ [ 🗀  Имя папки ……………… ]  4px  [ ⟳ ] │
             │   picker: flex-1, min-w-0        32px│
             └──────────────────────────────────────┘
```

Кнопка-пикер (утилиты в JSX, как и сейчас):

```
flex min-w-0 flex-1 items-center gap-2.5 rounded-control px-[11px] py-2
text-left text-sm font-medium text-ink transition-colors
hover:bg-[var(--sidebar-brand-hover)]
focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand
```

- `py-2` = 8px по вертикали (коридор ТЗ 8–9px), `px-[11px]` и `gap-2.5` — ровно как у `.catalog-new-chat` (`padding: 8px 11px; gap: 10px`). Высота кнопки 36px = 20px строки `text-sm` + 16px.
- `rounded-control` (8px) вместо литерала 9px: рядом стоит `.catalog-sidebar__icon-button` с тем же токеном, и два соседних контрола обязаны иметь один радиус. Разница с «Новым чатом» — 1px, невидима; согласованность внутри строки важнее буквального совпадения с легаси-литералом.
- Классы `rounded-none`, `py-[11px]`, `pl-5`, `pr-3`, `font-semibold`, `group` удаляются полностью.
- Ring — **внешний**, `focus-visible:ring-inset` снимается: кнопка теперь отстоит от кромок `aside` минимум на 12px, кольцу есть куда лечь, и оно совпадает по толщине/цвету с `box-shadow: 0 0 0 2px var(--brand)` у соседней icon-кнопки.

Слот рескана — всегда 32px, даже когда кнопки нет:

- есть воркспейс → `<button className="catalog-sidebar__icon-button size-8">` (как сейчас);
- нет воркспейса → `<span aria-hidden="true" className="size-8 shrink-0" />` (пустой, не в дереве доступности, не фокусируется).

### Три состояния

| Состояние | Условие | Слева | Метка | Справа | Высота строки |
|---|---|---|---|---|---|
| Нет воркспейса | `path === null` | `FolderIcon` 18px, `text-ink-faint` | «Папка не открыта», `text-sm font-normal text-ink-faint truncate` | пустой слот 32px | 36px |
| Есть воркспейс | `path` не пуст | то же | `folderLabel(...)`, `text-sm font-medium text-ink truncate` | `RefreshIcon` 18px в кнопке 32px | 36px |
| Идёт рескан | `rescanning === true` | то же | то же, что «есть воркспейс» | `SpinnerIcon` 18px, кнопка `disabled` + `aria-busy="true"` | 36px |

Высоту во всех трёх случаях диктует кнопка-пикер (36px > 32px слота), ширину — инсет футера. Ни один переход между состояниями не двигает геометрию: полная высота футера всегда 45px (1px линия + 8px `padding-top` + 36px строка).

Своих состояний loading/error у футера нет: результат рескана уходит в `RescanReportModal`, ошибки воркспейса — в `catalog-notice` шапки. Это не меняется.

### `<lg` (< 1024px)

`.catalog-sidebar { display: none }` — футер не виден, проверять нечего, кроме отсутствия регрессии: второй полосы прокрутки не появляется, `main` занимает всю высоту. Правки затрагивают только маржины/паддинги внутри скрытого `aside`, новых источников переполнения нет.

## Взаимодействия

- **Клик по строке** (иконка, текст, пустое место справа от текста внутри кнопки) → `onOpenPicker()`. Обработчик один, на кнопке.
- **Клик по рескану** → `onRescan()`, пикер не открывается: кнопки — сёстры в DOM, вложенности нет (сохраняем инвариант CATALOG-104).
- **Hover пикера:** `var(--sidebar-brand-hover)` со скруглением 8px в границах кнопки, до кромки сайдбара подложка больше не доходит. Цвет текста и иконки на hover не меняется — подсветки фона достаточно, а «оживать» тихая строка не должна.
- **Hover рескана:** собственный фон `var(--sidebar-selected)` из `.catalog-sidebar__icon-button` (правило не трогаем); подложка пикера при этом не появляется — элементы не вложены.
- **Клавиатура:** Tab даёт те же два стопа «пикер → рескан» (пустой слот не фокусируется), Enter/Space штатно. Порядок и число фокусируемых элементов не меняются ни в одном состоянии.
- **Рескан в процессе:** повторное нажатие невозможно (`disabled`), ширина не прыгает — `SpinnerIcon` и `RefreshIcon` оба 18px.
- **Шеврона больше нет**, поэтому пропадает и hover-эффект `group-hover:text-ink-muted`; класс `group` на кнопке остаётся без потребителей и удаляется.

Крайние случаи:

- **Длинное имя папки** — одна строка с многоточием (`truncate` + `min-w-0` на кнопке, `shrink-0` на иконке). Точка обрезки одинакова в состояниях «есть папка» и «нет папки» — слот рескана занимает 32px всегда.
- **Очень узкий сайдбар** — колонка фиксирована (`lg:grid-cols-[360px_...]`), но даже при сужении сначала схлопывается метка (`truncate`), а не иконка и не слот.
- **Двойной клик по рескану** — второй клик приходит уже в `disabled`-кнопку, поведение прежнее.
- **`prefers-reduced-motion`** — у пикера только `transition-colors` (цвет фона), это не движение; `SpinnerIcon` и `.catalog-sidebar__icon-button` уже уважают reduced-motion.

## Стиль и токены

Новых токенов нет; используем только уже объявленные в `:root`.

| Что | Значение | Откуда |
|---|---|---|
| Метка (есть папка) | 14px / `font-medium` / `var(--ink)` | `text-sm font-medium text-ink` |
| Метка (нет папки) | 14px / `font-normal` / `var(--ink-faint)` | `text-sm font-normal text-ink-faint` |
| Иконка папки | 18px, `var(--ink-faint)`, `shrink-0` | результат CATALOG-110, не меняем |
| Паддинг пикера | `8px 11px` | как `.catalog-new-chat` |
| Gap иконка↔текст | 10px | `gap-2.5`, как `.catalog-new-chat` |
| Радиус пикера | `var(--radius-control)` = 8px | `rounded-control` |
| Hover пикера | `var(--sidebar-brand-hover)` | тот же токен, что `.catalog-new-chat:hover` |
| Фокус пикера | внешний ring 2px `var(--brand)` | `focus-visible:ring-2 focus-visible:ring-brand` |
| Gap пикер↔рескан | 4px | `.catalog-sidebar__footer` |
| Инсет футера | 8px внутрь контент-бокса `aside` | `margin: 0 8px` |
| Линия | 1px `var(--sidebar-line)` | `border-top`, теперь инсет как у разделителей секций |

Шкала громкости сайдбара после шага: «Новый чат» 15px/400 → списки секций 14px/400–500 → **футер 14px/500 приглушённо** → заголовки секций 11px/600 uppercase faint. Футер перестаёт быть самым тяжёлым текстом сайдбара (было 14px/600 при `--ink`) и становится ровно тем, чем является — статусной строкой с действием.

Намеренные отклонения от прежнего решения (CATALOG-104): full-bleed подложка, прямые углы, вес 600, вертикальный паддинг 11px и inset-ring — все пять сняты сознательно, это и есть содержание задачи.

## Доступность (a11y)

- **Имя пикера:** `aria-label` = шаблон «Выбрать воркспейс: {label}» — «Выбрать воркспейс: Docs» / «Выбрать воркспейс: Папка не открыта». Прежнее имя (просто имя папки) не сообщало, что кнопка вообще что-то делает. Видимый текст целиком входит в доступное имя, поэтому WCAG 2.5.3 (Label in Name) не нарушен и голосовой ввод по видимой метке работает.
- `aria-haspopup="dialog"` остаётся: открывается модальный пикер. Шеврон был визуальным дублем этого атрибута и намекал на dropdown — убираем именно поэтому, семантика при этом не теряется.
- `title={path ?? undefined}` остаётся подсказкой с полным путём; доступное имя оно не подменяет (aria-label приоритетнее).
- **Имя рескана:** `aria-label` и `title` = «Пересканировать папку». `aria-busy={rescanning}`, `disabled={rescanning}`, `SpinnerIcon` — поведение без изменений.
- Пустой слот — `aria-hidden="true"`, без текста и без роли: число элементов в дереве доступности между состояниями не растёт.
- `FolderIcon` декоративна (`aria-hidden` из `iconBase`); скринридер читает только доступные имена кнопок.
- Фокус-кольцо видно целиком: кнопка отстоит от кромок `aside` (`overflow-hidden`) минимум на 12px слева и снизу, сверху между линией и кнопкой 8px.
- Контраст: `--ink` и `--ink-faint` на `--sidebar` / `--sidebar-brand-hover` — пары, уже используемые в сайдбаре; новых сочетаний нет. Уменьшение веса с 600 до 500 контраст не меняет.

## Контракты данных

Новых API, WS-сообщений и типов нет. `WorkspaceFooterProps` (`path`, `displayName`, `rescanning`, `onOpenPicker`, `onRescan`) и экспорт `folderLabel` не меняются — `App.tsx` не трогаем. Логика `folderLabel` (`null` → «Папка не открыта»; непустой `display_name` → он; иначе последний сегмент пути) сохраняется дословно: строка «Папка не открыта» остаётся видимым текстом и подставляется в шаблон `aria-label`.
