# CATALOG-110 — Дизайн UI

- **Источник:** `docs/plan/night-shift/02-CATALOG-110-ui-folder-icon.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Шаг замещающий: текстовый глиф `▱` (U+25B1) в четырёх местах уступает место одной SVG-иконке `FolderIcon`, нарисованной в том же штрихе, что и остальные иконки приложения. Новых экранов, состояний, данных и взаимодействий не появляется.

Что меняется для пользователя:

1. Открывает приложение — в шапке слева от названия стоит узнаваемая иконка папки, а не прямоугольник неопределённого начертания. Иконка декоративная: это якорь-логотип продукта, а не индикатор открытой папки.
2. Воркспейс не открыт — в центре пустого `main` над заголовком «Воркспейс не открыт» крупная (36px) иконка папки того же семейства.
3. Смотрит в футер сайдбара — перед именем папки та же иконка в размере 18px, визуально согласованная с `RefreshIcon` рескана справа.
4. Открывает пикер папок — каждая строка списка начинается с иконки папки 16px; длинные имена по-прежнему обрезаются, иконка не сжимается.

Почему так: `▱` — символ геометрических фигур, а не пиктограмма папки. Его начертание, толщина и вертикальная метрика зависят от подобранного системного шрифта, поэтому в одной строке с `RefreshIcon`/`SettingsIcon` он выглядит инородно и «плывёт» между платформами. Единый `iconBase` снимает и то, и другое.

### `FolderIcon` — геометрия

Форма — классическая папка с «язычком» из того же семейства, что `RefreshIcon`/`TrashIcon` (feather-подобный контур, один `path`, без заливки):

```tsx
export function FolderIcon({ className }: IconProps) {
  return (
    <svg {...iconBase} className={className}>
      <path d="M22 19a2 2 0 0 1-2 2H4a2 2 0 0 1-2-2V5a2 2 0 0 1 2-2h5l2 3h9a2 2 0 0 1 2 2z" />
    </svg>
  )
}
```

Требования к контуру (что проверяет ревью, если генератор нарисует иначе):

- `viewBox 0 0 24 24`, все атрибуты штриха и `aria-hidden`/`focusable` приходят **только** из `iconBase` — на `<svg>` не дублируем ни `stroke`, ни `strokeWidth`, ни `aria-hidden`.
- Заливки нет: контур читается на любом фоне, цвет — `currentColor`.
- Радиусы скруглений ≈2 (как у `rect rx="2"` в `CopyIcon`) — иначе иконка выглядит острее соседей.
- Оптический вес совпадает с `RefreshIcon`: одна замкнутая фигура, ширина ≈20 из 24, поля по краям ≥2.

### Использование по местам

| Место | Разметка | Размер | Цвет |
|---|---|---|---|
| Шапка `App.tsx` | `<FolderIcon className="catalog-header__folder size-5 shrink-0" />` | 20px | `var(--header-folder)` через класс |
| Пустое `main` `App.tsx` | `<FolderIcon className="size-9" />` внутри центрующей обёртки | 36px | наследует `text-ink-faint` обёртки |
| Футер `WorkspaceFooter.tsx` | `<FolderIcon className="size-[18px] shrink-0 text-ink-faint" />` | 18px | `--ink-faint` |
| Пикер `WorkspacePicker.tsx` | `<FolderIcon className="size-4 shrink-0 text-ink-faint" />` | 16px | `--ink-faint` |

Обёртки-`<span>` вокруг иконок не нужны нигде: `iconBase` уже отдаёт `aria-hidden` и `focusable={false}`, а размер и цвет задаются классом на самом `<svg>`. Все четыре старых `<span>` удаляются целиком вместе с `aria-hidden="true"`, `leading-none`, `text-[18px]` и `text-3xl` — эти свойства относились к тексту и для SVG бессмысленны.

## Layout и состояния

### Шапка — маркер остаётся декоративным

Решение по пункту плана: **иконка в шапке остаётся, имя папки в неё не выносится.** Обоснование:

- Шапка (`min-height: 62px`, `px-5`) сейчас начинается с визуального якоря; без него заголовок «Catalog — планировщик скиллов» упирается в левую кромку и блок теряет ритм с правой группой (`ModelSelector` + кнопка настроек).
- Имя открытой папки живёт в футере сайдбара и там же кликабельно (открытие пикера). Дублировать его в шапке — значит завести второй, некликабельный источник той же правды и предвосхитить CATALOG-111, который перерабатывает именно футер.
- Маркер не реагирует на наличие воркспейса: он одинаков и при открытой папке, и без неё. Это отличает его от футера, где иконка стоит рядом с изменяемой меткой.

Раскладка шапки не меняется: `flex items-center gap-3`, иконка первым ребёнком, `shrink-0` защищает её от сжатия при длинном заголовке (у `<h1>` есть `truncate`). 20px против прежних ~21.6px глифа — разница в пределах погрешности, высота строки не сдвигается, потому что `items-center` центрует по контейнеру, а не по базовой линии текста.

### Пустое `main` — центровка обязательна

Tailwind preflight выставляет `svg { display: block }`, поэтому `text-center` родителя (`.max-w-sm.text-center`) блочную иконку **не** центрует — она прижмётся влево. Обёртка обязана центровать явно:

```tsx
<div className="mb-3 flex justify-center text-ink-faint">
  <FolderIcon className="size-9" />
</div>
```

`mb-3` сохраняется (отступ до заголовка), `text-ink-faint` переезжает на обёртку и питает `currentColor`, `text-3xl` и `aria-hidden` с обёртки уходят. Допустима эквивалентная альтернатива `className="mx-auto mb-3 size-9 text-ink-faint"` прямо на иконке без обёртки — важен результат: иконка 36px, по центру, приглушённого цвета, отступ снизу 12px.

### Состояния экрана

| Состояние | Что показываем |
|---|---|
| Воркспейс открыт | Шапка: декоративная иконка. Футер: иконка + имя папки (`text-ink`, `font-semibold`). Пустого `main` нет — рендерится рабочая область. |
| Воркспейс не открыт | Шапка: та же иконка (не гаснет). Пустое `main`: 36px иконка + «Воркспейс не открыт» + кнопка. Футер: иконка + «Папка не открыта» (`font-normal text-ink-faint`) — иконка при этом остаётся `text-ink-faint`, то есть на уровне метки. |
| Рескан идёт (`rescanning`) | Иконка папки слева неизменна; меняется только правая кнопка (`SpinnerIcon`) — вне скоупа шага. |
| Пикер: загрузка / ошибка / «Нет вложенных папок» / «Ничего не найдено» | Списка строк нет — иконок нет. Тексты состояний не трогаем. |
| Пикер: есть строки | В каждой строке иконка 16px, затем имя (`truncate`), затем опциональный бейдж «воркспейс». |

## Взаимодействия

- Иконки не кликабельны сами по себе и не добавляют новых целей: в футере и пикере они лежат **внутри** уже существующих кнопок и просто расширяют их визуальную зону; в шапке и пустом `main` они вне интерактивных элементов.
- Hover/focus/disabled-состояния родительских кнопок работают как прежде. В футере hover красит только шеврон (`group-hover:text-ink-muted`) — иконку папки в этот эффект **не** втягиваем: любые hover-правки футера принадлежат CATALOG-111.
- В пикере `disabled={submitting}` красит всю кнопку; иконка гаснет вместе с ней штатно, отдельного стиля не заводим.
- Порядок табуляции и число фокусируемых элементов не меняются нигде.

Крайние случаи:

- **Длинное имя папки.** `shrink-0` на иконке в футере и пикере обязателен: без него flex-контейнер сожмёт `<svg>` до нуля раньше, чем сработает `truncate` у метки. Это единственная реальная регрессия шага — держим её под критерием приёмки.
- **Длинный заголовок в шапке.** `shrink-0` у иконки, `truncate` у `<h1>` — иконка и `gitSha` остаются на месте.
- **Масштабирование интерфейса.** Размеры заданы в `px`-утилитах Tailwind, как у остальных иконок; браузерный zoom масштабирует всё пропорционально. `rem`-размеры не вводим — это разошлось бы со шкалой `icons.tsx`.
- **Печать / высококонтрастный режим.** Контурная иконка на `currentColor` наследует цвет текста и остаётся видимой там, где глиф мог не отрисоваться из-за отсутствия символа в шрифте.

## Стиль и токены

- Новых CSS-классов, Tailwind-плагинов и зависимостей нет. Иконка рисуется вручную в `icons.tsx` — библиотеку иконок не подключаем (ADR-0011: утилитарный Tailwind + собственные компоненты).
- `.catalog-header__folder` переписывается под SVG и остаётся только носителем цвета:

```css
.catalog-header__folder { color: var(--header-folder); }
```

  `font-size: 1.35rem` и `line-height: 1` удаляются — оба были нужны исключительно текстовому глифу. Токен `--header-folder: #585858` сохраняется: он задаёт шапке чуть более тёмный, чем `--ink-faint`, оттенок и остаётся единственной точкой настройки цвета маркера.

- Размерная шкала иконок после шага: 36px (пустое состояние) → 20px (шапка) → 18px (футер) → 16px (`iconBase` по умолчанию: пикер, кнопки сайдбара, действия в списках). Иных размеров для `FolderIcon` не вводим.
- Цветовая иерархия сохраняется: `--header-folder` в шапке, `--ink-faint` в футере, пикере и пустом состоянии. Иконка нигде не громче текста, рядом с которым стоит.
- В пикере иконка получает явный `text-ink-faint` (раньше глиф наследовал цвет кнопки): имя папки — главное в строке, маркер должен быть тише. Это единственное намеренное отклонение от «пиксель-в-пиксель» переноса.

## Доступность (a11y)

- Все четыре вхождения декоративны: `aria-hidden="true"` и `focusable={false}` приходят из `iconBase`, дополнительно на `<svg>` их не пишем и на обёртки не переносим.
- Доступные имена не меняются нигде: кнопка футера сохраняет `aria-label={label}` и `title={path}`, кнопка строки пикера — `title={entry.path}` и текстовое имя папки, кнопка настроек — «Настройки». Ни одна иконка не становится единственным носителем смысла.
- Пустое состояние по-прежнему объявляется скринридеру заголовком «Воркспейс не открыт» (`<h2>`); иконка молчит, как молчал глиф.
- Порядок и число элементов в дереве доступности не меняются: `<span aria-hidden>` заменяется на `<svg aria-hidden>` один к одному.
- Контраст: `--header-folder` (#585858) на `--header-bg` и `--ink-faint` на `--surface`/`--sidebar` — те же пары, что у существующих контурных иконок; штрих 1.75 при 16px читается не хуже `RefreshIcon`, который уже принят.
- `prefers-reduced-motion` неактуален: анимации у `FolderIcon` нет.

## Контракты данных

Новых API, WS-сообщений и типов нет. Меняется только публичная поверхность `icons.tsx`: добавляется экспорт `FolderIcon` с существующим интерфейсом `IconProps` (`{ className?: string }`). Пропсы компонентов `WorkspaceFooter` и `WorkspacePicker` не меняются.
