## Контекст

### Что уже сделано

В `backend/app/documents/ingest.py` есть готовая инфраструктура для читаемых имён:

- `slugify(name)` (`ingest.py:24-33`) — транслитерация кириллицы → латиница, нормализация в `[a-z0-9-]`, обрезка до 60 символов. Возвращает `""` для пустого/небезопасного ввода.
- `ingest_file` (`ingest.py:44-72`) использует схему `{slug}-{doc_id[:8]}{ext}`, с фолбэком `{doc_id}{ext}` если slug пустой. Этот путь для **загружаемых** файлов уже работает корректно — именно поэтому `cover-letter-spiiran-ntbvt-java-ea411722` (пример из ТЗ) уже выглядит правильно.

### Что сломано

«Созданные в приложении» файлы — это результаты работы skills и runs, они пишутся в `workspace/results/{out_id}.md` буквально как 32-символьный hex UUID. Пользователь в UI видит `title` (например «Перевод — Cover Letter»), а на диске лежит `b4d15754a2a84cb8bd24f1e29275afa4.md`.

Два места формируют такие имена:

- `backend/app/api/runs.py:120-126` — `save_run_result_endpoint`: «Сохранить как новый документ» после preview-run. `out_id = uuid.uuid4().hex`, пишется `results/{out_id}.md`, в БД `path = f"results/{out_id}.md"`.
- `backend/app/skills/apply.py:297-313` — `apply_skill` в режиме `persist=True`: тот же паттерн, `out_id = uuid.uuid4().hex`, пишется `results/{out_id}.md`. Заголовок формируется как `{skill.name} — {docs[0].title}` или `{skill.name} — {docs[0].title} (+N)`.

Существующие UUID-имена в рабочем workspace видны в `backend/workspace/.obsidian/workspace.json:189-193` — всё `results/<uuid>.md`.

### Контракт для UI

UI отображает `Document.title` из БД — он формируется правильно и не меняется. Меняется только физическое имя файла на диске + `path` в БД. Идентификатор документа (`doc_id`) остаётся тем же UUID, slug — лишь префикс для читаемости.

## Затрагиваемые файлы

- `backend/app/api/runs.py` — в `save_run_result_endpoint` сформировать `{slug}-{doc_id[:8]}.md` через существующий `slugify`, фолбэк `{out_id}.md` если slug пустой.
- `backend/app/skills/apply.py` — то же в ветке `persist=True`;slug строить из `result_title` (там уже есть заголовок).
- `backend/app/documents/ingest.py` — вынести общую логику построения пути (`build_doc_filename(title, doc_id, ext)`) в переиспользуемую функцию, чтобы `ingest_file`, `runs.py` и `apply.py` делили один хелпер. Либо импортировать `slugify` напрямую — решение за исполнителем.
- `backend/tests/test_storage.py` — новый тест на `build_doc_filename` (если вводится хелпер) + обновить/дополнить существующие проверки.
- `backend/tests/test_apply.py` — проверить, что `apply_skill(persist=True)` создаёт файл вида `results/{slug}-{id[:8]}.md`.
- `backend/tests/test_api.py` — проверить, что `POST /runs/{id}/save` создаёт файл с slug-именем.

## План действий

1. **Вынести хелпер построения имени.** В `backend/app/documents/ingest.py` добавить публичную функцию `build_doc_path(title: str, doc_id: str, ext: str, subdir: str) -> str`, возвращающую `{subdir}/{slug}-{doc_id[:8]}{ext}` (или `{subdir}/{doc_id}{ext}` при пустом slug). Рефакторить `ingest_file` так, чтобы он вызывал этот хелпер вместо локального построения пути — поведение для загружаемых файлов не меняется (regression-защита).
2. **Применить хелпер в `apply.py`.** В ветке `persist=True` (`apply.py:296-315`) заменить прямое `f"results/{out_id}.md"` на вызов `build_doc_path(result_title, out_id, ".md", "results")`. Порядок: сначала вычислить `result_title`, потом `out_id`, потом путь.
3. **Применить хелпер в `runs.py`.** В `save_run_result_endpoint` (`runs.py:118-126`) заменить прямое `f"results/{out_id}.md"` на `build_doc_path(title, out_id, ".md", "results")`. Физическое имя файла и `path` в БД должны совпадать.
4. **Длина slug для составных заголовков.** Заголовки результатов могут быть длинными («Перевод — Cover Letter SPIIRAN…»). `slugify` уже обрезает до `_SLUG_MAX_LEN = 60`, так что ничего дополнительного не нужно — проверить, что замена `—` и других unicode-разделителей корректно даёт `-`.
5. **Тесты.** Добавить/обновить:
   - `test_storage.py`: unit-тест на `build_doc_path` — кириллица, пустой slug, длинный title, с/без `subdir`.
   - `test_apply.py`: после `apply_skill(persist=True)` с осмысленным заголовком проверять, что файл в `results/` соответствует `{slug}-{id[:8]}.md` (а не `{id}.md`). Один из существующих тестов стоит обновить под новое поведение.
   - `test_api.py`: `POST /runs/{id}/save` — аналогичная проверка.
6. **Проверить миграцию существующих файлов (out of scope).** Существующие `results/<uuid>.md` в рабочем workspace переименовывать автоматически НЕ нужно: это разовые данные, при желании пользователь может удалить и пересохранить. В плане явно отметить — миграция не выполняется.
