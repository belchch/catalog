# CATALOG-42 — Управление составом сессии в UI

- **Задача Plane:** [CATALOG-42](https://app.plane.so/belchch/projects/catalog-app/work-items/42) (id: `d8ee5f75-0aa3-4d20-8d38-dba99249bcb0`, state: In Progress)
- **Статус плана:** Draft
- **Тип шага:** ui
- **Цель:** Дать пользователю управлять составом документов planner-сессии из UI: удалять отдельные документы из сессии, видеть автодобавленные результаты skills/runs, понимать, что агент работает в scoped-режиме.

## Постановка задачи (актуальное ТЗ)

_(источник: описание задачи — комментариев нет)_

Пользователь всегда видит актуальный состав сессии. Документ можно удалить из сессии через UI; удаление прекращает доступ агента к документу, но не удаляет сам документ из глобального хранилища. Любой новый документ, созданный агентом или скиллом в рамках сессии, автоматически появляется в её составе. Состав восстанавливается после повторного открытия сессии.

## Контекст

### Парный code-план — предусловие

Backend-часть изоляции (scoped tools, API detach, автодобавление результатов) выполняется в `docs/plan/night-shift/CATALOG-42-code-session-docs-isolation.md`. Этот `ui`-план запускается **после** `code`-плана — он опирается на:

- `DELETE /sessions/{id}/documents/{doc_id}` (новый эндпоинт).
- Автодобавление результатов skills в `session_document` (кадр `session_docs` после `apply_skill`/`save_run_result`).
- Обновлённый system prompt с сообщением о scoped-режиме (косвенно влияет на UX — поведение агента при отсутствии документа).

### Что уже есть в UI

- **`Chat.tsx` (стр. 145-166)** — секция «Документы в сессии»: список пилюль `{kind}` + `{title}`. Сейчас **read-only** — нет кнопки удаления.
- **`usePlannerSession.ts`** — состояние `sessionDocuments: DocumentOut[]`:
  - инициализируется из `GET /sessions/{id}/documents` (стр. 224-230),
  - обновляется кадром `session_docs` из WS (стр. 158-160),
  - сбрасывается при смене сессии (стр. 104).
- **DocumentCombobox** (`Chat.tsx:202-214`) — добавление документов в draft-выбор (attach происходит при отправке сообщения через `doc_ids` в payload).
- **`api.ts`** — `getSessionDocuments`, `listSessionMessages`, типы `DocumentOut`.

### Что отсутствует

1. **Кнопка detach на пилюлях** «Документы в сессии». Сейчас их можно только смотреть.
2. **Обновление состояния после detach.** Придёт либо новый кадр `session_docs` (нужно убедиться, что бэкенд шлёт его после detach — это зона code-плана), либо фронт сам удаляет документ из `sessionDocuments` оптически и делает re-fetch.
3. **Индикация scoped-режима.** Пользователю стоит намекнуть, что агент видит только этот список, а не все документы приложения (иначе пользователь не поймёт, зачем добавлять документ, который «и так есть в библиотеке»).
4. **Сценарий «документа нет»** — если пользователь спрашивает агента про документ, которого нет в сессии, агент (по обновлённому промпту) попросит добавить. UI должен позволять это сделать из текущего чата (комбобокс уже есть, но пользователь должен понимать, что это ответ на его просьбу).

### Дизайн-решения

- Кнопка удаления — `×` в правой части пилюли, тот же визуальный язык, что у `selectedDocs` (стр. 191-200). Отличие: после нажатия идёт network-вызов и подтверждение не требуется (detach не деструктивный — документ остаётся в глобальном хранилище).
- **Оптимистичное обновление**: сразу убираем пилюлю из `sessionDocuments`, а если запрос упал — откатываем и показываем ошибку.
- **Индикация scoped-режима**: короткая подпись под заголовком «Документы в сессии»: «Агент видит только эти документы» (one-liner, без модалок).

## План действий

1. **API-клиент** (`api.ts`): `removeSessionDocument(sessionId, docId)` — `fetch DELETE /sessions/{sessionId}/documents/{docId}`, ожидать 204; на 404 «document not attached» — игнорировать (оптимистичное обновление уже убрало пилюлю).
2. **Hook** (`usePlannerSession.ts`):
   - Добавить `removeDocument(docId: string): Promise<void>`:
     - Оптимистично `setSessionDocuments(prev => prev.filter(d => d.id !== docId))`.
     - Вызвать `removeSessionDocument(sessionId, docId)`.
     - При ошибке — re-fetch через `getSessionDocuments(sessionId)` и `setError`.
   - Добавить в return-объект: `removeDocument`.
3. **Chat.tsx**:
   - Принять `onRemoveDocument` (пробросить из родителя, который владеет `usePlannerSession`).
   - В пилюлях «Документы в сессии» (стр. 152-163) добавить кнопку `×` с `aria-label="Убрать {title} из сессии"`, `disabled={streaming}`, `onClick={() => onRemoveDocument?.(d.id)}`.
   - Под заголовком секции добавить micro-copy: «Агент видит только эти документы».
4. **Состояние после автодобавления**: кадр `session_docs` уже обновляет `sessionDocuments` (стр. 158-160). Проверить, что backend в code-плане действительно шлёт этот кадр после `apply_skill`/`save_run_result` (если WS-соединение planner-сессии активно). Если WS-канал недоступен из apply — UI должен делать re-fetch `getSessionDocuments` после завершения run (или после `POST /runs/{id}/save`). Решение — согласовать с code-планом; в ui-плане зафиксировать: полагаемся на кадр `session_docs`, fallback — re-fetch после run-finish.
5. **Родительский компонент** (владелец `usePlannerSession`) — пробросить `removeDocument` в `Chat` через `onRemoveDocument`.
6. **Дизайн-спека** (опционально, для catalog-designer): описать визуальное поведение — состояние кнопки `×` при hover/disabled, скелетон/пустое состояние при удалении, поведение при ошибке (snackbar/inline).
