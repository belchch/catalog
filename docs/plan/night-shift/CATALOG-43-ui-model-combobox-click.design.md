## Цель и пользовательский путь

Пользователь настраивает модель через комбобокс `ModelCombobox` (шапка чата / панель настроек). Сценарий:

1. Выбирает провайдера → автоматически подставляется первая модель провайдера.
2. Кликает по триггеру-кнопке комбобокса моделей → раскрывается попап-список со строкой поиска и опциями.
3. **Кликает мышью по нужной опции списка** → выбранная модель применяется, попап закрывается, триггер немедленно показывает имя новой модели.

Дефект: сейчас клик по опции закрывает попап **без** применения выбора (визуально «ничего не изменилось»). Дизайн фиксирует корректное поведение выбора и не меняет внешний вид попапа.

Это правка поведения (interaction bug), а не редизайн: layout, размеры, цвета, типографика остаются прежними. Меняется только надёжность обработки клика/фокуса.

## Дерево компонентов и файлы

- `frontend/src/components/ModelCombobox.tsx` — **изменяется**. Основной носитель дефекта (root `onBlur` + autoFocus input + `<div role="option">`).
- `frontend/src/components/DocumentCombobox.tsx` — **проверяется, приводится к тому же безопасному паттерну**. У него нет root-`onBlur`, поэтому острого бага нет, но опции должны получить ту же защиту фокуса ради консистентности и устойчивости к будущим изменениям.
- Потребители не меняются: триггеры и раскладка задаются через `triggerClassName`/`placement` пропсы снаружи (шапка чата, `SkillSettingsModal`, панель настроек). Их разметка и вид остаются как есть.

Новых компонентов и зависимостей не вводится.

## Layout и состояния

Структура попапа сохраняется без изменений:

- **Триггер** — `<button role="combobox">`: слева усечённое имя модели (`truncate`) + опциональный бейдж `🧠` для reasoning-моделей; справа шеврон `▾`.
- **Попап** — `<div role="listbox">`: абсолютный, `z-10`, `max-h-48`, скролл по вертикали, рамка `border-slate-700`, фон `bg-slate-900`, тень `shadow-xl`.
  - **Sticky-строка поиска** сверху: `<input type="search">` с плейсхолдером «Поиск…».
  - **Список опций** — `<div role="option">` для каждой модели.

Состояния списка:

- **Закрыт** (`open=false`): виден только триггер с текущей моделью.
- **Открыт, есть опции** (`success`): строка поиска + опции; текущая модель подсвечена (`aria-selected`, фон `bg-indigo-600/20`, текст `text-white`).
- **Открыт, пусто / нет совпадений** (`empty`): строка «нет совпадений» (`text-slate-500`), как сейчас.
- **Disabled**: триггер `opacity-50`, `aria-disabled`, попап принудительно закрыт.
- Отдельных `loading`/`error` состояний у самого комбобокса нет — список моделей приходит готовым от родителя; их появление вне скоупа.

Поведение при выборе (ключевое изменение): после клика по опции состояние переходит `open → closed`, триггер показывает `selectedModel.name` новой модели, `onChange(model.id)` вызван ровно один раз.

## Взаимодействия

1. **Открытие/закрытие триггером:** клик по кнопке переключает `open`. При открытии фокус уходит в строку поиска (`autoFocus`) — сохраняется.
2. **Выбор опции мышью (главный фикс):** одинарный `click` по `<div role="option">` вызывает `onChange(id)` и затем `close()`. Клик **обязан** срабатывать и не должен «съедаться» преждевременным закрытием попапа.
   - Убрать преждевременное закрытие по `onBlur` корневого контейнера (в `ModelCombobox`), опираясь на уже существующий обработчик `mousedown`-вне-контейнера.
   - На каждую опцию добавить подавление увода фокуса при нажатии мыши (`onMouseDown` → `preventDefault`), чтобы `mousedown` по опции не выбрасывал фокус из строки поиска и не ронял попап до `click`. Это стандартный паттерн listbox с поиском.
3. **Поиск:** ввод в строку поиска фильтрует опции (`sortAndFilterModels`); клик по отфильтрованной опции применяет выбор так же, как без фильтра.
4. **Закрытие по клику вне:** `mousedown` вне корневого контейнера закрывает попап и сбрасывает фильтр — сохраняется.
5. **Escape:** закрывает попап (и с триггера, и из списка), возвращает фокус на кнопку-триггер — сохраняется.
6. **Смена провайдера:** при смене массива `models` (`modelsKey`) попап закрывается и фильтр сбрасывается — сохраняется; на выбор модели внутри одного провайдера не влияет.

Крайние случаи:
- Клик по уже выбранной опции — повторный `onChange` с тем же id, попап закрывается (допустимо, поведение стабильно).
- Клик мимо опций внутри попапа (например, по полосе поиска) — попап остаётся открытым.
- Пустой список / нет совпадений — кликать нечего, работает только поиск и закрытие.

## Стиль и токены

Без визуальных изменений. Сохранить существующие Tailwind-утилиты:

- Триггер: `rounded bg-slate-800 px-2 py-1 text-left text-xs text-slate-100 disabled:opacity-50` (в `ModelCombobox`; `text-[11px]` в `DocumentCombobox`).
- Попап: `absolute z-10 mt-1 max-h-48 w-full overflow-y-auto rounded border border-slate-700 bg-slate-900 shadow-xl`.
- Опция: `flex cursor-pointer items-center gap-1.5 px-2 py-1 text-xs`, hover `hover:bg-slate-800`, выбранная `bg-indigo-600/20 text-white`.
- Строка поиска: `w-full rounded bg-slate-800 px-2 py-1 text-xs text-slate-100 placeholder:text-slate-500`.

`onMouseDown`/`preventDefault` — чисто поведенческие, класс `cursor-pointer` на опции остаётся, курсор и hover не меняются.

## Доступность (a11y)

Сохранить и не регрессировать существующую семантику:

- Триггер: `role="combobox"`, `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls`, `aria-label`, `aria-disabled`.
- Список: `role="listbox"` с `id`, привязанным через `aria-controls`.
- Опции: `role="option"` + `aria-selected` на текущей модели.
- Клавиатура: `Escape` закрывает попап и возвращает фокус на триггер (сохранить).
- Фокус: `autoFocus` в строке поиска при открытии остаётся; `preventDefault` на `mousedown` опции удерживает фокус в поле поиска и не отправляет его на `<body>`.
- Контраст текста опций (`text-slate-300`/`text-white`) на фоне `bg-slate-900` не меняется.

Клавиатурная навигация стрелками по опциям — вне скоупа этого шага (не регрессируем существующее, новое не требуем).

## Контракты данных

UI использует существующие пропсы, без изменений API:

- `ModelCombobox`: `models: ModelOut[]`, `value: string`, `onChange(modelId: string)`, `ariaLabel?`, `disabled?`, `triggerClassName?`. Применение выбора идёт через `onChange` → у потребителя `useSettings.changeModel` (см. план, `useSettings.ts`).
- `DocumentCombobox`: существующие пропсы (`documents`, single/multiple режим, `placement` и т.д.) — без изменений.

Никаких новых вызовов API/WS дизайн не вводит; `onChange` дёргает уже существующую цепочку сохранения настроек.

## Критерии визуальной приёмки

- [ ] Клик мышью по опции в `ModelCombobox` немедленно применяет модель: триггер показывает имя выбранной модели, попап закрывается.
- [ ] После выбора провайдера (подставилась первая модель) можно открыть список и кликом выбрать любую другую модель — значение в триггере меняется.
- [ ] Клик по опции вызывает `onChange` ровно один раз с корректным `id` (визуально — без «мигания»/повторного открытия).
- [ ] Поиск работает: ввод фильтрует список, клик по отфильтрованной опции применяет выбор.
- [ ] Закрытие по клику вне контейнера и по `Escape` сохранено; после `Escape` фокус на триггере.
- [ ] `DocumentCombobox` приведён к тому же безопасному паттерну; выбор документа кликом работает в чате и в `SkillSettingsModal` (single и multiple режимы), внешний вид не изменился.
- [ ] Внешний вид триггера, попапа, строки поиска и опций (отступы, цвета, шрифты, подсветка выбранной, hover) не изменился относительно текущего.
- [ ] Reasoning-бейдж `🧠` в триггере и опциях отображается как раньше.
