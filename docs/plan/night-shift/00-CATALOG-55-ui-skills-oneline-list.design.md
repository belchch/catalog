## Цель и пользовательский путь

Список скилов в сайдбаре (секция «Скиллы», ширина 360px) превращается из стопки полноразмерных карточек в сканируемый однострочный индекс с поиском и общим тулбаром. Управление и запуск живут в контексте одной выбранной строки.

Сценарий:

1. Пользователь открывает секцию «Скиллы» и видит компактный список: каждый скил — одна строка фиксированной высоты (статус, имя, теги, arity). Список легко сканировать взглядом.
2. Много скилов → пользователь печатает в поле поиска над списком. Список фильтруется на лету по имени/описанию/тегам. Пустая выдача показывает сообщение и кнопку сброса.
3. Клик по строке выбирает скил: строка раскрывается вниз, показывая описание, мету модели и (для `committed`) блок запуска. Одновременно раскрыт максимум один скил.
4. Общий тулбар над списком становится активным: «Переименовать», «Редактировать», «Коммит» (только для draft), «Удалить» (в overflow-меню). Действия применяются к выбранному скилу.
5. Пользователь настраивает документы/промпт в раскрытой строке и жмёт «В док» или «На экран». Повторный клик по строке (или Esc) снимает выбор и сворачивает контекст. Выбранные документы и промпт сохраняются при переключении между скилами.
6. Клавиатура: `↑`/`↓` двигают выбор по видимому (отфильтрованному) списку, `Enter` на выбранном committed запускает «В док», `Esc` снимает выбор.

Выделять в отдельный файл, только если это заметно упрощает `SkillsPanel.tsx`; иначе оставить инлайн-блоком внутри `SkillsPanel`. Не обязателен для приёмки.
- `frontend/src/App.tsx` — **без изменений**. Контракт пропсов `SkillsPanel` (`skills`, `documents`, `defaultDocId`, `onApply`, `onEdit`, `onDelete`, `onRename`) сохраняется полностью.

Переиспользовать без изменений: `DocumentCombobox`, хелперы `skillArity`, `defaultSlots`, `filterValidSlots`, `isSelectionValid`, `applyDocIds`, `mode2Hint`, `showsApplyPrompt`, `applyPromptArg`, `nonempty`, компонент `SkillModelMeta`.

## Layout и состояния

Вертикальный стек (`flex flex-col gap-2`), сверху вниз:

1. **Ошибка загрузки** — `skills.error` как красный текст (`text-xs text-red-400`), как сейчас.
2. **Поиск** — поле над списком (см. «Взаимодействия»). Показывать всегда, когда есть хотя бы один скил.
3. **Тулбар** — ряд общих кнопок управления над списком (см. «Взаимодействия»). Показывать всегда, когда есть хотя бы один скил.
4. **Список** — `<ul role="listbox">` строк фиксированной высоты.
5. **Контекст выбранного** — раскрывается внутри выбранной `<li>` под строкой-заголовком.

Состояния экрана:

- **Loading** — отдельного спиннера в панели нет; индикатор загрузки живёт в кнопке «Обновить» в `CollapsibleSection` (не трогаем). Панель просто рендерит текущий список.
- **Empty (нет скилов вообще)** — `skills.skills.length === 0`: показать текущее сообщение «Скиллов пока нет — создайте из сессии планировщика.» (`text-xs text-slate-500`). Поиск и тулбар в этом случае скрыть.
- **Empty (поиск ничего не нашёл)** — есть скилы, но фильтр дал 0: показать «Ничего не найдено» (`text-xs text-slate-500`) + кнопку «Сбросить», которая очищает `query`. Поиск и тулбар остаются видимыми.
- **Success** — рендер отфильтрованного списка; выбранная строка раскрыта.
- **Error (запуск/удаление)** — обрабатывается на уровне `App.tsx` (глобальный notice), в панели новых состояний ошибок не вводим.

### Строка списка (невыбранная)

Одна строка фиксированной высоты, всё в один ряд, ничего не переносится:

- Контейнер: `<li>` → кликабельный `<div role="option">` (или `<button>`-обёртка) высотой в одну строку, `flex items-center gap-2`, горизонтальные паддинги как у соседних списков (`px-2 py-1.5`), `rounded`, `truncate`-контент, `cursor-pointer`.
- Слева направо:
  1. **Бейдж статуса** — компактная точка/капсула. committed → `emerald` (`bg-emerald-600/30 text-emerald-300`), draft → `amber` (`bg-amber-600/30 text-amber-300`). Достаточно короткой формы (точка или 1–2 символа), не полное слово, чтобы экономить ширину; полное значение — в `title`/`aria`.
  2. **Имя** — `flex-1 min-w-0 truncate text-xs font-medium text-slate-200`, `title={s.name}` для полного имени по наведению.
  3. **Теги** — компактно, `shrink-0`. Показать до 2 тегов теми же цветами, что сейчас (`python` → sky, иначе → fuchsia); при большем числе — «+N». Каждый тег — `text-[10px] uppercase rounded px-1.5 py-0.5`.
  4. **Arity** — маленький значок/капсула справа (`shrink-0 text-[10px] text-slate-400`): `1` для arity 1, `2` для arity 2, `∗` (или `n`) для multi/null. Дать `title` («Один документ» / «Два документа» / «Несколько документов»).
- Описание, `SkillModelMeta` и кнопки управления в невыбранной строке **не выводятся**.
- Все строки одинаковой высоты — не допускать переноса тегов/имени на вторую строку (`overflow-hidden`, `whitespace-nowrap` где нужно).

### Строка списка (выбранная) + контекст

- Строка-заголовок остаётся такой же одной строкой (тот же layout), но визуально помечена как активная: `aria-selected="true"`, фон-подсветка (`bg-slate-800` или `bg-indigo-600/15`, консистентно с выделением документа `bg-indigo-600` — но мягче, т.к. строка раскрыта), рамка/левый акцент по желанию.
- Под строкой-заголовком, внутри той же `<li>`, раскрывается **контекст-блок** (`mt-1.5 flex flex-col gap-1.5`, отделён тонкой границей сверху `border-t border-slate-800 pt-1.5`):
  1. **Описание** — если есть: `text-[11px] text-slate-400`, обрезка до 2 строк (`line-clamp-2`) + переключатель «ещё»/«свернуть», раскрывающий полный текст. Если описания нет — блок не рендерим.
  2. **`SkillModelMeta`** — вывести как есть (провайдер/модель/reasoning).
  3. **Блок запуска** — только для `status === 'committed'`: перенести существующую разметку 1:1 (комбобоксы по arity 1/2/multi, подсказка `mode2Hint`, textarea промпта при `showsApplyPrompt`, кнопки «В док» / «На экран» с суффиксом `(N)`). Логику `slotsFor`/`setSlots`/`isSelectionValid`/`applyDocIds`/`applyPromptArg` **не менять**.
  - Для `DocumentCombobox` внутри раскрытой строки использовать `placement="top"` при необходимости, чтобы выпадашка не обрезалась низом сайдбара (по усмотрению генератора; не обязательно).

### Тулбар (общий, над списком)

- Ряд `flex flex-wrap items-center gap-1.5` над списком.
- Кнопки в стиле существующих управляющих (`rounded px-2 py-1 text-[11px]`, `bg-slate-700 text-slate-200`), с `disabled:opacity-50 disabled:cursor-not-allowed`:
  - **Переименовать** — активна при выбранном скиле; запускает инлайн-редактор имени (см. ниже).
  - **Редактировать** — активна при выбранном; вызывает `onEdit(id, name)`.
  - **Коммит** — активна только при выбранном скиле со `status === 'draft'`; вызывает `skills.commit(id)`. При committed/невыбранном — disabled.
  - **Overflow «⋯» / «Удалить»** — деструктивное действие вынести из ряда частых: либо в overflow-меню «⋯», либо отдельной кнопкой справа (`ml-auto`) с красным текстом (`text-red-400`). Активна при выбранном скиле.
- Когда `selectedId === null` — все кнопки тулбара disabled (кроме, при желании, самого триггера overflow, который тоже ничего не делает без выбора).
- **Инлайн-переименование** запускается из тулбара для выбранного скила. Редактор (input + «Сохранить»/«Отмена») можно показывать: (а) на месте строки-заголовка выбранного скила, либо (б) в самом тулбаре. Поведение Enter (сохранить), Escape (отмена), blur-автоотмена и флаг `renameSavingRef` — **не менять** (перенести существующую логику `startRename`/`saveRename`/`clearRename`).
- **Подтверждение удаления** обязано содержать **имя** скила. Заменить текущее двухкнопочное подтверждение на явный текст с именем, например: «Удалить скил "{name}"?» + кнопки «Удалить» (`bg-red-600/80 text-white`) / «Отмена». Показывать как инлайн-подтверждение в тулбаре/overflow либо как маленький блок под тулбаром. Существующую blur-автоотмену подтверждения сохранить.

## Взаимодействия

**Выбор строки:**
- Клик по строке (по области заголовка, вне интерактивных контролов внутри) → `selectedId = s.id`. Клик по уже выбранной строке-заголовку → `selectedId = null` (toggle, сворачивает контекст).
- Клики по контролам внутри раскрытого контекста (комбобоксы, textarea, кнопки запуска) не должны сворачивать/переключать выбор — обработчик выбора вешать только на строку-заголовок, не на весь `<li>`.

**Поиск:**
- Поле `type="search"` над списком, стиль как в `DocumentCombobox` (`w-full rounded bg-slate-800 px-2 py-1 text-[11px] text-slate-100 placeholder:text-slate-500`), placeholder «Поиск скиллов…», `aria-label="Поиск скиллов"`.
- Фильтрация клиентская, регистронезависимая, по подстроке в объединении полей `name` + `description` + `tags` (tags — join через пробел). Backend/`api.ts` не трогаем.
- При смене фильтра, если выбранный скил выпал из выдачи — снять выбор (`selectedId = null`).
- Пустая выдача → сообщение «Ничего не найдено» + кнопка «Сбросить» (`query = ''`).

**Тулбар:** см. раздел выше — действия применяются к `selectedId`, неактивны без выбора.

**Клавиатура (навигация по списку):**
- Фокус на контейнере списка (`<ul tabIndex={0}>` c `role="listbox"`, либо строки как `role="option"`), обработчик `onKeyDown`:
  - `↑` / `↓` — переместить выбор на предыдущий/следующий элемент **отфильтрованного** списка (с клампом на границах; при отсутствии выбора — выбрать первый/последний). `preventDefault`, чтобы не скроллить страницу.
  - `Enter` — если выбран скил со `status === 'committed'` и текущий выбор документов валиден (`isSelectionValid`), выполнить «В док» (`onApply(id, docIds, 'persist', prompt)`). Иначе — no-op.
  - `Esc` — снять выбор (`selectedId = null`). Если открыт инлайн-редактор имени или подтверждение удаления — Esc сперва закрывает их (существующее поведение), затем снимает выбор.
- Выбранная строка должна прокручиваться в зону видимости при навигации клавишами (`scrollIntoView({ block: 'nearest' })`).

**Крайние случаи:**
- Скил удалён/список обновился и выбранного id больше нет → `selectedId` сбрасывается в `null`.
- Переключение выбора между скилами не теряет введённые документы/промпт (состояние keyed по skill id).
- Поле поиска не должно перехватывать `↑`/`↓`/`Enter` навигации списка, пока фокус в самом поле (в поле стрелки двигают каретку — это ожидаемо; навигация по списку работает, когда фокус на списке/строке).

## Стиль и токены

Tailwind v3, тёмная slate-палитра — консистентно с текущим сайдбаром:

- **Строка:** `px-2 py-1.5 rounded text-xs`, невыбранная — `text-slate-300 hover:bg-slate-800/70`; выбранная — подсветка `bg-slate-800` (или `bg-indigo-600/15`) + `aria-selected`. Высота строки одинаковая для всех (одна текстовая строка + вертикальные паддинги).
- **Имя:** `text-xs font-medium text-slate-200 truncate`.
- **Бейджи (статус/теги/arity):** `text-[10px] uppercase rounded px-1.5 py-0.5`; статус — emerald/amber, теги — sky/fuchsia (как сейчас), arity — нейтральный `text-slate-400`.
- **Поиск:** `rounded bg-slate-800 px-2 py-1 text-[11px] text-slate-100 placeholder:text-slate-500`.
- **Кнопки тулбара:** `rounded px-2 py-1 text-[11px] bg-slate-700 text-slate-200`, деструктив — `text-red-400` / подтверждение `bg-red-600/80 text-white`.
- **Контекст-блок:** мелкий текст `text-[11px]`, отступы `gap-1.5`, разделитель `border-t border-slate-800`.
- Не вводить новые зависимости. `line-clamp` — через Tailwind-утилиту `line-clamp-2` (в v3 доступна из коробки в актуальных версиях; если плагин не подключён, допустима эквивалентная реализация через `overflow-hidden` + max-height, на усмотрение генератора).

## Доступность (a11y)

- Список: `<ul role="listbox" aria-label="Скиллы" tabIndex={0}>`; строки: `role="option"` + `aria-selected={selectedId === s.id}`. Каждой строке — доступное имя (текст имени + статус через `title`/`aria-label`).
- Выбранная строка получает `aria-selected="true"`; связь раскрытого контекста — через положение внутри той же `<li>` (контекст сразу после заголовка).
- Полное имя и полный статус доступны при усечении: `title` на имени, текстовый `aria-label`/`title` на бейдже статуса и значке arity.
- Клавиатура: работают `↑`/`↓`/`Enter`/`Esc` на списке (см. «Взаимодействия»); все кнопки тулбара и контролы запуска достижимы табом и имеют видимый фокус (`focus:ring` там, где уже принято в проекте).
- Кнопки управления имеют текстовые подписи; overflow-триггер «⋯» — с `aria-label="Ещё действия"`. Инлайн-редактор имени сохраняет `aria-label="Имя скила"` и `autoFocus`.
- Контраст: сохранять текущие сочетания slate-фон / светлый текст; бейджи с `/30` фоном и `-300` текстом уже используются в проекте.

## Критерии визуальной приёмки

- [ ] Невыбранный скил занимает ровно одну строку фиксированной высоты; в строке видны только статус, имя (с усечением), теги (до 2 + «+N»), значок arity. Описание, мета модели и кнопки в строке отсутствуют.
- [ ] Все строки списка визуально одинаковой высоты; длинное имя/много тегов не ломают строку (усечение, без переноса).
- [ ] Одновременно раскрыт максимум один скил — выбранный; повторный клик по нему сворачивает контекст.
- [ ] Поле поиска расположено над списком; ввод фильтрует список по имени, описанию и тегам без запроса к backend.
- [ ] Пустая выдача поиска показывает «Ничего не найдено» + рабочую кнопку «Сбросить»; полное отсутствие скилов показывает исходное сообщение и скрывает поиск/тулбар.
- [ ] Тулбар с общими кнопками («Переименовать», «Редактировать», «Коммит», «Удалить») расположен над списком; без выбора все кнопки неактивны; «Коммит» активен только для draft.
- [ ] «Удалить» вынесен из ряда частых действий (overflow «⋯» или отдельная позиция справа); подтверждение удаления показывает имя скила.
- [ ] Выбранная строка визуально помечена (подсветка + `aria-selected`); контекст (описание с обрезкой 2 строки + «ещё», мета модели, блок запуска для committed) раскрывается под ней.
- [ ] Блок запуска в контексте выглядит и работает как раньше: комбобоксы по arity 1/2/multi, подсказка о двух разных документах, textarea промпта для ai/agent, кнопки «В док»/«На экран» с суффиксом «(N)».
- [ ] Переключение выбора на другой скил и обратно сохраняет выбранные документы и текст промпта.
- [ ] Клавиатура: `↑`/`↓` перемещают выбор по видимому списку, `Enter` на выбранном committed запускает «В док», `Esc` снимает выбор; строки имеют `role="option"`/`aria-selected`, список — `role="listbox"`.
- [ ] Стиль строк, бейджей, поиска и кнопок консистентен с существующим сайдбаром (slate-палитра, размеры `text-xs`/`text-[10px]`/`text-[11px]`).
