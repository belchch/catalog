# CATALOG-95 — Экран настроек: управление ключами провайдеров после онбординга

- **Задача Plane:** [CATALOG-95](https://app.plane.so/belchch/projects/catalog-app/work-items/95) (id: `4eebc942-9eaf-4c55-ad3b-7f07bfc4bec1`, state: In Progress)
- **Статус плана:** Analyzed
- **Тип шага:** ui
- **Очередь:** 10 · blocked_by CATALOG-94
- **Цель:** Добавить в хедер иконку настроек и панель с блоком «Провайдеры», где ключ любого известного провайдера можно ввести или заменить после онбординга; после сохранения провайдер становится доступен в `ModelSelector` без перезагрузки. Заодно починить онбординг: выбранный там провайдер должен становиться активным.

## Постановка задачи (актуальное ТЗ)
_(источник: описание задачи; комментариев нет)_

### Контекст
Единого экрана настроек в приложении нет. Шестерёнки в хедере нет (`frontend/src/App.tsx:524-543` — только заголовок и `ModelSelector`). Настройки размазаны по модалкам: `SetupKeyScreen` (одноразовый), `SessionTimeoutModal`, `SkillSettingsModal`, `WorkspacePicker`.

Из-за этого пользователь, подключивший на старте OpenRouter, не может добавить z.ai — форма ввода ключа больше не показывается.

Зависит от задачи «GET /setup: полный список провайдеров» — экран берёт данные оттуда.

### Что сделать
1. Добавить в хедер иконку настроек, открывающую модалку/панель настроек.
2. Блок «Провайдеры» в этой панели: список всех известных провайдеров из `GET /setup`, у каждого — статус и действие:
   - подключён → «Подключён» + кнопка «Заменить ключ»
   - без ключа → поле ввода + «Сохранить»
   - `managed_by_env: true` → «Задан через переменную окружения», поле ввода заблокировано с пояснением, что запись через UI не применится
3. Сохранение — `PUT /setup/keys` с одним полем (частичное обновление уже поддерживается на бэкенде).
4. Ключи не отображать: сервер их не возвращает, поэтому поле всегда пустое, а текущее состояние показывается статусом.
5. После успешного сохранения перезапросить список провайдеров и настройки, чтобы новый провайдер сразу появился в `ModelSelector` без перезагрузки страницы (`useSettings`, `useSetup`).
6. Заодно поправить онбординг: после сохранения ключа z.ai на `SetupKeyScreen` радио-кнопка выбирает только целевое поле ключа, но не переключает активного провайдера. Сделать следом `POST /settings` с выбранным провайдером.

## Контекст
- **Предусловие:** [CATALOG-94](docs/plan/night-shift/09-CATALOG-94-code-setup-providers-list.md) — backend-часть, добавляющая в `GET /setup` поле `providers` с `id`, `name`, `configured`, `managed_by_env`, `active`. Без него панель не сможет показать провайдера без ключа. `code` выполняется раньше этого `ui`-плана.
- Хедер подтверждён: `frontend/src/App.tsx:524-545` — слева заголовок с git sha (`:525-533`), справа `ModelSelector` (`:534-543`). Иконку настроек ставить рядом с `ModelSelector`.
- Гейт онбординга: `App.tsx:518-520` — при `!setup.keysConfigured` рендерится только `SetupKeyScreen`, весь основной UI недоступен. Поэтому иконка настроек живёт в основной ветке (после `:522`) и доступна всегда, когда UI отрисован.
- `useSetup` (`frontend/src/hooks/useSetup.ts`) сейчас хранит из ответа только `keys_configured` (`:8`, `:15`, `:29`) и не отдаёт наружу ни `provider`, ни список провайдеров. Для панели нужно расширить хук: сохранять весь `SetupOut` и добавить метод перезапроса (`refresh`), чтобы после `PUT /setup/keys` обновить статусы.
- Тип ответа на клиенте: `SetupOut` — `frontend/src/api.ts:484-489` (`keys_configured`, `provider`, `openrouter_configured`, `zai_configured`). Нужно добавить `providers: ProviderSetupOut[]` в соответствии с новой схемой бэкенда; `ProviderOut` (`api.ts:164-168`) — другой тип (для `/providers`), переиспользовать его нельзя.
- Сохранение ключа уже реализовано: `saveProviderKey` — `api.ts:504-510` (`PUT /setup/keys`), принимает `SetupKeysInput` (`:491-…`) с необязательными полями, то есть частичное обновление доступно с клиента без изменений API.
- `ModelSelector` получает список провайдеров из `useSettings` (`App.tsx:537`), а тот грузит `listProviders()` один раз в эффекте на `[enabled]` (`frontend/src/hooks/useSettings.ts:43-86`). Публичного метода перезагрузки списка нет — его надо добавить (например `refreshProviders`), иначе новый провайдер не появится без F5.
- Онбординг: `SetupKeyScreen` (`frontend/src/components/SetupKeyScreen.tsx`). Радио-группа выбирает `provider` (`:18`, `:79-105`), а `handleSubmit` (`:31-47`) отправляет только соответствующее поле ключа (`:37-40`) и вызывает `onConfigured(result)` (`:42`). Вызова `POST /settings` нет — активный провайдер остаётся тем, что выбрал бэкенд (по умолчанию `openrouter`, см. `select_provider` в `backend/catalog/llm/factory.py:51-65`). Это и есть баг из п. 6.
- Смена активного провайдера на клиенте уже есть: `updateSettings` (`api.ts:516-522`) и `changeProvider` в `useSettings` (`:88-116`). Важный нюанс: `POST /settings` на бэкенде отклоняет провайдера, которого нет среди собранных инстансов (404, `backend/catalog/api/models.py:129-131`). После `PUT /setup/keys` провайдер пересобирается (`models.py:187`, `apply_runtime_providers`), поэтому вызов `POST /settings` должен идти **после** успешного сохранения ключа, иначе получим 404.
- Существующие модалки как образец разметки и поведения (overlay, `role="dialog"`, `aria-modal`, `Escape`): `WorkspacePicker` (`frontend/src/components/WorkspacePicker.tsx:158-180`), плюс `SessionTimeoutModal`, `SkillSettingsModal`. Классы `.modal-overlay` / `.modal-card` уже есть в `frontend/src/index.css`.
- Безопасность: сервер ключи не возвращает (`SetupOut` их не содержит), поле ввода всегда пустое. Ключ нельзя писать в `localStorage` — заметим, что `useSettings` пишет туда только `provider`/`model` (`useSettings.ts:27-32`), эту практику расширять на ключи запрещено.
- Иконка настроек: готового модуля иконок в проекте нет. [CATALOG-89](docs/plan/night-shift/04-CATALOG-89-ui-message-command-icons.md) создаёт `frontend/src/components/icons.tsx` — если он выполнен раньше, шестерёнку добавить туда же; иначе создать модуль в рамках этой задачи. Новых npm-зависимостей не тянуть.
- Автотестов фронтенда нет; проверки — `pnpm run build`, `pnpm run lint`, `pnpm run typecheck` из `frontend/` плюс ручной прогон.

## План действий
1. Расширить типы в `api.ts`: `ProviderSetupOut { id, name, configured, managed_by_env, active }` и `providers: ProviderSetupOut[]` в `SetupOut` (`:484-489`).
2. Переписать `useSetup` (`useSetup.ts`): хранить весь ответ `GET /setup`, отдавать наружу `setup` (или `providers` + `provider`) вместе с существующими `status` / `keysConfigured` / `markConfigured`, добавить `refresh()`, который перезапрашивает `GET /setup` и обновляет состояние.
3. В `useSettings` (`useSettings.ts:43-86`) вынести загрузку `listProviders()` в отдельный колбэк и вернуть его как `refreshProviders`, не ломая существующую инициализацию и логику `changeProvider` (`:88-116`).
4. Создать `SettingsPanel.tsx`: модалка на `.modal-overlay` / `.modal-card` по образцу `WorkspacePicker` (`:158-180`) — `role="dialog"`, `aria-modal`, `aria-labelledby`, закрытие по `Escape` и по кнопке, начальный фокус.
5. Блок «Провайдеры» в панели: по каждому элементу `setup.providers` — имя, статус и действие. `configured && !managed_by_env` → «Подключён» + «Заменить ключ» (раскрывает поле ввода). `!configured && !managed_by_env` → поле ввода + «Сохранить». `managed_by_env` → «Задан через переменную окружения», ввод `disabled`, пояснение, что запись через UI не применится.
6. Поле ключа: `type="password"`, `autoComplete="off"`, `spellCheck={false}`, всегда пустое при открытии; после успешного сохранения очищать. Ключ не логировать и не писать в `localStorage`.
7. Сохранение: `saveProviderKey({ <нужное поле>: trimmed })` (`api.ts:504`). На время запроса — `disabled` + индикация; ошибки показывать через `extractApiDetail` в `role="alert"` (как в `SetupKeyScreen.tsx:126-130`).
8. После успешного сохранения последовательно вызвать `setup.refresh()` и `settings.refreshProviders()`, чтобы статусы в панели и список в `ModelSelector` обновились без F5. Проверить, что активный провайдер при этом не переключается сам собой.
9. Добавить в хедер (`App.tsx:524-545`) icon-кнопку настроек с `aria-label` «Настройки» и `title`, рядом с `ModelSelector`; состояние открытия панели держать в `App`. Кнопка доступна всегда в основной ветке рендера (после гейта `:518-520`).
10. Починить онбординг в `SetupKeyScreen.tsx`: в `handleSubmit` после успешного `saveProviderKey` (`:41`) вызвать `updateSettings({ provider, model: … })` (или узкий вариант с одним `provider`) и только затем `onConfigured(result)`. Порядок важен — до пересборки провайдеров `POST /settings` вернёт 404 (`backend/catalog/api/models.py:129-131`). Ошибку смены провайдера обработать так, чтобы она не блокировала вход в приложение с уже сохранённым ключом.
11. Проверить доступность: Tab-порядок в панели, focus-ring, закрытие по `Escape`, `aria-label` у иконки, объявление ошибок через `role="alert"`.
12. Ручные проверки: открыть панель при настроенном одном провайдере — видны оба; ввести ключ второго → он появляется в `ModelSelector` без F5; провайдер с ключом из env — ввод заблокирован с пояснением; введённый ключ нигде не показывается обратно и отсутствует в `localStorage` (проверить DevTools → Application); онбординг с ключом z.ai оставляет активным z.ai.
