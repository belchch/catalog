## Постановка задачи (актуальное ТЗ)
_(источник: последний комментарий от 2026-07-18)_

Сделано неверно. Пользователь может указать параметры. Это нужно сделать отдельным параметром при сохранении скила. Выбор в модалке сохранения: 1 документ, 2 документа, список документов. При выполнении скила контрол заполнения параметров разный в зависимости от типа: Combobox (single) / два combobox / Combobox (multi-select).

## Предыстория

> Это уже было: старое описание и предыдущие обсуждения. Приведено для контекста, НЕ является актуальным заданием.

**Описание задачи:** Сейчас можно выбирать только один документ в параметрах скила. Скилы могут принимать один, два или список. Расширить структуру данных, при необходимости доработать UI.

## Контекст

- `SkillSettingsModal.tsx` — model/provider/reasoning; **нет** выбора режима входа; `configureSkill` шлёт только эти три поля (`api.ts:165-173`).
- `SkillsPanel.tsx:104-140` — единый чек-лист документов для любого скила (не соответствует ТЗ).
- `SkillOut` на фронте без arity (`api.ts:11-21`); `SkillPreview.input_arity` есть (`api.ts:54`), но в модалке не редактируется.
- Backend API — в code-плане.

## Затрагиваемые файлы

- `frontend/src/components/SkillSettingsModal.tsx` — radio/select: 1 / 2 / список; передать в `configureSkill`.
- `frontend/src/api.ts` — типы + `configureSkill` + `SkillOut` поле режима.
- `frontend/src/components/SkillsPanel.tsx` — заменить чек-лист на контролы по режиму скила.
- Возможно маленький shared combobox-компонент для выбора документа(ов).

## План действий

1. В модалке сохранения — явный выбор режима входа; сохранить через configure.
2. Пробросить режим из `SkillOut` в `SkillsPanel`.
3. Apply UI:
   - режим 1 → один combobox (single);
   - режим 2 → два combobox;
   - список → combobox multi-select.
4. Кнопки «В док» / «На экран» disabled, пока выбор не валиден для режима.
5. Ручная проверка трёх режимов на разных скилах.
