## Цель и пользовательский путь

Пользователь может удалить скилл прямо из панели «Скиллы» в левом сайдбаре, с явным подтверждением, чтобы не удалить по случайному клику.

Сценарий:
1. В панели «Скиллы» пользователь видит карточку скилла (draft или committed).
2. В ряду действий карточки есть кнопка «Удалить».
3. По клику кнопка сменяется inline-подтверждением: «Удалить?» + [Удалить] / [Отмена] — без модального окна и без нативного `window.confirm`.
4. Клик «Удалить» → скилл удаляется, карточка исчезает из списка. При ошибке карточка остаётся, показывается сообщение.
5. Клик «Отмена» (или потеря фокуса с ряда действий) → возврат к обычному виду кнопки.

## Дерево компонентов и файлы

- `frontend/src/components/SkillsPanel.tsx` (изменяется) — добавляется кнопка «Удалить» с inline-подтверждением в блок действий каждой карточки скилла; локальный state подтверждения по `skill.id`. Новый проп `onDelete: (skillId: string) => void`.
- `frontend/src/hooks/useSkills.ts` (изменяется) — добавляется метод `remove(skillId: string): Promise<void>` в `UseSkillsResult`: вызывает `deleteSkill`, при успехе убирает скилл из локального стейта (`setSkills(prev => prev.filter(...))`), при ошибке — прокидывает наверх / выставляет `error`.
- `frontend/src/api.ts` (изменяется) — `deleteSkill(skillId: string): Promise<void>` (`DELETE /skills/{id}`), по образцу `deleteSession`.
- `frontend/src/App.tsx` (изменяется) — прокидывает `onDelete={(id) => void skillsHook.remove(id)}` в `SkillsPanel`; при необходимости показывает результат через существующий механизм `notice`/`skills.error`.

Новые зависимости не вводятся.

## Layout и состояния

Кнопка удаления живёт в существующем ряду действий карточки (`<div className="mt-2 flex flex-wrap items-center gap-1.5">`), рядом с «Редактировать»/«Коммит»/«В док»/«На экран». Кнопка «Удалить» показывается для **обоих** статусов (draft и committed).

Состояния карточки в контексте удаления:
- **default** — видна кнопка «Удалить» (обычный вид действия).
- **confirming** — вместо одиночной кнопки показаны две: «Удалить» (акцент опасности) и «Отмена». В этом состоянии только у той карточки, чей `id` в локальном `confirmId`; у остальных — default.
- **deleting** (опционально, если удобно генератору) — кнопки подтверждения `disabled`, чтобы избежать двойного клика; без обязательного спиннера.
- **error** — глобальная ошибка панели уже рендерится через `skills.error` (`<p className="text-xs text-red-400">`), отдельный per-card блок не требуется; при ошибке карточка остаётся в списке.
- **success** — карточка исчезает из `<ul>`; если удалён последний скилл, показывается существующий empty-state («Скиллов пока нет — создайте из сессии планировщика.»).

Панель в целом сохраняет текущий layout (`flex flex-col gap-2`, карточка — `rounded-md border border-slate-800 bg-slate-900/60 p-2`).

## Взаимодействия

- Клик «Удалить» (default) → `setConfirmId(skill.id)`; переход в confirming.
- Клик «Удалить» (confirming) → `setConfirmId(null)` затем `onDelete(skill.id)`.
- Клик «Отмена» → `setConfirmId(null)`, возврат в default.
- Потеря фокуса с ряда действий карточки (blur наружу контейнера) → сброс `confirmId` (как в `SessionsPanel` через проверку `relatedTarget`), чтобы «висящее» подтверждение не оставалось.
- Одновременно подтверждение активно максимум у одной карточки (single `confirmId`).
- Все кнопки — `type="button"`, чтобы не сабмитить формы.
- Крайние случаи:
  - Ошибка удаления → карточка остаётся, `skills.error` показывает текст; повторный клик возможен.
  - Быстрый повторный клик → защищается либо переходом confirming→удаление за один заход, либо `disabled` на время запроса.
  - Удаление скилла, у которого открыт combobox выбора документа (committed) — допустимо; карточка просто исчезает.

## Стиль и токены

Консистентно с существующими действиями карточки и с паттерном удаления в `SessionsPanel`:
- Кнопка «Удалить» (default): тот же размер, что соседние — `rounded px-2 py-1 text-[11px]`; для сигнала опасности использовать красный текст `text-red-400` на нейтральном фоне (`bg-slate-700` как у соседей) либо только текстовый вариант `text-red-400 hover:bg-slate-800`. Выбрать один вариант и применить единообразно.
- Confirming: «Удалить» — акцент опасности (`text-red-400`, при желании фон `bg-red-600/80 text-white`); «Отмена» — нейтраль (`text-slate-300`/`bg-slate-700`). Размер как у остальных действий (`text-[11px]`).
- Отступы/раскладка — переиспользовать существующий `flex flex-wrap items-center gap-1.5`; новых spacing-токенов не вводить.
- Никаких новых цветов вне текущей палитры slate/red/indigo/emerald/amber.

## Доступность (a11y)

- Кнопка удаления в default имеет понятный текст «Удалить» (текстовая, не только иконка); если используется иконочный вариант — обязателен `aria-label="Удалить скилл"`.
- В confirming кнопки имеют явный видимый текст «Удалить»/«Отмена».
- Управление с клавиатуры: все элементы — нативные `<button>`, фокусируемы и активируются Enter/Space.
- Логика blur-сброса не должна ломать переход фокуса между «Удалить» и «Отмена» (проверять `relatedTarget` в пределах контейнера действий, как в `SessionsPanel`).
- Контраст `text-red-400` на тёмном фоне достаточен; акцентный фон опасности — только с `text-white`.

## Контракты данных

- `DELETE /skills/{id}` → 204/200 при успехе, 404 если скилла нет (см. `CATALOG-26-code-delete-skill.md`). Backend сам обрабатывает связанные runs (cascade) — фронту дополнительная логика не нужна.
- Клиент: `deleteSkill(skillId): Promise<void>` в `api.ts` (по образцу `deleteSession`, бросает `Error` с телом ответа при `!res.ok`).
- Хук: `remove` в `useSkills` обновляет `skills` оптимистично/после ответа и управляет `error`.
- Типы дополнительные не требуются.

## Критерии визуальной приёмки

- [ ] В каждой карточке скилла (и draft, и committed) есть кнопка «Удалить» в ряду действий.
- [ ] Клик «Удалить» показывает inline-подтверждение с кнопками «Удалить» и «Отмена» (без нативного `confirm` и без модалки).
- [ ] Подтверждение активно максимум у одной карточки одновременно; «Отмена» и потеря фокуса сбрасывают его.
- [ ] После успешного удаления карточка исчезает из списка; при удалении последнего скилла виден empty-state.
- [ ] При ошибке удаления карточка остаётся, ошибка видна через `skills.error` (красный текст).
- [ ] Стиль кнопок консистентен с соседними действиями и с паттерном удаления в `SessionsPanel`; красный используется только как сигнал опасности.
- [ ] Кнопки — `type="button"`, доступны с клавиатуры; иконочный вариант (если выбран) имеет `aria-label`.
