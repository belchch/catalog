- **Статус дизайна:** Ready

## Цель и пользовательский путь

Две точки редактирования имени скила, обе — без захода в чат-планировщик:

1. **При сохранении (модалка настройки).** После «Создать скилл» открывается `SkillSettingsModal`. Сейчас имя показано read-only строкой. Пользователь должен иметь возможность поправить имя прямо здесь; новое имя уходит вместе с настройками модели в `configure` (draft).
2. **У сохранённых скилов (панель).** В `SkillsPanel` рядом с именем — быстрое действие «переименовать»: имя превращается в input, пользователь правит, жмёт Enter/«Сохранить», список сразу отражает новое имя. Работает и для `draft`, и для `committed`.

Важно не смешивать с уже существующей кнопкой «Редактировать» в панели — она открывает полноценную edit-сессию планировщика (правка промпта/инструментов через чат) и остаётся без изменений. Переименование — отдельное лёгкое действие «только имя».

## Дерево компонентов и файлы

- `frontend/src/api.ts` — **изменить:** добавить `name?: string` в аргумент `configureSkill`; **добавить** helper `renameSkill(skillId, name): Promise<SkillOut>` → `PATCH /skills/{id}` с телом `{ name }`.
- `frontend/src/hooks/useSkills.ts` — **изменить:** добавить в `UseSkillsResult` метод `rename(skillId, name): Promise<void>`, который зовёт `renameSkill`, обновляет имя в локальном `skills` (map по `id`) и прокидывает ошибку в `error`/наверх (как `remove`).
- `frontend/src/components/SkillSettingsModal.tsx` — **изменить:** read-only `<p>{preview.name}</p>` → редактируемое поле «Имя»; `name` в локальном стейте, уходит в `configureSkill`.
- `frontend/src/components/SkillsPanel.tsx` — **изменить:** имя-`<span>` + inline-режим переименования (input + «Сохранить»/«Отмена»); прокинуть новый проп `onRename(skillId, name): void`.
- `frontend/src/App.tsx` — **изменить:** передать `onRename={(id, name) => void skillsHook.rename(id, name)}` в `SkillsPanel` (по аналогии с `onDelete`), обработать ошибку в `notice` при необходимости.

Новых зависимостей и новых файлов не вводить.

## Layout и состояния

### Модалка (`SkillSettingsModal`)
- Поле «Имя» встаёт первым блоком под заголовком «Настройка скила» — на месте текущей строки `preview.name` (строка 93). Это `<label>` + `<input type="text">` в том же визуальном стиле, что и селекты (класс `fieldCls`), с подписью `text-[11px] text-slate-400` как у соседних полей («Провайдер», «Модель»).
- Состояния поля:
  - **normal** — значение = текущее имя, редактируемо.
  - **invalid** — значение после `trim()` пустое: кнопка «Сохранить» задизейблена (в дополнение к `saving`), под полем — подсказка `text-[10px] text-red-400` «Имя не может быть пустым».
  - **saving** — как сейчас: обе кнопки disabled, лейбл «Сохранение…».
  - **error** (ответ бэка) — существующий блок `error` над кнопками (например 422 при пустом имени).
- В `handleSave` в `configureSkill(...)` добавляется `name: name.trim()`. Остальная логика модалки не меняется.

### Панель (`SkillsPanel`)
Строка скила (`<li>`) получает два состояния имени:
- **view** (по умолчанию): как сейчас — `<span class="truncate text-xs font-medium text-slate-200">{s.name}</span>`, плюс рядом маленькая кнопка-триггер переименования (иконка-карандаш `✎`, `aria-label="Переименовать"`, стиль как у прочих мелких кнопок: `text-slate-400 hover:text-slate-200`). Теги/статус справа не трогаем.
- **edit**: вместо `<span>` — `<input type="text">` (стиль поля как `fieldCls`, но компактно в строку) с автофокусом и предзаполненным именем, плюс кнопки «Сохранить» (`bg-indigo-600`) и «Отмена» (`bg-slate-700`), в стиле мелких кнопок панели (`text-[11px]`).
  - **saving** — input и кнопки disabled на время запроса; лейбл кнопки «…».
  - **error** — сообщение через `skills.error` (уже рендерится вверху панели как `text-xs text-red-400`) либо локально под строкой; отдельного нового места не требуется.
- Одновременно в режиме переименования — только один скил (стейт `renameId: string | null`, по аналогии с `confirmId`). Открытие rename у другого скила / нажатие «Редактировать»/«Удалить» сбрасывает `renameId`.

Пустой список, теги, статусы, блоки применения (arity 1/2/список) — без изменений.

## Взаимодействия

Модалка:
- Ввод в поле «Имя» → обновляет стейт; пустое (после trim) → «Сохранить» недоступна.
- «Сохранить» → `configureSkill` с `name` → `onSave()` → `onClose()` (как сейчас).

Панель:
- Клик по `✎` → строка переходит в **edit**, input автофокусируется, курсор/выделение в конце.
- **Enter** в input → сохранить; **Escape** → отмена (вернуть view, значение не менять).
- Клик «Сохранить» → `onRename(s.id, value.trim())`; при пустом значении (после trim) — сохранение заблокировано (кнопка disabled), как в модалке.
- Клик «Отмена» / blur без изменений → вернуть view. (Blur-автосейв не делаем во избежание случайных правок; закрываем в view.)
- После успешного `rename` список показывает новое имя (обновление локального стейта в `useSkills`), строка возвращается в view. Если имя не изменилось — можно просто выйти из edit без запроса.
- Крайние случаи: имя из одних пробелов → блокируем как пустое; сетевые/валидационные ошибки → показать `skills.error`, оставить строку в edit, чтобы можно было повторить.

## Стиль и токены

- Полное соответствие текущей тёмной палитре: фон полей `bg-slate-800`, текст `text-slate-100`, подписи `text-slate-400`, акцент/подтверждение `bg-indigo-600 text-white`, вторичные `bg-slate-700 text-slate-200`, ошибки `text-red-400`.
- Размеры шрифта и отступы — как у соседей: модалка `text-xs`/`text-[11px]`, панель `text-[11px]`/`text-[10px]`.
- Поле имени в модалке переиспользует `fieldCls` (`w-full rounded bg-slate-800 px-2 py-1 text-xs text-slate-100`).
- Инпут в панели — тот же визуальный язык, компактный, не ломает высоту строки списка; `truncate` заменяется на нормальный ввод в режиме edit.
- Иконка-карандаш — текстовый глиф `✎` (как `✕` в модалке), без новых icon-зависимостей.

## Доступность (a11y)

- Модалка: `<label>Имя` связан с input (label оборачивает input, как у «Провайдер»/«Модель»). Подсказка о пустом имени — рядом с полем, читаемый контраст.
- Панель: кнопка-триггер `aria-label="Переименовать"`; input в edit-режиме `aria-label="Имя скила"`.
- Клавиатура: `autoFocus` на input при входе в edit; **Enter** — сохранить, **Escape** — отмена (`onKeyDown`).
- Фокус не теряется: при отмене/сохранении фокус логично вернуть на строку/кнопку `✎` (минимум — не оставлять фокус на удалённом DOM-узле).
- Кнопки disabled-состояния используют `disabled:opacity-50`, как в остальном UI.

## Контракты данных

- **Модалка (draft):** `PATCH /skills/{id}/configure`, тело `{ model, provider, reasoning, input_arity, name }`. Бэкенд (`SkillConfigureRequest`) уже принимает опциональный `name`, тримит и отклоняет пустой (валидатор `name must be non-empty`). Доступно только для `draft` (иначе 409) — это ровно сценарий модалки сохранения.
- **Панель (draft и committed):** `PATCH /skills/{id}`, тело `{ name }` → ответ `SkillOut`. Бэкенд (`SkillRenameRequest`, endpoint `rename_skill_endpoint`) тримит и отклоняет пустое имя. Работает вне зависимости от статуса — поэтому именно этот endpoint используется для переименования сохранённых скилов.
- Типы: `SkillOut`, `SkillBuilt`, `SkillPreview` уже определены в `api.ts`; `name` в них присутствует. Новых типов не требуется.
- Ссылки: план шага `docs/plan/night-shift/CATALOG-30-ui-skill-rename.md`; API-шаг `docs/plan/night-shift/CATALOG-30-code-skill-rename.md`.

## Критерии визуальной приёмки

- [ ] В модалке настройки имя — редактируемое текстовое поле (не read-only), первым блоком, в стиле соседних полей.
- [ ] Пустое имя (после trim) в модалке блокирует кнопку «Сохранить» и показывает подсказку.
- [ ] «Сохранить» в модалке отправляет `name` в `configure` вместе с настройками модели.
- [ ] У каждого скила в панели есть отдельное действие переименования (`✎`, `aria-label="Переименовать"`), не совпадающее с кнопкой «Редактировать».
- [ ] Клик по действию переводит имя в input с автофокусом и предзаполненным значением.
- [ ] Enter сохраняет, Escape отменяет; «Сохранить»/«Отмена» присутствуют и работают.
- [ ] Пустое имя в панели не сохраняется (кнопка disabled).
- [ ] После сохранения список сразу показывает новое имя без ручного «Обновить»; строка возвращается в view.
- [ ] Переименование доступно и для `draft`, и для `committed`.
- [ ] Стиль (цвета/размеры/отступы) консистентен с существующей панелью и модалкой; тёмная тема сохранена.
- [ ] Ошибка бэка при переименовании отображается пользователю (через `skills.error`), строка остаётся редактируемой.
