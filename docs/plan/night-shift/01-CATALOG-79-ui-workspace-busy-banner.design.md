# CATALOG-79 — Дизайн UI

- **Источник:** `docs/plan/night-shift/01-CATALOG-79-ui-workspace-busy-banner.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Пользователь открывает модалку «Открыть воркспейс» (`WorkspacePicker`) в момент, когда бэкенд считает воркспейс занятым (`GET /workspaces/busy` → `busy: true`, `reason: "run" | "session"`).

Сценарий:
1. Пользователь жмёт «Открыть папку» / «Проект → сменить папку» → модалка открывается, статус занятости уже запрошен из `App`.
2. **Сразу под заголовком модалки** видит баннер-предупреждение с причиной: идёт выполнение скилла либо активна сессия чата. Читает его до того, как начал ходить по дереву.
3. Все элементы, ведущие к смене воркспейса, визуально погашены и недоступны: карточки «Недавние», «Открыть эту папку», «Открыть» в строке списка, кнопки подтверждения в pending-панели.
4. Обзор остаётся живым: пользователь может войти в папку по клику на её имени, подняться «Вверх», прочитать бейдж «воркспейс», закрыть модалку по ✕ или Escape.
5. Когда ран/сессия завершились, `App` обновляет статус, баннер исчезает, кнопки открытия снова активны — без перемонтирования модалки и без потери текущей позиции в дереве.

Гонка: если занятость возникла между запросом статуса и нажатием «Открыть», приходит 409 — сообщение из `detail` показывается в существующей pending-панели (ошибка), а статус занятости обновляется, из-за чего дополнительно появляется баннер. Модалка остаётся интерактивной.

## Дерево компонентов и файлы

Новых файлов компонентов не добавляем — баннер живёт внутри пикера, чтобы не расширять скоуп шага.

- `frontend/src/components/WorkspacePicker.tsx` (изменяется)
  - Новые пропсы: `blocked: boolean`, `blockedReason: 'run' | 'session' | null`.
  - Локальная чистая функция уровня модуля (рядом с `folderName` / `formatLastOpened`) — маппинг `blockedReason` → `{ title, hint }` для текста баннера.
  - Новый блок разметки — секция-баннер между строкой заголовка (`:166-180`) и секцией «Недавние» (`:182`). Рендерится только при `blocked === true`.
  - `useId()` уже используется для `titleId`; добавляется второй id для баннера, чтобы кнопки открытия ссылались на него через `aria-describedby`.
  - Производный флаг `openDisabled = submitting || blocked` — единственная точка, из которой берут `disabled` все пути открытия. Навигация (`goInto`, `goUp`) и «Закрыть» продолжают смотреть только на `submitting`.
- `frontend/src/App.tsx` (изменяется) — прокидывает `blocked` / `blockedReason` из `useWorkspace` в `WorkspacePicker` (`:823-830`), обновляет статус в `openPicker` (`:167`), после завершения рана/стрима и после 409 в `handleBusyConflict`.
- `frontend/src/hooks/useWorkspace.ts`, `frontend/src/api.ts` — источник данных, вне визуальной части (см. «Контракты данных»).

## Layout и состояния

Порядок блоков внутри `modal-card` (сверху вниз):

1. Строка заголовка: «Открыть воркспейс» + ✕ (без изменений).
2. **Баннер занятости** — только при `blocked`.
3. Секция «Недавние» (если есть).
4. Секция «Обзор папок»: путь + «Вверх» + «Открыть эту папку», затем список.
5. Pending-панель (`needs_init` / `needs_confirm` / `error`).

Баннер:
- Контейнер: блок на всю ширину карточки, отступ снизу как у секций (`mb-4`), рамка + мягкий фон предупреждения, скругление как у pending-панели (`rounded`), внутренние отступы `px-3 py-2`.
- Внутри — двухстрочная композиция: строка-заголовок (`text-xs`, `font-medium`) и пояснение (`text-[11px]`, тон приглушённее). Слева — декоративный глиф-предупреждение (`aria-hidden="true"`, `shrink-0`), справа — текстовый столбец (`min-w-0`), выравнивание по верху (`items-start gap-2`).
- Баннер **не** перекрывает контент и не затемняет модалку: это подсказка, а не оверлей.

Состояния экрана:

| Состояние | Что показываем |
|---|---|
| `blocked === false` (в т.ч. статус ещё не получен или запрос упал) | Баннера нет, всё как сейчас. Отдельного скелетона/«загрузка статуса» нет — недоступность эндпоинта не должна ни блокировать, ни мигать в интерфейсе. |
| `blocked === true`, `reason === 'run'` | Заголовок: «Идёт выполнение скилла — переключение воркспейса недоступно». Пояснение: «Смотреть папки можно; открыть другую папку получится после завершения.» |
| `blocked === true`, `reason === 'session'` | Заголовок: «Активна сессия чата — переключение воркспейса недоступно». Пояснение то же. |
| `blocked === true`, `reason === null` | Заголовок: «Воркспейс занят — переключение недоступно». Пояснение то же. Ветка обязательна: `busy: true` без причины не должен давать пустой баннер. |
| `submitting` (собственный open/rescan) | Поведение как сейчас (кнопки disabled, тексты «…» / «Индексирую…»). Баннер занятости **не** показываем: локальный `busy` из `useWorkspace` в баннер не участвует. |
| 409 при гонке | Баннер (после обновления статуса) + pending-панель `error` с `detail` в стиле ошибки (`text-danger-ink`) — существующая ветка `:322-324`, не меняется. |
| Загрузка/ошибка обзора ФС | Без изменений: «Загрузка…» / текст ошибки / «Нет вложенных папок». Баннер и обзор независимы. |

## Взаимодействия

Недоступны при `blocked` (через `openDisabled`):
- карточка «Недавние» (`:190-210`);
- «Открыть эту папку» (`:235-242`);
- «Открыть» в строке списка (`:271-278`);
- «Создать воркспейс» (`:293-300`) и «Сделать воркспейсом и проиндексировать» (`:311-318`).

Исключений для «текущей папки» нет: даже если путь совпадает с открытым воркспейсом, кнопка гасится — так проще и совпадает с приёмкой плана.

Остаются рабочими:
- клик по имени папки → `goInto` (`:258-270`);
- «Вверх» (`:227-234`);
- ✕ «Закрыть» (`:170-179`) и Escape (`:97-103`);
- скролл модалки, `title`-подсказки с полными путями.

Обратная связь:
- Погашенные кнопки получают `title` с короткой причиной («Идёт выполнение скилла» / «Активна сессия чата»), чтобы наведение объясняло запрет без чтения баннера.
- Никаких тостов/алертов: единственный носитель объяснения — баннер, плюс `detail` при 409.
- Курсор на погашенных элементах — `not-allowed` (уже заложено в `.btn-secondary` / `.btn-primary` и в классах карточки недавних).

Крайние случаи:
- Занятость появилась, пока модалка открыта: баннер въезжает над секциями, кнопки гаснут; текущая позиция в дереве, `entries` и открытая pending-панель сохраняются (панель не закрываем — пользователь должен видеть, почему подтверждение стало недоступным).
- Занятость исчезла: баннер убирается, кнопки включаются; фокус никуда не перебрасываем.
- Появление/исчезновение баннера меняет высоту карточки — она уже `max-h-[80vh] overflow-y-auto`, поэтому скролл берёт это на себя; прыжка вёрстки в остальных секциях быть не должно.

## Стиль и токены

Только существующие Tailwind-утилиты и токены из `frontend/src/index.css` — новых зависимостей и новых CSS-классов не вводим.

- Тон баннера — предупреждение (не ошибка): `border border-warning-line bg-warning-soft text-warning-ink`. Danger-палитра остаётся за реальными ошибками (`pending.kind === 'error'`, 409), чтобы состояния визуально не сливались.
- Геометрия: `rounded`, `px-3 py-2`, `mb-4` — те же величины, что у pending-панели (`:286`) и секций пикера.
- Типографика: заголовок баннера `text-xs font-medium`, пояснение `text-[11px]`; ту же шкалу использует вся модалка (`text-xs` для контента, `text-[11px]` для подписей).
- Пояснение — тем же `text-warning-ink`, но с `opacity-80` (не `text-ink-faint`), чтобы вторая строка читалась как часть баннера и не проваливалась по контрасту на жёлтом фоне.
- Кнопки не перекрашиваем: погашенный вид даёт штатный `disabled:` в `.btn-secondary` / `.btn-primary`; карточка недавних использует уже прописанные `disabled:cursor-not-allowed disabled:opacity-60`.
- Глиф предупреждения — текстовый символ (`⚠`), как в проекте уже принято для декоративных иконок (`▱`, `✕`), без иконочных библиотек.

## Доступность (a11y)

- Баннер: `role="status"` + `aria-live="polite"` — появление занятости озвучивается, но не прерывает пользователя (`role="alert"` не используем: это не ошибка).
- Глиф `⚠` — `aria-hidden="true"`; смысл несут только слова, цвет не единственный носитель информации.
- Кнопки открытия при `blocked` получают `aria-describedby` с id баннера. Так связь «кнопка — причина» остаётся в DOM даже если браузер не даёт сфокусировать `disabled`-кнопку; дополнительно работает `title`.
- Семантика модалки не меняется: `role="dialog"`, `aria-modal="true"`, `aria-labelledby={titleId}`; фокус при монтировании по-прежнему на ✕ (`:89-91`).
- Клавиатура: Tab обходит только активные элементы (дерево, «Вверх», ✕), Escape закрывает модалку при `!submitting`. Баннер не является фокусируемым и не крадёт фокус.
- Контраст: `--warning-ink` на `--warning-soft` — читаемая пара из уже используемого набора (та же логика, что у `.badge-warning` и `.catalog-notice`).

## Контракты данных (если нужны)

- `GET /workspaces/busy` → `{ busy: boolean, reason: 'run' | 'session' | null }` (готово в парном backend-шаге `00-CATALOG-79-code-workspace-busy-api.md`; в UI — новый тип и функция в `frontend/src/api.ts`).
- `useWorkspace` отдаёт **отдельные** от существующего `busy` (`hooks/useWorkspace.ts:32`) поля — например `blocked` / `blockedReason` + `refreshBlocked()`. Пикер получает их пропами; смешивать с локальным `busy` нельзя, иначе баннер зажигается на собственном open/rescan.
- Ошибка запроса статуса трактуется как «не заблокировано»: `blocked = false`, баннера нет, кнопки активны.
- 409 от `POST /workspaces/open` → `onBusyConflict(detail)` + `pending = { kind: 'error', detail }` (существующее поведение `:132-138` сохраняется).

## Критерии визуальной приёмки

- [ ] При `blocked: true` баннер отрисован **над** секциями «Недавние» и «Обзор папок», сразу под заголовком модалки, и виден до выбора папки.
- [ ] Баннер использует warning-палитру (`border-warning-line`, `bg-warning-soft`, `text-warning-ink`), а не danger; геометрия `rounded px-3 py-2 mb-4`.
- [ ] Текст баннера различает `run` («выполнение скилла») и `session` («активна сессия чата»); для `reason: null` показан обобщённый текст, пустого баннера нет.
- [ ] Баннер состоит из декоративного глифа (`aria-hidden`) и двух строк: заголовок `text-xs font-medium` + пояснение `text-[11px]`.
- [ ] Все четыре группы кнопок открытия (карточка недавних, «Открыть эту папку», «Открыть» в строке, подтверждения pending) визуально погашены и не реагируют на клик; курсор — `not-allowed`.
- [ ] Клик по имени папки, «Вверх», ✕ и Escape работают при `blocked: true`; вёрстка обзора не меняется.
- [ ] При `blocked: false` разметка пикера визуально идентична текущей (никаких пустых отступов на месте баннера).
- [ ] Собственный open/rescan (`submitting`) не показывает баннер занятости.
- [ ] После 409 одновременно видны pending-ошибка с `detail` (danger-стиль) и баннер занятости (warning-стиль) — состояния различимы.
- [ ] Баннер имеет `role="status"` и `aria-live="polite"`; кнопки открытия при `blocked` ссылаются на него через `aria-describedby` и несут `title` с причиной.
- [ ] Новых CSS-классов и зависимостей не добавлено; использованы только существующие токены/утилиты.
