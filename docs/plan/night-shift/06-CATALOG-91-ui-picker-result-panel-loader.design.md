# CATALOG-91 — Дизайн UI

- **Источник:** `docs/plan/night-shift/06-CATALOG-91-ui-picker-result-panel-loader.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Экран — модалка «Открыть воркспейс» (`WorkspacePicker`). Сценарий:

1. Пользователь открывает модалку, видит шапку, (опционально) баннер занятости, блок «Недавние» и «Обзор папок».
2. Пользователь нажимает одну из кнопок запуска: карточка в «Недавних», «Открыть эту папку», «Открыть» в строке списка.
3. **Сразу** внутри нажатой кнопки появляется спиннер и текст текущей фазы («Проверяю папку…»). Остальные кнопки — `disabled` без спиннера. Модалка не закрывается ни по `Escape`, ни по «✕».
4. Ответ бэкенда:
   - `ok` → модалка закрывается (поведение как сейчас);
   - `needs_init` / `needs_confirm` / ошибка → в **закреплённой верхней зоне** модалки (не в скроллящемся теле) появляется панель результата. Она видна без прокрутки при любой длине списка папок.
5. Панель показывает вопрос/ошибку, **путь папки**, к которой относится результат, и (для `needs_confirm`) отчёт скана со собственным скроллом. Фокус переводится на основное действие панели, появление объявляется через `aria-live`.
6. Пользователь нажимает подтверждение — спиннер и текст фазы («Создаю воркспейс…» / «Индексирую файлы…») появляются в этой самой кнопке панели. Если индексация идёт дольше ~5 с, под кнопкой появляется пояснение про большие папки (без процентов).
7. Навигация по дереву (`Вверх` / вход в папку) снимает панель — как сейчас.

## Дерево компонентов и файлы

- `frontend/src/components/WorkspacePicker.tsx` — **изменяется**:
  - карточка модалки делится на закреплённую зону (`header`) и скроллящееся тело (`body`);
  - JSX панели результата переносится в закреплённую зону;
  - панель получает путь папки, обёртку отчёта со скроллом, `aria-live`, ref на primary-кнопку;
  - состояние занятости `submitting: boolean` заменяется на `busy: BusyTarget | null` (см. «Контракты данных»), производный `submitting = busy !== null` сохраняется для существующих `disabled` и обработчика `Escape`;
  - добавляется локальный хелпер отрисовки содержимого кнопки в состоянии загрузки (спиннер + текст фазы) — обычная функция/локальный компонент внутри файла, отдельный публичный компонент не нужен;
  - вариант `error` типа `PendingPanel` получает `path?: string`.
- `frontend/src/components/icons.tsx` — **изменяется**: добавляется `SpinnerIcon` рядом с `RefreshIcon` / `CopyIcon` / `CheckIcon`, на том же `iconBase` (16×16, `stroke="currentColor"`, `aria-hidden`), с вращением через Tailwind-утилиту `animate-spin` и `motion-reduce:animate-none`. Новых npm-зависимостей нет.
- `frontend/src/index.css` — **не меняется**: `animate-spin` есть в Tailwind по умолчанию, закреплённая шапка делается флексом, всех токенов достаточно. Правку CSS допускать только если flex-раскладка карточки действительно потребует нового класса.
- `frontend/src/components/ScanReportView.tsx` — **только чтение**, ограничение высоты живёт на обёртке в панели.

## Layout и состояния

### Раскладка карточки: закреплённая шапка + скроллящееся тело

Выбран вариант «разделить карточку», а не `sticky` — при `sticky` внутри карточки с `p-4` и скруглениями панель просвечивает содержимым под собой и требует хаков с отрицательными отступами и фоном.

Структура (порядок сверху вниз):

```
div.modal-overlay
└ div[role=dialog].modal-card.flex.max-h-[80vh].max-w-2xl.flex-col.overflow-hidden   ← вместо overflow-y-auto
  ├ div.shrink-0                       ← закреплённая зона
  │  ├ строка заголовка (h2 + кнопка «✕»)          — как сейчас
  │  ├ баннер занятости (если blocked)             — как сейчас
  │  ├ sr-only live-регион с текстом фазы (только когда идёт запрос)
  │  └ панель результата (если pending) — mb-3
  └ div.min-h-0.flex-1.overflow-y-auto ← скроллящееся тело
     ├ section «Недавние»
     └ section «Обзор папок»
```

Требования к раскладке:

- у последней секции тела убрать «висящий» `mb-4` или компенсировать его так, чтобы внизу не было двойного отступа;
- у тела допустим `pr-1` (или аналогичный небольшой отступ), чтобы скроллбар не наезжал на контент;
- панель результата **никогда** не попадает в скроллящееся тело — это и есть выполнение требования «не уезжает из вида»;
- дополнительный скролл панели в вид не нужен (она вне скролл-контейнера); если реализация всё же вызывает `scrollIntoView({ block: 'nearest' })`, это допустимо, но не обязательно.

### Панель результата: варианты

Общая обёртка панели: `rounded ... p-3` + тональность по варианту.

| Вариант | Тональность | Содержимое сверху вниз |
|---|---|---|
| `needs_init` | `border border-line-brand bg-brand-soft` | вопрос «Папка пустая. Создать здесь воркспейс?» → строка пути → кнопка `btn-primary` «Создать воркспейс» (справа) |
| `needs_confirm` | `border border-line-brand bg-brand-soft` | вопрос «Папка содержит файлы. Сделать воркспейсом и проиндексировать?» → строка пути → отчёт скана в скролл-обёртке → (после ~5 с индексации) пояснение → кнопка `btn-primary` «Сделать воркспейсом и проиндексировать» (справа) |
| `error` | `border border-danger-line bg-danger-soft` | текст ошибки `text-danger-ink` → строка пути (если `path` известен). Кнопок нет |

Тональность выбрана по уже существующему трио токенов (как у баннера занятости `warning-line / warning-soft / warning-ink`): вопрос — brand, ошибка — danger. Это визуально отделяет панель от нейтральных секций `bg-surface-muted` в теле.

Строка пути: `truncate text-[11px] text-ink-faint` c `title={path}` (как у строк списка). Формат — `Папка: <полный путь>`, слово-метка в том же стиле, без отдельного цвета.

Обёртка отчёта скана: `max-h-40 overflow-y-auto rounded border border-line bg-surface p-2` (≈160 px). Кнопка подтверждения — **вне** этой обёртки, поэтому всегда видна. Панель в сумме укладывается в ~260 px; на всякий случай допускается общий предохранитель `max-h-[60vh]` на панели.

### Состояния экрана

| Состояние | Что показываем |
|---|---|
| Загрузка списка папок (`browseLoading`) | «Загрузка…» в теле — как сейчас, панель не участвует |
| Ошибка `browse` | текст ошибки в секции «Обзор папок» — как сейчас (это не панель результата) |
| Пустая папка в обзоре | «Нет вложенных папок» — как сейчас |
| Запрос в работе (`busy !== null`) | спиннер + текст фазы в нажатой кнопке; все прочие кнопки запуска, «Вверх», «✕» и входы в папки — `disabled`; `Escape` игнорируется |
| Индексация дольше ~5 с | под кнопкой подтверждения строка `text-[11px] text-ink-faint`: «На больших папках это может занять несколько минут.» Никакого процента/прогресс-бара |
| `needs_init` / `needs_confirm` | панель-вопрос в закреплённой зоне, фокус на primary-кнопке |
| Ошибка открытия | панель-ошибка в закреплённой зоне, фокус на контейнере панели (`tabIndex={-1}`) |
| `blocked` (воркспейс занят) | баннер занятости остаётся выше панели; панель, если она есть, показывается под ним |
| Успех (`ok`) | модалка закрывается, панель не мелькает |

Про пересечение с CATALOG-79: баннер занятости (warning, постоянное состояние, объясняет `disabled`) и панель-ошибка (danger, результат конкретного действия, с путём) остаются оба — они различаются тоном, местом и формулировкой, поэтому 409 не нужно дедуплицировать и логику `onBusyConflict` менять не надо.

## Взаимодействия

### Привязка спиннера к нажатой кнопке

Спиннер показывается ровно в одной кнопке. Совпадения путей возможны (папка из «Недавних» может совпасть с текущей папкой обзора), поэтому сравнение только по пути недостаточно: цель занятости хранит и путь, и источник нажатия. Условие показа спиннера в кнопке: `busy?.source === <источник этой кнопки> && busy.path === <path этой кнопки>`.

Источники: `recent`, `browse-current` («Открыть эту папку»), `browse-entry` («Открыть» в строке), `panel` (кнопка подтверждения в панели).

### Тексты фаз

| Условие | Текст |
|---|---|
| `open(path, false)` — любой источник | «Проверяю папку…» |
| `open(path, true)` при `pending.kind === 'needs_init'` | «Создаю воркспейс…» |
| `open(path, true)` при `pending.kind === 'needs_confirm'` | «Индексирую файлы…» |

Фраза про большие папки — **не в кнопке** (кнопка не должна разъезжаться), а отдельной строкой под кнопкой панели, только для фазы `indexing` и только после ~5 с. Таймер очищается при завершении запроса и при unmount.

### Вид кнопки в состоянии загрузки

- Содержимое: `SpinnerIcon` (`size-3.5 shrink-0`) + текст фазы; между ними штатный `gap-1.5`/`gap-2`; кнопка `whitespace-nowrap`, чтобы текст не рвался.
- Кнопка остаётся `disabled` (как сейчас), но не должна выглядеть «серой мёртвой»: для занятой кнопки добавляются утилиты, перебивающие дефолтный `disabled`-вид (utilities-слой Tailwind перекрывает `@layer components`):
  - primary: `disabled:bg-brand disabled:text-white`;
  - secondary / карточка «Недавние»: остаются штатные `disabled`-стили, спиннер наследует `currentColor`;
  - обеим: `disabled:cursor-progress` вместо `not-allowed`.
- Занятая кнопка получает `aria-busy="true"`.
- Карточка «Недавние»: чтобы карточка не перестраивалась, спиннер + текст фазы занимают правый слот (там, где показывается дата последнего открытия), `shrink-0`; левая часть с именем и путём не меняется.
- «Открыть» в строке списка и «Открыть эту папку»: подпись кнопки целиком заменяется на спиннер + текст фазы; соседний текст пути остаётся `min-w-0 truncate`, поэтому строка не переполняется.

### Фокус и появление панели

- При появлении/смене панели (`pending` изменился на непустое значение):
  - `needs_init` / `needs_confirm` → фокус на primary-кнопку панели (второй ref рядом с существующим `closeRef`);
  - `error` → фокус на контейнер панели (`tabIndex={-1}`), чтобы текст ошибки был прочитан и виден.
- Первичный фокус при монтировании модалки остаётся на «✕» (текущее поведение).
- Фокус не перехватывается повторно, если панель не менялась (эффект зависит от «идентичности» панели: вид + путь).
- Порядок табуляции после переноса: «✕» → (баннер — не фокусируемый) → primary-кнопка панели → «Недавние» → «Обзор папок». Это ожидаемо: главное действие идёт раньше списков.
- Закрытие модалки и `Escape` во время запроса остаются заблокированными.

### Крайние случаи

- Кнопка панели нажата, ответ — снова ошибка: панель меняет вид с brand на danger, фокус уходит на контейнер панели, спиннер снимается.
- Пользователь ушёл в другую папку — `pending` сбрасывается, панель исчезает, закреплённая зона схлопывается без «прыжка» тела (тело просто получает больше высоты).
- Очень длинный путь — `truncate` + `title`; перенос строк не допускается.
- Отчёт скана пустой (`ScanReportView` рисует «Изменений нет») — обёртка со `max-h-40` не создаёт лишней пустоты (высота по контенту).
- Список папок пуст, панель есть — панель всё равно в закреплённой зоне, тело показывает «Нет вложенных папок».

## Стиль и токены

- Только существующие токены и утилиты: `bg-brand-soft`, `border-line-brand`, `text-brand-ink`, `bg-danger-soft`, `border-danger-line`, `text-danger-ink`, `bg-surface`, `border-line`, `text-ink`, `text-ink-faint`.
- Типографика панели: вопрос — `text-xs text-ink`; путь и пояснение — `text-[11px] text-ink-faint`; ошибка — `text-xs text-danger-ink`. Совпадает с остальной модалкой.
- Отступы: панель `p-3`, между блоками внутри `mb-2`, до тела `mb-3`; кнопки — существующие `btn-primary` / `btn-secondary`, без кастомных размеров.
- Скругления — штатный `rounded` (как у текущей панели и строк списка); `rounded-control` только у кнопок через классы `btn-*`.
- Спиннер: 1.5 px обводка через `iconBase`, размер `size-3.5` в кнопках `text-xs`, цвет — `currentColor`.
- Анимация уважает `prefers-reduced-motion` (`motion-reduce:animate-none`); при отключённой анимации остаётся статичная иконка + текст фазы, смысл не теряется.
- Никаких новых CSS-переменных и цветов вне палитры.

## Доступность (a11y)

- Контейнер панели: `aria-live="polite"` + `aria-atomic="true"` + `tabIndex={-1}`. `role="alert"` не используется — иначе ошибка объявляется дважды.
- Кнопка «✕», `aria-modal`, `aria-labelledby` шапки — без изменений.
- Текст фазы дополнительно объявляется через `sr-only` live-регион в закреплённой зоне (`role="status" aria-live="polite"`), как уже сделано в `MessageCommands.tsx`: смена подписи внутри кнопки, на которой стоит фокус, скринридером не гарантируется. Этот же регион объявляет пояснение про большие папки.
- Занятая кнопка — `aria-busy="true"`; спиннер — `aria-hidden`, смысл несёт текст.
- Клавиатура: `Escape` заблокирован во время запроса; фокус после появления панели попадает на её основное действие; из панели `Tab` уводит в тело модалки; фокус не уходит за пределы диалога сильнее, чем сейчас (ловушку фокуса в этом шаге не вводим).
- Контраст: `text-danger-ink` на `bg-danger-soft` и `text-ink` на `bg-brand-soft` — уже используемые в проекте пары; белый текст на `bg-brand` у занятой primary-кнопки сохраняет контраст, в отличие от `text-ink-faint` на `bg-surface-muted`.
- Спиннер не единственный индикатор: всегда есть текстовая фраза фазы.

## Контракты данных

Изменения только клиентские, API `/workspaces/open` и `/fs/browse` не трогаем (см. «Вне рамок» в плане).

```ts
type PendingPanel =
  | { kind: 'needs_init'; path: string }
  | { kind: 'needs_confirm'; path: string; scan: ScanReport }
  | { kind: 'error'; detail: string; path?: string }

type BusyPhase = 'checking' | 'creating' | 'indexing'
type BusySource = 'recent' | 'browse-current' | 'browse-entry' | 'panel'
type BusyTarget = { path: string; phase: BusyPhase; source: BusySource }
```

- Фаза вычисляется на клиенте в `tryOpen`: `confirm === false` → `checking`; `confirm === true` и `pending.kind === 'needs_init'` → `creating`; `confirm === true` и `pending.kind === 'needs_confirm'` → `indexing`.
- `submitting` остаётся производным (`busy !== null`), чтобы не переписывать существующие `disabled` и обработчик `Escape`.
- `path` в варианте `error` заполняется из аргумента `tryOpen` в `catch`.
- Пересечение с CATALOG-92 (фильтр папок): фильтр живёт в секции «Обзор папок», то есть в скроллящемся теле; закреплённая зона его не касается — конфликт раскладок не возникает.

## Критерии визуальной приёмки

- [ ] Карточка модалки — flex-колонка: `overflow-hidden` на карточке, скролл только у тела; заголовок, баннер занятости и панель результата не скроллятся.
- [ ] Порядок сверху вниз: заголовок с «✕» → баннер занятости (если есть) → панель результата (если есть) → скроллящееся тело с «Недавние» и «Обзор папок».
- [ ] На списке из 30+ папок все три варианта панели (`needs_init`, `needs_confirm`, `error`) видны без прокрутки, вместе с кнопкой действия.
- [ ] Панель остаётся на месте при прокрутке списка папок.
- [ ] Панель-вопрос — тональность `border-line-brand` + `bg-brand-soft`; панель-ошибка — `border-danger-line` + `bg-danger-soft` с `text-danger-ink`.
- [ ] В панели есть строка пути: `truncate`, `title` с полным путём; для `error` путь показывается, когда известен.
- [ ] Отчёт скана обёрнут в контейнер `max-h-40 overflow-y-auto`; при высоком отчёте кнопка подтверждения остаётся видимой без прокрутки панели.
- [ ] Во время запроса спиннер + текст фазы видны **только** в нажатой кнопке (проверить в том числе случай, когда путь из «Недавних» совпадает с текущей папкой обзора); прочие кнопки — `disabled` без спиннера.
- [ ] Тексты фаз ровно такие: «Проверяю папку…», «Создаю воркспейс…», «Индексирую файлы…».
- [ ] Занятая кнопка не выглядит «серой мёртвой»: primary сохраняет brand-фон и белый текст, курсор — `progress`, атрибут `aria-busy="true"`.
- [ ] Спиннер — inline SVG из `icons.tsx` c `animate-spin` и `motion-reduce:animate-none`, `aria-hidden`, размер `size-3.5`; новых зависимостей нет.
- [ ] После ~5 с фазы `indexing` под кнопкой панели появляется пояснение про большие папки в `text-[11px] text-ink-faint`, без процентов и прогресс-бара; таймер снимается по завершении запроса и при unmount.
- [ ] Карточка «Недавние» в состоянии загрузки не перестраивается: спиннер с текстом занимает правый слот, имя и путь остаются на месте.
- [ ] Панель имеет `aria-live="polite"`, `aria-atomic="true"`, `tabIndex={-1}`; текст фазы дублируется в `sr-only` live-регионе.
- [ ] Появление `needs_init` / `needs_confirm` переводит фокус на primary-кнопку панели; появление `error` — на контейнер панели.
- [ ] `Escape` и «✕» во время запроса не закрывают модалку; `aria-modal` и `aria-labelledby` сохранены.
- [ ] Навигация «Вверх» / вход в папку убирает панель, раскладка не «прыгает».
