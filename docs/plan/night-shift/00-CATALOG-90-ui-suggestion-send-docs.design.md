# CATALOG-90 — Дизайн UI

- **Источник:** docs/plan/night-shift/00-CATALOG-90-ui-suggestion-send-docs.md
- **Статус дизайна:** Ready

## Цель и пользовательский путь
Клик по подсказке — это полноценная отправка сообщения, а не «быстрая реплика без вложений». Пользователь не должен догадываться, что один способ отправки теряет выбранные документы, а другой — нет.

Основной сценарий (новый чат):
1. Пользователь открывает пустой чат — под композером видит стартовые подсказки («Изучи доступные документы» и т.д.), поле ввода пустое.
2. Жмёт «+», выбирает в комбобоксе N документов. Над композером появляется полоса вложений; выбранные документы показаны как pending-карточки с подписью «· к отправке».
3. Кликает по подсказке (а не по «Отправить»).
4. Сообщение уходит вместе с выбранными документами: композер очищается, выбор в пикере сбрасывается, подсказки скрываются на время ответа.
5. Карточки документов **не исчезают**: они переходят из pending-состояния в состояние «документ в сессии» (после подтверждения от планировщика) и остаются в полосе после ответа.

Ключевое требование к восприятию: между шагами 3 и 5 полоса вложений не должна «мигать пустотой» — набор карточек тот же, меняется только их визуальное состояние (pending → session).

## Дерево компонентов и файлы
Новых компонентов нет. Изменение — поведенческое, внутри одного файла.

- `frontend/src/components/Chat.tsx` — единственный изменяемый компонент:
  - новая внутренняя функция отправки `sendCurrent(text: string)` — общий путь для всех отправок из чата;
  - `submit()` становится тонкой обёрткой: берёт `input.trim()` и зовёт `sendCurrent`;
  - кнопки в `visibleSuggestions` зовут `sendCurrent(s)` вместо `onSend(s)`;
  - `onRepeat` у `ChatMessage` передаётся явным колбэком «текст без документов» (см. «Взаимодействия»).
- `frontend/src/components/ChatMessage.tsx`, `frontend/src/components/MessageCommands.tsx` — **не меняются**: контракт `onRepeat: (content: string) => void` сохраняется.
- `frontend/src/components/DocumentCombobox.tsx`, `frontend/src/App.tsx`, `frontend/src/hooks/usePlannerSession.ts` — **не меняются**.
- `frontend/src/components/Chat.test.tsx` (новый) — тест на поведение, разметку не затрагивает.

Разметка (JSX-структура, классы, порядок блоков) остаётся прежней. Любое изменение верстки, кроме перечисленного, считается выходом за скоуп.

## Layout и состояния
Layout композерной зоны не меняется, порядок сверху вниз сохраняется: строка подсказок → полоса вложений → composer (textarea + кнопки) → блок ошибки сборки.

Состояния полосы вложений и подсказок:

| Состояние | Подсказки | Полоса вложений | Композер |
|---|---|---|---|
| Пустой чат, документы не выбраны | 3 стартовых chip | скрыта | placeholder, «Отправить» disabled |
| Документы выбраны, сообщение не отправлено | chip активны | карточки с рамкой `border-line-brand` и подписью «· к отправке» | «Отправить» активна (даже при пустом тексте) |
| Сразу после клика по подсказке | скрыты (`streaming`) | те же карточки, состояние pending до подтверждения | textarea пустая и `disabled`, вместо «Отправить» — «Остановить генерацию» |
| Планировщик подтвердил документы | скрыты (`streaming`) | те же карточки, рамка `border-line`, подписи «· к отправке» больше нет | без изменений |
| Ответ завершён | до 3 подсказок из `suggestions` | карточки сессии остаются | композер доступен, пустой |
| Ошибка/закрытое соединение | подсказки видны (если не `streaming`) | без изменений | баннер «Соединение закрыто» / «Ошибка: …» как сейчас |

Отдельного loading-состояния у подсказок нет: индикатор работы — существующая строка «●●● планировщик думает…» и скрытие ряда подсказок.

## Взаимодействия

**Клик по подсказке.** Ведёт себя ровно как «Отправить», отличается только источником текста:
- отправляет текст chip вместе с текущими `selectedDocIds` / `selectedDocs` (если выбор пуст — оба аргумента `undefined`, как сейчас в `submit`);
- очищает поле ввода, сбрасывает выбор документов, закрывает поповер выбора документов;
- текст chip **не** подставляется в textarea как черновик — он сразу уходит сообщением;
- при `streaming` chip остаётся `disabled` (текущее поведение), повторный клик невозможен.

**Черновик в поле ввода.** Если пользователь что-то напечатал и затем кликнул по подсказке, отправляется текст подсказки, а черновик очищается — единый путь отправки не оставляет расходящихся состояний композера. Это осознанное решение: композер после любой отправки выглядит одинаково (пустой), пользователь не получает «остаточный» текст, непонятно к чему относящийся.

**Повтор сообщения (`onRepeat`).** Решение: **повтор идёт без документов и не трогает выбор в композере.**
- `ChatMessage` получает колбэк вида «отправить только текст» (`(content) => onSend(content)`), контракт `MessageCommands` не меняется;
- pending-карточки, если они есть, остаются на месте и не улетают вместе с повтором — иначе пользователь молча отправил бы вложения, которых не выбирал для этого сообщения;
- документы, уже привязанные к сессии, остаются привязанными на бэкенде, поэтому повтор их не теряет;
- решение фиксируется в описании PR (пункт из Definition of Done плана).

**Крайние случаи:**
- Пустой текст + выбранные документы: «Отправить» работает (как сейчас); у подсказки текст всегда непустой, так что общий guard `if (!text && docIds.length === 0) return` сохраняется.
- Отправка во время `streaming` блокируется общим guard-ом внутри `sendCurrent`, а не только `disabled` у кнопок.
- Двойной клик по подсказке до появления `streaming` (пока создаётся сессия) — известное ограничение текущего поведения, **в скоуп не входит**: новых блокировок chip не добавляем.
- Смена `sessionId` по-прежнему обнуляет `selectedDocIds` — эффект не трогаем; после корректной отправки документы уже ушли в сессию, поэтому чипы не пропадают, а меняют состояние.

## Стиль и токены
Новых стилей нет. Используются существующие утилиты и классы:
- подсказки — `chip shrink-0` + hover `hover:border-line-brand hover:bg-surface-hover`, фокус `focus-visible:ring-2 focus-visible:ring-brand`, disabled `disabled:bg-surface-muted disabled:text-ink-faint`;
- полоса вложений — `catalog-attachments`, карточки `rounded-lg border bg-surface px-2.5 py-2`, pending отличается только рамкой `border-line-brand` и суффиксом «· к отправке» в мета-строке `text-[11px] text-ink-faint`;
- композер — `catalog-composer` / `catalog-composer--attached` без изменений.

Никаких новых зависимостей и никаких новых CSS-классов вводить не требуется (React 19 + Vite + TS + Tailwind v3, ADR-0011).

## Доступность (a11y)
Текущая семантика сохраняется, ничего не удаляем:
- ряд подсказок — `role="group"` + `aria-label="Быстрые ответы"`, элементы `<button type="button">`, доступны с клавиатуры (Tab + Enter/Space);
- клик и Enter по подсказке дают идентичный результат (обработчик один — `onClick`);
- полоса вложений — `role="list"` + `aria-label="Документы в сессии"` + `aria-live="polite"`: смена состояния pending → session и очистка выбора озвучиваются скринридером без дополнительных объявлений;
- фокус после отправки подсказки остаётся на нажатом chip до его скрытия по `streaming`; специального переноса фокуса не добавляем (это изменило бы текущее поведение «Отправить»);
- у карточки вложения сохраняется `aria-label="Убрать <title>"`; кнопка `disabled` во время `streaming`;
- кнопка «Повторить» сохраняет свои `title`/`aria-label` («Переотправить это сообщение» / «Недоступно во время ответа»).

## Контракты данных
- `Chat.onSend(text: string, docIds?: string[], docs?: DocumentOut[])` — сигнатура не меняется; меняется только то, что путь подсказки теперь передаёт 2-й и 3-й аргументы.
- `App.handleSend` → `ensureSession(docIds)` → `planner.send(text, docIds, docs)` — не трогаем; защиты гидрации `dc8b3b0` в `usePlannerSession` остаются как есть.
- Источник pending-карточек: `selectedDocIds` минус `sessionDocuments`; источник session-карточек: `sessionDocuments` из WS-кадра `session_docs`. Логика вычисления `attachmentDocs` не меняется.
- Backend не меняется.

## Критерии визуальной приёмки
- [ ] Разметка композерной зоны (порядок блоков, классы подсказок, полосы вложений и composer) не изменилась — диф в JSX ограничен заменой обработчиков.
- [ ] Клик по подсказке при выбранных документах: композер очищается, поповер выбора документов закрывается, pending-подпись «· к отправке» уходит, карточки документов остаются в полосе.
- [ ] Полоса «Документы в сессии» не исчезает и не «мигает пустотой» между отправкой и ответом планировщика.
- [ ] Клик по подсказке при пустом выборе документов даёт тот же результат, что и раньше (обычная отправка текста).
- [ ] Отправка через «Отправить» и Enter визуально и по состояниям работает как прежде.
- [ ] Во время `streaming` ряд подсказок скрыт, chip недоступны, вместо «Отправить» — «Остановить генерацию».
- [ ] «Повторить» отправляет только текст: pending-карточки остаются на месте, композер и выбор документов не меняются.
- [ ] Никаких новых CSS-классов, инлайновых стилей и зависимостей; сохранены `role`/`aria-label`/`aria-live` у подсказок и полосы вложений.
