# CATALOG-112 — Дизайн UI

- **Источник:** `docs/plan/night-shift/05-CATALOG-112-ui-busy-banner.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Шаг чисто копирайтерский: баннер блокировки в пикере воркспейсов при `reason='session'` должен называть настоящую причину. Новых компонентов, состояний, данных и интерактивных элементов не появляется — меняются три строки в `blockedBannerText`.

Почему это не косметика. До шага 04 (`docs/plan/night-shift/04-CATALOG-112-code-busy-by-turn.md`) `session`-busy означал «открыт WebSocket чата», и формулировка «Активна сессия чата» была честной: пока чат открыт, папку не сменить. После 04 busy живёт ровно столько, сколько идёт turn планировщика (backend уже отдаёт `cannot switch workspace while an agent reply is in progress`). Старый текст теперь врёт дважды: называет причиной сам факт открытого чата и подталкивает пользователя закрыть сессию — действие, которое не поможет и уничтожит контекст диалога.

Пользовательский путь:

1. Пользователь отправил сообщение, агент печатает ответ. Не дожидаясь, жмёт «Открыть воркспейс» в футере сайдбара — `openPicker` дёргает `refreshBlocked`, пикер открывается с баннером.
2. Видит: **«Агент отвечает — переключение воркспейса недоступно»**, ниже подсказка, что смотреть папки можно, а открыть другую получится, когда агент закончит; чат закрывать не нужно.
3. Кнопки открытия (`Недавние`, «Открыть эту папку», «Открыть» в строках, кнопка панели подтверждения) погашены; наведение даёт тултип «Агент отвечает».
4. Пользователь ходит по дереву папок, находит нужную. Агент дописывает ответ → `planner.streaming` падает → `App` вызывает `refreshBlocked` → `blocked` становится `false`, баннер исчезает, кнопки оживают **без переоткрытия пикера**. Пользователь открывает папку тем же кликом, к которому уже подвёл мышь.

Шаг 4 — та причина, по которой формулировка «после ответа агента» точна: ожидание измеряется секундами и заканчивается само, в отличие от прежнего «закройте чат».

## Дерево компонентов и файлы

| Файл | Что делаем |
|---|---|
| `frontend/src/components/WorkspacePicker.tsx` | Ветка `reason === 'session'` в `blockedBannerText` (`:60-66`): новые `title`, `short` и собственный `hint`. Больше в файле ничего. |

Новых компонентов, пропсов, хуков, типов и зависимостей нет. `WorkspacePickerProps`, `WorkspaceBusyReason`, `useWorkspace`, `App.tsx` не трогаем.

Целевой вид функции (эталон для ревью — важны сами строки и то, что ветки `run`/fallback побайтово прежние):

```tsx
function blockedBannerText(reason: WorkspaceBusyReason | null): {
  title: string
  hint: string
  short: string
} {
  const hint =
    'Смотреть папки можно; открыть другую папку получится после завершения.'
  if (reason === 'run') {
    return {
      title: 'Идёт выполнение скилла — переключение воркспейса недоступно',
      hint,
      short: 'Идёт выполнение скилла',
    }
  }
  if (reason === 'session') {
    return {
      title: 'Агент отвечает — переключение воркспейса недоступно',
      hint: 'Смотреть папки можно; открыть другую папку получится, когда агент закончит ответ. Чат закрывать не нужно.',
      short: 'Агент отвечает',
    }
  }
  return {
    title: 'Воркспейс занят — переключение недоступно',
    hint,
    short: 'Воркспейс занят',
  }
}
```

### Разбор формулировок

| Поле | Значение | Почему так |
|---|---|---|
| `title` | `Агент отвечает — переключение воркспейса недоступно` | Держит шаблон соседней ветки `run`: «<что происходит> — <что недоступно>». Настоящее время «отвечает» описывает процесс, который идёт прямо сейчас и вот-вот кончится. |
| `short` | `Агент отвечает` | Уходит в `title=` погашенных кнопок; тултип должен читаться за долю секунды и не дублировать «недоступно» — это и так видно по disabled-состоянию. |
| `hint` | `Смотреть папки можно; открыть другую папку получится, когда агент закончит ответ. Чат закрывать не нужно.` | Первая половина сохранена дословно из общего хинта (единый ритм с `run`), «после завершения» уточнено до «когда агент закончит ответ». Вторая фраза снимает главное заблуждение старого текста. |

Чего в текстах быть не должно: слов «сессия», «чат активен», «закройте чат», «дождитесь окончания сессии», а также технических «planner», «turn», «WebSocket». Пользователь видит агента, а не транспорт.

Общий `hint` остаётся локальной константой внутри функции и продолжает обслуживать `run` и fallback. Выносить его в модульную константу, заводить словарь текстов или менять сигнатуру функции в этом шаге не нужно — диф должен читаться как правка копии.

## Layout и состояния

Раскладка баннера (`:317-332`) не меняется ни на пиксель: `flex items-start gap-2`, значок `⚠` с `shrink-0`, справа блок `min-w-0` с двумя абзацами — `title` (`text-xs font-medium`) и `hint` (`text-[11px] opacity-80`).

| Состояние | Что показываем |
|---|---|
| `blocked=false` | Баннера нет, кнопки активны, `aria-describedby` у кнопок не выставлен. Не меняется. |
| `blocked=true`, `reason='session'` | Новый текст. Баннер занимает две строки на десктопе (заголовок + хинт); хинт длиннее прежнего и на узкой карточке (`max-w-2xl`, при сжатии окна) переносится на вторую строку — это штатно, `min-w-0` + перенос по словам уже обеспечены, `truncate` в баннере нет и не появляется. |
| `blocked=true`, `reason='run'` | Без изменений, включая общий хинт. |
| `blocked=true`, `reason=null` (fallback) | Без изменений. |
| `blocked` снялся при открытом пикере | Баннер размонтируется, `openDisabled` становится `false`, тултипы `blockedTitle` пропадают, у кнопок «Недавние» возвращается `title={ws.path}`. Поведение существующее — важно его не сломать: логика вокруг `banner`, `openDescribedBy`, `blockedTitle` (`:166-168`) остаётся как есть. |
| Идёт открытие папки (`busy !== null`) поверх снявшейся блокировки | `BusyLabel` и фазы (`Проверяю папку…` / `Создаю воркспейс…` / `Индексирую файлы…`) не трогаем — это другой словарь, к busy-баннеру отношения не имеет. |

Высота баннера при `session` вырастает максимум на одну строку хинта, карточка пикера скроллится телом (`min-h-0 flex-1 overflow-y-auto`), шапка с баннером — `shrink-0`. Риска обрезки контента нет.

## Взаимодействия

- Никаких новых кликов, ввода и навигации. Набор фокусируемых элементов и порядок табуляции неизменны.
- Тултипы погашенных кнопок берут новый `short`: «Открыть эту папку», «Открыть» в строках, кнопки панелей `needs_init` / `needs_confirm` и строки «Недавние» (там `blockedTitle ?? ws.path` — при блокировке путь по-прежнему уступает место причине).
- Гонка «блокировка началась при открытом пикере» остаётся как есть: `refreshBlocked` вызывается на открытии пикера, на завершении стриминга планировщика и на завершении run'а, но не на старте turn'а. Если пользователь успел кликнуть в этот зазор, backend отвечает 409, `onBusyConflict` показывает нотис и вызывает `refreshBlocked` — баннер появляется следом. Добавлять поллинг или подписку на старт turn'а в этом шаге **не нужно**: это расширение скоупа.
- Текст нотиса при 409 приходит из backend (английская `detail`) и в этом шаге не локализуется — смысл у него тот же, что у нового баннера («an agent reply is in progress»), противоречия с русским текстом баннера нет.

## Стиль и токены

- Изменений в стилях нет вообще: ни одного класса не добавляем и не удаляем, `index.css` не трогаем.
- Баннер продолжает жить на паре `border-warning-line` + `bg-warning-soft` + `text-warning-ink` — предупреждение, не ошибка: пользователь ничего не сломал, просто ждёт.
- Типографика прежняя: `text-xs font-medium` у заголовка, `text-[11px] opacity-80` у хинта. Второе предложение хинта отдельным абзацем **не** выносим — иначе баннер визуально потяжелеет и начнёт спорить с содержимым пикера.
- Тире в заголовке — длинное «—», как в ветке `run`. Пунктуация хинта: точка с запятой в первой части (унаследована), точка между предложениями.

## Доступность (a11y)

- Баннер сохраняет `id={bannerId}`, `role="status"`, `aria-live="polite"`; кнопки — `aria-describedby={bannerId}` при блокировке. Атрибуты не переписываем.
- Скринридер при появлении баннера зачитывает оба абзаца: «Агент отвечает — переключение воркспейса недоступно. Смотреть папки можно; открыть другую папку получится, когда агент закончит ответ. Чат закрывать не нужно.» Формулировки самодостаточны вне визуального контекста — это и есть причина держать причину блокировки в `title`, а не только в тултипе.
- `title` (тултип) остаётся дублирующим, а не единственным носителем смысла: погашенная кнопка описана через `aria-describedby`, поэтому пользователи без указателя ничего не теряют.
- Контраст и размеры шрифта не меняются; `⚠` по-прежнему `aria-hidden`.

## Контракты данных

Новых API, WS-сообщений и типов нет. UI читает `GET /workspaces/busy` через `useWorkspace` и получает `reason: 'run' | 'session' | null` — контракт из шага 04 не меняется, значение `'session'` сохраняется, меняется только его человеческая расшифровка.
