# CATALOG-91 — WorkspacePicker: панель результата над списком папок + лоадер с описанием процесса

- **Задача Plane:** [CATALOG-91](https://app.plane.so/belchch/projects/catalog-app/work-items/91) (id: `56f9dc8b-f268-421b-ae39-0ec2f2be2238`, state: In Progress)
- **Статус плана:** Analyzed
- **Тип шага:** ui
- **Очередь:** 06 · blocked_by CATALOG-86 · blocking CATALOG-92, CATALOG-93
- **Цель:** Перенести панель результата (`needs_init` / `needs_confirm` / `error`) выше списка папок, чтобы вопрос-подтверждение, отчёт скана и ошибка всегда попадали в первый экран, и добавить в нажатую кнопку спиннер с текстом текущей фазы вместо немого `disabled`.

## Постановка задачи (актуальное ТЗ)
_(источник: описание задачи; комментариев нет)_

`frontend/src/components/WorkspacePicker.tsx` — модалка «Открыть воркспейс». Сейчас блок результата (`pending`: «Папка пустая. Создать здесь воркспейс?» / «Папка содержит файлы. Сделать воркспейсом и проиндексировать?» / ошибка) рендерится **последней секцией**, после списка папок (строки ~285–326). Список «Обзор папок» может быть длинным, модалка скроллится (`max-h-[80vh] overflow-y-auto`), поэтому после нажатия «Открыть эту папку» пользователь не видит ни вопроса-подтверждения, ни отчёта скана, ни текста ошибки — они уезжают за пределы вьюпорта.

Вторая проблема: `POST /workspaces/open` (и особенно повторный вызов с `confirm=true`, который делает индексацию) может выполняться заметное время. В это время единственная обратная связь — `disabled` на кнопках и подмена подписи на `…` / `Индексирую…` внутри pending-панели. У кнопки «Открыть эту папку», «Открыть» у элемента списка и у карточек «Недавние» никакого индикатора нет: интерфейс просто замирает.

### Что сделать

**1. Перенести панель результата наверх, поверх списка папок**

- Блок `pending` (все три варианта: `needs_init`, `needs_confirm`, `error`) показывать **выше** секции «Обзор папок» — сразу под заголовком модалки (или под блоком «Недавние»), чтобы он всегда попадал в первый экран без скролла.
- Панель не должна уезжать из вида при скролле списка: либо она вне скроллящейся области, либо `sticky` у верхней границы.
- При появлении панели фокус/скролл модалки уводится к ней (для скринридера — корректный `aria-live` / перевод фокуса на первичную кнопку действия).
- Внутри панели явно показывать, **к какой папке** относится вопрос (полный путь, `title` с полным путём при усечении) — сейчас путь виден только по контексту нажатой кнопки, а после переноса наверх контекст теряется.
- Отчёт скана (`ScanReportView`) остаётся внутри панели; если он высокий — ограничить его высоту и скроллить внутри панели, чтобы кнопка подтверждения оставалась видимой.

**2. Лоадер с описанием текущего процесса**

- У кнопки «Открыть эту папку» (и по тем же правилам у «Открыть» в строке списка и у карточек «Недавние») на время запроса показывать индикатор загрузки внутри самой нажатой кнопки: спиннер + текст.
- Текст лоадера описывает текущую фазу, а не просто «Загрузка». Минимальный набор фраз:
  - первый вызов `open(path, false)` — «Проверяю папку…»;
  - подтверждение `open(path, true)` для пустой папки — «Создаю воркспейс…»;
  - подтверждение `open(path, true)` для папки с файлами — «Индексирую файлы…»;
  - если индексация длится дольше ~5 с — дополнить фразой про то, что на больших папках это может занять время (без фейкового прогресса в процентах).
- Индикатор привязан к конкретной нажатой кнопке (нужно хранить, какая цель сейчас в работе, а не только булев `submitting`). Остальные кнопки остаются `disabled`, но без спиннера.
- Закрытие модалки и `Escape` во время запроса остаются заблокированными, как сейчас.

### Вне рамок
- Реальный прогресс индексации по SSE/WebSocket от бэкенда (`open_for_api` сейчас синхронный, стадий не отдаёт) — фразы лоадера формируются на клиенте по типу запроса.
- Изменения API `/workspaces/open` и `/fs/browse`.

### Тип
UI (нужна дизайн-спека: расположение панели, поведение при скролле, вид спиннера и тексты).

## Контекст
- Всё в одном файле — `frontend/src/components/WorkspacePicker.tsx` (330 строк). Порядок секций подтверждён: заголовок с кнопкой «Закрыть» (`:166-180`), «Недавние» (`:182-216`), «Обзор папок» (`:218-283`), и только потом `pending`-панель (`:285-326`).
- Скроллится вся карточка модалки: `div[role=dialog].modal-card.max-h-[80vh].overflow-y-auto` (`:160-165`). Значит «вне скроллящейся области» требует разделить карточку на фиксированную шапку и скроллящееся тело, либо сделать панель `sticky top-0` внутри текущего контейнера — выбор зафиксировать в дизайн-спеке.
- Состояние панели: `PendingPanel` — union из `needs_init { path }`, `needs_confirm { path, scan }`, `error { detail }` (`:20-23`). Путь уже есть в двух вариантах из трёх, поэтому «показать, к какой папке относится вопрос» для `needs_init` / `needs_confirm` делается без изменения модели; для `error` путь в состоянии не хранится — его надо добавить в вариант `error`, иначе показать папку в ошибке нечем.
- Единственный флаг занятости — `submitting: boolean` (`:61`), выставляется в `tryOpen` (`:105-142`). Он не знает, какая кнопка нажата, поэтому для привязки спиннера нужно отдельное состояние цели, например `{ path, phase }`, где `phase` ∈ `checking` | `creating` | `indexing`.
- Фазу можно вычислить в `tryOpen` без запросов к бэкенду: `confirm === false` → «Проверяю папку…»; `confirm === true` при `pending.kind === 'needs_init'` → «Создаю воркспейс…»; `confirm === true` при `pending.kind === 'needs_confirm'` → «Индексирую файлы…». Ветки вызова: `:194` (недавние), `:239` («Открыть эту папку»), `:275` («Открыть» в строке), `:297` и `:315` (подтверждения).
- Текущая имитация лоадера, которую надо заменить: `{submitting ? '…' : 'Создать воркспейс'}` (`:299`) и `{submitting ? 'Индексирую…' : '…'}` (`:317`). У кнопок `:194`, `:239`, `:275` индикатора нет вовсе — только `disabled`.
- Блокировка закрытия во время запроса уже есть и должна сохраниться: `Escape` игнорируется при `submitting` (`:97-103`), кнопка «Закрыть» дизейблится (`:175`).
- Фокус сейчас уводится на кнопку закрытия при монтировании (`:89-91`, `closeRef`). Для «фокус на первичное действие панели» понадобится второй ref на primary-кнопку панели и эффект по появлению `pending`.
- Отчёт скана рендерит `ScanReportView` (`:309`, компонент `frontend/src/components/ScanReportView.tsx`) — ограничение высоты и внутренний скролл делаются на обёртке в панели, сам компонент менять не обязательно.
- Ошибка 409 (воркспейс занят) обрабатывается особо: `onBusyConflict(e.detail)` плюс `pending = error` (`:132-138`). Это точка пересечения с [CATALOG-79](docs/plan/night-shift/01-CATALOG-79-ui-workspace-busy-banner.md) — оба плана правят одну и ту же модалку и её обработку ошибок. Если задачи выполняются подряд, изменения надо согласовать: панель результата и баннер занятости не должны дублировать одно и то же сообщение.
- Пересечение №2: [CATALOG-92](docs/plan/night-shift/07-CATALOG-92-ui-picker-folder-filter.md) добавляет поле фильтра в ту же секцию «Обзор папок» (`:218-219`). Конфликт правок вероятен — оба изменения затрагивают верх этой секции.
- Автотестов на компонент нет; проверки — `pnpm run build`, `pnpm run lint`, `pnpm run typecheck` из `frontend/` плюс ручной прогон на папке с 30+ подпапками.

## Критерии приёмки (Definition of Done)
- [ ] При списке из 30+ папок нажатие «Открыть эту папку» на папке с файлами приводит к тому, что вопрос «Сделать воркспейсом и проиндексировать?» вместе с кнопкой подтверждения видны **без прокрутки**.
- [ ] То же для пустой папки (`needs_init`) и для ошибки (403/404/409/400) — текст видно сразу.
- [ ] Панель не уезжает из вида при скролле списка папок.
- [ ] В панели виден путь папки, к которой относится вопрос (с `title` при усечении).
- [ ] Высокий отчёт скана скроллится внутри панели, кнопка подтверждения остаётся видимой.
- [ ] Во время `POST /workspaces/open` в нажатой кнопке виден спиннер и текст фазы; после ответа индикатор снимается.

- [ ] `Escape` и кнопка «Закрыть» во время запроса по-прежнему не срабатывают.
- [ ] Клавиатурная навигация и `aria-modal`-семантика не сломаны; фокус после появления панели попадает на её основное действие, появление объявляется через `aria-live`.
- [ ] API `/workspaces/open` и `/fs/browse` не изменены.
- [ ] Новых npm-зависимостей не добавлено.
- [ ] Из `frontend/`: `pnpm run build`, `pnpm run lint`, `pnpm run typecheck` — зелёные.
