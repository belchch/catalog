## Цель и пользовательский путь

Пользователь работает в шапке приложения (`ModelSelector`): слева выпадающий список провайдеров, справа комбобокс моделей. Он меняет провайдера — и должен сразу понять, что список моделей нового провайдера ещё грузится, а не считать старый список актуальным.

Сценарий:
1. Пользователь открывает провайдерский `<select>`, выбирает другого провайдера.
2. Мгновенно (в том же кадре) у комбобокса моделей появляется индикатор загрузки, комбобокс становится недоступным, старые модели исчезают из триггера.
3. Провайдерский `<select>` остаётся активным — пользователь может сразу переключиться ещё раз, не дожидаясь ответа.
4. Приходит ответ `/providers/{id}/models`: индикатор гаснет, комбобокс снова активен и показывает модели нового провайдера, автоматически выбрана первая доступная модель.
5. Если запрос упал — индикатор гаснет, список пуст, комбобокс недоступен (как при пустом списке), UI не завис.

Первая загрузка настроек ведёт себя как раньше: общий лоадер, оба контрола заблокированы, пока не пришли провайдеры и модели.

## Дерево компонентов и файлы

- `frontend/src/components/ModelSelector.tsx` (изменяется) — принимает раздельные состояния загрузки; размещает индикатор загрузки моделей рядом с комбобоксом; управляет `disabled` провайдерского `<select>` и `ModelCombobox` независимо.
- `frontend/src/components/ModelCombobox.tsx` (без обязательных правок) — уже закрывает дропдаун и чистит фильтр по `disabled` (эффект 39–44) и по смене `modelsKey` (48–51). Правится только при необходимости добавить `aria-busy` на триггер.
- `frontend/src/hooks/useSettings.ts` (изменяется, backend не UI, но определяет контракт) — вводит признак «модели грузятся» и очистку `models` на время refetch.
- `frontend/src/App.tsx` (изменяется) — прокидывает новый признак загрузки моделей в `ModelSelector`.

## Layout и состояния

Раскладка не меняется: `flex items-center gap-2`, слева индикатор+select провайдера, справа контейнер `min-w-[12rem] max-w-[18rem]` с комбобоксом. Индикатор загрузки моделей закрепляется **у комбобокса** (в его контейнере), а не у провайдера — ТЗ касается только списка моделей.

Состояния (два независимых признака: `loading` — первичная загрузка, `modelsLoading` — refetch моделей после смены провайдера):

- **Initial loading** (`loading === true`): виден индикатор загрузки; провайдерский `<select>` и комбобокс оба `disabled`; триггер комбобокса показывает пустой/плейсхолдерный лейбл. Дропдаун открыть нельзя.
- **Idle / success** (`loading === false`, `modelsLoading === false`, `models.length > 0`): индикатора нет; оба контрола активны; триггер показывает имя выбранной модели.
- **Models loading** (`modelsLoading === true`): у комбобокса виден индикатор загрузки; комбобокс `disabled`; провайдерский `<select>` **остаётся активным**; список моделей на время загрузки пуст (`models = []`), чтобы старые модели не мелькали и не выдавались за актуальные.
- **Empty / error** (`loading === false`, `modelsLoading === false`, `models.length === 0`): индикатора нет; комбобокс `disabled` (нечего выбирать); провайдерский `<select>` активен; триггер показывает пустой лейбл. Это же состояние возникает после неудачного refetch.

Индикатор загрузки: сохраняем текстовый маркер «загрузка…» (`text-[11px] text-slate-500`) как в текущем UI — консистентность важнее нового спиннера. Разрешён вариант заменить текст на маленький крутящийся индикатор (`animate-spin`) того же цвета, если он ставится в тот же слот; текст остаётся дефолтом.

## Взаимодействия

- **Смена провайдера** (`onChange` у `<select>`): немедленно, синхронно — новый провайдер отражён в `<select>`, поднят признак `modelsLoading`, `models` очищены, комбобокс заблокирован и показывает индикатор. Без задержки/дебаунса.
- **Повторная смена во время загрузки:** провайдерский `<select>` активен, пользователь может выбрать ещё раз; отображается провайдер из последнего выбора, индикатор держится до прихода соответствующего списка.
- **Клик по комбобоксу во время загрузки:** невозможен (`disabled`); открытый ранее дропдаун закрывается (существующий эффект по `disabled`).
- **Успех:** индикатор снят, комбобокс активен, показан новый список, выбрана первая модель — триггер сразу отражает её имя.
- **Ошибка refetch:** индикатор снят, список пуст, комбобокс `disabled`; UI не остаётся в состоянии загрузки (флаг снимается в `finally`).
- **Крайние случаи:** пустой список после успешного ответа = состояние empty; отсутствие провайдеров = провайдерский `<select>` `disabled` (как сейчас, `providers.length === 0`).

## Стиль и токены

- Контейнеры и контролы — как сейчас: `rounded bg-slate-800 px-2 py-1 text-xs text-slate-100 disabled:opacity-50`.
- Индикатор: `text-[11px] text-slate-500`, слот у комбобокса; при использовании спиннера — иконка `h-3 w-3 animate-spin text-slate-500`.
- `disabled:opacity-50` уже даёт визуальную обратную связь недоступности — отдельных цветов не вводим.
- Никаких новых зависимостей и цветовых токенов; палитра `slate/indigo` из существующего UI.

## Доступность (a11y)

- Индикатор загрузки моделей помечается `role="status"` + `aria-live="polite"`, чтобы смена состояния озвучивалась скринридером; текст «загрузка…» остаётся его содержимым.
- Триггер комбобокса на время загрузки получает `aria-busy="true"` (в дополнение к `disabled`), чтобы состояние «идёт загрузка» было программно доступно.
- Заблокированный комбобокс не участвует в табуляции (нативный `disabled` у `<button>`); фокус на нём не застревает.
- Провайдерский `<select>` сохраняет `aria-label="Провайдер"`; во время `modelsLoading` он фокусируем и управляем с клавиатуры.
- Контраст `slate-500` на тёмном фоне сохраняется прежним — не регрессируем.

## Контракты данных (если нужны)

- `getProviderModels(provider)` → `ModelOut[]` (см. `frontend/src/api.ts`), используется в `changeProvider`. Backend не меняется (см. план, «Backend не меняется»).
- `ModelSelector` получает от `useSettings` (через `App.tsx`): `provider`, `model`, `providers: ProviderOut[]`, `models: ModelOut[]`, признак первичной загрузки и признак загрузки моделей. Точные имена/форма пропсов — за фазой генерации; UI-контракт: провайдерский `<select>` блокируется только на первичной загрузке, комбобокс — на первичной загрузке и на refetch моделей.

## Критерии визуальной приёмки

- [ ] Сразу после смены провайдера у комбобокса моделей виден индикатор загрузки (до прихода ответа `/providers/{id}/models`).
- [ ] Во время загрузки моделей комбобокс недоступен и не показывает старые модели нового провайдера (старый список не выдаётся за актуальный).
- [ ] Провайдерский `<select>` во время загрузки моделей остаётся активным (доступна повторная смена).
- [ ] После загрузки индикатор исчезает, комбобокс активен и показывает модели нового провайдера с автоматически выбранной первой моделью.
- [ ] При ошибке загрузки индикатор снят, список пуст, комбобокс недоступен, UI не завис в состоянии загрузки.
- [ ] Первичная загрузка настроек по-прежнему показывает индикатор и блокирует оба контрола.
- [ ] Индикатор снабжён `role="status"`/`aria-live`, триггер комбобокса — `aria-busy` во время загрузки.
