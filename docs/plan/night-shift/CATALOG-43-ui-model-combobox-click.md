## Контекст

### Симптом

После выбора провайдера первая модель подставляется автоматически (`useSettings.changeProvider`, `useSettings.ts:87-97`). Если затем открыть комбобокс моделей и кликнуть на другой элемент — `value` не меняется, отображение остаётся на первой модели. То есть `onChange` на option не срабатывает (или срабатывает, но после `close`, и React батчит так, что пользовательского эффекта нет).

### Корневая причина

В `frontend/src/components/ModelCombobox.tsx`:

1. **`<input>` с `autoFocus`** (`ModelCombobox.tsx:118-125`) — при открытии попапа фокус сразу уходит в поиск.
2. **`onBlur` на контейнере** (`ModelCombobox.tsx:66-70`):
   ```
   onBlur={(e) => {
     if (!rootRef.current?.contains(e.relatedTarget as Node)) {
       close()
     }
   }}
   ```
3. **`<div role="option">`** без `tabIndex` (`ModelCombobox.tsx:133-154`) — не является фокусируемым. Клик по нему через `onClick`.

Когда пользователь кликает на `<div role="option">`, последовательность событий:

- `mousedown` на div-option → браузер пытается перевести фокус; т.к. div не tabbable, фокус из `<input>` уходит на `<body>` (или `relatedTarget = null`).
- `onBlur` на корневом контейнере срабатывает **до** `onClick`.
- В `onBlur` проверка: `rootRef.current?.contains(e.relatedTarget)`. `relatedTarget === null` (или body) → не содержится в root → `close()` → `setOpen(false)`.
- `onClick` на option либо не доходит (popup уже размонтирован), либо `onChange` вызывается, но это уже не видно — попап закрыт, и впечатление «ничего не изменилось». Если `value` всё же обновляется в state, но визуально кнопка-триггер обновляется на новую модель — пользователь не видит попапа и думает, что выбор не применился.

Самый вероятный сценарий по жалобе «выбор модели не изменился» — `onClick` **не срабатывает**, потому что попап закрывается на `mousedown`/`blur` раньше.

### Дополнительный фактор — `modelsKey` reset

`ModelCombobox.tsx:46-51`:

```
const modelsKey = useMemo(() => models.map((m) => m.id).join('\0'), [models])
useEffect(() => { setOpen(false); setFilter('') }, [modelsKey])
```

Это закрывает попап при смене `models` (после `changeProvider` — ок). На сценарий выбора модели не влияет, потому что `changeModel` не меняет массив `models`. Но это полезно знать: любые будущие подписки на `models` (например, polling или refetch) будут закрывать попап неожиданно.

### Тот же паттерн в `DocumentCombobox`

Похожий комбобокс есть в `frontend/src/components/DocumentCombobox.tsx` (используется в чате и в SkillSettings). Если у него та же логика с `onBlur` + autoFocus input + `<div role="option">`, та же проблема может проявляться и там. Проверить и при необходимости пофиксить вместе.

## План действий

1. **Убрать `onBlur`-закрытие или сделать его безопасным.** Варианты:
   - **(рекомендуется)** Заменить `onBlur`-закрытие на проверку только `mousedown` вне контейнера (этот механизм уже есть в `ModelCombobox.tsx:27-37`). Удалить обработчик `onBlur` на корневом div — `mousedown`-outside достаточно и не ломает клик по option.
   - Альтернатива: оставить `onBlur`, но в `relatedTarget === null` **не** закрывать (считать это «фокус ушёл внутрь»), либо использовать `setTimeout(close, 0)` — но это хрупко.
2. **Сделать option фокусоустойчивым.** Добавить `onMouseDown={(e) => e.preventDefault()}` на `<div role="option">` — это предотвращает увод фокуса из `<input>` при клике, сохраняя `relatedTarget` корректным, и `onClick` гарантированно срабатывает. Это классический паттерн для listbox с поиском.
3. **Унифицировать с `DocumentCombobox`.** Если там та же структура (autoFocus input + onBlur + div-option), применить пункты 1–2.
4. **Регрессионный тест** (опционально, если в проекте есть vitest/react-testing-library): рендер `ModelCombobox`, открыть, кликнуть на 2-ю опцию, убедиться, что `onChange` позван с правильным `id`. Проверить структуру тестов в `frontend/`.
5. **Ручная проверка**: выбрать провайдера → открыть список моделей → кликнуть на 2-ю модель → значение должно обновиться в триггере; попап закрыт; backend `updateSettings` позван (через `useSettings.changeModel`).
