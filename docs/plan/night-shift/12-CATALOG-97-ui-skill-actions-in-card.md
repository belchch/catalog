### Описание
Сейчас действия над скилом («Переименовать», «Редактировать», «Коммит», «⋯» → «Удалить») живут в тулбаре **над** списком скилов, а выбранный скил раскрывается **внизу списка**. Пользователь не замечает, что действия появились, и не понимает, к какому скилу они относятся.

Причина не в контрасте кнопок, а в двух вещах:

- **Change blindness.** Клик происходит по карточке, а активация кнопок — вверху панели, вне зоны внимания. Повышение контраста тут не помогает: кнопки станут заметнее только после того, как пользователь туда посмотрит, а смотреть он не начнёт.
- **Нет общей области (Gestalt).** Между тулбаром и выбранной карточкой стоят поиск и часть списка. Ничто не связывает кнопки с конкретным скилом.

Побочная проблема: клик по уже выбранной строке снимает выбор (toggle), поэтому пользователь, повторно тыкая в карточку, случайно гасит и её раскрытие, и все действия.

### Что сделать

**1. Перенести панель действий внутрь раскрытой карточки.** Ряд «Переименовать / Редактировать / Коммит / ⋯» переезжает в блок, который раскрывается под выбранной строкой — там, куда пользователь уже смотрит. Верхний тулбар удаляется целиком, вместе с ним уходит мёртвое disabled-состояние из трёх серых кнопок.

Позиция внутри раскрытого блока: под метаданными (описание, провайдер/модель), отдельной группой, визуально отделённой от кнопок запуска «В док» / «На экран» — это разные по смыслу и по риску действия, их нельзя ставить в один ряд.

**2. Иконки быстрых действий на самой строке.** На hover и на выбранной строке справа проявляются иконки (редактировать, коммит, kebab) — паттерн Linear/Notion/GitHub. В узком сайдбаре текстовые подписи не влезают, поэтому иконки + `title`. Не должны прыгать при появлении: место под них резервируется всегда.

**3. Усилить признак выбора.** Сейчас выделение — только `bg-brand-soft`, без рамки. Добавить левую акцентную полоску 2–3px цветом `--brand` к фону, чтобы выбранная строка читалась как активный объект, с которым что-то можно делать, а не как просто подсвеченная строка.

**4. Убрать toggle на повторном клике по выбранной строке.** Снятие выбора остаётся на Escape и на клике вне списка.

### Связь с другими задачами
Существующая задача про повышение контраста кнопок становится необязательной: после переноса действий внутрь карточки заметность решается размещением, а не яркостью. Стоит либо закрыть её, либо переформулировать в «ревизия контраста `.btn-secondary` в сайдбаре» отдельно от этой.

## Контекст
- Все указанные в ТЗ ориентиры в `frontend/src/components/SkillsPanel.tsx` сверены с кодом и совпадают: `selectSkill` с toggle — `:250-253` (`setSelectedId((prev) => (prev === id ? null : id))`), `toolbarDisabled` / `commitDisabled` — `:317-318`, строка скила — `:531-580`, стили выделения — `:539-544` (`isSelected ? 'bg-brand-soft text-ink' : 'text-ink-muted hover:bg-surface-hover'`), раскрытый блок — `:582` и далее.
- Строка скила — это `div[role="option"]` с `aria-selected` (`:535-536`) внутри `li` (`:530`), то есть список реализован как listbox. Иконки быстрых действий встраиваются внутрь этой строки — значит, у вложенных кнопок нужен `e.stopPropagation()`, чтобы клик не уходил в `onClick={() => selectSkill(s.id)}` (`:545`). Приём в файле уже применяется — например в кнопке «ещё» для описания (`:598-601`).
- Раскрытый блок начинается с описания скила (`:584-604`), туда же по ТЗ уезжает группа действий — под метаданными и визуально отдельно от кнопок запуска.
- Клавиатура: обработчик `onListKeyDown` (`:281-313`) — `ArrowDown` / `ArrowUp` через `moveSelection` (`:255-270`), `Enter` → `applyPersistSelected` (`:272-279`, запуск в док), `Escape` с каскадом: сначала закрывает подтверждение удаления (`:299-302`), затем overflow-меню (`:303-306`), затем переименование (`:307-310`), и только потом снимает выбор (`:311`). Этот каскад нужно сохранить целиком — после удаления toggle он остаётся единственным способом снять выбор с клавиатуры.
- «Клик вне списка снимает выбор» из ТЗ в коде сейчас **не реализован** — есть только toggle (`:251`) и `Escape` (`:311`). Значит обработчик клика вне списка нужно добавить, иначе после удаления toggle снятие выбора мышью станет невозможным. Это отдельный пункт работы, а не «оставить как есть».
- `moveSelection` (`:255-270`) прокручивает выбранный элемент через `optionRefs` и `scrollIntoView({ block: 'nearest' })` (`:267-269`). После добавления раскрытого блока с действиями высота выбранного элемента вырастет — проверить, что прокрутка по ↑↓ по-прежнему показывает саму строку, а не только её раскрытую часть.
- `clearRename()` вызывается при выборе (`:252`) и при перемещении (`:266`) — при переносе формы переименования внутрь карточки эта связка должна сохраниться, иначе форма «переедет» на другой скил.
- Состояния меню и подтверждения (`confirmOpen`, `overflowOpen`, `renameId`) сейчас глобальные для панели — это корректно, пока действия относятся к единственному выбранному скилу. При переносе внутрь карточки их можно оставить глобальными, но рендерить строго внутри выбранной карточки; альтернатива — привязать к `s.id`. Решение зафиксировать в дизайн-спеке.
- Подтверждение удаления по ТЗ не должно перекрывать соседние скилы — то есть это inline-блок внутри карточки, а не абсолютно позиционированный поповер.
- Стилевые ресурсы подтверждены: `--brand`, `--brand-soft` и `--radius-control` есть в `frontend/src/index.css` (`:34`, `:36`, `:64`), иконочные классы `.btn-icon` / `.btn-icon-brand` / `.btn-icon-danger` — `index.css:128-139`.
- Иконки: готового модуля иконок в проекте нет. [CATALOG-89](docs/plan/night-shift/04-CATALOG-89-ui-message-command-icons.md) создаёт `frontend/src/components/icons.tsx` — если он выполнен раньше, добавить туда edit / commit / kebab; иначе создать модуль здесь. Новых npm-зависимостей не тянуть.

Левая полоска и hover-состояния должны опираться на токены, а не на конкретные значения цветов, тогда порядок выполнения не критичен.

## Критерии приёмки (Definition of Done)
- [ ] Действия над скилом видны только при выборе скила и находятся внутри его раскрытой карточки; тулбара над списком нет.
- [ ] Кнопки действий визуально отделены от кнопок запуска скила («В док», «На экран»).
