## Цель и пользовательский путь

Когда WebSocket-соединение чата закрывается (idle-таймаут, обрыв сети, StrictMode-remount), пользователь видит не только пассивную плашку «Соединение закрыто», но и явную кнопку **«Переподключить»**. Клик пересоздаёт сокет для текущего `sessionId`, плашка исчезает, диалог продолжается без перезагрузки страницы и без потери ленты.

Сценарий:
1. Пользователь ведёт диалог. Соединение живёт.
2. Соединение падает (сеть/idle) → под лентой появляется строка-баннер «Соединение закрыто» и рядом кнопка «Переподключить».
3. Клик по «Переподключить» → кнопка переходит в состояние «Переподключаю…» (disabled), сокет пересоздаётся на том же `sessionId`.
4. Успех (`onopen`) → баннер и кнопка исчезают, поле ввода снова активно, можно отправлять сообщения. Лента сохраняется (сообщения не сбрасываются).
5. Если сокет снова сразу закрылся (реконнект не удался) → баннер «Соединение закрыто» возвращается, кнопку можно нажать повторно.
6. Ложный `closed` после StrictMode-remount / смены сессии не залипает: баннер не показывается при живом сокете.

## Дерево компонентов и файлы

- `frontend/src/hooks/usePlannerSession.ts` (**изменить**) — источник состояния и действия реконнекта (детали в code-плане CATALOG-23; UI полагается на контракт ниже):
  - в `UsePlannerSessionResult` добавить `reconnect: () => void` и `reconnecting: boolean`.
  - `reconnect()` пересоздаёт `PlannerConnection` для текущего `sessionId`, сбрасывает `closed`/`error`, ставит `reconnecting = true` до `onOpen`/`onClose`.
  - при `onOpen` всегда `setClosed(false)` и `setReconnecting(false)`.
  - не залипающий `closed`: сброс `closed` в начале эффекта подключения (паттерн из `useRunStream`) / флаг намеренного close в cleanup.
- `frontend/src/components/Chat.tsx` (**изменить**) — принять новые пропсы `onReconnect: () => void` и `reconnecting: boolean`; отрисовать кнопку «Переподключить» рядом с существующим баннером «Соединение закрыто» (`Chat.tsx:90`).
- `frontend/src/App.tsx` (**изменить**) — пробросить в `<Chat>` пропсы `onReconnect={planner.reconnect}` и `reconnecting={planner.reconnecting}` (рядом с уже передаваемыми `closed`, `error`).

Новых зависимостей и новых компонентов не вводить — только текущий стек (React 19 + Vite + TS + Tailwind v3) и существующие паттерны.

## Layout и состояния

Общий layout `Chat` не меняется. Баннер живёт там же, где сейчас, — в конце ленты внутри скроллируемой области (`flex-1 overflow-y-auto`), перед `bottomRef`. Меняется только его наполнение: вместо одиночной строки текста — компактная строка «текст + кнопка».

Структура блока баннера (заменяет `Chat.tsx:90`):
- Обёртка-строка: `my-2 flex items-center gap-2 text-xs`.
- Текст статуса: `text-amber-400` — «Соединение закрыто».
- Кнопка «Переподключить» справа от текста (компактная, в стиле вторичных кнопок чата).

Состояния (взаимоисключающие для этого блока):
- **live** (`!closed && !reconnecting`): баннер и кнопка не отображаются (как сейчас при живом сокете).
- **closed** (`closed && !reconnecting`): виден баннер «Соединение закрыто» + активная кнопка «Переподключить».
- **reconnecting** (`reconnecting`): текст меняется на «Переподключаю…», кнопка `disabled` с подписью «Переподключаю…» (или тем же лейблом в disabled-виде). Баннер `amber` остаётся, чтобы не «прыгал» layout.
- **success**: после `onOpen` `closed`/`reconnecting` = `false` → блок исчезает, поле ввода активно.

Взаимодействие с существующими состояниями:
- `error` (`Chat.tsx:91`) остаётся отдельной строкой ниже; при реконнекте `error` сбрасывается (см. хук), поэтому строка ошибки не конфликтует с баннером.
- `streaming`-индикатор («планировщик думает…») и баннер `closed` в норме не показываются одновременно; специальная обработка не требуется.

## Взаимодействия

- **Клик «Переподключить»** → `onReconnect()`. Кнопка сразу `disabled` (через `reconnecting`), чтобы исключить двойной клик и параллельные сокеты.
- **Успешный реконнект** → баннер и кнопка исчезают; поле ввода и кнопка «Отправить» снова активны (они завязаны на `streaming`, не на `closed`, так что специально ничего не блокируем).
- **Неуспешный реконнект** (сокет закрылся снова) → `reconnecting = false`, `closed = true`; пользователь видит баннер и может нажать кнопку ещё раз.
- **Очередь сообщений**: если пользователь отправлял сообщение при закрытом сокете, оно уже кладётся в `pendingRef` (текущее поведение `send`); после успешного реконнекта `onOpen` отправляет очередь. Дизайн это поведение не меняет и на него не завязывается.

Крайние случаи:
- Двойной клик по кнопке — исключён `disabled` в состоянии `reconnecting`.
- Реконнект без выбранной сессии (`sessionId === null`) невозможен: при `null` баннер `closed` не показывается (сессии нет), кнопка отсутствует.
- Быстрый повторный обрыв: цикл closed → reconnecting → closed повторяем без ограничения ретраев (ручной реконнект, авто-ретраев в этом срезе нет).

## Стиль и токены

Консистентность с существующим тёмным UI (Tailwind v3, палитра slate/indigo/amber):
- Обёртка баннера — `my-2 flex items-center gap-2 text-xs` (сохраняем прежние вертикальные отступы `my-2`).
- Текст статуса — `text-amber-400` (без изменений относительно текущего).
- Кнопка «Переподключить» — вторичная кнопка в стиле нижней панели чата: `rounded-md border border-slate-700 px-2 py-1 text-xs text-slate-300 transition-colors hover:border-indigo-500 hover:bg-slate-800 disabled:opacity-50` (согласуется с кнопкой «Создать скилл из сессии» и чипами-подсказками).
- Никаких новых цветовых токенов, иконок-ассетов или карточек — плоская строка «текст + кнопка».

## Доступность (a11y)

- Блок баннера — контейнер с `role="status"` и `aria-live="polite"`, чтобы смена «Соединение закрыто» / «Переподключаю…» озвучивалась скринридером.
- Кнопка «Переподключить» — обычный `<button type="button">`, фокусируемая, активируется Enter/Space; в состоянии `reconnecting` — `disabled` (и `aria-busy` на контейнере или кнопке по желанию генератора).
- Текст кнопки самодостаточен («Переподключить»); отдельный `aria-label` не обязателен, но при иконочном варианте — обязателен (иконочный вариант не выбран).
- Контраст: `amber-400` на тёмном фоне и `slate-300` текст на `slate-700`-бордюре соответствуют остальному UI.
- Порядок фокуса естественный (баннер в потоке ленты, до поля ввода); фокус после исчезновения баннера не «теряется» — управление им не требуется, т.к. поле ввода остаётся на месте.

## Контракты данных

UI не ходит в API напрямую — потребляет контракт `usePlannerSession` (реализуется в парном code-плане `CATALOG-23-code-ws-idle-timeout.md` и в самом хуке, см. план CATALOG-23):
- `closed: boolean` — сокет закрыт без завершения; управляет показом баннера.
- `reconnecting: boolean` — идёт пересоздание сокета; управляет disabled-состоянием и текстом «Переподключаю…».
- `reconnect(): void` — пересоздать WS для текущего `sessionId`, сбросить `closed`/`error`.
- `error: string | null` — существующее поле, показывается отдельной строкой; сбрасывается при реконнекте.

WS-протокол и endpoint (`/sessions/{sessionId}`) — без изменений (`ws.ts`); реконнект = новый `connectPlanner(sessionId, …)` на том же id.

## Критерии визуальной приёмки

- [ ] При закрытом соединении (`closed`) под лентой видны текст «Соединение закрыто» (`amber-400`) и кнопка «Переподключить» рядом.
- [ ] Клик по «Переподключить» переводит кнопку в disabled-состояние с текстом «Переподключаю…» на время реконнекта.
- [ ] При успешном переподключении баннер и кнопка исчезают, поле ввода активно, лента сообщений сохранена (не сброшена).
- [ ] При неуспешном реконнекте баннер «Соединение закрыто» возвращается и кнопку можно нажать повторно.
- [ ] Ложный баннер после StrictMode-remount / смены сессии не залипает (при живом сокете баннер не показан).
- [ ] Строка ошибки (`error`, `red-400`) не конфликтует с баннером; при реконнекте ошибка сбрасывается.
- [ ] Кнопка стилистически консистентна с вторичными кнопками чата (border-slate-700 / hover indigo), без новых токенов и иконок.
- [ ] Баннер и кнопка доступны с клавиатуры; контейнер баннера имеет `role="status"`/`aria-live` для озвучивания смены состояния.
