- **Задача Plane:** [CATALOG-68](https://app.plane.so/belchch/projects/catalog-app/work-items/68) (id: `645ad178-9dca-4daf-94ee-e733a1d0ed5e`, state: In Progress)

- **Тип шага:** ui
- **Очередь:** 01 · независимый
- **Цель:** После смены провайдера сразу показать лоадер у списка моделей и не давать выбрать модель, пока не пришёл новый список с `/providers/{id}/models`. Сейчас комбобокс продолжает показывать старый список.

## Постановка задачи (актуальное ТЗ)

_(источник: описание задачи — комментариев не было)_

Списку моделей нужно время на загрузку после переключения провайдера. Нужно показывать лоадер, пока грузится список.

Сейчас лоадер есть только на **первой** загрузке настроек. После смены провайдера список моделей ещё едет с `/providers/{id}/models`, а комбобокс уже показывает **старый** список — флаг `loading` в этот момент не поднимается.

Нужно: при смене провайдера сразу показать лоадер у списка моделей и не давать выбрать модель, пока новый список не пришёл.

## Контекст

`useSettings` (`frontend/src/hooks/useSettings.ts`):

- `loading` стартует как `true` и сбрасывается только в `finally` начального `useEffect` (49–85). Это единственное место, где `setLoading` вызывается.
- `changeProvider` (87–97) сразу делает `setProvider(newProvider)`, затем `await getProviderModels(newProvider)` **без** `setLoading(true)` и **без** очистки `models`. Пока запрос идёт, UI держит предыдущий `models` и `loading === false`.
- После ответа: `setModels` → берётся `newModels[0]` → `writeLocal` + `updateSettings`. Ошибки `getProviderModels` не ловятся — промис уходит в `void settingsHook.changeProvider` из `App.tsx:441`.

`ModelSelector` (`frontend/src/components/ModelSelector.tsx:29, 49`):

- лоадер — текст «загрузка…», если `loading`;
- `ModelCombobox` `disabled={loading || models.length === 0}`.

Пока `loading === false` и старый `models` непустой, комбобокс кликабелен и показывает модели предыдущего провайдера. `ModelCombobox` закрывает дропдаун только при смене `modelsKey` (47–51) — то есть уже после прихода нового списка.

`App.tsx:435–443` прокидывает `loading={settingsHook.loading}` и `onProviderChange={(p) => void settingsHook.changeProvider(p)}`. Контракт пропсов менять не обязательно, если достаточно общего `loading`; отдельный `modelsLoading` нужен только если провайдер должен оставаться переключаемым во время загрузки моделей.

Backend (`getProviderModels` в `api.ts`) не меняется.

## Затрагиваемые файлы

- `frontend/src/hooks/useSettings.ts` — в `changeProvider` поднять loading (или `modelsLoading`), очистить/не показывать stale `models`, `try/finally`, чтобы флаг не залип при ошибке.
- `frontend/src/components/ModelSelector.tsx` — лоадер у списка моделей на время refetch; комбобокс disabled, пока список не пришёл. При отдельном флаге — не блокировать select провайдера.
- `frontend/src/App.tsx` — только если появится отдельный проп `modelsLoading`.
- `frontend/src/components/ModelCombobox.tsx` — правки не обязательны: `disabled` уже закрывает дропдаун (`40–44`).

## План действий

1. **Хук.** В `changeProvider`: сразу `setLoading(true)` (или отдельный `modelsLoading`), очистить `models` (`setModels([])`), чтобы не мелькал чужой список. `getProviderModels` в `try/finally` с `setLoading(false)`. При ошибке — пустой список, модель сбросить, не оставлять stale.
2. **Порядок state.** `setProvider` можно оставить сразу (select показывает новый провайдер). `setModel` / persist / `updateSettings` — только после успешного списка, как сейчас.
3. **Селектор.** Пока модели грузятся: видимый лоадер рядом с комбобоксом (существующий «загрузка…» или индикатор на триггере). `ModelCombobox` disabled. Select провайдера: либо тоже disabled через общий `loading` (проще), либо оставить активным через отдельный флаг — предпочтительно второе, ТЗ говорит только про список моделей.
4. **Не ломать первую загрузку.** Начальный `useEffect` по-прежнему использует `loading`; оба сценария должны показывать лоадер и блокировать выбор модели.
5. **Проверки.** Сменить провайдера вручную: сразу лоадер, старые модели не выбираются, после ответа — новый список и автовыбор первой модели. `pnpm run build`, `pnpm run lint`, `pnpm run typecheck` из `frontend/`.
