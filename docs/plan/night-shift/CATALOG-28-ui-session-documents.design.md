# CATALOG-28 — Дизайн UI

- **Источник:** docs/plan/night-shift/CATALOG-28-ui-session-documents.md
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Пользователь детерминированно указывает, с какими документами планировщик работает в этой сессии, и всегда видит актуальный состав сессии.

Сценарий:
1. В чате пользователь жмёт «+ документ» в composer → открывается пикер со списком документов.
2. Отмечает нужные → над полем ввода появляются чипы выбранных документов (pending-выбор, ещё не отправлено).
3. Ненужный чип можно снять крестиком; выбор можно очистить целиком.
4. Отправляет сообщение (или пустой текст с выбранными доками — см. «Взаимодействия») → фронт передаёт `doc_ids` в WS-фрейме `user`.
5. Сервер отвечает фреймом `session_docs`; блок «Документы в сессии» показывает актуальный состав (кумулятивно, с сервера). Pending-выбор в composer очищается.
6. При переоткрытии/выборе сессии состав подтягивается через `GET /sessions/{id}/documents` — блок наполняется без отправки сообщения.

Ключевое разграничение: состав сессии (planner-контекст) живёт в области чата и **не связан** с `currentDocId` (apply-выбор в сайдбаре `DocumentList` / `SkillsPanel`). Это два независимых механизма; в UI они разнесены визуально и по расположению.

## Дерево компонентов и файлы

Изменяемые:
- `frontend/src/api.ts` — новая обёртка `getSessionDocuments(sessionId): Promise<DocumentOut[]>` (`GET /sessions/{id}/documents`). Тип ответа — существующий `DocumentOut`.
- `frontend/src/ws.ts` — расширить `ServerEvent` вариантом `{ type: 'session_docs'; documents: DocumentOut[] }`; расширить `PlannerConnection.send` до `send(text: string, docIds?: string[])`, который при непустом `docIds` шлёт JSON-фрейм `{"type":"user","content":text,"doc_ids":docIds}`, иначе сохраняет текущее поведение (plain text).
- `frontend/src/hooks/usePlannerSession.ts` — держит серверное состояние `sessionDocuments: DocumentOut[]`; обрабатывает событие `session_docs`; при загрузке/смене `sessionId` делает `getSessionDocuments` (мягко, ошибки не критичны); сбрасывает список при смене сессии; расширяет `send` до `send(text, docIds?)` с прокидыванием `docIds` в WS (в т.ч. через очередь `pendingRef`).
- `frontend/src/components/Chat.tsx` — новый локальный state `selectedDocIds: string[]`; блок «Документы в сессии» (read-only, из props); ряд composer с pending-чипами и триггером «+ документ»; submit прокидывает `selectedDocIds` и очищает выбор.
- `frontend/src/App.tsx` — прокидывает в `Chat` список доступных документов (`docs.documents`) и `planner.sessionDocuments`; расширяет `handleSend` до `(text, docIds?)`.

Переиспользуемые (без правок логики):
- `frontend/src/components/DocumentCombobox.tsx` — используем в режиме `multiple` как пикер «+ документ» (управляем `values={selectedDocIds}` / `onChange`). Новых зависимостей и компонентов не вводим.

Новые файлы кода не требуются (кроме опционального выделения чипа в маленький presentational-компонент внутри `Chat.tsx` — на усмотрение генератора, не обязательно).

## Layout и состояния

Экран чата (`Chat.tsx`) — колонка `flex h-full flex-col`:
- Сверху вниз без изменений: баннер редактирования (если есть) → лента сообщений (`flex-1 overflow-y-auto`).
- Футер `border-t border-slate-800 p-3` перекомпонован в порядке сверху вниз:
  1. **Блок «Документы в сессии»** (серверное состояние) — виден только когда `sessionDocuments.length > 0`.
  2. Ряд быстрых ответов (`visibleSuggestions`) — как сейчас.
  3. **Ряд выбора**: pending-чипы выбранных документов + триггер «+ документ».
  4. Ряд ввода: `input` + кнопка «Отправить»/«Стоп» — как сейчас.
  5. Кнопка «Создать скилл из сессии» — как сейчас.

Состояния:
- **Loading (состав сессии):** во время `getSessionDocuments` отдельного скелета не показываем; блок просто отсутствует, пока список пуст. Допустимо тихое ожидание (нет глобального спиннера ради одного среза).
- **Empty (нет привязанных доков):** блок «Документы в сессии» скрыт. Ряд выбора всегда доступен (кнопка «+ документ»), даже если ещё не выбрано ничего.
- **Empty (нет документов вообще, `documents.length === 0`):** триггер «+ документ» показывается, но по клику пикер сообщает «нет совпадений» (поведение `DocumentCombobox`). Дополнительно допустимо задизейблить триггер — на усмотрение генератора; предпочтительно оставить активным для единообразия.
- **Success (есть состав):** блок «Документы в сессии» рендерит read-only чипы: бейдж `kind` (uppercase) + `title`. Чипы не кликабельны для навигации (это не apply-выбор).
- **Pending-выбор:** выбранные, но не отправленные документы показаны отдельными removable-чипами в ряду выбора; их набор синхронизирован с состоянием пикера.
- **Error:** ошибка загрузки состава не блокирует чат и не показывается как критичная (в крайнем случае — уже существующая строка `error` чата). Отдельного error-состояния для блока не вводим.
- **Streaming:** во время `streaming` триггер «+ документ» и удаление чипов задизейблены (консистентно с задизейбленным вводом), pending-выбор сохраняется до завершения turn.

## Взаимодействия

- **Открыть пикер:** клик по «+ документ» → dropdown `DocumentCombobox` (поиск + чекбоксы, поведение уже реализовано). Закрытие по клику вне / Esc — как в компоненте.
- **Выбрать/снять в пикере:** тумблит `selectedDocIds`; чип появляется/исчезает в ряду выбора немедленно.
- **Снять pending-чип:** клик по «×» на чипе (или Backspace/Enter при фокусе на крестике) удаляет id из `selectedDocIds`.
- **Отправка:**
  - Есть текст → `onSend(text.trim(), selectedDocIds)`, затем `setInput('')` и `setSelectedDocIds([])`.
  - Крайний случай — пустой текст, но есть выбранные доки: разрешаем «прикрепление без текста» — отправляем с пустым `content` и `doc_ids` (бэкенд принимает `content=""`). Кнопка «Отправить» активна, если `input` непустой **или** `selectedDocIds` непустой. Это обеспечивает критерий «выбор → после отправки виден в составе».
  - Во время `streaming` submit заблокирован (как сейчас).
- **Синхронизация с сервером:** после turn приходит `session_docs` → `sessionDocuments` обновляется; pending-выбор уже очищен на submit, поэтому дублирования чипов нет. Идемпотентность привязки — на бэкенде; повторный выбор уже привязанного дока безопасен.
- **Смена сессии:** `sessionDocuments` сбрасывается и перезапрашивается; `selectedDocIds` сбрасывается в `Chat` (через смену контекста/ключа или эффект по `sessionId`).
- **Отсутствие сессии (первое сообщение):** выбор возможен до создания сессии; при отправке `App.ensureSession()` создаёт сессию, затем `planner.send(text, docIds)` — `docIds` не теряются (кладутся в `pendingRef` до открытия WS).

## Стиль и токены

Строго в текущей палитре и утилитах Tailwind v3, без новых цветов.

- **Блок «Документы в сессии»:** контейнер `mb-2`. Заголовок-подпись: `mb-1 text-[11px] uppercase tracking-wide text-slate-500` с текстом «Документы в сессии». Чипы: `inline-flex items-center gap-1 rounded-full border border-slate-700 bg-slate-800/60 px-2.5 py-1 text-xs text-slate-300`; внутри бейдж kind `rounded bg-slate-700/60 px-1 text-[10px] uppercase text-slate-400`. Раскладка чипов: `flex flex-wrap gap-1.5`.
- **Pending-чипы (ряд выбора):** тот же чип-паттерн, но с акцентом выбора — `border-indigo-500/40 bg-indigo-600/15 text-indigo-100` и кнопкой удаления «×» справа (`ml-0.5 text-slate-400 hover:text-slate-100`).
- **Триггер «+ документ»:** визуально как существующие вторичные кнопки composer — `rounded-full border border-slate-700 bg-slate-800/60 px-3 py-1 text-xs text-slate-200 hover:border-indigo-500 hover:bg-slate-800 disabled:opacity-50` (совпадает со стилем quick-reply/suggestion-кнопок). `DocumentCombobox` оборачиваем в контейнер ограниченной ширины (например `w-44`/`max-w-[12rem]`), чтобы не растягивался на всю строку.
- **Ряд выбора:** `mb-2 flex flex-wrap items-center gap-1.5`.
- Отступы/типографика согласованы с уже существующими рядами composer (`text-xs`, `gap-2`, `mb-2`). Никаких теней/радиусов вне текущего словаря (`rounded`, `rounded-md`, `rounded-full`).

## Доступность (a11y)

- Блок «Документы в сессии» — секция с доступным именем: подпись-заголовок связана как `aria-label`/видимый заголовок; список чипов `role="list"`/элементы `role="listitem"` (или семантический `ul>li`). Read-only чипы не в табнавигации (не кнопки).
- Pending-чип: кнопка удаления — `<button type="button">` с `aria-label={`Убрать ${title}`}`, доступна с клавиатуры и по фокусу.
- Триггер «+ документ»: `DocumentCombobox` уже даёт `role="combobox"`, `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls`, `aria-label`; передать осмысленный `ariaLabel` («Добавить документы в сессию») и `placeholder="+ документ"`.
- Управление с клавиатуры пикера (Esc-закрытие, поиск, чекбоксы) — из существующего компонента, не регрессировать.
- Контраст: используемые slate/indigo-токены соответствуют текущему UI (тёмная тема), достаточный контраст текста чипов на `bg-slate-800/60`.
- Disabled-состояния во время `streaming` выставляют `disabled` (и, где уместно, `aria-disabled`), фокус не теряется на удалённых чипах.

## Контракты данных

- **Тип документа:** `DocumentOut` (`{ id, title, kind, created_at }`) — уже в `api.ts`.
- **REST:** `GET /sessions/{id}/documents` → `DocumentOut[]` (реализован в code-плане; см. `backend/app/api/sessions.py`). Обёртка `getSessionDocuments`.
- **WS исходящий (send):** `{"type":"user","content":<string>,"doc_ids":<string[]>}` при непустом выборе; иначе plain text (backend `_parse_user_payload` принимает оба). См. `CATALOG-28-code-session-documents.md`.
- **WS входящий (session_docs):** `{ type: "session_docs", documents: DocumentOut[] }` — источник истины для блока «Документы в сессии». Приходит сразу после attach в рамках turn.
- **Доступные для выбора документы:** `docs.documents` из `useDocuments` (глобальный список), пробрасывается из `App` в `Chat` как проп `documents`.
- Разделение с apply: `currentDocId` и `SkillsPanel` НЕ используют `sessionDocuments` и наоборот; проп сессионного состава не передаётся в сайдбар.

## Критерии визуальной приёмки

- [ ] В composer есть триггер «+ документ», открывающий пикер со списком доступных документов (поиск + мультивыбор).
- [ ] Выбранные (ещё не отправленные) документы отображаются removable-чипами над полем ввода; «×» снимает выбор.
- [ ] Кнопка «Отправить» активна, если есть текст **или** выбран хотя бы один документ; после отправки поле ввода и pending-выбор очищаются.
- [ ] После отправки с `doc_ids` появляется/обновляется блок «Документы в сессии» из серверного фрейма `session_docs` (а не только из локального выбора).
- [ ] При выборе/переоткрытии сессии блок «Документы в сессии» наполняется данными из `GET /sessions/{id}/documents` без отправки сообщения; при смене сессии сбрасывается.
- [ ] Блок «Документы в сессии» скрыт, когда состав пуст; read-only чипы показывают бейдж `kind` и `title`, не кликабельны как apply-выбор.
- [ ] Состав сессии визуально и по расположению отделён от `currentDocId` (сайдбар не отражает сессионный состав, и наоборот).
- [ ] Во время стриминга триггер «+ документ», удаление чипов и отправка задизейблены; pending-выбор не теряется.
- [ ] Стиль чипов/кнопок совпадает с существующими паттернами composer (rounded-full, slate/indigo токены); новых цветов/зависимостей нет.
- [ ] У кнопок удаления чипов и триггера пикера есть доступные имена (`aria-label`), управление с клавиатуры работает (Esc/Tab/Enter).
