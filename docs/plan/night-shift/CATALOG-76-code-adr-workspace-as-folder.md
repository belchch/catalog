## План действий

1. **Номер.** Создать `docs/adr/0016-workspace-as-folder.md`. В шапке: Date сегодня, Status Accepted, Revises/Supersedes частично ADR-0012 (и уточняет 0005/0008). В тексте явно: Plane CATALOG-76 называл это «ADR-0013»; номер сдвинут из-за занятого 0013.
2. **Содержание Decision** — покрыть все пункты ТЗ:
   - Воркспейс = произвольная папка пользователя; маркер `.catalog/`; бизнес-БД `.catalog/index.db`.
   - Две базы: workspace (`document`, `session`, `session_document`, `message`, `session_artifact`, `skill`, `skill_run`) и глобальная (настройки + реестр воркспейсов). Состав таблиц сверить со `schema.py`.
   - Открытие/переключение: нельзя переключить папку при активных `skill_run` со статусом `running`.
   - Три уровня проверки: маркер + `user_version` → `PRAGMA quick_check` → ре-скан файлов.
   - Папка с файлами без `.catalog` → не молчаливая инициализация, а **явное подтверждение**.
   - Имена файлов: без slug-переименования; `document.path` = файл там, где его положил пользователь.
   - Бэкапы: ротация `.catalog/backups/` для `index.db`.
   - Отказ от dulwich git-репо внутри пользовательской папки (пересмотр 0012 п.2–5 для user-folder; внутренние app-owned репо больше не модель воркспейса).
   - FTS5: задел в workspace `index.db`, связь с ADR-0008 (системный скилл, не UI-поле).
   - Чистый разрыв со старым `catalog.db`: **без миграции данных**.
3. **Consequences / Alternatives.** Плюсы (нативная доставка, папка = источник истины). Минусы (нет переноса из `catalog.db`, нет git-версий в папке). Альтернативы: оставить data-root+dulwich; мигрировать старую БД; молча создавать `.catalog`.
4. **Индекс.** Строка ADR-0016 в `docs/adr/README.md`. У 0012 — пометка в таблице или в самом файле: частично superseded.
5. **README.md.** Стек/архитектура/структура репо: не `workspace/` внутри инсталляции как единственная модель, а «открытая папка + `.catalog/index.db`». Список ADR до 0016. Быстрый старт оставить нативным (уже совпадает с новой доставкой).
6. **README-RUN.md.** Основной путь: нативный запуск (Python/venv + frontend или тот сценарий, который уже в README). Docker — вторичный/опциональный абзац, не шаг 1. «Где мои документы» = выбранная папка, не том `catalog-data`.
7. Код и Docker-скрипты не менять. Комментариев в markdown-ADR придерживаться стиля существующих файлов (это документация, не код).
