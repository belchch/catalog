# CATALOG-109 — Дизайн UI

- **Источник:** `docs/plan/night-shift/01-CATALOG-109-ui-sidebar-refresh-icons.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Шаг вычитающий: из заголовков секций сайдбара уходят три кнопки «Обновить …». Новых экранов, состояний и данных не появляется.

Что меняется для пользователя:

1. Пользователь наводит курсор на заголовок «Сессии» — справа проявляется **одна** кнопка «Новый чат» вместо двух.
2. Наводит на «Документы» или «Скиллы» — справа не проявляется ничего; строка заголовка только подсвечивается фоном и работает как переключатель сворачивания.
3. Списки он не обновляет вручную вообще: содержимое приходит само при загрузке приложения, смене воркспейса и после операций (создание сессии, загрузка документа, коммит/удаление скилла, завершение рана).
4. Единственный `RefreshIcon` в сайдбаре — рескан воркспейса в футере. Глиф перестаёт быть омонимом: раньше он означал и «перечитать список с бэкенда», и «пересканировать папку».

Почему так: глиф `RefreshIcon` в четырёх местах сайдбара обозначал два разных действия, а три из четырёх кнопок дублировали то, что хуки делают сами. Убираем дубли, оставляем одно значение за глифом.

## Layout и состояния

Строка заголовка — `.catalog-section-header` (`index.css:280-284`): `display:flex`, `justify-content: space-between`, `gap: 8px`, `min-height: 32px`, `padding: 0 8px`, sticky. Высота задана `min-height`, а не содержимым, поэтому исчезновение кнопок её не меняет.

| Секция | Строка заголовка после шага |
|---|---|
| Сессии | `[▸ СЕССИИ (12)] … [＋]` — правый блок проявляется по hover/focus-within |
| Документы | `[▸ ДОКУМЕНТЫ (3)]` — правого блока нет в DOM вообще |
| Скиллы | `[▸ СКИЛЛЫ (2)]` — правого блока нет в DOM вообще |

Выравнивание счётчика не уезжает: `.catalog-section-header__title` имеет `flex: 1`, то есть кнопка-заголовок и раньше занимала всю свободную ширину, а бейдж стоял сразу после текста (`gap: 6px`), а не у правой кромки. Удаление соседа меняет только доступную ширину, но не позицию бейджа относительно надписи.

Состояния экрана:

| Состояние | Что показываем |
|---|---|
| Загрузка списка (`X.loading`) | Ничего нового в заголовке. Индикатор загрузки секций **не добавляем** — это явное требование плана. Контент секции ведёт себя как сейчас. |
| Пусто | Как сейчас: бейдж не рендерится (`count > 0`), внутри секции — существующее пустое состояние панели. |
| Ошибка | Как сейчас: ошибки хуков показывают панели/`notice`, заголовок к этому не причастен. |
| Нет воркспейса (`!hasWorkspace`) | «Новый чат» в заголовке «Сессий» — `disabled` (`opacity: .5`, `cursor: not-allowed`). У «Документов» и «Скиллов» отключать больше нечего. |

## Взаимодействия

- Клик по строке заголовка «Документы» / «Скиллы» — сворачивание/разворачивание секции. Раньше правая часть строки была занята кнопкой, теперь вся ширина строки — цель переключателя. Это улучшение попадания, специально ничего добавлять не нужно.
- Hover-раскрытие `.catalog-section-header__actions` не трогаем: правило остаётся в CSS и продолжает работать для «Сессий». У «Документов» и «Скиллов» обёртки нет — правило просто не находит цель.
- Hover-подсветка строки (`--sidebar-brand-hover`) сохраняется у всех трёх заголовков, включая те, где кнопок больше нет: строка остаётся кликабельной, и обратная связь на наведение обязана быть.
- Обновление данных — только автоматическое, через существующие хуки: первичная загрузка, смена воркспейса, создание/удаление сессии, загрузка документа, коммит/удаление/переименование скилла, завершение рана. Новых вызовов `refresh()` не добавляем и существующие не удаляем — методы хуков остаются в публичном API и продолжают вызываться из операций.
- Рескан в футере не меняет поведения: он остаётся единственным ручным «обновить» в сайдбаре и относится к папке, а не к спискам.

Крайние случаи:

- **Клавиатура.** У «Документов» и «Скиллов» из порядка табуляции уходит по одной кнопке; фокус-цепочка сайдбара становится: «Новый чат» (крупная кнопка) → заголовок «Сессии» → «Новый чат» (иконка) → содержимое секции → заголовок «Документы» → содержимое → заголовок «Скиллы» → содержимое → футер. Ловушек и «прыжков» не возникает.
- **Тач (`hover: none`).** Кнопка «Новый чат» в заголовке «Сессий» видима всегда — правило `opacity: 0` живёт внутри `@media (hover: hover)`. Поведение не меняется.
- **Фокус на удаляемой кнопке.** Кнопки исчезают вместе с релизом, а не по условию в рантайме, — сценария «фокус потерялся на живом экране» нет.
- **Дублирование «Новый чат».** Крупная кнопка над списком секций и иконка в заголовке «Сессий» сосуществуют, как сейчас. Это вне скоупа шага — не трогаем.

## Стиль и токены

Новых токенов, классов и утилит не появляется; ни одна строка `index.css` не меняется.

- Сохраняются: `.catalog-sidebar__icon-button size-7` у «Нового чата», 16px-глиф `PlusIcon` из общего `iconBase`, радиус `--radius-control`, hover `--sidebar-selected`, фокус `box-shadow: 0 0 0 2px var(--brand)`.
- Шкала громкости сайдбара из CATALOG-105 не затрагивается: футер (14px/600/`--ink`) → списки (14px) → заголовки (11px/600/uppercase/`--ink-faint`) → бейджи и иконки.
- Визуальный эффект шага — снижение плотности: в покое сайдбар и раньше не показывал эти кнопки, но при наведении на «Документы»/«Скиллы» больше не появляется ничего лишнего, а у «Сессий» проявляется один глиф вместо двух почти одинаковых по весу.
- Никаких Tailwind-цепочек взамен удалённого JSX не добавляем: удаление — это удаление, компенсирующей вёрстки не требуется.

## Доступность (a11y)

- Из дерева доступности уходят три кнопки с именами «Обновить сессии», «Обновить документы», «Обновить скиллы». В сайдбаре не остаётся ни одного доступного имени, начинающегося с «Обновить».
- Заголовки «Документы» и «Скиллы» сохраняют `aria-expanded`, `aria-controls`, `role="region"` + `aria-label={title}` на панели — контракт `CollapsibleSection` не меняется.
- Доступное имя кнопки-заголовка по-прежнему включает счётчик («Сессии 12»); `aria-hidden` на бейдже не ставим.
- `aria-hidden` на `.catalog-section-header__actions` не добавляем (запрет из CATALOG-106 остаётся в силе): скрытие идёт `opacity`, кнопка «Новый чат» обязана быть доступна с клавиатуры и скринридеру всегда.
- `focus-within` на строке заголовка остаётся — без него клавиатурный фокус попадал бы на невидимую кнопку «Новый чат».
- Контрасты и размеры целей не меняются: 28px icon-кнопка в 32px строке, `--ink-faint` на фонах сайдбара ≥5:1.
- Потери информации о загрузке нет по существу: `aria-busy` на удалённых кнопках сообщал о запросе, который пользователь сам и инициировал; автоматических запросов пользователь не инициирует, и объявлять их нечего. Замену (`aria-live`, спиннер в заголовке) не вводим — план это запрещает.

## Контракты данных

Новых API, WS-сообщений и типов нет. Публичные контракты не меняются:

- `CollapsibleSectionProps` остаётся прежним, включая `actions?: ReactNode`; вызовы без `actions` уже поддержаны (`:7`, `:40`).
- Хуки `useSessions` / `useDocuments` / `useSkills` сохраняют метод `refresh()` — он продолжает использоваться внутри операций и в других местах приложения. Удаляются только вызовы из JSX заголовков.
- Экспорты `icons.tsx` не меняются.
