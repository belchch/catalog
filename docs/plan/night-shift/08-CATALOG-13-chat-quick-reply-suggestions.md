# CATALOG-13 — Кнопки быстрых ответов (suggestions) в чате

- **Задача Plane:** [CATALOG-13](https://app.plane.so/belchch/projects/catalog-app/work-items/13) (id: `c6eece51-7ef4-4258-8a8e-a19f779cae58`, state: In Progress)
- **Статус плана:** Analyzed
- **Тип шага:** ui
- **Предпосылки:** нет
- **Цель:** Показывать в чате планировщика **кликабельные кнопки быстрых ответов** (suggestions) — стандартные варианты ответа «под рукой», в т.ч. при старте общения (когда сообщений ещё нет). На первом этапе список генерируется **моделью через системный промпт** (пробный вариант); позже возможен детерминированный источник. Клик по кнопке отправляет её текст как обычное user-сообщение.

## Контекст

Сейчас чат планировщика — инпут + кнопка «Отправить», никаких подсказок:

- **Бэкенд:** `PLANNER_SYSTEM_PROMPT` (`backend/app/api/sessions.py:32-38`) инструктирует модель быть планировщиком и пользоваться инструментами документов; **никаких требований предлагать варианты ответа нет**. WS `session_ws` (`sessions.py:68-145`) стримит кадры: `token/step/tool_call/tool_result/finish` (`sessions.py:98-140`) — кадра `suggestions` нет. Финальный текст ассистента досылается одним `token`-кадром (`sessions.py:128-132`).
- **Фронтенд:** протокол `ServerEvent` (`frontend/src/ws.ts:9-26`) не содержит `suggestions`; `usePlannerSession` (`frontend/src/hooks/usePlannerSession.ts:41-89`) обрабатывает только существующие типы; `Chat.tsx` (весь файл) рисует только инпут + кнопку «Отправить» + состояние стрима; пустой чат показывает подсказку «Опишите задачу…» (`Chat.tsx:41-45`). Кнопок-ответов нет.
- **Отправка:** `usePlannerSession.send(text)` (`usePlannerSession.ts:121-133`) — единый путь отправки; клик по suggestion просто вызовет `send(item)`.

Решение «модель генерирует системным промптом»: расширить системный промпт, чтобы модель завершала ответ компактным списком коротких вариантов, распарсить его на бэке и отдать отдельным кадром `suggestions`. Стартовые подсказки (при пустом чате) — статический набор или мини-обращение к модели.

## Затрагиваемые файлы

**Backend:**
- `backend/app/api/sessions.py:32-38` — расширить `PLANNER_SYSTEM_PROMPT`: модель должна предлагать 1–3 коротких варианта следующего ответа пользователя в фиксированном, легко парсимом формате (например, блок `<suggestions>a | b | c</suggestions>` или последняя строка `SUGGESTIONS:`); парсер вырезает этот блок из показываемого текста.
- `backend/app/api/sessions.py:98-140` — после получения финального текста модели: распарсить suggestions, вырезать их из `final_text` (чтобы не дублировались в сообщении), дослать кадр `{"type":"suggestions","items":[...]}` перед `finish`.
- (опц.) стартовые suggestions при подключении WS/пустой сессии — статический список (например, «Изучи документы», «Опиши задачу») или быстрый LLM-оборот; досылать сразу после `accept`.
- `backend/tests/test_api.py` — парсер suggestions корректно извлекает/вырезает; WS досылает `suggestions`-кадр.

**Frontend:**
- `frontend/src/ws.ts:9-26` — добавить `{ type:'suggestions'; items: string[] }` в `ServerEvent`.
- `frontend/src/hooks/usePlannerSession.ts:41-89,135` — обрабатывать `suggestions` → состояние `suggestions: string[]` в `UsePlannerSessionResult`; сбрасывать при новом сообщении/старте.
- `frontend/src/components/Chat.tsx:41-45,56-82` — рендерить кнопки suggestions (под сообщениями или над инпутом): при пустом чате — стартовый набор, после ответа модели — предложенные; клик → `onSend(item)`; прятать во время стрима.
- `frontend/src/App.tsx` (передача `suggestions`/`send` в `Chat`) — проброс без изменений, если `Chat` уже получает хук.

## План действий

1. **Формат suggestions.** Зафиксировать машинно-читаемый блок в ответе модели (напр. `<suggestions>…</suggestions>` с разделителем `|`); модель инструктируется системным промптом. Парсер `parse_suggestions(text) -> (clean_text, items)` вырезает блок и возвращает чистый текст + список.
2. **Системный промпт.** Дополнить `PLANNER_SYSTEM_PROMPT`: «предложи 1–3 коротких варианта следующего шага пользователя в блоке `<suggestions>`».
3. **Backend WS.** После финального текста парсить suggestions, чистить `final_text`, досылать `{"type":"suggestions","items": [...]}`. Сохранять в БД очищенный текст (`add_message` assistant, `sessions.py:130-132`).
4. **Стартовые suggestions.** Определить источник: статический набор или быстрый LLM-оборот при пустой сессии; досылать после `accept`. Зафиксировать статический для простоты (детерминизм — на будущее).
5. **Frontend ws.ts.** Тип `suggestions` в `ServerEvent`.
6. **Frontend хук.** `suggestions` в `UsePlannerSessionResult`; сброс при отправке/смене сессии.
7. **Frontend UI.** В `Chat` рендерить кнопки suggestions (чипы); клик → `onSend(item)`; скрытие во время стрима; стартовый набор при `messages.length===0`.
8. **Тесты.** Backend: парсер извлекает/вырезает; WS досылает `suggestions`. Frontend: typecheck/lint.
9. **Ручная проверка.** При входе в чат — стартовые кнопки; после ответа модели — её предложенные варианты; клик отправляет текст; блок suggestions не виден в сообщении.
