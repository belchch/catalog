# CATALOG-55 — UI: навигация по скилам (однострочный список + общий контекст)

- **Задача Plane:** [CATALOG-55](https://app.plane.so/belchch/projects/catalog-app/work-items/55) (id: `93396143-da98-4d27-8858-67b308bc65d9`, state: In Progress)
- **Статус плана:** Analyzed
- **Тип шага:** ui
- **Цель:** Превратить список скилов из стопки полноразмерных карточек в сканируемый однострочный список с поиском. Управление и запуск живут в контексте выбранного скила: одна выбранная строка вместо N развёрнутых форм.

## Постановка задачи (актуальное ТЗ)

_(источник: описание задачи — комментариев не было)_

Навигация по скилам затруднена из-за объёма информации внутри скила. Кнопки управления сделать общими: выбор скила, дальше управление в контексте выбранного. Текст коллапсить.

Уточнение: сворачиваемость карточек сама по себе проблему поиска не решает, поэтому в шаг входит и поиск по списку.

Разделить три роли, которые сейчас смешаны в карточке:

1. **Индекс** — однострочная строка: статус, имя (обрезка), теги, arity. Одинаковая высота у всех строк.
2. **Управление** — общий тулбар над списком, действует на выбранный скил.
3. **Запуск** — раскрывается в выбранной строке (раскрыт максимум один скил).

Плюс поиск по имени/описанию/тегам над списком; фильтрация клиентская. Backend не трогаем.

Вынос контекста в закреплённую панель или drawer/main (V2/V3) — вне объёма.

## План действий

1. **Состояние выбора.** Добавить `selectedId: string | null`. Клик по строке выбирает, повторный клик по выбранной — снимает выбор. Клавиатура: `↑`/`↓` двигают выбор, `Enter` на выбранном committed — «В док», `Esc` — снять выбор. У строк `aria-selected` / роль списка.
2. **Строка списка.** Свести `<li>` к одной строке фиксированной высоты: бейдж статуса, имя с `truncate`, теги компактно, значок arity. Описание, `SkillModelMeta`, кнопки управления из строки убрать.
3. **Поиск.** Поле над списком, фильтрация по `name` + `description` + `tags`, регистронезависимо, по подстроке. Пустой результат — «ничего не найдено» с кнопкой сброса. При смене фильтра выбранный скил, выпавший из выдачи, теряет выбор.
4. **Общий тулбар.** Кнопки «Переименовать», «Редактировать», «Коммит» (активна только для draft) над списком; неактивны, когда ничего не выбрано. «Удалить» — не в одном ряду с частыми действиями (overflow-меню «⋯» или отдельная позиция справа). Подтверждение обязано содержать **имя** скила.
5. **Контекст выбранного.** Внутри выбранной строки: описание (обрезка до 2 строк + «ещё»), `SkillModelMeta`, и для `status === 'committed'` — существующий блок запуска. Логику arity/слотов/валидации/промпта переиспользовать без изменений.
6. **Сохранение состояния форм.** `target` и `prompts` остаются `Record<skillId, …>` — переключение выбора не теряет документы и текст промпта.
7. **Переименование.** Инлайн-редактор запускать из тулбара для выбранного скила; поведение Enter/Escape/blur и `renameSavingRef` не менять.
8. **Проверки.** `pnpm run build`, `pnpm run lint`, `pnpm run typecheck` из `frontend/`. Визуальная приёмка по `CATALOG-55.design.md` (фаза catalog-designer).

## Критерии приёмки (Definition of Done)

- [ ] Невыбранный скил занимает одну строку фиксированной высоты; описание, мета модели и кнопки в строке не выводятся.
- [ ] Одновременно раскрыт максимум один скил — выбранный.
- [ ] Поиск фильтрует список по имени, описанию и тегам; пустая выдача показывает понятное сообщение.
- [ ] Кнопки управления общие, действуют на выбранный скил и неактивны без выбора.
- [ ] Подтверждение удаления содержит имя удаляемого скила.
- [ ] Блок запуска (документы по arity 1/2/multi, промпт для ai/agent, «В док» / «На экран») работает как раньше, включая валидацию двух разных документов.
- [ ] Выбранные документы и текст промпта сохраняются при переключении выбора на другой скил и обратно.
- [ ] Переименование, «Редактировать», «Коммит», «Удалить» вызывают те же пропсы `SkillsPanel`, контракт с `App.tsx` не сломан.
- [ ] Навигация с клавиатуры: `↑`/`↓` — выбор, `Enter` — запуск, `Esc` — снятие выбора; у строк корректные `aria-selected` / роль списка.
- [ ] Из `frontend/`: `pnpm run build`, `pnpm run lint`, `pnpm run typecheck` зелёные.
- [ ] Визуальная приёмка — по дизайн-спеке `CATALOG-55.design.md` (фаза catalog-designer на UI-шаге pipeline).
