# CATALOG-92 — Дизайн UI

- **Источник:** `docs/plan/night-shift/07-CATALOG-92-ui-picker-folder-filter.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Экран — модалка «Открыть воркспейс» (`WorkspacePicker`), секция «Обзор папок» в скроллящемся теле карточки (раскладка после CATALOG-91: закреплённая зона сверху + `div.min-h-0.flex-1.overflow-y-auto`). Сценарий:

1. Пользователь открывает модалку и попадает в папку с несколькими десятками подпапок. Под строкой навигации («текущий путь · Вверх · Открыть эту папку») он видит одно поле ввода с плейсхолдером «Фильтр по имени».
2. Он печатает часть имени — список под полем сужается **мгновенно, на каждый символ**, без запросов к бэкенду и без debounce. Регистр не важен, пробелы по краям игнорируются.
3. Если совпадений нет — на месте списка появляется «Ничего не найдено». Поле остаётся на экране, курсор в нём, текст можно поправить или стереть.
4. Пользователь очищает поле — возвращается полный список уровня.
5. Пользователь входит в найденную папку (клик по строке) или нажимает «Вверх» — новый уровень открывается **с пустым фильтром** и полным списком.
6. Секция «Недавние» на всё это не реагирует — она выше и живёт своей жизнью.

Вне сценария: рекурсивный поиск по дереву, подсветка совпавшей подстроки, история фильтров, фильтрация по пути.

## Дерево компонентов и файлы

- `frontend/src/components/WorkspacePicker.tsx` — **единственный изменяемый файл**:
  - новое состояние `filter: string` (начальное `''`) рядом с остальными состояниями компонента;
  - новый `useId()` для связи `label` ↔ `input` (в компоненте уже есть `titleId`, `bannerId` — тот же приём);
  - производное значение `visibleEntries` (фильтрованный массив) — вычисляется в теле рендера, без `useMemo` (список одного уровня, десятки элементов);
  - блок поля фильтра в JSX между строкой навигации и блоком состояний списка;
  - новая ветка «Ничего не найдено» в цепочке состояний списка;
  - `map` по `visibleEntries` вместо `entries`;
  - сброс фильтра при смене уровня — отдельный эффект.
- Новых компонентов, файлов и npm-зависимостей нет. `frontend/src/index.css` не меняется — класс `.field` уже есть в `@layer components`. `frontend/src/components/icons.tsx` не трогаем: иконка лупы в поле не нужна (плейсхолдера достаточно, остальные поисковые поля проекта — `ModelCombobox`, `DocumentCombobox`, `SkillsPanel` — тоже без иконки).

## Layout и состояния

### Место поля в секции «Обзор папок»

Порядок сверху вниз внутри `<section>`:

```
section
├ p.mb-1.text-[11px].text-ink-faint            «Обзор папок»            — без изменений
├ div.mb-2.flex.flex-wrap.items-center.gap-2   путь · Вверх · Открыть эту папку — без изменений
├ ▸ НОВОЕ: блок фильтра (label.sr-only + input.field), mb-2
└ блок состояний списка (загрузка / ошибка / пусто / ничего не найдено / ul)
```

Поле — **отдельная строка на всю ширину**, а не ещё один элемент в строке навигации: строка навигации уже `flex-wrap` с путём и двумя кнопками, добавление туда поля даёт непредсказуемые переносы на узкой модалке.

Разметка блока:

```
div.mb-2
├ label[htmlFor=filterId].sr-only            → «Фильтр по имени папки»
└ input#filterId[type=search].field          → placeholder «Фильтр по имени»
```

### Условие показа поля

Поле рендерится **только** при `!browseLoading && !browseError && entries.length > 0`, где `entries` — исходный, нефильтрованный массив уровня. Ключевое следствие: при непустом уровне и нулевом результате фильтрации (`entries.length > 0 && visibleEntries.length === 0`) поле **остаётся на экране** — иначе пользователь не сможет исправить запрос.

### Цепочка состояний списка

Порядок веток строго такой (первое истинное условие выигрывает):

| # | Условие | Поле фильтра | Что показываем |
|---|---|---|---|
| 1 | `browseLoading` | скрыто | `p.text-xs.text-ink-faint` «Загрузка…» — как сейчас |
| 2 | `browseError` | скрыто | `p.text-xs.text-danger-ink` с текстом ошибки — как сейчас |
| 3 | `entries.length === 0` | скрыто | `p.text-xs.text-ink-faint` «Нет вложенных папок» — как сейчас, текст не менять |
| 4 | `visibleEntries.length === 0` (новая ветка) | видно | `p.text-xs.text-ink-faint` «Ничего не найдено» с `role="status"` |
| 5 | иначе | видно | `ul.space-y-1` по `visibleEntries` — разметка строк без изменений |

Ветки 3 и 4 — разные сообщения и разные причины; текст «Нет вложенных папок» остаётся привязан **только** к `entries.length === 0`.

### Прочие состояния

- **Идёт запрос (`busy !== null`)**: поле фильтра остаётся **включённым**. Фильтрация — чисто клиентское сужение уже загруженного списка, она ничего не запускает и не отменяет; блокировать её смысла нет, а `disabled`-вид поля выглядел бы как поломка. Кнопки строк («Открыть», вход в папку) при этом остаются `disabled`, как сейчас, — это поведение CATALOG-91 не трогаем.
- **Смена уровня**: `filter` сбрасывается в `''` (см. «Взаимодействия»), поле на новом уровне пустое.
- **Панель результата / баннер занятости**: живут в закреплённой зоне карточки, фильтр их не касается — пересечения раскладок с CATALOG-91 нет.
- **Секция «Недавние»**: не меняется ни в разметке, ни в поведении.

## Взаимодействия

### Правило фильтрации

```ts
const query = filter.trim().toLowerCase()
const visibleEntries = query
  ? entries.filter((e) => e.name.toLowerCase().includes(query))
  : entries
```

- Подстрока, не префикс; регистр не учитывается (`toLowerCase()` с обеих сторон); края обрезаются (`trim()`).
- Фильтруем строго `entry.name`; `entry.path` не участвует.
- Пустая строка и строка из одних пробелов → полный список (тот же массив, без копии).
- Порядок элементов сохраняется — сортировку задаёт бэкенд, фильтр её не меняет.
- `has_catalog`-бейдж «воркспейс», `title={entry.path}`, `key={entry.path}` и обработчики `goInto` / `tryOpen(entry.path, false, 'browse-entry')` остаются как есть: фильтруется только массив перед `map`.

### Сброс при смене уровня

Один-единственный источник сброса — отдельный эффект по текущему уровню:

```ts
useEffect(() => {
  setFilter('')
}, [currentBrowsePath])
```

Это покрывает и `goInto`, и `goUp` (оба меняют `stack`), и любую будущую точку навигации. В `goInto` / `goUp` руками `setFilter('')` **не** добавлять — двойной логики быть не должно. В существующий эффект загрузки (`[currentBrowsePath, loadBrowse]`) сброс тоже не встраивать: он перезапускается ещё и при смене идентичности пропа `browse`, а это не смена уровня.

### Никаких новых запросов

`loadBrowse` зависит только от `currentBrowsePath`; состояние `filter` не должно попадать ни в его зависимости, ни в зависимости эффекта загрузки. Проверяется по вкладке Network: ввод в поле не порождает `/fs/browse`.

### Клавиатура и фокус

- Поле **не** автофокусится: первичный фокус при открытии модалки остаётся на кнопке «✕» (поведение CATALOG-91). `autoFocus` не ставить.
- Порядок табуляции в секции: «Вверх» → «Открыть эту папку» → поле фильтра → строки списка. Фокус-кольцо у поля — штатное из `.field` (`focus-visible:ring-2 focus-visible:ring-brand`).
- `Escape` продолжает закрывать модалку через существующий глобальный обработчик. Кастомной обработки `Escape` в поле нет, `stopPropagation` не добавляем. Побочный эффект `type="search"` в Chromium/WebKit (нативная очистка поля по `Escape`) допустим: модалка всё равно закрывается, состояние фильтра теряется вместе с ней.
- Нативный крестик очистки у `type="search"` (WebKit/Chromium) допустим и не стилизуется; отдельной кнопки «очистить» не рисуем — поле короткое, `Cmd/Ctrl+A` + Backspace достаточно.

### Крайние случаи

- Уровень пустой → поля нет, «Нет вложенных папок» (ветка 3), фильтр в состоянии `''`.
- Фильтр набран, пользователь нажал «Вверх» → уровень сменился, поле очистилось, полный список.
- Фильтр набран, вход в папку кликом по единственной найденной строке → тот же сброс.
- Фильтр набран, `browse` вернул ошибку после перехода → поле скрыто (ветка 2), состояние `filter` уже `''`.
- Очень длинные имена → строки списка не меняются, `truncate` + `title` работают как раньше.
- Фильтр совпал с папкой, у которой идёт открытие (`busy`) → строка со спиннером просто остаётся видимой; ничего специального.
- Ввод символов, которых нет ни в одном имени (например латиница в кириллических именах) → ветка 4, «Ничего не найдено».

## Стиль и токены

- Поле: `className="field"` — существующий компонентный класс (`w-full rounded bg-surface-muted px-2 py-1 text-xs text-ink`, плейсхолдер `text-ink-placeholder`, focus-ring `ring-brand`). Никаких дополнительных размеров/цветов: `text-xs` совпадает с типографикой модалки (путь, строки списка, кнопки), поэтому размер-модификатор вроде `text-[11px]` (как в плотном сайдбаре `SkillsPanel`) здесь **не** применяем.
- Отступ блока фильтра: `mb-2` — тот же ритм, что у строки навигации над ним.
- Сообщение «Ничего не найдено»: `text-xs text-ink-faint` — ровно как «Нет вложенных папок», чтобы два пустых состояния читались как один класс сообщений и различались только текстом.
- Ни новых CSS-переменных, ни правок `index.css`, ни рамок/иконок вокруг поля.

## Доступность (a11y)

- Видимо скрытый `<label htmlFor={filterId} className="sr-only">Фильтр по имени папки</label>` + `id={filterId}` на `input` (`useId`). Именно `label`, а не `aria-label`: в проекте уже есть этот паттерн (`SetupKeyScreen`), и текст label («Фильтр по имени папки») точнее плейсхолдера, который остаётся коротким «Фильтр по имени» по ТЗ.
- Плейсхолдер — не замена label: он исчезает при вводе, поэтому label обязателен.
- `type="search"` — семантика поиска/фильтра, консистентно с `ModelCombobox`, `DocumentCombobox`, `SkillsPanel`.
- «Ничего не найдено» получает `role="status"`: сообщение появляется по факту ввода, и скринридер должен его объявить. Отдельный `aria-live`-регион со счётчиком результатов **не** вводим — он тараторил бы на каждый символ; sr-only live-регион фазы из CATALOG-91 не трогаем.
- Контраст: пары `text-ink` на `bg-surface-muted` и `text-ink-placeholder` на `bg-surface-muted` уже используются в проекте.
- Клавиатурная навигация и focus-ring существующих элементов не меняются; ловушку фокуса не вводим.

## Контракты данных

Изменения строго клиентские. API не трогаем: `GET /fs/browse` вызывается только при смене уровня, `POST /workspaces/open` — как раньше.

```ts
type FsEntry = { name: string; path: string; has_catalog: boolean } // из frontend/src/api.ts, без изменений

const [filter, setFilter] = useState('')
const filterId = useId()
const visibleEntries: FsEntry[]  // производное, не состояние
```

Ни `FsEntry`, ни `PendingPanel`, ни `BusyTarget` (CATALOG-91) не меняются.

## Критерии визуальной приёмки

- [ ] В секции «Обзор папок» между строкой навигации и списком есть отдельная строка с полем на всю ширину, класс `field`, `type="search"`, плейсхолдер ровно «Фильтр по имени».
- [ ] У поля есть `id` из `useId` и связанный `label` с классом `sr-only` и текстом «Фильтр по имени папки»; визуально label не виден.
- [ ] Поле не отображается при `browseLoading`, при `browseError` и при `entries.length === 0`; отображается при непустом уровне, включая случай нулевого результата фильтрации.
- [ ] Ввод сужает список на каждый символ; в Network нет новых вызовов `/fs/browse`.
- [ ] Фильтрация — подстрока в `entry.name`, без учёта регистра, с `trim()`; путь не учитывается; строка из одних пробелов эквивалентна пустой.

- [ ] Вход в папку и «Вверх» очищают поле; сброс сделан **одним** местом — эффектом по `currentBrowsePath`, а не дублированием в `goInto` / `goUp`.
