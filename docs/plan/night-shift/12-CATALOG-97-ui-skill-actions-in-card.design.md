## Цель и пользовательский путь

Действия над скилом должны попадать в зону внимания пользователя — в саму карточку скила, а не в тулбар над списком.

Сценарий (мышь):
1. Пользователь видит список скилов в сайдбаре. Каждая строка при наведении показывает справа три иконки быстрых действий: «Редактировать», «Коммит», «Ещё» (kebab).
2. Клик по строке выбирает скил: появляется левая акцентная полоска, фон `bg-brand-soft`, иконки на строке остаются видимыми, под строкой раскрывается карточка.
3. В карточке пользователь читает описание и метаданные модели, сразу под ними видит группу управляющих действий («Переименовать», «Редактировать», «Коммит», «⋯»), ниже — отделённый линией блок запуска («Документ…», «Промпт», «В док» / «На экран»).
4. «Переименовать» превращает группу действий в inline-форму (`input` + «Сохранить» / «Отмена») на том же месте.
5. «⋯» → «Удалить» → inline-подтверждение внутри карточки («Удалить скил «X»?» + «Удалить» / «Отмена»), которое сдвигает содержимое карточки вниз, но не накрывает соседние скилы.
6. Повторный клик по выбранной строке ничего не гасит. Выбор снимается только `Escape` или кликом вне списка.

Сценарий (клавиатура): фокус на списке → `↑` / `↓` переходят по скилам и подскроливают саму строку → `Tab` уводит фокус в карточку к действиям → `Escape` закрывает подтверждение → меню → переименование → снимает выбор.

## Layout и состояния

### Структура выбранного `li`

```
li (min-w-0)
├─ div[role=option]  — строка, h-8, px-2, rounded, border-l-2
│   ● статус │ Имя скила (truncate) │ [badges] │ ∗ │ [✎] [◉] [⋯]  ← группа иконок
└─ div — карточка (mt-1.5 border-t border-line pt-1.5 px-2 pb-1, flex-col gap-1.5)
    ├─ описание + «ещё» / «свернуть»            (как сейчас, если есть)
    ├─ SkillModelMeta                            (как сейчас, если есть)
    ├─ ГРУППА ДЕЙСТВИЙ  ← новое
    │   ├─ либо ряд: [Переименовать] [Редактировать] [Коммит] … [⋯]
    │   │            + меню «Удалить» под kebab
    │   │            + inline-подтверждение удаления (отдельной строкой снизу)
    │   └─ либо форма переименования: [input] [Сохранить] [Отмена]
    └─ БЛОК ЗАПУСКА (border-t border-line pt-1.5) — только для committed
        Документ(ы) → Промпт → [В док] [На экран]
```

Порядок зафиксирован: группа действий стоит **сразу под метаданными**, до блока запуска. Причина — задача решает change blindness: действия должны быть в нескольких десятках пикселей от строки, по которой кликнули. Если положить их после блока запуска (два комбобокса + textarea + две кнопки), в сайдбаре 360px они уезжают за пределы видимой области и проблема возвращается.

Разделение групп:
- между действиями и блоком запуска — `border-t border-line pt-1.5` **на блоке запуска** (всегда, потому что группа действий выше есть всегда);
- между метаданными и действиями — `border-t border-line pt-1.5` на группе действий, но **только** когда выше есть контент: `desc.length > 0 || hasModelMeta(s)`. Иначе линия сдвоилась бы с верхней границей карточки.

## Взаимодействия

### Выбор строки
- `selectSkill(id)` → `setSelectedId(id)` без toggle + `clearRename()`. Повторный клик по выбранной строке — no-op по выбору (побочно закрывает форму переименования, это ожидаемо: `clearRename` уже вызывается и сейчас).
- Снятие выбора: `Escape` (последний шаг каскада) и `mousedown` вне списка.
- Клик вне списка: `document.addEventListener('mousedown', …)` при `selectedId != null`; границей считается элемент `ul[role=listbox]` (`listRef`) — вся управляющая обвязка (меню, подтверждение, форма переименования, поповеры `DocumentCombobox`, у которого попап рендерится инлайн, без портала) теперь внутри него, поэтому проверки `listRef.current.contains(e.target)` достаточно. При срабатывании: `clearRename()`, `setOverflowOpen(false)`, `setConfirmOpen(false)`, `setSelectedId(null)`, фокус не двигаем.
- Исключение: пока `renameSavingRef.current === true` (сохранение имени в полёте) внешний клик игнорируем, чтобы не размонтировать форму в середине запроса — тот же приём, что в существующем `onBlur` (`:344-352`).

### Иконки быстрых действий на строке
Три `button.btn-icon-ghost` размера `size-6` внутри `span` с классом `catalog-skill-row__actions`, всегда в DOM (место зарезервировано, сдвига layout при появлении нет).

| Иконка | `aria-label` / `title` | Действие |
| --- | --- | --- |
| `PencilIcon` | «Редактировать скил» | `selectSkill(s.id)` → `clearRename()` → `onEdit(s.id, s.name)` |
| `CommitIcon` | «Коммит» (`disabled` при `s.status !== 'draft'`, тогда `title="Скил уже закоммичен"`) | `selectSkill(s.id)` → `void skills.commit(s.id)` |
| `MoreHorizontalIcon` | «Ещё действия» | `selectSkill(s.id)` → `setConfirmOpen(false)` → `setOverflowOpen(true)`; `aria-expanded={isSelected && overflowOpen}` |

Правила для всех трёх:
- `onClick` начинается с `e.stopPropagation()`, чтобы не сработал `onClick` строки (`:545`) и выбор не «перемигивал»;
- сначала выбираем строку (действие всегда относится к той строке, по иконке которой кликнули), затем выполняем действие;
- `tabIndex={-1}` на невыбранных строках и `tabIndex={0}` на выбранной — иначе `Tab` протаскивает фокус через невидимые кнопки всех скилов; все действия при этом доступны с клавиатуры (в карточке они есть текстовыми кнопками).

Меню kebab рендерится **только внутри карточки** (у кнопки «⋯» в группе действий, `div.relative` + `absolute right-0 mt-1`), поэтому иконка kebab на строке работает как ярлык: открывает то же меню на несколько пикселей ниже. Дублирующего поповера у строки нет — иначе он накрывал бы соседние скилы.

### Группа действий в карточке
- «Переименовать» → `startRename(s)`; кнопка держит `renameTriggerRef`.
- «Редактировать» → `clearRename()` + `onEdit(s.id, s.name)`.
- «Коммит» → `void skills.commit(s.id)`; `disabled={s.status !== 'draft'}`.
- «⋯» (`kebabRef`) → `setConfirmOpen(false)` + `setOverflowOpen(o => !o)`; `aria-expanded={overflowOpen || confirmOpen}`, `aria-label="Ещё действия"`.
- «Удалить» в меню → `clearRename()`, `setOverflowOpen(false)`, `setConfirmOpen(true)`.
- Подтверждение: «Удалить» (`btn-danger`, `autoFocus`) → `setConfirmOpen(false)` + `onDelete(s.id)`; «Отмена» → `setConfirmOpen(false)` + фокус на `kebabRef`.
- `onBlur`-обвязка (закрытие меню и подтверждения, когда фокус ушёл из группы) переносится с бывшего тулбара (`:396-404`) на контейнер группы действий, логика та же (`requestAnimationFrame` + `contains(document.activeElement)`).
- Форма переименования: сохраняется вся текущая логика (`renameValue`, `renameSaving`, `renameEmpty`, `saveRename`, `onBlur`-автозакрытие, `Enter` = сохранить, `Escape` = отмена, `autoFocus` + курсор в конец). После закрытия формы по `Escape` / «Отмена» фокус возвращается на `renameTriggerRef`.

### Клавиатура
- `onListKeyDown` на `ul` обрабатывает `↑` / `↓` / `Enter` / `Escape` **только когда `e.target === e.currentTarget`**. Это обязательный пункт: после переезда формы переименования внутрь списка её `Enter` иначе всплывал бы в обработчик и запускал скил, а `↑` / `↓` — перескакивали бы на другой скил прямо во время ввода имени.
- Каскад `Escape` выносится в хелпер `escapeCascade(): boolean`: `confirmOpen` → `overflowOpen` → `renameId` → иначе `setSelectedId(null)`. Используется и в `onListKeyDown`, и в `onKeyDown` контейнера группы действий (там дополнительно `e.stopPropagation()`; если каскад дошёл до снятия выбора — фокус переводится на `listRef`, чтобы не потерять его на размонтированной кнопке).
- `↑` / `↓`: `optionRefs` продолжают указывать на **div строки**, а не на `li`, поэтому `scrollIntoView({ block: 'nearest' })` (`:267-269`) показывает саму строку, несмотря на выросшую карточку. Менять цель ref нельзя.
- `Enter` на списке — запуск в док (`applyPersistSelected`), без изменений.

### Крайние случаи
- Скил в статусе `draft`: блока запуска нет вообще, группа действий — единственная в карточке; «Коммит» активен.
- Скил без описания и без метаданных модели: у группы действий нет верхней линии (не сдваиваем с границей карточки).
- Скил удалён / выпал из фильтра: существующий `useEffect` (`:173-188`) снимает выбор и сбрасывает все под-состояния — карточка с действиями исчезает вместе со строкой.
- Открыто меню/подтверждение и пользователь кликает по другой строке: `useEffect` на `selectedId` закрывает их, действия переезжают в новую карточку.
- Ввод в поиск: строка поиска вне `ul`, поэтому `mousedown` по ней снимает выбор — это то же поведение, что «клик вне списка», и оно согласуется с уже существующим сбросом выбора при фильтрации.

## Стиль и токены

- Кнопки действий — существующий `btnClass` (`btn-secondary text-[11px]`), «Сохранить» — `btn-primary text-[11px]`, «Удалить» в подтверждении — `btn-danger text-[11px]`, пункт меню — текстовая кнопка `text-[11px] text-danger-ink hover:bg-surface-hover` (как сейчас, `:454`). Ничего не переизобретаем: классы переезжают вместе с разметкой.
- Иконочные кнопки строки — `btn-icon-ghost` (`index.css:146-152`) с `size-6` вместо дефолтного `size-7`, чтобы уложиться в `h-8` строки; глиф 16×16. Ряд иконок: `flex shrink-0 items-center gap-0.5` ≈ 76px — их зарезервированная ширина забирается у имени скила (`min-w-0 flex-1 truncate`), поэтому длинные имена в сайдбаре 360px обрезаются раньше; badges и символ арности не сжимаются (`shrink-0`) и не перекрываются иконками.
- Строка: вертикальные паддинги убираются (`h-8` + `items-center` их делают лишними, а с `overflow-hidden` они зажимали бы 24px кнопки) — остаётся `px-2`.
- Левая полоска: `border-l-2` всегда, цвет `border-transparent` → `border-brand` у выбранной. Через прозрачную рамку в базовом состоянии геометрия строки не меняется при выборе (никакого сдвига текста на 2px).
- Группировка в карточке: `flex flex-col gap-1.5`, ряды кнопок — `flex flex-wrap items-center gap-1.5` (в узком сайдбаре перенос по строкам, горизонтального распирания нет), разделители — `border-t border-line pt-1.5`.
- Анимация появления иконок: `transition-opacity duration-150 motion-reduce:transition-none` (как у `.catalog-message-commands`).
- Цвета — только через токены/утилиты (`brand`, `brand-soft`, `line`, `ink-muted`, `ink-faint`, `danger-ink`, `surface-hover`), никаких хардкод-значений; `rounded` / `rounded-control` как в файле сейчас.

## Доступность (a11y)

- Список остаётся `ul[role=listbox]` + `div[role=option][aria-selected]`. Иконки быстрых действий по ТЗ живут внутри строки, то есть внутри `role="option"` — сознательное отклонение от чистого listbox-паттерна: компенсируем `aria-label` + `title` на каждой кнопке, `tabIndex={-1}` на невыбранных строках и полным дублированием всех действий текстовыми кнопками в карточке (они вне `role="option"`).
- Каждая кнопка (иконочная и текстовая) имеет `aria-label`; у иконочных дополнительно `title` — tooltip-компонента в проекте нет, это принятая конвенция.
- kebab: `aria-expanded`, меню закрывается по `Escape`, потере фокуса и клику вне списка.
- Фокус: видимый `focus-visible:ring-2 ring-brand` уже в классах кнопок; `focus-within` на строке проявляет иконки; после закрытия подтверждения фокус → kebab, после закрытия переименования → «Переименовать», после снятия выбора → `ul`.
- Иконки — `aria-hidden` (наследуется из `iconBase` в `icons.tsx`), смысл несёт `aria-label` кнопки.
- Признак выбора не сводится к цвету: `aria-selected`, фон и левая полоска вместе.
- Контраст: полоска `--brand` на `--brand-soft` и текст `text-ink` — токены, не абсолютные значения, поэтому ревизия палитры в CATALOG-86 их подтянет автоматически.

## Контракты данных (если нужны)

Новых API и типов не требуется. Используются уже прокинутые в `SkillsPanel` props: `onEdit`, `onDelete`, `onRename`, `skills.commit`, `onApply`, плюс поля `SkillOut` (`status`, `name`, `description`, `provider`, `model`, `reasoning`, `tags`, `input_arity`). Блок запуска (`DocumentCombobox`, промпт, `onApply`) переносу не подлежит и работает как сейчас.

## Критерии визуальной приёмки

- [ ] Над списком скилов нет ряда кнопок «Переименовать / Редактировать / Коммит / ⋯» ни в каком состоянии (в том числе когда скил не выбран) — остались только поиск и список.
- [ ] Группа действий отрисована внутри раскрытой карточки, сразу под описанием и метаданными модели, **до** блока запуска.
- [ ] Кнопки «В док» / «На экран» отделены от группы действий горизонтальной линией `border-t border-line`; в одном ряду с действиями они не стоят.
- [ ] У скила без описания и без метаданных модели над группой действий нет второй горизонтальной линии подряд.
