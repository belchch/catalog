# CATALOG-89 — Дизайн UI

- **Источник:** `docs/plan/night-shift/04-CATALOG-89-ui-message-command-icons.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Панель под сообщением пользователя перестаёт быть строкой ссылок и становится тихой панелью действий — как в ChatGPT/Claude.

1. Пользователь отправил сообщение. Под пузырём — пусто: панель занимает своё место, но невидима (`opacity: 0`). Лента выглядит чище, текст сообщения ни с чем не конкурирует по весу.
2. Наводит курсор на сообщение — справа под пузырём проявляются две 28×28 иконки: circular arrow (переотправить) и два листа (копировать). Ничего не сдвигается: место было зарезервировано с самого начала.
3. Клик по copy — иконка на ~1.5 с превращается в галочку успешного цвета, затем возвращается. Текстовой подписи «Скопировано» больше нет; скринридер получает её через `aria-live`.
4. Во время стрима ответа и при закрытом сокете иконка refresh приглушена и не реагирует на hover — видно, что кнопка недоступна.
5. С клавиатуры: Tab доводит до кнопок, панель становится видимой по `focus-within` даже без наведения мыши, focus-visible рисует привычное синее кольцо.
6. На тач-устройстве (hover нет) панель видна всегда — иначе действия были бы недостижимы.

Изменения касаются **только** сообщений роли `user`. Ветки `assistant` и `tool` в `ChatMessage.tsx` не трогаем.

### `icons.tsx` — контракт модуля

Три именованных экспорта, каждый — функциональный компонент с пропсом `{ className?: string }`, общая база:

```
width=16 height=16 viewBox="0 0 24 24" fill="none" stroke="currentColor"
strokeWidth={1.75} strokeLinecap="round" strokeLinejoin="round"
aria-hidden="true" focusable="false"
```

Геометрия (Feather-совместимая, рисуем руками, npm-зависимость не добавляем):

- `RefreshIcon` — замкнутая круговая стрелка с двумя наконечниками: `polyline "23 4 23 10 17 10"`, `polyline "1 20 1 14 7 14"`, `path "M3.51 9a9 9 0 0 1 14.85-3.36L23 10M1 14l4.64 4.36A9 9 0 0 0 20.49 15"`.
- `CopyIcon` — два наложенных листа: `rect x=9 y=9 w=13 h=13 rx=2 ry=2`, `path "M5 15H4a2 2 0 0 1-2-2V4a2 2 0 0 1 2-2h9a2 2 0 0 1 2 2v1"`.
- `CheckIcon` — `polyline "20 6 9 17 4 12"`.

Иконки не задают цвет и размер шрифта — только `currentColor`; цветом управляет кнопка-родитель. `className` пробрасывается на `<svg>` для точечных правок в будущем; в этом срезе не используется.

## Layout и состояния

### Структура пользовательского сообщения

```
div.catalog-message.catalog-message--user.group.my-4.flex.flex-col.items-end   ← +group
├── div (пузырь, max-w-[80%] … )                                              ← без изменений
└── div.catalog-message-commands.mt-1.flex.justify-end.gap-0.5                 ← панель
    ├── span.sr-only[role=status][aria-live=polite]                            ← «Скопировано» / ''
    ├── button.btn-icon-ghost  (refresh)
    └── button.btn-icon-ghost  (copy | check)
```

- Панель **всегда в DOM и всегда занимает место** — прячется только `opacity`. Высота фиксирована содержимым: 28 px кнопок + `mt-1` (4 px). Сдвиг ленты при появлении/скрытии конструктивно невозможен.
- Класс `catalog-message-commands` — стилевой хук (нужен для правила `@media (hover: none)`); визуальную часть в обычных условиях несут Tailwind-утилиты.
- Выравнивание по правому краю сохраняется: правая граница кнопочного квадрата совпадает с правой границей пузыря. Негативных margin'ов для оптического выравнивания иконки не вводим — лишняя сущность в этом срезе.
- `gap-0.5` (2 px) вместо прежнего `gap-3`: с внутренними отступами кнопок это даёт ~10 px между глифами — плотная панель, а не строка ссылок.

### Видимость панели

| Условие | Прозрачность | Как задано |
|---|---|---|
| Покой | `opacity-0` | утилита на панели |
| Hover по любому месту сообщения | `opacity-100` | `group-hover:opacity-100` (`group` на контейнере сообщения) |
| Фокус на любой кнопке панели | `opacity-100` | `focus-within:opacity-100` |
| Устройство без hover (тач) | `opacity-100` всегда | правило в `index.css`, см. ниже |

Переход: `transition-opacity duration-150 motion-reduce:transition-none`.

Правило для тач (специфичность `0-2-0` — гарантированно перебивает утилиту `opacity-0`, порядок в бандле роли не играет):

```css
@media (hover: none) {
  .catalog-message--user .catalog-message-commands { opacity: 1; }
}
```

`opacity: 0` не убирает элемент из дерева доступности и не отключает клики — это осознанно: скринридер и клавиатура работают с панелью всегда, а невидимая кнопка не «ловит» мышь по чужой территории, потому что панель занимает только свою узкую полосу под пузырём.

### Состояния кнопки (`.btn-icon-ghost`)

| Состояние | Фон | Цвет глифа | Курсор |
|---|---|---|---|
| Покой | прозрачный | `--ink-faint` | обычный |
| Hover | `--surface-hover` | `--ink` | обычный |
| Focus-visible | без изменений фона | без изменений | обычный + кольцо `ring-2 ring-brand` |
| Active | как hover | как hover | обычный |
| Disabled (только refresh) | **прозрачный, hover-подложки нет** | `--ink-faint` при `opacity-40` | `not-allowed` |
| Copy в состоянии «скопировано» | как обычно/hover | `--success` (перебивает hover-цвет) | обычный |

Определение класса (в `@layer components`, сразу после `.btn-icon-danger`):

```css
.btn-icon-ghost {
  @apply inline-flex size-7 shrink-0 items-center justify-center rounded-control bg-transparent text-ink-faint transition-colors;
  @apply hover:bg-surface-hover hover:text-ink;
  @apply focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand;
  @apply disabled:cursor-not-allowed disabled:opacity-40;
  @apply disabled:hover:bg-transparent disabled:hover:text-ink-faint;
}
```

**Почему новый класс, а не правка `.btn-icon`** (осознанное отклонение от буквы плана, п. 8): у существующего `.btn-icon` disabled-состояние — `disabled:bg-surface-muted`, то есть закрашенный квадрат; для ghost-кнопки под сообщением это ровно тот hover-подобный фон, который ТЗ запрещает в disabled. Плюс `.btn-icon` — 36 px и `rounded-full`, в одном семействе с `.btn-icon-brand` / `.btn-icon-danger` (кнопки композера, `Chat.tsx:259,270`); менять его геометрию на 28 px значит рассинхронизировать семейство. Поэтому вводим соседний класс в том же `@layer components` — требование «никаких ad-hoc utility-простыней в JSX» соблюдено, существующие кнопки не задеты. `.btn-icon` остаётся как есть.

Размеры: `size-7` = 28×28, глиф 16×16 → 6 px внутреннего поля со всех сторон. `rounded-control` (8 px) — та же скруглённость, что у остальных контролов приложения.

### Loading / empty / error

Своих состояний у панели нет. Ошибка клипборда, как и раньше, гасится молча: галочка просто не появляется, `aria-live` остаётся пустым. Отдельного error-UI не вводим — вне скоупа.

## Взаимодействия

- **Refresh.** Клик → `handleRepeat` (без изменений). При `repeatDisabled` кнопка нативно `disabled`: клик не проходит, фокус её пропускает, hover-подложки нет.
- **Copy.** Клик → `handleCopy` (без изменений: `navigator.clipboard` с fallback через `document.execCommand`). При успехе `copied = true` → глиф `CheckIcon` в `--success` + live-регион получает «Скопировано»; через 1500 мс всё возвращается к `CopyIcon`. Повторный клик до истечения таймера сбрасывает и перезапускает таймер — поведение существующего кода, не меняем.
- **Клавиатура.** Обе кнопки — нативные `<button type="button">`, поэтому Enter/Space работают без обработчиков. Панель проявляется по `focus-within`, так что видно, что именно в фокусе.
- **`aria-label` и `title`** совпадают и повторяют прежние подписи:
  - refresh: `repeatDisabled ? 'Недоступно во время ответа' : 'Переотправить это сообщение'`;
  - copy: `'Копировать'` — **постоянно**, в том числе при `copied`. Меняющийся `aria-label` дал бы двойное объявление вместе с live-регионом.

**Крайние случаи:**

- Курсор ушёл с сообщения, пока показана галочка: панель гаснет, таймер продолжает идти, по возвращении курсора виден уже актуальный глиф. Дополнительной логики не нужно.
- Размонтирование во время таймера: существующий cleanup в `useEffect` уже покрывает.
- `title` на `disabled`-кнопке: браузеры показывают нативный tooltip на disabled `<button>` — прежнее поведение сохраняется.
- Длинное многострочное сообщение: панель по-прежнему одна на сообщение, прижата вправо под последней строкой.
- Тач + клавиатура одновременно (планшет с клавиатурой): `@media (hover: none)` держит панель видимой, `focus-within` ничего не ломает.

## Стиль и токены

- Цвета — только через токены/утилиты: `text-ink-faint`, `hover:text-ink`, `hover:bg-surface-hover`, `ring-brand`, `text-success`. Никаких hex в разметке и в новом CSS-правиле — CATALOG-86 меняет значения этих же токенов, порядок выполнения задач не важен.
- Приглушение disabled — через `opacity-40`, а не через отдельный «серый» токен: заводить новый цвет ради одного состояния избыточно, а прозрачность гарантированно даёт ступень вниз от `--ink-faint` на любом фоне.
- Успех копирования — `--success` (`#25835c`), единственный семантический акцент в панели. `--brand` в панели не используем: он закреплён за focus-ring и primary-кнопками.
- Типографика из панели уходит совсем: `text-xs` на контейнере больше не нужен (текста нет), остаётся только у `sr-only` — визуально не проявляется.
- Новых утилит, плагинов, npm-зависимостей и правок `tailwind.config.cjs` нет.

## Доступность (a11y)

- У каждой кнопки есть доступное имя через `aria-label`, дублированное в `title` (визуальный tooltip для мыши).
- SVG внутри кнопок — `aria-hidden="true"` + `focusable="false"` (второе — против таб-стопа в старых движках); имя кнопки формирует только `aria-label`.
- Факт копирования сообщается через визуально скрытый регион: `<span className="sr-only" role="status" aria-live="polite">{copied ? 'Скопировано' : ''}</span>`. Регион присутствует в DOM постоянно (иначе объявление может потеряться), меняется только его текст.
- `opacity: 0` не скрывает панель от скринридера и не выключает клавиатуру — доступ к действиям не зависит от наличия мыши.
- Focus-visible — существующее кольцо `ring-2 ring-brand`; на белом фоне ленты контраст индикатора выше 3:1.
- Контраст глифов (нетекстовая графика, порог 3:1): `--ink-faint` на белом — 6.05:1, `--ink` на `--surface-hover` — ~11:1, `--success` на белом — ~4.6:1. Disabled-состояние под порог не подпадает (WCAG выводит неактивные контролы из требования), но остаётся различимым по форме и курсору.
- Состояние disabled передаётся не только цветом: нативный атрибут `disabled` + `title`/`aria-label` «Недоступно во время ответа».
- Порядок фокуса не меняется: refresh → copy, как и раньше (`sr-only`-span не фокусируемый).
