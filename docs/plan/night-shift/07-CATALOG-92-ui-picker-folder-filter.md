- **Задача Plane:** [CATALOG-92](https://app.plane.so/belchch/projects/catalog-app/work-items/92) (id: `6ea7f82c-22b7-48f6-9f45-8103b90bddf1`, state: In Progress)
- **Статус плана:** Analyzed
- **Тип шага:** ui
- **Очередь:** 07 · blocked_by CATALOG-91
- **Цель:** Добавить в секцию «Обзор папок» модалки `WorkspacePicker` клиентское поле фильтра по имени подпапки: сужает уже загруженный список без запросов к бэкенду, сбрасывается при смене уровня, различает «ничего не найдено» и «нет вложенных папок».

## Постановка задачи (актуальное ТЗ)
_(источник: описание задачи; комментариев нет)_

**Фильтр по имени в списке папок пикера воркспейса**

Контекст: WorkspacePicker (`frontend/src/components/WorkspacePicker.tsx`) показывает плоский список подпапок текущего уровня, полученный из `GET /fs/browse`. В папках с несколькими десятками подпапок нужную приходится искать глазами. ADR-0017 фиксирует отсутствие поиска как известный минус серверного пикера.

Скоуп: только frontend. Бэкенд и API не меняются — фильтруем уже загруженный массив `entries` на клиенте. Рекурсивный поиск по дереву в эту задачу не входит.

Что сделать:

1. Над списком папок (секция «Обзор папок») добавить поле ввода с плейсхолдером «Фильтр по имени» и доступным label.
2. Список фильтруется по подстроке в `entry.name`, без учёта регистра и с обрезкой пробелов по краям. Совпадения в пути не учитываем — только имя папки.
3. Значение фильтра сбрасывается при переходе внутрь папки (`goInto`) и вверх (`goUp`), то есть каждый новый уровень открывается с пустым фильтром.
4. Если после фильтрации ничего не осталось — показать «Ничего не найдено» вместо существующего «Нет вложенных папок» (это разные состояния).
5. Поле скрывается или не показывается, когда на уровне нет папок вообще, а также во время загрузки и при ошибке обзора.
6. Секция «Недавние» фильтром не затрагивается.

Критерии приёмки перенесены в раздел ниже.

## Контекст
- Компонент — `frontend/src/components/WorkspacePicker.tsx`. Список подпапок хранится в `entries` (`:56`), заполняется в `loadBrowse` из `browse(path)` (`:67-87`), то есть данные уровня уже целиком на клиенте — фильтрация не требует запросов.
- Секция «Обзор папок» — `:218-283`. Заголовок секции `:219`, строка навигации с текущим путём и кнопками «Вверх» / «Открыть эту папку» — `:220-243`. Поле фильтра логично ставить между строкой навигации и списком.
- Ветвление состояний списка уже реализовано в одном месте — `:245-282`: `browseLoading` → «Загрузка…» (`:246`), `browseError` → текст ошибки (`:248`), `entries.length === 0` → «Нет вложенных папок» (`:250`), иначе `<ul>` с элементами (`:252-281`). Состояние «ничего не найдено» добавляется как новая ветка между пустым списком и рендером `ul`, при этом сообщение о пустой папке остаётся привязанным именно к `entries.length === 0`.
- Рендер элемента: кнопка перехода внутрь (`:258-270`, вызывает `goInto`) и кнопка «Открыть» (`:271-278`, вызывает `tryOpen(entry.path, false)`). Фильтрация не должна менять эти обработчики — фильтруется только массив перед `map`.
- Сброс фильтра вешается на уже существующие переходы: `goInto` (`:144-150`) и `goUp` (`:152-156`). Оба уже сбрасывают `pending`, так что точка расширения очевидна. Альтернатива — сбрасывать по изменению `currentBrowsePath` (`:63`) в эффекте (`:93-95`), что покрывает оба перехода одним местом.
- Условие показа поля: `!browseLoading && !browseError && entries.length > 0`. Все три флага уже есть в состоянии (`:56`, `:58`, `:59`).
- Доступный label: в компоненте уже используется `useId` (`:53`) для `aria-labelledby` модалки — тот же приём подойдёт для связи `label` и `input`. Визуально скрытый label или `aria-label` — на выбор дизайн-спеки.
- `entry.name` приходит из `FsEntry` (`frontend/src/api.ts`), у элементов также есть `path` и `has_catalog` (используется для бейджа «воркспейс», `:267-269`). По ТЗ фильтруем строго по `name`.
- ADR-0017 (`docs/adr/0017-folder-picker-via-backend-browse.md`) действительно описывает серверный пикер и его ограничения — на него стоит ссылаться в PR; рекурсивный поиск остаётся вне объёма.
- Дубликат: [CATALOG-93](docs/plan/night-shift/08-CATALOG-93-ui-picker-folder-filter.md) — отдельный тикет Plane с идентичным текстом ТЗ (созданы почти одновременно). Реализовывать нужно один раз; второй тикет закрывается тем же PR. Решение о том, какой тикет считать основным, — за человеком.
- Пересечение: [CATALOG-91](docs/plan/night-shift/06-CATALOG-91-ui-picker-result-panel-loader.md) правит ту же модалку и ту же секцию (переносит `pending`-панель выше «Обзор папок» и меняет структуру карточки). Конфликт правок вероятен — выполнять последовательно и сверять диф.
- Автотестов на компонент нет; проверки — сборка/линт/typecheck из `frontend/` плюс ручной прогон и вкладка Network.

## Затрагиваемые файлы
- `frontend/src/components/WorkspacePicker.tsx` — новое состояние фильтра, поле ввода с label в секции «Обзор папок» (после `:243`), фильтрация `entries` перед `map` (`:253`), новая ветка «Ничего не найдено» в блоке `:245-282`, сброс фильтра при смене уровня (`goInto` `:144-150` / `goUp` `:152-156` либо эффект по `currentBrowsePath`).

## План действий
1. Добавить состояние `filter` (строка, начальное значение `''`) рядом с остальными состояниями компонента (`:55-61`).
2. Между строкой навигации (`:220-243`) и блоком состояний списка (`:245`) вставить поле ввода: `placeholder="Фильтр по имени"`, доступный label через `useId` (визуально скрытый label или `aria-label`), `value` / `onChange` на состояние фильтра.
3. Показывать поле только при `!browseLoading && !browseError && entries.length > 0`; во время загрузки, при ошибке и на уровне без подпапок — не рендерить.
4. Вычислить отфильтрованный список: `entries.filter((e) => e.name.toLowerCase().includes(filter.trim().toLowerCase()))`; при пустом фильтре — исходный массив. Мемоизация не обязательна (список одного уровня), но допустима.
5. В блоке `:245-282` добавить ветку: если `entries.length > 0`, а отфильтрованный список пуст — «Ничего не найдено»; сообщение «Нет вложенных папок» (`:250`) оставить только для `entries.length === 0`.
6. Рендерить `map` по отфильтрованному списку (`:253`), не меняя обработчики `goInto` (`:262`) и `tryOpen` (`:275`) и бейдж «воркспейс» (`:267-269`).
7. Сбрасывать фильтр при смене уровня: добавить сброс в `goInto` (`:144-150`) и `goUp` (`:152-156`), либо один сброс в эффекте по `currentBrowsePath` (`:93-95`) — выбрать одно место, чтобы не было двойной логики.
8. Убедиться, что секция «Недавние» (`:182-216`) не затронута.
9. Проверить, что фильтр не приводит к вызовам `browse`: `loadBrowse` зависит только от `currentBrowsePath` (`:93-95`), новых зависимостей не добавлять.
10. Ручные проверки: ввод текста мгновенно сужает список и в Network нет новых `/fs/browse`; переход в подпапку и «Вверх» очищают поле; пустой результат и пустая папка дают разные сообщения; кнопки «Открыть» у отфильтрованных элементов работают; Tab / focus-ring по полю и элементам, `Escape` закрывает модалку.
11. Прогнать из `frontend/`: `pnpm run build`, `pnpm run lint`, `pnpm run typecheck`.

## Критерии приёмки (Definition of Done)
- [ ] Над списком папок есть поле с плейсхолдером «Фильтр по имени» и доступным label.
- [ ] Ввод текста мгновенно сужает список, без запросов к бэкенду (проверяется по сетевой панели: новых вызовов `/fs/browse` нет).
- [ ] Фильтрация идёт по подстроке в `entry.name`, без учёта регистра, с обрезкой пробелов по краям; путь не учитывается.
- [ ] Переход в подпапку и обратно («Вверх») очищает фильтр.
- [ ] Пустой результат фильтрации и пустая папка дают разные сообщения («Ничего не найдено» / «Нет вложенных папок»).
- [ ] Поле не отображается во время загрузки, при ошибке обзора и когда на уровне нет подпапок.
- [ ] Секция «Недавние» фильтром не затронута.
- [ ] Кнопки «Открыть» у отфильтрованных элементов работают как раньше.
- [ ] Клавиатурная навигация и focus-ring не сломаны, `Escape` по-прежнему закрывает модалку.
- [ ] Бэкенд и API не изменены; рекурсивный поиск не добавлен.
- [ ] Из `frontend/`: `pnpm run build`, `pnpm run lint`, `pnpm run typecheck` — зелёные.
