# CATALOG-93 — Дизайн UI

- **Источник:** `docs/plan/night-shift/08-CATALOG-93-ui-picker-folder-filter.md`
- **Статус дизайна:** Ready (дубликат — сверка, без нового дизайна)
- **Канонический дизайн:** `docs/plan/night-shift/07-CATALOG-92-ui-picker-folder-filter.design.md`

## Резюме шага

CATALOG-93 — побайтовый дубликат ТЗ CATALOG-92. Визуал фильтра по имени в списке папок `WorkspacePicker` **полностью спроектирован и закрыт** дизайн-спекой CATALOG-92, а реализация уже присутствует в `frontend/src/components/WorkspacePicker.tsx`.

Следствия для этого шага:

- **Новых дизайн-решений нет.** Единственный источник истины по внешнему виду и поведению — спека CATALOG-92; здесь она не переписывается и не дополняется.
- **Новых компонентов, файлов, зависимостей и правок стилей нет.** Ожидаемый диф шага — пустой по `frontend/` и `backend/`.
- Задача UI-части шага сводится к **сверке** уже существующей реализации со спекой CATALOG-92 и фиксации дубликата в отчёте/PR.

Если сверка обнаружит расхождение с канонической спекой — это дефект реализации CATALOG-92, и он правится точечно по той же спеке, без введения второй, независимой реализации фильтра.

## Цель и пользовательский путь

Без изменений относительно CATALOG-92 (раздел «Цель и пользовательский путь»): пользователь в секции «Обзор папок» вводит подстроку в поле «Фильтр по имени», список сужается мгновенно и без запросов, пустой результат даёт «Ничего не найдено», смена уровня очищает поле. Дублировать сценарий здесь не нужно — читать по ссылке.

## Дерево компонентов и файлы

- Новых компонентов **нет**.
- Изменяемых файлов **нет**. Ожидаемое состояние после шага: `frontend/src/components/WorkspacePicker.tsx` содержит фильтр в том виде, как описано в CATALOG-92, и не получает дополнительных правок в рамках CATALOG-93.
- `frontend/src/index.css`, `frontend/src/components/icons.tsx`, `frontend/src/api.ts`, любые файлы `backend/` — не трогаются.

Фактическое расположение уже реализованного UI (точки для сверки):

| Элемент | Где | Ожидание |
|---|---|---|
| состояние `filter` + `filterId` | `WorkspacePicker.tsx`, блок состояний компонента | `useState('')`, `useId()` |
| `visibleEntries` + `showFilter` | там же, производные значения перед `loadBrowse` | производные, не состояние |
| эффект сброса фильтра | отдельный `useEffect` по `currentBrowsePath` | ровно один, без дублей в `goInto` / `goUp` |
| блок поля фильтра | секция «Обзор папок», после строки навигации | `div.mb-2` + `label.sr-only` + `input.field` |
| цепочка состояний списка | сразу после блока фильтра | 5 веток в порядке из CATALOG-92 |

## Layout и состояния

Без изменений — см. CATALOG-92, разделы «Layout и состояния» (место поля, условие показа `!browseLoading && !browseError && entries.length > 0`, порядок из пяти веток списка, поведение при `busy !== null`).

Новых состояний экрана CATALOG-93 не вводит.

## Взаимодействия

Без изменений — см. CATALOG-92, раздел «Взаимодействия» (правило фильтрации по подстроке `entry.name` с `trim()` и `toLowerCase()`, единственный источник сброса, отсутствие новых запросов, клавиатура и фокус, крайние случаи).

## Стиль и токены

Без изменений — см. CATALOG-92, раздел «Стиль и токены». Ни новых утилит, ни правок `index.css`, ни модификаторов размера у поля.

## Доступность (a11y)

Без изменений — см. CATALOG-92, раздел «Доступность». Проверяемый минимум при сверке: `label.sr-only` связан с полем через `useId`, `type="search"`, `role="status"` у «Ничего не найдено», порядок табуляции и focus-ring не сломаны.

## Контракты данных

Изменений нет: `FsEntry` из `frontend/src/api.ts`, `GET /fs/browse` только при смене уровня, `POST /workspaces/open` как раньше. Фильтрация — строго клиентская.
