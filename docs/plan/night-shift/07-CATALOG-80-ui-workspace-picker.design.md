# CATALOG-80 — Дизайн UI

- **Источник:** docs/plan/night-shift/07-CATALOG-80-ui-workspace-picker.md
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Пользователь работает в модели «воркспейс = папка». UI должен дать: выбрать папку, увидеть её статус, подтвердить индексацию, переключаться между папками, пересканировать открытую папку с отчётом и понятно показывать состояние «папка не открыта».

Сценарии:

1. **Первый запуск / папка не открыта.** `GET /workspaces/current` вернул 204. Сайдбар вместо статичного «Catalog» показывает индикатор «Папка не открыта» с кнопкой «Открыть папку». Центральная область (main) — заглушка с той же CTA. Списки сессий/документов/скиллов не запрашиваются (нет 409-шума).
2. **Открытие через пикер.** Клик по индикатору или CTA открывает модалку `WorkspacePicker`. Сверху — недавние воркспейсы; ниже — обзор дерева папок (`GET /fs/browse`). Пользователь либо жмёт недавний, либо навигирует по дереву и выбирает папку.
3. **Три исхода выбора папки** (по `status` из `POST /workspaces/open` при `confirm=false`):
   - `ok` — папка уже воркспейс → модалка закрывается, приложение подгружает данные.
   - `needs_init` — пустая папка → внутри модалки предложение «Создать воркспейс» (`confirm=true`).
   - `needs_confirm` — папка с файлами → preview отчёта скана + кнопка «Сделать воркспейсом и проиндексировать» (`confirm=true`).
   - Невалидная папка / нет доступа (400/403/404) — текст ошибки, кнопки подтверждения нет.
4. **Переключение.** С открытой папкой индикатор показывает путь; клик снова открывает пикер и позволяет выбрать другую папку. Если активен ран (409) — баннер с текстом бэкенда, текущая папка не сбрасывается.
5. **Ре-скан.** Кнопка «Пересканировать» у индикатора. По завершении — модалка с отчётом `added/updated/renamed/removed/skipped`, затем обновление списка документов.
6. **Upload.** Кнопка загрузки документа работает как раньше (кладёт файл в открытую папку), но заблокирована пока папка не открыта.

## Layout и состояния

### Сайдбар — `WorkspaceBar` (на месте `.catalog-project-title`)

- Заголовок секции «Проект» (`.catalog-sidebar__section-label`) сохраняется.
- **Есть воркспейс:** строка-кнопка во всю ширину: иконка папки (`▱`) + `display_name` (или последний сегмент пути), `title`=полный путь (обрезка `truncate`). Справа — иконка-кнопка ре-скана (`⟳`), `aria-label="Пересканировать"`, `disabled` во время скана (показывает `…`). Клик по основной части — открыть пикер.
- **Нет воркспейса:** та же строка, но текст «Папка не открыта» в `text-ink-faint`; клик — открыть пикер; кнопки ре-скана нет (или `disabled`). Ниже — компактная кнопка `btn-secondary` «Открыть папку».
- Стиль строки — как существующий `.catalog-project-title` (те же отступы/типографика), плюс `hover:bg-[var(--sidebar-brand-hover)]` и фокус-ринг, так как теперь это интерактивный элемент.

### `WorkspacePicker` (модалка)

Оверлей `.modal-overlay` + карточка `.modal-card` шире обычного (`max-w-2xl`), внутренняя прокрутка при переполнении (`max-h-[80vh] overflow-y-auto`).

- **Шапка:** заголовок «Открыть воркспейс» (`text-sm font-semibold`) + кнопка-крестик `btn-ghost` `aria-label="Закрыть"`.
- **Блок «Недавние»** (если `recents.length > 0`): заголовок-лейбл + список строк-кнопок. В строке: `display_name` (или имя папки), путь мелким `text-ink-faint`, справа `last_opened` (если есть). Клик → `open(path, confirm=false)`.
- **Блок «Обзор папок»:**
  - Строка текущего пути: путь (обрезка), кнопка «Вверх» (`btn-secondary`, `disabled` на корне API — когда `browse` вернул путь без родителя в пределах `fs_root`), и действие «Открыть эту папку» (`open` текущего просматриваемого пути).
  - Список `FsEntry` (только папки): иконка `▱` + имя. Если `has_catalog` — бейдж `badge-success` «воркспейс». Клик по строке — навигация внутрь (`browse(entry.path)`). Отдельная кнопка «Открыть» в строке — `open(entry.path, confirm=false)`.
- **Панель подтверждения / результата** (появляется после `open(confirm=false)`), состояния:
  - `ok` — модалка закрывается, вызывается `onOpened()`; отдельной панели нет.
  - `needs_init` — блок с текстом «Папка пустая. Создать здесь воркспейс?» + кнопка `btn-primary` «Создать воркспейс» → `open(path, confirm=true)`.
  - `needs_confirm` — `ScanReportView` (preview `result.scan`) + кнопка `btn-primary` «Сделать воркспейсом и проиндексировать» → `open(path, confirm=true)`.
  - ошибка (400/403/404) — текст `detail` в `text-danger-ink`, без кнопки подтверждения.
  - 409 — текст `detail` (папка занята активным раном); текущий воркспейс не меняется.

Состояния данных пикера: `loading` (обзор/недавние грузятся — плейсхолдер/спиннер-текст «Загрузка…»), `empty` (пустая папка при обзоре — «Нет вложенных папок»), `error` (ошибка `browse` — текст `detail`), рабочее (списки).

### Main — empty state (нет воркспейса)

Когда `current == null` и нет активного рана: вместо чата — центрированная карточка: иконка папки, заголовок «Воркспейс не открыт», подпись «Откройте папку, чтобы начать работу с документами и скиллами», кнопка `btn-primary` «Открыть папку». Табы «Чат/Черновик» и композер скрыты. (Если активен ран — приоритет у `RunView`, как сейчас.)

### Секции сайдбара при отсутствии воркспейса

Секции «Сессии/Документы/Скиллы» остаются видимыми, но пустые (данные не запрашиваются). Кнопки «Обновить»/«Новый чат»/upload — `disabled`. Никаких сырых 409 в списках.

### `RescanReportModal`

Оверлей + карточка (`max-w-lg`): заголовок «Отчёт пересканирования», `ScanReportView`, кнопка `btn-primary` «Готово». Если все группы пусты — строка «Изменений нет».

## Взаимодействия

- **Открыть пикер:** клик по `WorkspaceBar` (основная часть), по CTA в empty state, по кнопке «Открыть папку».
- **Навигация по дереву:** клик по папке — вход внутрь; «Вверх» — на уровень выше (не выше корня API); «Открыть эту папку»/«Открыть» у строки — попытка открыть.
- **Подтверждение индексации:** внутри пикера, без перехода на другой экран; после успешного `open` (`ok` либо `confirm=true` вернул `ok`) — закрыть модалку и вызвать `onOpened()`, который в App: `refreshCurrent()` + рефреш docs/sessions/skills.
- **Ре-скан:** клик по `⟳` в баре → `rescan()` → открыть `RescanReportModal` с отчётом → по закрытии `docs.refresh()`.
- **409 при переключении/ре-скане:** показать `detail` в верхнем баннере App (`.catalog-notice`) или в панели пикера; текущий воркспейс/список не сбрасывать.
- **Обратная связь:** во время `open`/`rescan` — кнопки в состоянии загрузки (текст «…»/«Индексирую…»), повторные клики блокируются.
- **Крайние случаи:**
  - `getCurrentWorkspace` → 204: трактовать как «нет воркспейса» (не ошибка).
  - Пустой список недавних: блок «Недавние» не рендерится.
  - Корень API в обзоре: «Вверх» задизейблена.
  - Папка исчезла/нет прав (404/403) при `browse` или `open`: текст ошибки, без подтверждения.
  - Открыт пикер, пришёл фоновой апдейт — не закрывать модалку самопроизвольно.

## Стиль и токены

- Только Tailwind-утилиты и существующие компонент-классы (`.modal-overlay`, `.modal-card`, `.btn-*`, `.badge-*`, `.field`, `.catalog-*`), новых CSS-файлов не вводим.
- Модалки — по образцу `SkillTrackPicker`/`SessionTimeoutModal`: `useId` для `aria-labelledby`, крестик `btn-ghost`, кнопки действий в правом нижнем ряду (`flex justify-end gap-2`).
- Типографика: заголовки `text-sm font-semibold text-ink`; вторичный текст `text-xs`/`text-[11px] text-ink-faint`; пути — обрезка `truncate` + `title` с полным значением.
- Отступы карточек — `p-4` (как у существующих модалок); списки — `space-y-2`/`gap-1`.
- Бейджи: `badge-success` для «воркспейс» (has_catalog); счётчики групп отчёта — `badge-neutral`.
- Цвета отчёта скана (в терминах токенов): added → `text-success-ink`, updated → `text-info-ink`/`text-brand-ink`, renamed → `text-accent-ink`, removed → `text-danger-ink`, skipped → `text-ink-faint`. Заголовки групп нейтральные, акцент — на счётчике/иконке.
- Индикатор в сайдбаре наследует отступы `.catalog-project-title`; интерактивность добавляет `hover`/`focus-visible:ring-2 focus-visible:ring-brand`.

## Доступность (a11y)

- Модалки: `role="dialog"`, `aria-modal="true"`, `aria-labelledby` на заголовок; закрытие по `Escape` (кроме момента выполнения запроса); фокус на первый интерактивный элемент при открытии (крестик или поле обзора); возврат фокуса на триггер после закрытия — желателен.
- Список папок и недавних — нативные `<button>`, доступны с клавиатуры (Tab/Enter). Стрелочная навигация по дереву — не обязательна для среза, но фокус-ринги обязательны.
- Кнопка ре-скана — `aria-label="Пересканировать"`; состояние загрузки отражать текстом/`aria-busy`, не только цветом.
- Индикатор воркспейса — кнопка с доступным именем (путь/имя папки или «Папка не открыта»).
- Контраст: использовать существующие `--ink*`/`--danger-ink`/`--success-ink` (уже выверены).
- Ошибки — текстом (`text-danger-ink`), не только цветовой индикацией.

## Контракты данных

Типы (в `api.ts`, зеркалят схемы CATALOG-79):

- `WorkspaceOut { path: string; display_name: string | null; last_opened: string | null }`
- `ScanReport { added: string[]; updated: string[]; renamed: string[]; removed: string[]; skipped: string[] }`
- `WorkspaceOpenResult { status: 'ok' | 'needs_init' | 'needs_confirm'; path: string | null; display_name: string | null; scan: ScanReport | null }`
- `FsEntry { name: string; path: string; has_catalog: boolean }`

Эндпоинты:

- `GET /workspaces` → `WorkspaceOut[]` (недавние/реестр).
- `GET /workspaces/current` → `WorkspaceOut | null`. **204 = нет воркспейса**; клиент `getCurrentWorkspace` должен обработать пустой ответ (204) и вернуть `null`, не пытаясь парсить JSON.
- `POST /workspaces/open` `{ path, confirm }` → `WorkspaceOpenResult`; ошибки: 409 (busy), 404 (not found), 403 (access), 400 (validation) → `ApiError` с `detail`.
- `POST /workspaces/rescan` → `ScanReport`; 409 если воркспейс не открыт.
- `GET /fs/browse?path=` → `FsEntry[]` (только папки в пределах `APP_FS_ROOT`); `path` пустой/отсутствует = корень; 400/403/404 — `ApiError`.

Гейт хуков: `useDocuments/useSessions/useSkills` получают `enabled` (= `Boolean(current)`); при `false` — не запрашивать и очищать список. После открытия воркспейса `onOpened` в App поднимает `enabled` → хуки рефрешатся.

## Критерии визуальной приёмки

- [ ] При отсутствии воркспейса сайдбар показывает «Папка не открыта» + «Открыть папку»; main — заглушку с CTA; списки docs/sessions/skills пустые, без 409-ошибок в UI.
- [ ] Индикатор с открытой папкой показывает путь/имя (полный путь в `title`, обрезка длинного), клик открывает пикер.
- [ ] Пикер содержит блок «Недавние» (когда есть) и обзор дерева с навигацией внутрь и «Вверх»; «Вверх» задизейблена на корне API.
- [ ] Папки с `.catalog` помечены бейджем «воркспейс» (`badge-success`).
- [ ] `needs_init` показывает «Создать воркспейс»; `needs_confirm` — preview отчёта + «Сделать воркспейсом и проиндексировать»; ошибка пути — текст без кнопки подтверждения.
- [ ] Кнопка «Пересканировать» открывает модалку отчёта с группами added/updated/renamed/removed/skipped (счётчики + раскрываемые списки); «Изменений нет» при пустом отчёте.
- [ ] 409 при переключении/ре-скане показан текстом (`detail`), текущая папка не сбрасывается.
- [ ] Upload заблокирован без открытой папки и работает после открытия.
- [ ] Модалки: `role="dialog"`/`aria-modal`/`aria-labelledby`, закрытие по Escape, фокус на первый элемент; все интерактивные элементы имеют фокус-ринг.
- [ ] Стиль консистентен с `SkillTrackPicker`/`SessionTimeoutModal` и токенами `index.css`; новых CSS-файлов и зависимостей не добавлено.
