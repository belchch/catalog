# CATALOG-155 — Дизайн UI

- **Источник:** docs/plan/shift-2026-08-20-claude/04-CATALOG-155-ui-output-block-settings-modal.md
- **Статус дизайна:** Ready

## Цель и пользовательский путь

`SkillSettingsModal` — последняя дешёвая точка правки контракта скилла перед заморозкой конфига (ADR-0002, ADR-0004). Сейчас в ней настраивается **Вход**, но не **Выход**: декларацию выходов пишет модель, а человек видит её только в карточке OUTPUTS панели артефактов.

Путь: *собрал черновик → открыл «Настройка скила» → увидел «Вход: 1 документ» и сразу под ним «Выход» с теми выходами, что объявил планировщик → заметил, что основной (первая строка) не тот → нажал ↑ на нужной строке → поправил описание → «Сохранить» → конфиг заморожен уже с правильным primary*.

Жёсткие рамки шага:

1. **`OutputsList` переиспользуется как есть.** Ни форка, ни копии, ни новых пропов сверх существующих (`value`, `onChange`, `disabled`, `rowErrors`, `firstKeyRef`). Флаг `multiple` (CATALOG-154) и починка фокуса (CATALOG-157) обязаны подхватиться в модалке автоматически.
2. **Порядок = смысл.** Первая строка — primary; ↑ ↓ реально меняют порядок в теле `PATCH /skills/{id}/configure`.
3. **Пустой список — не ошибка.** Скилл без объявленных выходов показывает пояснение, а не красную строку, и сохраняется как раньше.
4. **Скилл без выходов выглядит и сохраняется ровно как сегодня** — кроме появившегося блока с пояснением.

## Layout и состояния

### 1. Каркас модалки становится прокручиваемым

Блок «Выход» при восьми строках выше всей остальной формы, поэтому карточка получает предел высоты и внутренний скролл — по образцу `SettingsPanel.tsx:156` и `WorkspacePicker.tsx:298`:

```
<div className="modal-overlay">
  <div role="dialog" aria-modal="true" aria-labelledby={titleId}
       className="modal-card flex max-h-[80vh] max-w-md flex-col">
    <div className="mb-3 flex shrink-0 items-center justify-between"> …заголовок + ✕… </div>
    <div className="min-h-0 flex-1 overflow-y-auto pr-1"> …все поля формы… </div>
    <div className="shrink-0 pt-3"> …error + кнопки… </div>
  </div>
</div>
```

- `max-w-md` не меняется — ширина формы прежняя.
- Кнопки «Отмена» / «Сохранить» **всегда видны** и не уезжают за экран при восьми выходах.
- Существующие отступы полей (`mb-2`, последний блок `mb-4`) сохраняются внутри прокручиваемого тела.

### 2. Блок «Выход»

Стоит **сразу после** блока «Вход» и **до** «Провайдер» — вход и выход читаются парой.

```
Выход                                     ← text-[11px] text-ink-faint, mb-1
Выходов нет — прогон даёт один документ.  ← text-[10px] text-ink-faint, mb-1
                                             (или «Первый в списке — основной результат прогона.»)
┌ [основной] ключ [__________]  ↑ ↓ ✕ ┐   ← OutputsList, как в карточке OUTPUTS
│           описание [________]        │
│           [ ] несколько документов    │
└           число документов … прогоне ─┘
[ Добавить выход ]
```

Разметка блока:

```
<div className="mb-2">
  <div id={outputsLabelId} className="mb-1 text-[11px] text-ink-faint">Выход</div>
  <p id={outputsHintId} className="mb-1 text-[10px] text-ink-faint">{hint}</p>
  <div role="group" aria-labelledby={outputsLabelId} aria-describedby={outputsHintId}>
    <OutputsList value={outputs} onChange={…} disabled={saving} rowErrors={mergedRowErrors} />
  </div>
  {limitError && <p className="mt-1 text-[11px] text-danger-ink">максимум 8 выходов</p>}
  {outputsInvalid && <p className="mt-1 text-[10px] text-danger-ink">Поправьте выходы — иначе не сохранить.</p>}
</div>
```

Подпись «Выход» — тем же паттерном, что «Вход» и «Модель» (`div` с `text-[11px] text-ink-faint`), а не `<label>`: внутри блока несколько контролов.

### 3. Состояния блока

| Состояние | Условие | Что видно |
| --- | --- | --- |
| Пусто | `outputs.length === 0` | пояснение «Выходов нет — прогон даёт один документ.» + кнопка «Добавить выход». **Ни красного текста, ни `aria-invalid`.** Сохранение не блокируется |
| Обычное | `outputs.length > 0`, ошибок нет | пояснение «Первый в списке — основной результат прогона.», строки, бейдж `основной` на первой |
| Ошибка строки | `mergedRowErrors[i] != null` | сообщение под соответствующим полем строки (рендерит сам `OutputsList`), «Сохранить» заблокирована, под списком — сводка «Поправьте выходы — иначе не сохранить.» |
| Лимит достигнут | `outputs.length >= MAX_SKILL_OUTPUTS` | «Добавить выход» `disabled` + `title="максимум 8 выходов"` (уже в `OutputsList`) |
| Лимит превышен | `outputs.length > MAX_SKILL_OUTPUTS` (данные пришли из preview) | блочная ошибка «максимум 8 выходов», «Сохранить» заблокирована |
| Сохранение | `saving === true` | `OutputsList` целиком `disabled` (поля, ↑ ↓ ✕, «Добавить выход»); disabled-стиль — `bg-surface-muted` + `text-ink-faint` + `cursor-not-allowed`, он уже внутри компонента |
| 422 от бэкенда | адресный `outputs[i].…` | сообщение легло на строку `i`; неадресный остаток — в блоке `error` подвала |

### 4. Кнопка «Сохранить»

| Условие | Поведение |
| --- | --- |
| `saving` | подпись «Сохранение…», `disabled` |
| `nameInvalid` | `disabled`, `title="Имя не может быть пустым"` |
| `outputsInvalid` | `disabled`, `title="Поправьте выходы"` |
| иначе | активна, `title` не задан |

Итог: `disabled={saving || nameInvalid || outputsInvalid}`. Приоритет `title`: имя → выходы. Классы (`btn-primary` / `btn-secondary`) и расположение кнопок не меняются.

## Взаимодействия

- **Инициализация.** `outputs` инициализируются один раз из `preview.outputs ?? []` (ленивый инициализатор `useState`, как `inputArity` на `SkillSettingsModal.tsx:45`), с сохранением порядка. `multiple` читается строго как `boolean` (`o.multiple === true`). Никакой сортировки, дедупликации и «починки» данных на входе — что объявил планировщик, то человек и видит.
- **Правка строк.** Любое изменение идёт единственным `onChange` из `OutputsList`: `setOutputs(next)` + сброс серверных ошибок строк (`setServerRowErrors([])`). Собственного редактирования полей выхода модалка не реализует.
- **Перестановка.** Кнопки ↑ ↓ уже переставляют элементы массива; модалка обязана отправлять `outputs` **в текущем порядке состояния**, без пересортировки при сериализации. Перестановка первой строки меняет primary в теле запроса.
- **Добавление/удаление.** Кнопки внутри `OutputsList`; лимит 8 — его же. Новая строка приходит как `{ key: '', description: '', multiple: false }` и сразу показывает ошибки незаполненных полей (это же объясняет, почему «Сохранить» заблокирована).
- **Клиентская валидация — «живая».** `validateOutputs(outputs)` считается на каждый рендер через `useMemo`; результат даёт `outputsInvalid` и клиентские `rowErrors`. Отложенной валидации «по blur» нет: состояние кнопки и красные строки обязаны совпадать всегда.
- **Слияние ошибок.** Отображаемый `rowErrors[i]` = поля клиентской ошибки, дополненные серверными по тем полям, где клиентской нет (клиент приоритетнее — его формулировки на русском). Массив выровнен по индексам строк, длина = `outputs.length`.
- **Сохранение.** `handleSave` шлёт `outputs` **всегда** (блок отрисован — человек его видел), рядом с `input_arity`; семантика ручки «поле отсутствует = не трогать» здесь не используется. Пустой список отправляется как `[]` — это валидное «выходов нет».
- **422.** `extractApiDetail(e)` → разбор адресных сегментов (см. «Контракты данных»): адресные ложатся в `serverRowErrors`, неадресный остаток — в `error`. Если адресным оказалось всё, в `error` пишется «Бэкенд не принял выходы — поправьте отмеченные строки.», чтобы ответ не терялся молча.
- **Отмена / ✕.** Поведение не меняется: закрытие без сохранения, `disabled` во время `saving`. Правки выходов не сохраняются — как и правки имени сегодня.
- **Фокус.** `firstKeyRef` в модалку не передаётся (он существует для восстановления фокуса в карточке артефактов). Автофокус на первый ключ при открытии не делаем — первое поле формы остаётся «Имя».

## Доступность (a11y)

- Карточка модалки получает `role="dialog"`, `aria-modal="true"` и `aria-labelledby` на заголовок «Настройка скила» (сегодня их нет; форма становится длиннее и прокручиваемой, поэтому обвязка обязательна). Кнопка ✕ получает `aria-label="Закрыть"`. Фокус-ловушку в этом шаге не делаем.
- Блок «Выход» — `role="group"` с `aria-labelledby` на подпись «Выход» и `aria-describedby` на строку-пояснение: скринридер объявляет группу и её смысл до полей.
- Пустое состояние озвучивается как пояснение (`<p>` в `aria-describedby`), а не как ошибка: `aria-invalid` и `role="alert"` в этом состоянии не используются.
- Ошибки строк связаны с полями через `aria-invalid` + `aria-describedby` — механикой самого `OutputsList`; модалка обязана лишь передать корректный `rowErrors`.
- Порядок табуляции: Имя → radiogroup «Вход» (roving `tabIndex`) → поля и кнопки строк выходов сверху вниз → «Добавить выход» → Провайдер → Модель → Режим рассуждений → Отмена → Сохранить. Дополнительных `tabIndex` не вводить.
- Кнопки ↑ ↓ ✕ уже имеют осмысленные `aria-label` с меткой строки (`Поднять выход <ключ|номер>`); глифы смысла не несут.
- Причина заблокированной кнопки «Сохранить» доступна текстом: сводка под списком и `title` на кнопке.
- Прокручиваемое тело — обычный контейнер со скроллом; фокус на элементе внутри него доводится браузером, дополнительная логика не нужна.

```ts
//  порядок сохраняется 1:1.

    model?: string
    provider?: string
    reasoning?: string

```

`SkillPreview.outputs` объявлено опциональным сознательно: клиент терпим к ответу без поля и читает его как `preview.outputs ?? []` — та же семантика «отсутствие = выходов нет», что в конфиге (ADR-0024).

**Разбор адресного 422.** Вход — строка из `extractApiDetail(e)`; сегменты разделены `; `, у каждого срезается префикс `Value error, `. Соответствие сегментов строкам:

| Шаблон сегмента | Куда ложится | Текст на строке |
| --- | --- | --- |
| `outputs[<i>].key …` | `rowErrors[i].key` | `ключ: только a-z, цифры и _` |
| `duplicate output key: '<key>'` | первая строка с таким `key.trim()` | `такой ключ уже есть` |
| `outputs[<i>].description …` | `rowErrors[i].description` | `описание не может быть пустым` |
| `outputs[<i>].multiple …` | `rowErrors[i].multiple` | `несколько документов: только true или false` |
| всё остальное (в т.ч. `outputs must have at most 8 items`) | блок `error` | текст сегмента как есть |

Индекс вне диапазона `outputs` → сегмент считается неадресным и уходит в `error`. Формулировки на строках берутся из `validateOutputs` (`api.ts:739`) — второго набора текстов не заводить.

**Формулировки (единый источник):**

| Место | Текст |
| --- | --- |
| подпись блока | `Выход` |
| пустой список | `Выходов нет — прогон даёт один документ.` |
| непустой список | `Первый в списке — основной результат прогона.` |
| превышен лимит | `максимум 8 выходов` |
| сводка под списком | `Поправьте выходы — иначе не сохранить.` |
| `title` заблокированной кнопки (выходы) | `Поправьте выходы` |
| `title` заблокированной кнопки (имя) | `Имя не может быть пустым` |
| весь 422 разложен по строкам | `Бэкенд не принял выходы — поправьте отмеченные строки.` |

## Критерии визуальной приёмки

- [ ] В `SkillSettingsModal` блок «Выход» стоит в разметке **между** блоком «Вход» (radiogroup) и блоком «Провайдер»; подпись — `text-[11px] text-ink-faint`, блок в той же сетке отступов `mb-2`, что соседи.
- [ ] Внутри блока рендерится импортированный `OutputsList` с пропсами `value`, `onChange`, `disabled={saving}`, `rowErrors`; в `frontend/src` нет второй реализации строки выхода, копии `OutputsList` и новых пропов у него.
- [ ] Состояние выходов инициализируется из `preview.outputs ?? []` ленивым инициализатором `useState` с сохранением порядка; `multiple` читается как `o.multiple === true`, сортировки/дедупликации на входе нет.
- [ ] Пустой список даёт пояснение «Выходов нет — прогон даёт один документ.» в `text-ink-faint`; в этой ветке нет `text-danger-ink`, `aria-invalid` и блокировки «Сохранить».
- [ ] Непустой список даёт пояснение «Первый в списке — основной результат прогона.»; бейдж `основной` на первой строке приходит из `OutputsList` и в модалке не дублируется.
- [ ] `outputsInvalid` считается через `validateOutputs` (импорт из `api.ts`) плюс проверка `outputs.length > MAX_SKILL_OUTPUTS`; собственных правил валидации ключа/описания в компоненте нет.
- [ ] Кнопка «Сохранить» имеет `disabled={saving || nameInvalid || outputsInvalid}` и `title` по таблице из раздела «Кнопка Сохранить».
- [ ] Под списком при `outputsInvalid` рендерится сводка «Поправьте выходы — иначе не сохранить.», а при `outputs.length > MAX_SKILL_OUTPUTS` — блочная ошибка «максимум 8 выходов».
- [ ] `handleSave` передаёт `outputs` в `configureSkill` рядом с `input_arity`, всегда (без условия «если изменилось»), массивом объектов и в текущем порядке состояния; повторной сортировки перед отправкой нет.
- [ ] В `api.ts` есть экспорт `outputsPayload`, `serializeOutputs` реализован через него, `multiple` попадает в payload только при `true`, `key`/`description` тримятся.
- [ ] `SkillPreview` в `api.ts` содержит поле выходов, а `configureSkill` — параметр `outputs?: SkillOutputOut[]` (массив, не строка).
- [ ] Ошибки 422 разбираются: в коде есть разбор сегментов `outputs[<i>].<field>` и `duplicate output key`, адресные попадают в `rowErrors`, неадресные — в существующий блок `error`; при полностью адресном ответе в `error` пишется «Бэкенд не принял выходы — поправьте отмеченные строки.».
- [ ] Тексты ошибок строк, приходящие с бэкенда, берутся из формулировок `validateOutputs`, а не переводятся заново по месту.
