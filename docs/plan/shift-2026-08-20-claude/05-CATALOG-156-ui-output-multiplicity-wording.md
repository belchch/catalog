# CATALOG-156 — ui: формулировки не отражают множественность выходов

- **Задача Plane:** [CATALOG-156](https://app.plane.so/belchch/projects/84997489-c485-4448-9ebe-0a06c4fa3cbc/issues/9eef3e11-8ef1-4647-b11b-ee019f495120) (id: `9eef3e11-8ef1-4647-b11b-ee019f495120`, state: In Progress)

- **Тип шага:** ui
- **Очередь:** 05 · независимый (катится отдельно от остальных подзадач)
- **Цель:** Убрать из UI обещание «один документ» там, где у скилла объявлено несколько выходов, не заводя второй числовой счётчик рядом с существующим счётчиком входных документов.

## Постановка задачи (актуальное ТЗ)
_(источник: описание задачи — комментариев не было)_

Тип: ui (малая). Родитель: CATALOG-142. Катится независимо от остальных подзадач.

**Контекст.** Скилл теперь умеет отдавать несколько документов, но тексты в UI остались от эпохи «один прогон = один документ» и теперь вводят в заблуждение.

**Что уже починено и трогать не надо:** кнопка сохранения в `RunView` уже переключается по числу артефактов (`RunView.tsx:110`, сделано в CATALOG-146).

**Что осталось:**

1. **Кнопка «В док» в `SkillsPanel.tsx:782-798`.** Подпись и тултип «Результат сразу сохраняется в **новый документ**» говорят про один документ даже у скилла с тремя объявленными выходами. Число уже есть на клиенте — `outputs_count` в `SkillOut`.
2. **Суффикс `(N)` сейчас значит входы.** На обеих кнопках висит `docIds.length > 1 ? ` (${docIds.length})` : ''` — это число **входных** документов. Приставить рядом второе число нельзя — «В док (3) (2)» нечитаемо. Множественность выходов выражать словом в подписи и числом в тултипе, а не вторым счётчиком.
3. **Пройти остальные строки** про «документ» в единственном числе на пути прогона: тосты после сохранения, подсказки, пустые состояния. Комментарии в коде (`api.ts:44`, `useRunStream.ts:62-63`) — это названия режимов из CATALOG-18, их менять не надо.

**Граница.** Сами названия режимов — «В док» / «На экран» — отвечают на вопрос _куда_ идёт результат, а не _сколько_ его. Переименовывать режимы целиком в этой задаче не надо — только убрать ложное «один документ» там, где оно неправда.

  - Кнопка «На экран»: тултип «Результат выводится на экран; документ можно сохранить отдельно» — рядом; подпись — [:814](frontend/src/components/SkillsPanel.tsx:814), с тем же суффиксом по `docIds.length`.

**Главная ловушка — два разных числа.** В подписи кнопки уже живёт `(N)` для входов. Второе число туда добавлять нельзя. Правило из ТЗ: **множественность выходов — словом в подписи, числом в тултипе**. Счётчик входов остаётся ровно как есть.

**Вторая ловушка — не пересолить.** У скилла с одним выходом тексты обязаны остаться **буквально прежними**: никаких «документ(ы)» на всякий случай. Значит, ветвление по `outputs_count > 1`, а не универсальная переформулировка.

**Стиль.** Только токены и примитивы [docs/ui-style-guide.md](docs/ui-style-guide.md). Визуальная приёмка — по дизайн-спеке `05-CATALOG-156-ui-output-multiplicity-wording.design.md` от `catalog-designer`; она же фиксирует точные формулировки.
