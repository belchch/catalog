# CATALOG-156 — Дизайн UI

- **Источник:** docs/plan/shift-2026-08-20-claude/05-CATALOG-156-ui-output-multiplicity-wording.md
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Убрать обещание «один документ» из кнопок запуска скилла в `SkillsPanel`, когда у
скилла объявлено больше одного выхода. Второй числовой счётчик рядом с уже
существующим счётчиком **входных** документов не появляется: множественность
выходов выражается **словом в подписи** и **числом в тултипе**.

Путь пользователя (без изменений в навигации):

1. Пользователь выбирает скилл в списке `SkillsPanel` → раскрывается блок запуска.
2. Выбирает входные документы (1 / 2 / N) и, при необходимости, промпт.
3. Видит две кнопки режима: «В док» (`btn-primary`) и «На экран» (`btn-secondary`).
4. У многовыходного скилла подпись «В док» несёт словесный маркер множественности,
   а тултип — число объявленных выходов, явно названных выходами.
5. Дальше — прогон и `RunView`, который уже корректно ветвится по числу артефактов
   (CATALOG-146). В этом шаге `RunView` не трогается.

Инвариант шага: **у скилла с одним объявленным выходом все строки остаются
побайтово прежними**.

### Хелперы (модульный уровень `SkillsPanel.tsx`, рядом с `arityLabel`)

Чистые функции, без React-состояния; допускается экспорт для юнит-тестов:

```
declaredOutputs(skill: SkillOut): number      // Math.max(1, skill.outputs_count ?? 1)
hasMultipleOutputs(skill: SkillOut): boolean  // declaredOutputs(skill) > 1
outputsCountPhrase(skill: SkillOut): string   // "3" | "3 и более" (если outputs_has_collection === true)
applyLabel(base: 'В док' | 'На экран', skill, inputCount: number): string
applyTitle(mode: ApplyMode, skill): string
```

`inputCount` — это `docIds.length` (входные документы). Суффикс входов остаётся
ровно сегодняшним выражением `inputCount > 1 ? ` (${inputCount})` : ''` и всегда
стоит **последним** в подписи.

## Layout и состояния

Раскладка, классы и размеры не меняются: обе кнопки живут в
`<div className="flex flex-wrap gap-1.5">`, классы `btn-primary text-[11px]` и
`btn-secondary text-[11px]` остаются как есть. Подпись «В док» у многовыходного
скилла длиннее — контейнер уже `flex-wrap`, поэтому кнопка при нехватке ширины
переносится на следующую строку. Запрещено: `whitespace-nowrap`, фиксированная
ширина, `truncate` на этих кнопках, перенос суффикса входов в начало подписи.

Матрица строк (N — число объявленных выходов, `outputs_count`; K — число входных
документов, `docIds.length`):

| Условие | Кнопка | Подпись | `title` |
| --- | --- | --- | --- |
| `N <= 1` (или `outputs_count` отсутствует) | В док | `В док` + суффикс входов | `Результат сразу сохраняется в новый документ` |
| `N <= 1` | На экран | `На экран` + суффикс входов | `Результат выводится на экран; документ можно сохранить отдельно` |
| `N > 1` | В док | `В док · несколько` + суффикс входов | `Результат сразу сохраняется в новые документы; выходов у скилла — {фраза}` |
| `N > 1` | На экран | `На экран` + суффикс входов (**без изменений**) | `Результат выводится на экран; документы можно сохранить отдельно; выходов у скилла — {фраза}` |

`{фраза}` = `outputsCountPhrase(skill)`: `3` при обычных выходах, `3 и более`
при `outputs_has_collection === true` (коллекционный выход, число документов
известно только после прогона — ADR-0025; та же семантика, что у бейджа
`N+ вых.` в карточке).

Суффикс входов: `` ` (${K})` `` при `K > 1`, иначе пустая строка.

Примеры итоговых подписей:

- `N = 1, K = 1` → `В док` / `На экран`
- `N = 1, K = 3` → `В док (3)` / `На экран (3)`
- `N = 2, K = 1` → `В док · несколько` / `На экран`
- `N = 2, K = 3` → `В док · несколько (3)` / `На экран (3)`

Разделитель — символ `·` (U+00B7) с пробелами: тот же приём, что в табах
`RunView` (`${baseLabel} · ${n}`) и в подписи чипа `· основной`.

Состояния кнопок не меняются: `disabled={!valid || documents.length === 0}`
(стиль disabled — из `.btn-*`, `surface-muted` + `ink-faint` + `cursor-not-allowed`),
focus-visible — кольцо `ring-2 ring-brand` из примитивов.

### Инвентаризация строк пути «запустить → увидеть → сохранить»

| Место | Строка | Вердикт |

| `SkillsPanel.tsx` кнопка «На экран», `title` | «Результат выводится на экран; документ можно сохранить отдельно» | **менять** только при `N > 1` |
| `SkillsPanel.tsx` подписи кнопок | суффикс `(K)` по `docIds.length` | оставить как есть, второго числа не добавлять |

| `SkillSettingsModal.tsx:195` «Выходов нет — прогон даёт один документ.» | — | редактор скилла, при нуле выходов утверждение истинно; не трогать |
| `api.ts:44`, `useRunStream.ts:62` | комментарии-названия режимов | не трогать (CATALOG-18) |

**Осознанно вне скоупа:** скилл с `outputs_count <= 1` и
`outputs_has_collection === true`. Формально у него один объявленный выход, а
план требует, чтобы у односоставного скилла строки остались побайтово прежними
(ловушка №2). Множественность такого прогона уже коммуницируют бейдж `1+ вых.`
в карточке и `RunView` после прогона. Ветвление строго по `outputs_count > 1`.

## Взаимодействия

- Клик по «В док» → `onApply(s.id, docIds, 'persist', applyPromptArg(...))`;
  клик по «На экран» → тот же вызов с `'preview'`. Сигнатуры, порядок аргументов
  и условие `valid && …` не меняются.
- Тултип — нативный `title` на самой кнопке (существующий паттерн панели), без
  кастомного поповера, без задержек и без новых обработчиков наведения.
- Смена выбранных входных документов немедленно пересчитывает суффикс `(K)`;
  смена выбранного скилла — весь блок формулировок. Никакого локального состояния
  для формулировок не заводится: всё выводится из `skill` и `docIds` при рендере.
- Клавиатура: порядок табуляции и обработчики `Escape` / стрелок в списке скиллов
  не меняются.

## Стиль и токены

- Только примитивы и токены из `docs/ui-style-guide.md`: `.btn-primary` («В док»),
  `.btn-secondary` («На экран»), размер `text-[11px]`, контейнер
  `flex flex-wrap gap-1.5`.
- Сырые палитры Tailwind (`slate-*`, `indigo-*`, `red-*`, …) запрещены.
- Значения `className` обеих кнопок в этом шаге **не меняются вообще**: правка
  только текстовая (подпись + `title`).
- Новых токенов, иконок, бейджей и CSS-классов не вводится. Маркер
  множественности — текст, а не бейдж: бейдж выходов уже есть в строке карточки,
  дублировать его на кнопке нельзя.

## Доступность (a11y)

- Доступное имя кнопок остаётся текстовым содержимым; `aria-label` на этих
  кнопках не добавляем (иначе имя разойдётся с видимой подписью и сломается
  сопоставление «вижу — озвучено»).
- `title` служит описанием кнопки; текст описания самодостаточен и явно называет
  число **выходов** словом «выходов», чтобы его нельзя было спутать со счётчиком
  входов `(K)` в подписи.
- Разделитель `·` — пунктуация внутри подписи, отдельной семантики не несёт;
  скринридер получает полный смысл из `title`.
- Никаких `aria-live`, ролей и `aria-describedby` не добавляем: содержимое кнопок
  меняется только по действию пользователя (выбор скилла/документов).
- Контраст и состояния фокуса/disabled наследуются от примитивов и не правятся.

## Контракты данных (если нужны)

Только чтение уже существующих полей `SkillOut` (`frontend/src/api.ts`), запросов
и типов не меняем:

```ts
interface SkillOut {
  // …
  outputs_count?: number          // число объявленных выходов скилла
  outputs_has_collection?: boolean // среди выходов есть коллекционный (ADR-0025)
}
```

Правила чтения: `outputs_count` может отсутствовать (старые ответы) — тогда
считается `1`; значения `0` и `1` трактуются одинаково («один документ»).
Число входных документов берётся только из `docIds.length` и никогда не
смешивается с `outputs_count` в одном выражении подписи.

## Критерии визуальной приёмки

- [ ] В `SkillsPanel.tsx` подпись и `title` кнопки «В док» вычисляются через
      чистый хелпер от `skill` (поле `outputs_count`) и `docIds.length`; условие
      множественности — строго `(skill.outputs_count ?? 1) > 1`.
- [ ] При `outputs_count` отсутствующем / `0` / `1` подпись даёт ровно
      `В док` + существующий суффикс входов, а `title` — ровно строку
      `Результат сразу сохраняется в новый документ` (побайтово как сегодня).
- [ ] При `outputs_count` отсутствующем / `0` / `1` `title` кнопки «На экран» —
      ровно `Результат выводится на экран; документ можно сохранить отдельно`.
- [ ] При `outputs_count > 1` подпись «В док» содержит словесный маркер
      множественности `В док · несколько` и не содержит числа выходов.
- [ ] При `outputs_count > 1` `title` кнопки «В док» содержит слово «выходов»,
      число выходов и не содержит подстроки `новый документ`.
- [ ] При `outputs_count > 1` `title` кнопки «На экран» не содержит подстроки
      `документ можно сохранить` в единственном числе и содержит число выходов
      со словом «выходов».
- [ ] При `outputs_has_collection === true` и `outputs_count > 1` число в тултипе
      подано как нижняя граница (`N и более`).
- [ ] В выражении подписи каждой кнопки ровно один интерполируемый счётчик —
      `docIds.length`; никаких вторых круглых скобок с числом и никакого
      `outputs_count` внутри подписи.
- [ ] Подпись кнопки «На экран» и её выражение суффикса не изменены; названия
      режимов «В док» / «На экран» сохранены как начало подписи.
- [ ] `className`, `disabled`, `onClick` и порядок обеих кнопок не изменены;
      новых элементов (бейджей, иконок, поповеров) в блоке кнопок не появилось.
- [ ] `aria-label` на кнопках режимов не добавлен; тултип реализован атрибутом
      `title` на самой кнопке.
- [ ] Файлы `RunView.tsx`, `RunView.test.tsx`, `api.ts`, `hooks/useRunStream.ts`
      не изменены (пустой дифф).
- [ ] Бейдж выходов в строке карточки скилла (`N вых.` / `N+ вых.` и его `title`)
      не изменён.
- [ ] Сырых палитр Tailwind в диффе нет; использованы только примитивы
      `docs/ui-style-guide.md`.
- [ ] `SkillsPanel.test.tsx` покрывает: `outputs_count: 3` (подпись с маркером,
      тултип с `3` и словом «выходов», отсутствие `новый документ`),
      `outputs_count: 1` (подпись и оба тултипа побайтово прежние),
      `outputs_count: 2` при трёх входных документах (в подписи ровно один
      счётчик — `(3)`), `outputs_has_collection: true` (`N и более` в тултипе).
- [ ] Новых npm-зависимостей не добавлено.
