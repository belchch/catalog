# CATALOG-154 — Дизайн UI

- **Источник:** docs/plan/shift-2026-08-20-claude/02-CATALOG-154-ui-collection-outputs.md
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Коллекционный выход (`multiple: true`, значение — `list[str]`) должен быть выразим в трёх точках пути:

1. **Черновик скилла.** В карточке OUTPUTS автор помечает выход как коллекционный (строка `OutputsList`) и понимает, что число документов станет известно только при прогоне.
2. **Прогон.** В `RunView` коллекция — **одна** вкладка с числом элементов, а не N вкладок; внутри — свёрнутый список элементов, первый раскрыт. До нажатия «Сохранить» видно, сколько документов будет создано; после сохранения видно, сколько создано и куда перейти.
3. **Список скиллов.** Бейдж выходов у скилла с коллекционным выходом не выдаёт точное число за достоверное.

Путь: *объявил выход → пометил «несколько документов» → сохранил outputs → запустил → увидел одну вкладку «Главы · 7» → раскрыл нужную главу → нажал «Сохранить как 8 документов» → увидел «Создано 8 документов» и список, свёрнутый в «Показать 8 документов»*.

Жёсткая рамка: **прогон без коллекций и черновик без коллекций выглядят и звучат ровно как сегодня**. Все новые элементы появляются только при `multiple: true` / `Array.isArray(artifact.text)`.

## Layout и состояния

### 1. `OutputsList` — строка выхода

Строка остаётся: `[ ключ ] [ описание ] [ ↑ ↓ ✕ ]`. Под полем «описание», внутри той же левой колонки (`min-w-0 flex-1`), добавляется третья, чекбокс-строка:

```
[✓] несколько документов
    число документов определяется при прогоне
```

- Разметка: `<label className="mt-1 flex items-start gap-1.5 text-[11px] text-ink-faint">` c `<input type="checkbox" className="mt-0.5 h-3 w-3 shrink-0 accent-brand" …>` (тот же приём, что в `DocumentCombobox.tsx:180-181`) и текстом «несколько документов».
- Пояснение — отдельный `<p id={multiHintId} className="ml-[1.125rem] text-[10px] text-ink-faint">число документов определяется при прогоне</p>`, привязан через `aria-describedby`.
- Порядок в строке: ключ → описание → чекбокс → пояснение → ошибки строки (ошибки остаются последними, как сейчас).
- **Состояния:** `disabled` — чекбокс `disabled`, текст остаётся `text-ink-faint`, `cursor-not-allowed` на `<label>`; `checked` — значение `row.multiple === true`; `undefined` трактуется как `false`. Ошибка типа — параграф `text-[11px] text-danger-ink` под строкой (тот же вид, что `err.key`/`err.description`), плюс `aria-invalid` на чекбоксе.
- Кнопка «Добавить выход» и лимит `MAX_SKILL_OUTPUTS` — без изменений; новая строка создаётся как `{ key: '', description: '', multiple: false }`.

Ничего в карточке OUTPUTS (`ArtifactsPanel.tsx:874-929`) не двигается: строка просто становится выше на две текстовые линии.

### 2. `RunView` — вкладки по выходам

Модель отображения строится из `run.artifacts` (`RunArtifact[]`), одна вкладка = один артефакт:

| Величина | Правило |
| --- | --- |
| `items(artifact)` | `Array.isArray(text) ? text : [text]` |
| `isCollection(artifact)` | `Array.isArray(artifact.text)` |
| `hasCollection` | `artifacts.some(isCollection)` |
| `multi` | `artifacts.length > 1 \|\| hasCollection` |
| `showTablist` | `artifacts.length > 1` |
| `plannedDocs` | `artifacts.length === 0 ? 1 : sum(items(a).length)` |

- `artifacts.length === 0` → как сегодня: `run.resultText` / «Ожидание результата…» / «Нет текстового результата.».
- `artifacts.length === 1 && !isCollection` → как сегодня (без вкладок).
- `artifacts.length === 1 && isCollection` → **без** `role="tablist"` (одна вкладка не даёт навигации), но с шапкой выхода и панелью коллекции.
- `artifacts.length > 1` → `role="tablist"` ровно на **число выходов**; коллекция не размножается.

**Подпись вкладки.**
- Обычный выход: `description?.trim() || key` — **буквально как сейчас** (защищено тестом `tabs[0].textContent === 'Краткое резюме'`).
- Коллекционный: `${description?.trim() || key} · ${n}`, где `n = items.length`. `title` = `${key} — ${description} · элементов: ${n}` (без описания — `${key} · элементов: ${n}`).
- Классы вкладки, `id={`run-tab-${key}`}`, `aria-selected`, `aria-controls`, `tabIndex` — без изменений.

**Шапка активного выхода** (строка под вкладками, сегодня `key` + бейдж «основной») дополняется для коллекции третьим элементом: `<span className="text-ink-faint">элементов: {n}</span>`. Для обычного выхода строка не меняется.

**Панель коллекции** (`role="tabpanel"`, `id={`run-panel-${key}`}`): вертикальный список `flex flex-col gap-1`, каждый элемент —

```
<div className="rounded border border-line bg-surface">
  <button id="run-item-{key}-{i}" aria-expanded aria-controls="run-item-panel-{key}-{i}"
          className="flex w-full items-center gap-1.5 rounded px-2 py-1 text-left text-xs text-ink
                     hover:bg-surface-hover focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand">
    <span aria-hidden>▸ / ▾</span>
    <span className="min-w-0 flex-1 truncate">{i+1}. {itemTitle}</span>
  </button>
  {open && <div id="run-item-panel-{key}-{i}" role="region" aria-labelledby="run-item-{key}-{i}" className="border-t border-line px-2 py-1.5">
              <MarkdownView text={item} defaultMode="md" className="text-sm text-ink" />
           </div>}
</div>
```

- **Заголовок элемента** `itemTitle`: первый markdown-заголовок текста (`/^\s{0,3}#{1,6}\s+(.+)$/m`, `trim()`, обрезка до 80 символов с многоточием); если заголовка нет — `Элемент ${i + 1}` (правило зеркалит ADR-0025, но используется **только для отображения**; заголовки документов считает бэкенд).
- **Первый элемент раскрыт**, остальные свёрнуты. Тело закрытого элемента **не монтируется** (`{open && …}`) — 30 инстансов `MarkdownView` рендерить нельзя.
- Пустая строка элемента → вместо `MarkdownView` — `<p className="text-xs text-ink-faint">Пустой элемент.</p>`.
- Состояние раскрытия — `Set<number>` (или `Record<number, boolean>`) на активный выход; сбрасывается на `{0}` при смене активной вкладки, `runId` и состава ключей.

Обычный (строковый) выход рендерится в панели ровно как сегодня: `MarkdownView` или «Пустой результат.».

### 3. Кнопка сохранения

Позиция и классы не меняются (`btn-primary mb-2`, `disabled={savingResult}`, текст «Сохраняю…» во время сохранения).

| Условие | Подпись |
| --- | --- |
| `savingResult` | `Сохраняю…` (без изменений) |
| `hasCollection` | `Сохранить как ${plannedDocs} ${plural}` — «документ / документа / документов» |
| `!hasCollection && artifacts.length > 1` | `Сохранить как новые документы` (**без изменений**) |
| иначе | `Сохранить как новый документ` (**без изменений**) |

При `hasCollection` на кнопку добавляется `title={`Будет создано ${plannedDocs} ${plural} в рабочей папке`}`. Отдельной строки-подсказки не заводить — число уже в подписи.

Защита от дубля: кнопка `disabled` при `savingResult` (уже есть) и исчезает, как только `docIds.length > 0` (`canSaveResult`). Дополнительной логики не добавлять.

### 4. Созданные документы

Блок успеха (`docIds.length > 1`) перестраивается в три яруса внутри той же плашки `border-success-line bg-success-soft`:

```
┌ (плашка success)
│ <div role="status" aria-live="polite">
│   Создано 8 документов                       ← formatCreatedCount, без изменений
│   Документы прогона — откройте нужный        ← вторая строка, если есть onOpenDoc;
│ </div>                                          иначе прежнее «Документы прогона»
│ (свёрнуто)  [ Показать 8 документов ]        ← при docIds.length > RESULT_DOC_CHIPS_LIMIT
│ (раскрыто)  [чип·основной] [чип] [чип] …  [ Скрыть список ]
└
```

- `RESULT_DOC_CHIPS_LIMIT = 6`. При `docIds.length <= 6` чипы рендерятся сразу, как сегодня (порядок, `chip-brand` на первом, `title`/`aria-label` с «· основной», `CHIP_INTERACTIVE`) — **разметка не меняется**.
- При `docIds.length > 6` по умолчанию свёрнуто: `btn-secondary` с `aria-expanded={false}` и `aria-controls="run-created-docs"`, подпись `Показать ${n} ${plural}`. Раскрытое состояние: контейнер чипов `id="run-created-docs"` + кнопка `Скрыть список` (`aria-expanded={true}`).
- Раскрытый контейнер чипов при большом числе документов ограничен по высоте: `max-h-40 overflow-y-auto`.
- `role="status" aria-live="polite"` переезжает с внешней плашки на внутренний блок со счётчиком, чтобы раскрытие/сворачивание списка не переозвучивалось скринридером. Текст «Создано N документ(а/ов)» остаётся достижим через `getByRole('status')`.
- Ветка одного документа (`Документ создан: «…»`) не меняется.

### 5. Бейдж в списке скиллов

`SkillsPanel.tsx:492-496`, внутри существующего `<span className="flex shrink-0 items-center gap-1">`:

| Условие | Бейдж | `title` |
| --- | --- | --- |
| `outputs_has_collection === true` | `badge-neutral`, текст `${outputs_count ?? 1}+ вых.` | `выходов: N, один из них коллекционный — число документов известно только после прогона` |
| иначе и `(outputs_count ?? 0) > 1` | `${outputs_count} вых.` (**без изменений**) | не задаётся (как сейчас) |
| иначе | бейджа нет (**без изменений**) |

Условие рендера становится `outputs_has_collection === true || (outputs_count ?? 0) > 1`: скилл с **одним** коллекционным выходом тоже обязан получить бейдж, потому что документов у него много. Знак `+` читается как «N или больше» и не выдаёт точное число за достоверное.

CATALOG-156 (план `05-…`) правит в этом же файле подписи и тултипы кнопок «В док» / «На экран» — другое место файла; счётчик входных документов `(N)` в подписях кнопок здесь не трогать.

## Взаимодействия

- **Чекбокс «несколько документов»** — `onChange` вызывает `updateRow(index, { multiple: e.target.checked })`; изменение делает карточку OUTPUTS «грязной» (сравнение через `serializeOutputs`) и уезжает на бэкенд по кнопке «Сохранить outputs» существующим PATCH-путём. Отдельной кнопки/автосейва нет.
- **Клавиатура по вкладкам** (`onTabKeyDown`): индексация и `%` — по **списку выходов** (`artifacts`), как и сейчас; элементы коллекции в навигацию вкладок не входят. `ArrowLeft/ArrowRight` циклично, `Home`/`End` — края, фокус переносится на `run-tab-${key}`. Обработчик по-прежнему выходит рано, когда вкладок меньше двух.
- **Сброс активной вкладки:** ключ пересчёта — только состав ключей выходов (`artifacts.map(a => a.key).join('\0')`) и `runId`. Число элементов коллекции в ключ **не входит**: досыл элементов по стриму не должен перекидывать пользователя на первую вкладку.
- **Раскрытие элемента коллекции** — клик/`Enter`/`Space` по кнопке-заголовку (нативная кнопка), toggle одного элемента; несколько элементов могут быть раскрыты одновременно. При переключении вкладки раскрытие сбрасывается к «первый раскрыт».
- **Сохранение** — один клик, кнопка блокируется `savingResult`, после успеха заменяется плашкой успеха.
- **Сворачивание списка документов** — клик по кнопке-раскрывашке; состояние локальное, сбрасывается при смене `runId`.
- **Чип документа** — клик открывает документ (`onOpenDoc`), как сегодня; без `onOpenDoc` чипы остаются `<span>`.

## Доступность (a11y)

- Чекбокс обёрнут `<label>` (клик по тексту переключает), связан с пояснением через `aria-describedby={multiHintId}`; при ошибке `aria-invalid` + `aria-describedby` включает id параграфа ошибки (тот же приём, что у полей «ключ»/«описание»).
- `role="tablist"` с `aria-label="Результаты прогона"` рендерится только при двух и более выходах; roving `tabIndex` (`selected ? 0 : -1`) сохраняется; число `role="tab"` строго равно числу выходов.
- Доступное имя коллекционной вкладки содержит число элементов (`Главы · 7`), `title` расшифровывает: `ключ — описание · элементов: 7`.
- Элемент коллекции: нативная `<button>` с `aria-expanded` и `aria-controls`; раскрытое тело — `role="region"` с `aria-labelledby` на кнопку. Идентификаторы: `run-item-${key}-${i}` / `run-item-panel-${key}-${i}`.
- `aria-live="polite"` остаётся ровно на блоке с числом созданных документов; список чипов и раскрывашка живут вне live-региона.
- Раскрывашка списка документов: `aria-expanded` + `aria-controls` на контейнер чипов; подпись меняется («Показать N документов» ↔ «Скрыть список»).
- Все интерактивные элементы получают видимое кольцо `focus-visible:ring-2 ring-brand`; порядок табуляции — сверху вниз: вкладки → шапка → элементы коллекции → кнопка сохранения/чипы.
- Стрелки-глифы (`▸`/`▾`, `↑`/`↓`/`✕`) — `aria-hidden`, смысл несут текст и `aria-label`.

## Контракты данных

```ts
// api.ts
export interface OutputDraft {
  key: string
  description: string
  multiple?: boolean          // отсутствие === false
}

export interface OutputRowError {
  key?: string
  description?: string
  multiple?: string           // новое
}

export interface RunArtifact {
  key: string
  description?: string | null
  text: string | string[]     // строка — обычный выход, массив — коллекция
}

export interface SkillOut {
  // …
  outputs_count?: number
  outputs_has_collection?: boolean  // из бэкенда CATALOG-153; отсутствие === false
}
```

- `parseOutputsArtifact` читает `multiple` **только** как настоящий `boolean` (без truthy-приведения). Значение чужого типа → строка получает ошибку `multiple: 'несколько документов: только true или false'`, которая **видна на строке** (парсер возвращает третьим полем `rowErrors: (OutputRowError | null)[]`, выровненный по индексам, а карточка OUTPUTS показывает их в `OutputsList.rowErrors`, пока пользователь не отредактировал строку). Артефакт целиком в `parseError` из-за этого не падает.
- `serializeOutputs` пишет `multiple` **только когда `true`** — JSON черновика без коллекций обязан остаться байт-в-байт прежним.
- `validateOutputs` дополняется проверкой: `row.multiple !== undefined && typeof row.multiple !== 'boolean'` → та же формулировка ошибки на строке.
- `normalizeRunArtifacts` принимает `text` как `string` **или** массив строк (нестроковые элементы массива отбрасываются; артефакт с пустым массивом после фильтрации трактуется как коллекция без элементов и рендерится с текстом «Пустой результат.»).
- `SkillOut.outputs_has_collection` — поле бэкенда; клиент **не выводит** признак эвристикой из `outputs_count` или из артефактов.

Формулировки (единый источник):

| Место | Текст |
| --- | --- |
| чекбокс | `несколько документов` |
| пояснение | `число документов определяется при прогоне` |
| ошибка типа | `несколько документов: только true или false` |
| подпись коллекционной вкладки | `{описание или ключ} · {N}` |
| шапка выхода | `элементов: {N}` |
| элемент без заголовка | `Элемент {i}` |
| кнопка сохранения (коллекция) | `Сохранить как {N} документ/документа/документов` |
| `title` кнопки | `Будет создано {N} документ/документа/документов в рабочей папке` |
| вторая строка плашки успеха | `Документы прогона — откройте нужный` (при `onOpenDoc`), иначе `Документы прогона` |
| раскрывашка чипов | `Показать {N} документ/документа/документов` / `Скрыть список` |
| бейдж скилла | `{N}+ вых.` + `title`: `выходов: {N}, один из них коллекционный — число документов известно только после прогона` |

Склонение «документ / документа / документов» считает один общий хелпер; `formatCreatedCount` переиспользует его и **сохраняет прежний вывод** («Создано 2 документа»).

## Критерии визуальной приёмки

- [ ] В строке `OutputsList` есть чекбокс с видимой подписью «несколько документов», обёрнутый в `<label>`, и пояснение «число документов определяется при прогоне», связанное через `aria-describedby`; чекбокс отражает `row.multiple` и уходит в `updateRow(index, { multiple })`.
- [ ] `add()` в `OutputsList` создаёт строку `{ key: '', description: '', multiple: false }`; чекбокс уважает `disabled` и получает `aria-invalid` при ошибке строки; ошибка `multiple` рендерится тем же `text-[11px] text-danger-ink`, что `key`/`description`.
- [ ] `serializeOutputs` пишет `multiple` только при `true` (в коде видно условие), `parseOutputsArtifact` не приводит значение по truthy, `OutputRowError` имеет поле `multiple`.
- [ ] `RunView` строит вкладки по `run.artifacts`: число элементов с `role="tab"` равно числу артефактов; ни один `artifacts[i].text: string[]` не разворачивается в несколько вкладок.
- [ ] `role="tablist"` рендерится только при `artifacts.length > 1`; единственный коллекционный выход показывает панель коллекции без tablist.
- [ ] Подпись коллекционной вкладки содержит число элементов (`… · N`); подпись обычной вкладки — ровно `description?.trim() || key`, без суффиксов.
- [ ] `onTabKeyDown` индексирует по `artifacts` (выходам), переносит фокус на `run-tab-${key}`; в обработчике нет плоского списка элементов коллекции.
- [ ] Ключ сброса активной вкладки собран только из ключей артефактов и `runId`; длины коллекций в него не входят.
- [ ] Панель коллекции рендерит по элементу карточку `rounded border border-line bg-surface` с кнопкой-заголовком (`aria-expanded`, `aria-controls`, `id="run-item-…"`), нумерацией `i+1` и заголовком по первому markdown-заголовку либо «Элемент i»; первый элемент раскрыт.
- [ ] Тело закрытого элемента не монтируется: `MarkdownView` находится под условием раскрытия; раскрытое тело — `role="region"` с `aria-labelledby`.
- [ ] Подпись кнопки сохранения при наличии коллекции содержит суммарное число документов со склонением, а при `savingResult` — «Сохраняю…»; кнопка `disabled={savingResult}`.
- [ ] Подписи «Сохранить как новый документ» и «Сохранить как новые документы» сохранены дословно для прогонов без коллекций.
- [ ] Плашка успеха: `role="status" aria-live="polite"` стоит на блоке со счётчиком, а список чипов и раскрывашка — вне live-региона; при `onOpenDoc` есть строка, указывающая, куда перейти.
- [ ] При `docIds.length > 6` чипы свёрнуты за кнопку «Показать N документов» (`aria-expanded`, `aria-controls`), раскрытый контейнер ограничен `max-h-40 overflow-y-auto`; при `docIds.length <= 6` разметка чипов не изменилась.
- [ ] `SkillsPanel`: бейдж рендерится при `outputs_has_collection === true || (outputs_count ?? 0) > 1`; при коллекции текст — `{N}+ вых.` с поясняющим `title`, при её отсутствии — прежний `{N} вых.` без `title`.
- [ ] Признак коллекции берётся из поля `SkillOut.outputs_has_collection`, а не выводится из `outputs_count` или артефактов.
- [ ] Во всех новых узлах — только токены и примитивы `docs/ui-style-guide.md`; в диффе нет сырых палитр (`slate-*`, `indigo-*`, `red-*`, `gray-*` и т. п.) и нет `opacity-50` для disabled.
- [ ] Все новые интерактивные элементы имеют `focus-visible:ring-2 focus-visible:ring-brand`, а декоративные глифы — `aria-hidden`.
- [ ] Формулировки совпадают с таблицей «Контракты данных» дословно; склонение «документ/документа/документов» идёт через общий хелпер, вывод `formatCreatedCount` не изменился.
