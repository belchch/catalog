# CATALOG-146 — Дизайн UI

- **Источник:** `docs/plan/shift-2026-08-20/04-CATALOG-146-ui-named-outputs-panel.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Два сценария, оба про «у скилла может быть несколько именованных выходов».

**A. Объявление выходов в черновике.** Пользователь открывает «Черновик скилла» → «Редактор артефактов» и видит карточку `Outputs` сразу под `Meta`. Если планировщик уже вызвал `set_skill_outputs`, в карточке список строк «ключ — описание», первая помечена как основная. Пользователь правит ключ/описание, добавляет строку, удаляет, меняет порядок (тем самым меняет, какой выход основной), жмёт «Сохранить outputs» → PATCH `/sessions/{id}/artifacts/outputs`. Ошибка валидации (своя клиентская или пришедшая с бэкенда) видна на карточке, рамка карточки красная, кнопка сборки не блокируется этим дизайном (это зона backend-шагов).

**B. Чтение результатов прогона.** Пользователь применяет скилл и попадает в `RunView`.
- Скилл с одним выходом (или старый прогон без новых полей): экран ровно такой, как сегодня — одно полотно результата, одна кнопка «Сохранить как новый документ». Никаких вкладок, бейджей и чипов не появляется.
- Скилл с N > 1: в правой колонке над результатом появляется полоса вкладок; выбрана первая (primary), подписи вкладок — из описаний выходов. Пользователь переключает вкладки и читает каждый артефакт.
- Режим «на экран»: одна кнопка «Сохранить как новые документы» создаёт всю пачку; после успеха на месте кнопки — сообщение «Создано N документов» и чипы созданных документов; клик по чипу открывает документ.
- Режим «в док»: сразу после финиша вместо строки про один документ показываются те же чипы всей пачки.

**C. Список скиллов.** В строке скилла при N > 1 появляется компактный бейдж с числом выходов; при N ≤ 1 строка не меняется.

## Layout и состояния

### Карточка `Outputs` (черновик)

Место: третья по счёту область панели — **после `Meta`, перед `Steps`**. Декларация контракта читается раньше реализации.

Разметка внутри `sectionShell` (тот же `rounded-md border bg-surface p-3`, что у остальных карточек):

```
[ OUTPUTS ]                         source · время          ← заголовок + statusRow
подсказка (одна строка, text-[10px] text-ink-faint)
┌ строка выхода ─────────────────────────────────────────┐
│ [основной]  key: [input]                               │
│             описание: [input]              ↑ ↓ ✕       │
└────────────────────────────────────────────────────────┘
… ещё строки
[ Добавить выход ]                                       ← btn-secondary
ошибка карточки / ошибка сохранения
                                   Сохранено   [ Сохранить outputs ]
```

Состояния:

| Состояние | Что показываем |
|---|---|
| `loading` | ничего своего — панель уже рисует «Загружаю артефакты…» |
| нет артефакта `outputs` | карточка видна, список пуст, текст `Выходов нет — прогон даёт один результат.` + кнопка «Добавить выход». Карточка видна всегда, при любом `kind`: иначе выходы нельзя объявить руками |
| артефакт есть и валиден | список строк, у первой бейдж `основной` |
| `is_valid === false` | рамка `border-danger-line`, текст ошибки из `artifact.error` под списком (`id="outputs-error"`); строки при этом всё равно рисуем из того, что удалось распарсить |
| контент не парсится как JSON-массив | список пуст, сообщение о разборе + `<details>` «сырой JSON» с `artifact.content` (как у `Steps`) |
| клиентская ошибка в строке | ошибка под конкретной строкой, `aria-invalid` на проблемном поле, кнопка сохранения не отправляет запрос |
| ошибка PATCH | `saveErrors.outputs` под кнопкой (`id="outputs-save-error"`), существующий механизм |
| успех PATCH | флеш «Сохранено» на 1.5 с (существующий `flashSaved`) |
| `streaming` | все поля и кнопки `disabled` через существующий `inputsDisabled` |
| `highlightType === 'outputs'` | скролл к карточке + фокус в поле `key` первой строки; кольцо `ring-2 ring-danger-line` (общий механизм `sectionShell`) |

Клиентская валидация — зеркало backend-правил из CATALOG-144, чтобы не гонять заведомо битый PATCH: ключ по `^[a-z][a-z0-9_]{0,31}$`, ключи уникальны, не больше 8 строк, описание непустое. Сообщения короткие и по строке: `ключ: только a-z, цифры и _`, `такой ключ уже есть`, `описание не может быть пустым`. Лимит 8: кнопка «Добавить выход» становится `disabled` с подсказкой `максимум 8 выходов`.

Пустой список сохраняется как удаление всех выходов — PATCH с `[]`; это легальное состояние (скилл с одним результатом).

### `RunView` — правая колонка «Результат»

N = число артефактов прогона (`run.artifacts.length`).

| N | Layout |
|---|---|
| 0 | как сегодня: заголовок `Результат`, `run.resultText` либо `Ожидание результата…` / `Нет текстового результата.` |
| 1 | как сегодня, ровно тот же DOM-порядок и те же тексты; вкладок нет, кнопка «Сохранить как новый документ» |
| > 1 | под заголовком `Результат` — полоса вкладок, под ней строка `key` + бейдж `основной` для первой, затем полотно активного артефакта |

Порядок блоков при N > 1 (сверху вниз): плашка документов → кнопка сохранения → экспорт docx → вкладки → мета активного артефакта → `MarkdownView` текста активного артефакта.

Плашка результата:

| Состояние | Что показываем |
|---|---|
| документов нет | плашки нет |
| один документ | текущая формулировка `Документ создан: «title»` — без изменений |
| N документов | `bg-success-soft` / `border-success-line` / `text-success-ink`: `Создано 2 документа` (русская плуризация), ниже подпись `Документы прогона` и чипы: primary — `chip-brand`, остальные — `chip`; подпись чипа = заголовок документа, если он найден в `documents` или в `savedDocs`, иначе `id.slice(0, 8)`; `title` / `aria-label` чипа содержат полное имя и, для первого, слово «основной» |

Кнопка сохранения:

- показывается при `run.finished && status === 'ok' && созданных документов нет && есть что сохранять`;
- подпись: N > 1 → `Сохранить как новые документы`, иначе `Сохранить как новый документ`;
- `savingResult` → `Сохраняю…` + `disabled`;
- после успеха исчезает (документы появились) — повторное сохранение недоступно, дублей нет.

Вкладки: `flex flex-wrap gap-1` — при 8 вкладках в узкой колонке перенос читается лучше горизонтального скролла. Подпись вкладки = описание выхода; если описание пустое или не пришло — сам `key`. Подпись обрезается `max-w-[12rem] truncate`, полный текст в `title` как `key — описание`.

Экспорт docx: `exportDocIds` = все документы прогона, если они есть, иначе `run.meta.inputDocs` (текущее поведение). Логика `disabled` / подсказок не меняется.

### `SkillsPanel`

Бейдж рисуется в существующем `span` с тегами, перед символом arity, `shrink-0`, только при `(skill.outputs_count ?? 0) > 1`. Ни ширина строки (8 px высота, `h-8`), ни truncate имени не меняются: бейдж короткий (`N вых.`).

## Взаимодействия

**Карточка `Outputs`:**
- ввод в `key` / `description` — обычный `onChange`, dirty считается сравнением сериализованного черновика со снапшотом сервера (как `metaSnapshot`);
- `↑` / `↓` — перестановка строки; для первой `↑` `disabled`, для последней `↓` `disabled` (стиль disabled по style-guide: `bg-surface-muted text-ink-faint cursor-not-allowed`, не `opacity-50`);
- перемещение строки на первое место = смена primary; бейдж `основной` переезжает мгновенно, без сохранения — это визуальный черновик;
- `✕` удаляет строку; отдельного подтверждения нет (правка не деструктивна до сохранения);
- «Добавить выход» добавляет строку в конец с пустыми полями и ставит фокус в её поле `key`;
- «Сохранить outputs» доступна только когда есть изменения; при клике сначала клиентская валидация — при провале запрос не уходит, показываются ошибки строк и фокус переезжает в первое проблемное поле;
- внешнее обновление артефакта (кадр `session_artifacts` от планировщика) не перетирает несохранённый черновик — тот же приём `dirtyRef`, что у prompt/script/meta;
- смена сессии сбрасывает черновик выходов вместе с остальными.

**Вкладки прогона:**
- клик по вкладке переключает панель;
- клавиатура: `ArrowLeft` / `ArrowRight` — предыдущая/следующая с зацикливанием, `Home` / `End` — первая/последняя; активация автоматическая (фокус = выбор), roving `tabIndex` (активная `0`, остальные `-1`);
- активная вкладка сбрасывается на primary при смене `runId` и при приходе нового набора артефактов; если выбранный ключ исчез из набора — откат на первый;
- крайние случаи: артефакт с пустым текстом → в панели `Пустой результат.` (`text-xs text-ink-faint`), вкладка остаётся; дублирующиеся ключи в наборе не ожидаются, но `key` в React строится как `${index}-${key}`, чтобы не падать.

**Чипы документов:** клик вызывает `onOpenDoc(docId)`; `App` ставит `currentDocId` и закрывает `RunView` (`setActiveRunId(null)`) — иначе документ не виден, главную область занимает прогон. Если `onOpenDoc` не передан, чипы рендерятся как неинтерактивные `span`.

## Стиль и токены

Только токены и примитивы из `docs/ui-style-guide.md`, сырые палитры Tailwind запрещены.

- карточка выхода: контейнер карточки — существующий `sectionShell`; строка выхода — `rounded border border-line bg-surface-muted p-2`;
- поля — примитив `.field`, подписи полей — `text-[11px] text-ink-faint`, как в `Meta`;
- заголовок карточки — `text-[11px] uppercase tracking-wide text-ink-faint`, `statusRow` — `text-[10px] text-ink-faint`;
- бейдж `основной` — `badge-neutral`;
- «Добавить выход» — `btn-secondary`; «Сохранить outputs» — `btn-primary` через существующий `saveBtn`; `↑ ↓ ✕` — `btn-ghost` с `aria-label`;
- вкладки прогона — тот же пилюльный стиль, что у радиогрупп `Kind` / `Вход` в `ArtifactsPanel`: `rounded px-2 py-1 text-[11px]`, активная `bg-brand text-white`, неактивная `bg-surface-muted text-ink-muted hover:bg-surface-hover`;
- плашка «Создано N документов» — `border border-success-line bg-success-soft px-2 py-1 text-xs text-success-ink` (та же, что сегодня у одного документа);
- чипы документов — примитив `.chip`, primary — `.chip-brand`; интерактивный чип добавляет `hover:border-accent-line hover:bg-accent-soft hover:text-accent-ink focus-visible:ring-2 focus-visible:ring-accent` по образцу чипов в `Chat.tsx`;
- бейдж выходов в списке скиллов — `badge-neutral`;
- ошибки — `text-danger-ink` для строчных сообщений, блок ошибки — `border-danger-line bg-danger-soft text-danger-ink`;
- никаких новых зависимостей и никаких новых CSS-переменных: React 19 + Vite + TS + Tailwind v3 по ADR-0011.

## Доступность (a11y)

- карточка: `sectionShell('outputs', invalid, …)` даёт `aria-invalid` и `aria-describedby` на проблемных полях; каждое поле связано с сообщением своей строки через `aria-describedby`;
- поля строк подписаны видимыми `label` (`ключ`, `описание`); кнопки строк — иконки с `aria-label`: `Поднять выход {key}`, `Опустить выход {key}`, `Удалить выход {key}`;
- бейдж `основной` — текст, а не только цвет; порядок в DOM совпадает с визуальным;
- вкладки прогона: контейнер `role="tablist"` + `aria-label="Результаты прогона"`; вкладка `role="tab"`, `id="run-tab-{key}"`, `aria-selected`, `aria-controls="run-panel-{key}"`; панель `role="tabpanel"`, `id="run-panel-{key}"`, `aria-labelledby="run-tab-{key}"`, `tabIndex={0}` — чтобы длинный результат можно было скроллить с клавиатуры;
- плашка «Создано N документов» — `role="status"` + `aria-live="polite"`, чтобы результат сохранения объявлялся;
- disabled-состояния оформляются заливкой и `cursor-not-allowed`, а не прозрачностью — контраст остаётся читаемым;
- фокус везде виден: `focus-visible:ring-2 ring-brand` (у чипов — `ring-accent`, как в композере).

## Контракты данных

Всё уже определено соседними шагами (CATALOG-144 / 145 / 147); UI только читает.

**Черновик:** артефакт `outputs`, контент — JSON `[{"key": "...", "description": "..."}]`, порядок значим, `outputs[0]` — primary. Чтение через существующий `GET /sessions/{id}/artifacts`, запись через `PATCH /sessions/{id}/artifacts/outputs` (`patchArtifact(sessionId, 'outputs', content)`), ответ — `SessionArtifact` с `is_valid` / `error`.

**Клиентские типы:**

- `OutputDraft { key: string; description: string }`; `parseOutputsArtifact(content): { outputs: OutputDraft[]; parseError: string | null }` — по образцу `parseStepsArtifact`: пустой контент → пустой список без ошибки, не-массив → `parseError`;
- `RunArtifact { key: string; description?: string | null; text: string }`;
- `normalizeRunArtifacts(raw: unknown): RunArtifact[]` — единая точка разбора набора и для `RunOut`, и для кадра `finish`. Принимает массив объектов `{key, text, description?}` **и** объект-словарь `key → text` (порядок вставки сохраняется, `description` тогда отсутствует), всё остальное → `[]`. Так UI не ломается ни на прогонах без новых полей, ни на той форме, которую в итоге зафиксирует CATALOG-145;
- `RunOut` += `output_doc_ids: string[] | null`, `result_artifacts: unknown` (нормализуется), старые `output_doc_id` / `result_text` на месте;
- `SkillOut` += `outputs_count?: number` — опциональное поле; при его отсутствии бейдж просто не рисуется, клиентского парсинга `config_json` не делаем;
- кадр `finish` += `output_doc_ids?: string[] | null` и набор артефактов (те же опциональные поля).

**`useRunStream`:** `outputDocIds: string[]` (пусто, если поля нет), `artifacts: RunArtifact[]`. Деградация обязательна: если новых полей в кадре нет, `artifacts` остаётся пустым, `resultText` / `outputDocId` работают как сегодня. Если `artifacts` пришёл, `resultText` = текст primary (совместимость с экспортом и с N = 1).

## Критерии визуальной приёмки

- [ ] Карточка `Outputs` стоит между `Meta` и `Steps`, видна при любом `kind` и при пустом списке показывает текст про один результат + кнопку «Добавить выход».
- [ ] Строки показывают `key` и `description`, первая помечена текстовым бейджем `основной`; перестановка строки вверх переносит бейдж.
- [ ] Ошибка валидации (клиентская и серверная) видна на карточке: красная рамка карточки, сообщение под проблемной строкой или под кнопкой; невалидный черновик не уходит в PATCH.
- [ ] Во время генерации (`streaming`) все поля и кнопки карточки задизейблены заливкой `surface-muted` + `cursor-not-allowed`.
- [ ] Прогон с двумя выходами показывает полосу вкладок с подписями из описаний, primary выбран по умолчанию, переключение работает мышью и стрелками, у вкладок есть `role="tab"` / `aria-selected` / `aria-controls`.
- [ ] При N > 1 кнопка называется «Сохранить как новые документы»; после успеха она исчезает, вместо неё — `role="status"` плашка «Создано N документов» и чипы всех документов; primary-чип визуально отличается.
- [ ] Клик по чипу открывает документ (прогон закрывается), у чипа видимое кольцо фокуса.
- [ ] Прогон с одним выходом и прогон без новых полей выглядят точно как до изменений: нет вкладок, нет чипов, подпись кнопки — «Сохранить как новый документ».
- [ ] В списке скиллов бейдж `N вых.` появляется только при N > 1, не ломает высоту строки и не съедает имя скилла.
- [ ] В сводке черновика строка «Выходы» появляется только когда артефакт существует; счётчик «Готово X из Y» у черновиков без выходов не меняется.
