# CATALOG-90 — Дизайн UI

- **Источник:** `docs/plan/first-shift/01-CATALOG-90-ui-session-docs-disappear.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Экран — рабочая область чата (`Chat.tsx`), блок «Документы в сессии» над композером.

Основной сценарий (тот, что сейчас сломан):

1. Пользователь жмёт «Новый чат» — сессии ещё нет (`sessionId === null`), блока «Документы в сессии» нет (список пуст).
2. Через «+ документ» выбирает один или несколько документов — в композере появляются brand-чипы выбора.
3. Печатает текст и жмёт «Отправить» (или Enter).
4. Композер очищается (текст + чипы выбора), затем **одним кадром** появляются: пузырь пользовательского сообщения в ленте и блок «Документы в сессии» с теми же документами. Пустого промежутка, где документ не виден нигде, быть не должно — только общая задержка на создание сессии, одинаковая для сообщения и для чипов.
5. Дальше идёт ответ ассистента; список документов в сессии не мигает и не обнуляется — авторитетные источники (`session_docs`, GET на `finish`) приносят тот же состав.

Побочный сценарий: часть выбранных id бэкенд не нашёл (`skipped_doc_ids` в ответе `POST /sessions`). Тогда эти документы **не** попадают в блок сессии, а пользователь видит одну строку-нотис вверху приложения с их названиями.

Остальные сценарии, которые дизайн обязан не сломать: второе сообщение с документами в той же сессии, F5 в середине и после хода, переключение сессий, ручное удаление документа из сессии.

## Дерево компонентов и файлы

Новых компонентов нет — меняется только состав props/аргументов и одна ветка рендера. Никаких новых зависимостей UI (vitest/jsdom/testing-library из плана — тестовая оснастка, не часть дизайна).

- `frontend/src/components/Chat.tsx`
  - `onSend: (text: string, docIds?: string[], docs?: DocumentOut[]) => void` — третьим аргументом уходит снимок `selectedDocs` (полные `DocumentOut`, уже вычисляются в компоненте) **до** `setSelectedDocIds([])`.
  - Блок «Документы в сессии» — без структурных изменений, только a11y-атрибут (см. ниже).
  - `onRepeat={onSend}` в `ChatMessage` и кнопки быстрых ответов вызывают `onSend(text)` без документов — сигнатура должна остаться совместимой (2-й и 3-й аргументы опциональны).
- `frontend/src/App.tsx`
  - `ensureSession(docIds?: string[])` → возвращает `{ id: string; skippedDocIds: string[] }`; для уже существующей сессии `skippedDocIds` пуст.
  - `handleSend(text, docIds, docs)`: создаёт сессию с `doc_ids`, отфильтровывает пропущенные id из `docIds` и `docs`, показывает нотис при непустом `skipped_doc_ids`, затем `planner.send(text, filteredIds, filteredDocs)`.
  - Нотис — существующий `notice` / `.catalog-notice`, новых контейнеров не заводить.
- `frontend/src/hooks/usePlannerSession.ts`
  - `send(text: string, docIds?: string[], docs?: DocumentOut[])` — в том же вызове, что и добавление пользовательского сообщения, мержит `docs` в `sessionDocuments`.
  - Публичный тип `UsePlannerSessionResult.send` обновляется соответственно.
- `frontend/src/api.ts`
  - `createSession(docIds?: string[])` — JSON-body `{ "doc_ids": [...] }` только когда массив непустой; `SessionCreated` получает поле `skipped_doc_ids: string[]`.
- `frontend/src/ws.ts` — **не меняется**: кадр `user` по-прежнему несёт `doc_ids`, повторный attach на бэкенде идемпотентен.

## Layout и состояния

Расположение и разметка блока «Документы в сессии» не меняются: `section` в верхней части `.catalog-composer`, заголовок `Документы в сессии`, подпись «Агент видит только эти документы», ниже — `ul` с чипами. Условие показа тоже прежнее: блок рендерится только при непустом списке.

Состояния:

- **Пусто** — блока нет вовсе. Empty-state с текстом не добавлять: композер и так объясняет, как добавить документ.
- **Оптимистичное** (сразу после отправки, до авторитетного списка) — чипы визуально **неотличимы** от подтверждённых: тот же `.chip`, тот же порядок «сначала уже бывшие в сессии, затем новые в порядке выбора». Отдельного «pending»-вида, спиннера или полупрозрачности нет: любое отличие потребовало бы нового флага (план это прямо запрещает) и давало бы моргание в момент прихода `session_docs`.
- **Гидрация/refetch** — скелетона и спиннера нет; на экране остаётся текущий список, авторитетный ответ заменяет его целиком и мгновенно.
- **Успех** — состав после ответа сервера совпадает с оптимистичным; визуальных переходов пользователь не замечает.
- **Частичный отказ (`skipped_doc_ids`)** — пропущенные документы в блок не попадают; сверху появляется строка `.catalog-notice`:
  - один документ: `Документ «<title>» не добавлен в сессию: не найден в воркспейсе.`
  - несколько: `Не добавлены в сессию: «<title>», «<title>» — документы не найдены в воркспейсе.`
  - если названия нет в списке документов — подставлять id.
  - Нотис закрывается штатно, как остальные (следующее действие, меняющее `notice`).
- **Отказ создания сессии** — существующее поведение: нотис с текстом ошибки, сообщение не уходит. Восстановление введённого текста и чипов после ошибки — **вне скоупа шага** (текст теряется и сейчас); не расширять.
- **Стриминг** — кнопки `×` в чипах сессии и в композере, комбобокс и textarea остаются `disabled`, как сейчас.

Один визуальный контракт отдельно: чипы блока сессии и пузырь пользовательского сообщения появляются в **одном** React-коммите (обе записи состояния — в одном вызове `send`). Задержка от нажатия «Отправить» до их появления равна ответу `POST /sessions` и одинакова для обоих; отдельного «висящего» состояния композера для этого не вводить.

## Взаимодействия

- **Отправка только с документами, без текста** — разрешена (текущий `canSubmit`); документы уходят в сессию и появляются в блоке.
- **Повторная отправка с документами в той же сессии** — merge по `id`: уже присутствующие документы не дублируются и не меняют позицию, новые добавляются в конец в порядке выбора.
- **Быстрые ответы / повтор сообщения** (`onSend(text)` без документов) — список документов в сессии не трогают.
- **Удаление чипа в композере до отправки** — на блок сессии не влияет.
- **`×` в блоке сессии** — прежнее оптимистичное удаление через `removeDocument`; удалённый документ не должен «воскресать» поздней гидрацией (существующий бамп поколения сохраняется).
- **Переключение сессии** — блок показывает список выбранной сессии, полученный по HTTP; оптимистичные записи предыдущей сессии не протекают.
- **F5** — состав блока совпадает с тем, что было на экране до перезагрузки.
- **Фокус после отправки** остаётся в textarea; появление блока над композером не должно перехватывать фокус и не должно «прыгать» полосой прокрутки ленты (блок живёт в области композера, лента скроллится независимо).
- **Крайние случаи:** дубли id в выборе схлопываются в один чип; все выбранные id оказались skipped — блок не появляется, показывается только нотис; на существующей сессии бэкенд о пропусках молчит, поэтому оптимистичный чип может быть «лишним» — его снимет ближайший авторитетный `session_docs`, это допустимое самоисправление.

## Стиль и токены

Tailwind v3 + существующие компонентные классы из `index.css`; новых классов, цветов и утилит не вводить.

- Чип документа сессии — `.chip` (`rounded-full border border-line bg-surface-muted px-2.5 py-1 text-xs text-ink-muted`), внутри `.badge-neutral` для `kind` и `truncate` для заголовка.
- Чип выбора в композере — `.chip-brand`; контраст «выбрано, но ещё не отправлено» vs «в сессии» держится именно на этой паре, дополнительных оттенков не добавлять.
- Заголовок секции — `text-[11px] uppercase tracking-wide text-ink-faint`, подпись — `text-[11px] text-ink-faint`, отступы `mb-2` / `mb-1`, сетка чипов — `flex flex-wrap gap-1.5`.
- Кнопка `×` — существующая связка `text-ink-faint hover:text-ink focus-visible:ring-2 focus-visible:ring-brand disabled:...`.
- Нотис — существующий `.catalog-notice px-5 py-2 text-xs`, без иконок и без нового цвета: это информирующее сообщение того же класса, что и остальные.

## Доступность (a11y)

- Секция сохраняет `aria-label="Документы в сессии"`, список — `role="list"`, элементы — `role="listitem"`.
- Список документов сессии получает `aria-live="polite"`: появление документов после отправки и их удаление должны объявляться скринридером, поскольку блок меняется без действия фокуса.
- Контейнер нотиса получает `role="status"` и `aria-live="polite"` — сообщение о непривязанных документах появляется вне фокуса и иначе останется незамеченным. Это не `alert`: сценарий не блокирующий.
- Кнопки удаления сохраняют осмысленный `aria-label` (`Убрать <title> из сессии`), достижимы с клавиатуры, видимый фокус — `focus-visible:ring-brand`.
- Отключённые во время стриминга элементы остаются `disabled` (а не просто визуально приглушёнными), чтобы табом их нельзя было активировать.
- Контраст: используются только существующие токены `--ink-*` / `--surface-*` / `--notice-*`, новых сочетаний не вводится.

## Контракты данных

- `POST /sessions` — опциональный body `{ "doc_ids": string[] }`; ответ `{ "id": string, "skipped_doc_ids": string[] }` (парный code-шаг, ветка В). Документы привязаны до возврата ответа, поэтому первый `GET /sessions/{id}/documents` уже видит их.
- `createSession(docIds?: string[]): Promise<SessionCreated>`; body отправляется только при непустом массиве.
- WS-кадр `{"type":"user","content":...,"doc_ids":[...]}` — без изменений; `session_docs` остаётся авторитетным источником и заменяет список целиком.
- `Chat.onSend(text: string, docIds?: string[], docs?: DocumentOut[])`.
- `usePlannerSession.send(text: string, docIds?: string[], docs?: DocumentOut[])` — `docs` используются только для оптимистичного показа; порядок и состав списка после прихода `session_docs` / GET определяет сервер.
- Тип `DocumentOut` = `{ id, title, kind, created_at }` — блок рендерит `kind` и `title`.
- Приоритет источников для `sessionDocuments`: оптимистичный merge → любой авторитетный ответ (`session_docs`, GET на `finish`, гидрация при смене сессии) заменяет список целиком; ручное удаление (`removeDocument`) не откатывается поздней гидрацией.

## Критерии визуальной приёмки

- [ ] Новый чат → «+ документ» → текст → «Отправить»: блок «Документы в сессии» с выбранными документами и пузырь пользовательского сообщения появляются одновременно, без промежуточного кадра, где документ не виден ни в композере, ни в блоке.
- [ ] Чипы оптимистичного списка визуально идентичны подтверждённым (`.chip` + `.badge-neutral` + `truncate`); при приходе `session_docs` список не мигает и не меняет порядок.
- [ ] Чипы выбора в композере (`.chip-brand`) очищаются в момент отправки и не дублируют блок сессии.
- [ ] Пустой список — блока нет; никакого empty-state текста или пустой рамки не появилось.
- [ ] Второе сообщение с документами в той же сессии: дублей чипов нет, порядок прежних документов сохранён, новые добавлены в конец.
- [ ] `skipped_doc_ids` непуст: пропущенные документы в блоке отсутствуют, вверху показана строка `.catalog-notice` с их названиями по заданной формулировке.
- [ ] Контейнер нотиса имеет `role="status"` и `aria-live="polite"`; список документов сессии — `aria-live="polite"`.
- [ ] Во время стриминга кнопки `×` в блоке и в композере, комбобокс и textarea отключены; фокус после отправки остаётся в textarea.
- [ ] `×` в блоке сессии убирает документ сразу, и он не возвращается после завершения хода и после F5.
- [ ] Переключение сессий показывает список соответствующей сессии; документы предыдущей сессии не протекают.
- [ ] F5 в середине хода и после него даёт тот же состав блока, что был на экране.
- [ ] Новых CSS-классов, цветов и UI-зависимостей не добавлено; разметка блока и композера отличается от текущей только описанными изменениями.
