# CATALOG-103 — Дизайн UI

- **Источник:** `docs/plan/first-shift/06-CATALOG-103-ui-skills-card-actions.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Сейчас у скила два конкурирующих набора действий: призрачные иконки, проявляющиеся по hover прямо в строке списка, и текстовые кнопки с kebab-меню в раскрытой панели. Пользователь не понимает, какой набор «главный», строка мерцает при проведении мышью, а удаление спрятано за два клика в `⋯`.

Целевой сценарий:

1. Пользователь просматривает список скилов. Строка — только информация: индикатор статуса, имя, теги, арность. Наведение курсора **ничего не проявляет**, строка лишь подсвечивается фоном.
2. Клик по строке раскрывает панель скила. В панели, сразу под описанием и мета-данными, — **один ряд из четырёх иконок**: карандаш (переименовать), `</>` (редактировать), коммит, корзина (прижата вправо).
3. Цвет читается раньше глифа: серая — нейтральное действие, синяя — правка содержимого, зелёная — коммит, красная — удаление.
4. Клик по корзине **сразу** открывает существующий inline-confirm «Удалить скил «имя»?» под рядом иконок. Промежуточного меню нет.
5. «Отмена» или Escape возвращают фокус на корзину — пользователь остаётся там, откуда начал.

Ключевая идея: **действие живёт там, где живёт контекст**. Раскрытая панель — единственное место, где скил «активен», значит и весь его набор действий там же. Строка снова становится просто строкой списка.

## Layout и состояния

### Строка скила

Состав после правки (слева направо): индикатор статуса (точка), имя (`flex-1 truncate`), теги, символ арности. Всё, что правее арности, удаляется.

- Класс `group` со строки **снимается**: `group-hover:` / `group-focus-within:` больше не используются ни одним потомком, оставлять его — мусор.
- Геометрия строки не меняется: `h-8`, `px-2`, `gap-2`, `border-l-2`. Освободившиеся ~84px справа забирает `truncate` у имени — имена станут читаться длиннее, это побочный плюс.
- Состояния строки прежние: обычная (`text-ink-muted`, `hover:bg-surface-hover`), выбранная (`border-brand bg-brand-soft text-ink`). Hover больше не меняет ничего, кроме фона.

### Ряд действий в панели

Ряд рендерится в существующем контейнере действий (тот, что с `onBlur` и `onKeyDown={onActionsEscape}`), в ветке «переименование не активно» — то есть форма переименования и ряд иконок **взаимоисключающи**, как и сейчас.

- Контейнер ряда: `flex items-center gap-1.5`. **Без `flex-wrap`** — перенос запрещён по постановке; при 4 × 28px + 3 × 6px = 130px и ширине контента панели ≈ 300px (сайдбар 360px минус паддинги) перенос физически невозможен даже с запасом.
- Порядок в DOM = порядок на экране = порядок табуляции: Переименовать → Редактировать → Коммит → Удалить.
- Корзина отделена `ml-auto`: пустое пространство между зелёной и красной кнопкой — часть защиты от промаха.

| # | Действие | Иконка | Класс | Особенности |
|---|---|---|---|---|
| 1 | Переименовать | `PencilIcon` | `btn-icon-soft` | несёт `renameTriggerRef` (возврат фокуса после Escape из формы) |
| 2 | Редактировать | `CodeIcon` | `btn-icon-soft-brand` | вызывает `onEdit(s.id, s.name)` после `clearRename()` |
| 3 | Коммит | `CommitIcon` | `btn-icon-soft-success` | `disabled={s.status !== 'draft'}`, динамический `title` |
| 4 | Удалить | `TrashIcon` | `btn-icon-soft-danger ml-auto` | несёт `deleteBtnRef`, сразу ставит `confirmOpen` |

### Состояния экрана

| Состояние | Что показываем |
|---|---|
| скилов нет | текст «Скиллов пока нет…» — без изменений |
| поиск ничего не нашёл | «Ничего не найдено» + «Сбросить» — без изменений |
| строка не выбрана | только информация; hover красит фон и **не проявляет ни одной кнопки** |
| строка выбрана | панель + ряд из четырёх иконок |
| открыта форма переименования | ряд иконок скрыт, на его месте поле + «Сохранить» / «Отмена» (существующая разметка) |
| открыт confirm удаления | ряд иконок остаётся на месте, под ним появляется строка confirm; ряд не подменяется и не «прыгает» |
| скил `committed` | коммит-кнопка `disabled` и приглушена, остальные три активны |
| ошибка операции | как сейчас — текст ошибки от `skills.error` над списком; отдельного состояния у ряда нет |

Отдельного loading-состояния у кнопок нет и не вводится: коммит и удаление уже обрабатываются на уровне списка (`skills.error`, перерисовка списка), спиннеров в кнопках в этом срезе не появляется.

## Взаимодействия

- **Переименовать** — открывает существующую форму (`startRename`): ряд иконок заменяется полем ввода с автофокусом. Escape в поле → форма закрывается, фокус возвращается на карандаш (`renameTriggerRef`).
- **Редактировать** — `clearRename()` + `onEdit(...)`, как в текущей панельной кнопке. Открывается модалка настроек скила; поведение не меняется.
- **Коммит** — `void skills.commit(s.id)`. При `status !== 'draft'` кнопка `disabled`, `title` = «Скил уже закоммичен»; активная — `title` = «Коммит». Disabled-кнопка выпадает из таб-порядка нативно; это ожидаемое поведение, дублирующего «объяснения» рядом не добавляем — его несёт `title` и приглушённый вид.
- **Удалить** — один клик: `clearRename()` + `setConfirmOpen(true)`. Промежуточного меню нет. В confirm автофокус уже стоит на красной кнопке «Удалить» (существующий `autoFocus`), то есть подтверждение требует осознанного второго клика или Enter.
- **Отмена / Escape в confirm** — `setConfirmOpen(false)` + фокус на `deleteBtnRef`. Это единственная правка внутри блока confirm; тексты, разметка и классы там не меняются.
- **Escape-каскад** (`escapeCascade`): confirm → фокус на корзину; форма переименования → фокус на карандаш; иначе — снять выбор. Шаг `overflow` удаляется целиком.
- **↑ / ↓ / Enter** в списке работают как раньше; `moveSelection` и `selectSkill` продолжают закрывать confirm и форму переименования, просто без `setOverflowOpen`.
- **Клик вне списка** — снимает выбор и закрывает confirm (существующий `mousedown`-слушатель, минус `setOverflowOpen`).
- **`onBlur` контейнера действий** — упрощается: если фокус ушёл за пределы контейнера, закрываем confirm. Поиск `.catalog-skill-row__actions` по `closest('li')` удаляется вместе с самим блоком — искать больше нечего.
- **Крайние случаи:**
  - Кнопки в панели не должны триггерить выбор строки: они лежат вне строки, `stopPropagation` для них больше не нужен (в удалённом row-блоке он был обязателен).
  - Confirm появляется **под** рядом иконок внутри того же `li`, поэтому раздвигает список вниз и не перекрывает соседние скилы (в отличие от прежнего абсолютного меню kebab с `z-10`).
  - Скил удалён извне (список обновился) — существующий эффект снимает выбор и закрывает confirm.
  - Touch-устройства: правило `@media (hover: none)`, форсившее `opacity: 1` у row-иконок, удаляется — проявлять больше нечего, а действия и так всегда видимы в раскрытой панели.

## Стиль и токены

Вводится семейство залитых icon-кнопок в `@layer components`, рядом с `.btn-icon-ghost`. Утилиты в каждом варианте выписываются полностью (как у `.btn-primary` / `.btn-secondary` / `.btn-icon-*`) — композиция через `@apply` чужого компонентного класса в проекте не используется.

Общий скелет всех четырёх вариантов:

```
inline-flex size-7 shrink-0 items-center justify-center rounded-control border transition-colors
focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand
disabled:cursor-not-allowed disabled:opacity-40  (+ нейтрализация hover в disabled)
```

Палитра вариантов — только токены, ни одного hex в новых классах:

| Класс | Заливка | Иконка | Рамка (rest) | Hover |
|---|---|---|---|---|
| `.btn-icon-soft` | `bg-surface-muted` | `text-ink-muted` | `border-line-strong` | `hover:bg-surface-hover hover:text-ink` |
| `.btn-icon-soft-brand` | `bg-brand-soft` | `text-brand-ink` | `border-line-brand` | `hover:bg-brand hover:border-brand hover:text-white` |
| `.btn-icon-soft-success` | `bg-success-soft` | `text-success-ink` | `border-success-line` | `hover:bg-success hover:border-success hover:text-white` |
| `.btn-icon-soft-danger` | `bg-danger-soft` | `text-danger-ink` | `border-danger-line` | `hover:bg-danger hover:border-danger hover:text-white` |

Обоснования:

- **`size-7` (28px)** — как у `.btn-icon-ghost`; минимальный хит-таргет из постановки. Иконка 16px в боксе 28px даёт 6px внутреннего поля.
- **Отклонение от плана по рамке.** План допускает «рамка `--line` / `--danger-line`» («варианты вроде…»), но серая `--line` (#ebebeb) вокруг цветной заливки читается как грязь и почти не видна на фоне сайдбара `--sidebar` (#f8f8f8). Берём для каждого варианта **его собственный** `*-line`-токен, а для нейтрального — `--line-strong`. Это не новый паттерн: `.chip-brand` уже собран ровно так — `border-line-brand bg-brand-soft text-brand-ink`; brand-вариант icon-кнопки — его квадратная 28px-версия.
- **Hover = заливка становится плотной, иконка белеет.** Это то же «hover насыщеннее», что просит план, но выраженное заливкой, а не рамкой: на 28px-кнопке смена цвета 1px-рамки почти не читается. Плотные состояния совпадают с уже принятыми `.btn-icon-brand` / `.btn-icon-danger` (сплошной фон + белый глиф), так что новый паттерн не появляется. У нейтральной кнопки плотного токена нет — она уходит на `bg-surface-hover` + `text-ink`, ровно как `.btn-secondary`.
- **`active:` не задаётся** — как и у `.btn-icon-ghost`; hover-состояние само по себе достаточно контрастное, отдельный press-стиль в этом срезе не нужен.
- **Disabled — только гашение, без смены hue.** `disabled:opacity-40` (как у `.btn-icon-ghost`), плюс явное подавление hover-правил (`disabled:hover:*` возвращает rest-заливку, рамку и цвет иконки). Переводить disabled-кнопку на `bg-surface-muted`, как делают `.btn-primary`/`.btn-secondary`, **нельзя**: план прямо запрещает менять hue, а выцветшая зелёная кнопка честнее сообщает «это коммит, но он недоступен».
- **Контраст иконки к заливке** (rest): нейтральная ≈ 7.1:1, brand ≈ 6.0:1, success ≈ 5.7:1, danger ≈ 5.9:1. Hover (белый глиф на плотной заливке): brand ≈ 4.2:1, success ≈ 4.8:1, danger ≈ 4.4:1. Все значения выше требуемых 3:1 с запасом.
- **Про `bg-brand-soft` выбранной строки.** Раскрытая панель фон не задаёт и лежит на `--sidebar`, а не на `bg-brand-soft` — заливка `brand-soft` на `brand-soft` не возникает по построению. Но даже в этом гипотетическом случае критерий выполняется: контраст иконки считается к **собственной заливке кнопки**, а внешнюю границу кнопки держит `border-line-brand` (≈2.5:1 к `brand-soft`).
- **Форма иконок.** `CodeIcon` — feather `code`: две шевронные `polyline` (`16 18 22 12 16 6` и `8 6 2 12 8 18`). `TrashIcon` — feather `trash` **без** внутренних вертикальных штрихов: `polyline 3 6 5 6 21 6` + контур корпуса с крышкой. Вариант `trash-2` отклонён: две дополнительные линии при stroke 1.75 в боксе 16px превращаются в кашу.
- Ряд действий не получает ни фона, ни рамки, ни отдельного заголовка: он уже отделён существующим `border-t border-line` контейнера действий.

## Доступность (a11y)

- У каждой из четырёх кнопок есть **и** `aria-label`, **и** `title`, и они не конфликтуют по смыслу:
  - «Переименовать» / «Переименовать»
  - «Редактировать скил» / «Редактировать скил»
  - «Коммит» / динамический `title` («Коммит» либо «Скил уже закоммичен»)
  - «Удалить скил» / «Удалить скил»
- Имя корзины намеренно отличается от кнопки «Удалить» внутри confirm: два элемента с одинаковым доступным именем в одной области — ловушка для скринридера.
- Иконки остаются `aria-hidden` + `focusable={false}` (из `iconBase`), поэтому доступное имя кнопки — ровно `aria-label`.
- Корзина получает `aria-expanded={confirmOpen}`: она работает как disclosure для inline-confirm.
- Фокус: `focus-visible:ring-2 ring-brand` у всех четырёх (как у остальных кнопок проекта). Кольцо описывает квадрат 28×28.
- Возврат фокуса: Escape/«Отмена» из confirm → корзина (`deleteBtnRef`); Escape/«Отмена» из переименования → карандаш (`renameTriggerRef`). Фокус никогда не «проваливается» на `body`.
- Таб-порядок внутри панели: карандаш → код → коммит (если активен) → корзина → дальше существующие контролы запуска. `tabIndex={-1}`-костыли, нужные скрытым row-иконкам, исчезают вместе с ними.
- Клавиатурная навигация по списку (`↑`, `↓`, `Enter`, `Escape` на `ul[role=listbox]`) не меняется.
- Удаление hover-only иконок из строки — само по себе плюс к доступности: действия перестают быть недостижимыми для тач-устройств и клавиатуры без hover.
