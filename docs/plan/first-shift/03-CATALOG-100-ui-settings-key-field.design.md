# CATALOG-100 — Дизайн UI

- **Источник:** `docs/plan/first-shift/03-CATALOG-100-ui-settings-key-field.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Экран — модалка «Настройки» (`SettingsPanel`), список провайдеров. Каждый провайдер — карточка `<li>` с именем, бейджем статуса и, если ключа нет, формой ввода ключа.

Целевой контракт: **в карточке провайдера без ключа поле ввода видно сразу** — до hover, до фокуса, без клика. Пользователь понимает, куда вставлять ключ, по трём одновременным признакам: белая заливка поля на серой подложке карточки, отчётливая рамка и плейсхолдер «Вставьте API-ключ».

Сценарии:

1. **Провайдер без ключа.** Пользователь открывает «Настройки». Видит карточку `z.ai` с бейджем «нет ключа», под ней — прямоугольник поля с плейсхолдером и кнопку «Сохранить» (неактивную). Вставляет ключ → кнопка становится активной → «Сохранить» → «Сохранение…» → бейдж меняется на «подключён», форма исчезает.
2. **Замена ключа.** Пользователь жмёт «Заменить ключ» у подключённого провайдера — раскрывается та же форма с тем же плейсхолдером и кнопкой «Отмена». Фокус ставится в поле автоматически. Escape сворачивает форму, фокус возвращается на «Заменить ключ».
3. **Ключ из окружения.** Карточка с бейджем «через окружение»: форма показана, но поле заблокировано и выглядит выцветшим; под ним подсказка «Ключ задан через переменную окружения…». Пользователь видит, что вводить бессмысленно, ещё до попытки клика.
4. **Неизвестный провайдер** (нет в `KEY_FIELDS`): то же заблокированное поле + подсказка «Этот провайдер пока нельзя настроить через интерфейс».
5. **Ошибка сохранения.** Под формой красная строка ошибки; поле остаётся видимым и активным, введённое значение не теряется.

Соседние экраны с `.field` (`SetupKeyScreen`, `SkillSettingsModal`, комбобоксы, композер) сценарий не затрагивает — там поле лежит на `surface` и контраст уже есть.

## Layout и состояния

Геометрия карточки, отступы, порядок элементов и ширины не меняются. Меняется только «читаемость» поля как элемента управления.

### Целевой набор классов инпута

```
field min-w-0 flex-1 border border-line-strong bg-surface disabled:opacity-60
```

Разбор, почему именно так:

| Класс | Зачем |
| --- | --- |
| `field` | базовые размеры, типографика, `::placeholder`, фокус-ринг, `disabled:` — берём как есть |
| `min-w-0 flex-1` | уже было, поле занимает свободную ширину строки |
| `bg-surface` | перебивает `bg-surface-muted` из `.field`: утилита той же специфичности (`0,1,0`) лежит в слое `utilities`, ниже слоя `components` → выигрывает. Белая заливка отделяет поле от карточки |
| `border border-line-strong` | несущий признак видимости: `#c9c9c9` читается и на белой заливке, и на подложке `#f5f6f6`. `border-line` (`#ebebeb`) на карточке `#f5f6f6` практически не виден — не использовать |
| `disabled:opacity-60` | локальное отличие заблокированного состояния (см. ниже) |

Явный `disabled:bg-surface-muted` **не добавлять**: `.field` уже даёт `.field:disabled { background: surface-muted }` со специфичностью `0,2,0`, что выше утилиты `bg-surface` (`0,1,0`). Заблокированное поле само возвращается к серой заливке.

### Состояния поля

| Состояние | Условие в коде | Вид |
| --- | --- | --- |
| Активное пустое | `showForm && !busy && !formLocked`, `value === ''` | белая заливка, рамка `line-strong`, плейсхолдер «Вставьте API-ключ» (`ink-placeholder`), кнопка «Сохранить» неактивна |
| Активное заполненное | то же, `value !== ''` | точки пароля цветом `ink`, кнопка «Сохранить» активна |
| Фокус | `focus-visible` | к рамке добавляется внешний ring 2px `brand` из `.field`; рамка `line-strong` остаётся под рингом |
| Заблокированное | `busy \|\| formLocked` | серая заливка `surface-muted` (из `.field`), текст/плейсхолдер выцветшие через `opacity-60`, рамка приглушена той же прозрачностью, `cursor-not-allowed` |
| Сохранение | `saving` | поле в заблокированном виде, `aria-busy` на форме, кнопка «Сохранение…» |
| Ошибка | `error !== null` | поле активно и сохраняет введённое значение; красная строка ошибки под формой (без изменения стилей поля — рамку в `danger` **не** красим, это вне скоупа шага) |
| Формы нет | `connected && known && !replacing` | вместо формы кнопка «Заменить ключ» — как сейчас |

Отличие активного от заблокированного держится на трёх сигналах сразу: заливка (белая ↔ серая), общая прозрачность (`100% ↔ 60%`), курсор. Пары «заливка + курсор» недостаточно: пустое активное и пустое заблокированное поле различались бы только фоном `#ffffff` vs `#f5f6f6` — глазом это не читается, поэтому `disabled:opacity-60` обязателен. Приём не новый для проекта: `.btn-icon-ghost` уже гасит disabled через `disabled:opacity-40`.

### Выравнивание строки формы

Рамка добавляет инпуту 2px высоты (16px строка + 8px паддинги + 2px рамка = 26px против 24px у кнопок `.btn-*`). При `items-start` кнопки «Сохранить»/«Отмена» повисают на 2px выше нижнего края поля. Поэтому строка формы переводится на `items-center` — при этом сдвиг раскладывается симметрично и визуально незаметен. `hint` и `error` лежат вне этой flex-строки, на них смена не влияет.

## Взаимодействия

Поведенческий контракт шага — **нулевой**: ни один обработчик не меняется. Проверяемые инварианты после правки:

- **Ввод** — `onValueChange` на каждый символ; `canSubmit = trimmed.length > 0 && !busy && !formLocked` управляет кнопкой «Сохранить», как сейчас.
- **Сабмит** — Enter в поле и клик по «Сохранить» дают один и тот же `handleSubmit` с `preventDefault`; при `!canSubmit` — no-op.
- **«Заменить ключ»** — раскрывает форму, `useEffect` ставит фокус в инпут (`inputRefs`). Фокус-ринг должен читаться поверх новой рамки.
- **«Отмена»** — сворачивает форму, чистит значение и ошибку, возвращает фокус на «Заменить ключ» через `pendingFocusId`.
- **Escape** — при раскрытой замене сворачивает её (не закрывая модалку), иначе закрывает модалку; при `busy` игнорируется.
- **Плейсхолдер** — один и тот же текст «Вставьте API-ключ» во всех состояниях, включая замену ключа и заблокированное поле. Вариаций («Вставьте новый ключ» и т.п.) не вводить: ТЗ фиксирует одну формулировку, а роль поля объясняют бейдж и подсказка.
- **Крайние случаи:** длинный ключ — поле не растёт, текст скроллится внутри (`min-w-0 flex-1`); узкая модалка (`max-w-md`) — кнопки не выдавливают поле в ноль; несколько провайдеров в списке — прокрутка `<ul>` не меняется; провайдер с ошибкой и подсказкой одновременно — обе строки под формой, поле не смещается.

## Стиль и токены

Tailwind v3 + существующие CSS-переменные. Новых токенов, цветов, утилит и правил в `index.css` не вводить.

- Палитра правки: `bg-surface` (`#ffffff`), `border-line-strong` (`#c9c9c9`), заливка disabled `surface-muted` (`#f5f6f6`) — всё уже в `tailwind.config.cjs`.
- Скругление поля остаётся `rounded` из `.field` (4px), несмотря на `rounded-control` (8px) у соседних кнопок. Унификация радиусов — вне скоупа шага.
- Подложка карточки остаётся `bg-surface-muted`: план допускает оба варианта, но перекраска `<li>` в белый утащила бы за собой бейджи, вложенную кнопку «Заменить ключ» и вид всего списка. Правка на инпуте локальнее и не задевает соседние состояния карточки.
- `border-line-strong` вместо `border-line`: `#ebebeb` на `#f5f6f6` даёт контур на грани различимости, ради которого весь шаг и затевался. `#c9c9c9` — самый тёмный нейтральный line-токен, уже используется в проекте (`DocumentList`, dropzone).
- Отклонённая альтернатива — `ring-1 ring-inset ring-line-strong` вместо рамки (не меняет высоту, не требует правки выравнивания). Отклонена: `.field` использует ring под фокус (`focus-visible:ring-2 ring-brand`), статический inset-ring конфликтует с ним по семантике и делает фокус-ринг внутренним, ломая единообразие с остальными полями приложения.

## Доступность (a11y)

- `<label className="sr-only">API-ключ {provider.name}</label>` остаётся — плейсхолдер добавляется **в дополнение** к метке, а не вместо неё.
- `aria-describedby` (`hintId` / `errorId`), `role="alert"` у ошибки, `aria-busy` у формы, sr-only `role="status"` панели — без изменений.
- Порядок табуляции не меняется: поле → «Сохранить» → «Отмена». Заблокированное поле, как и сейчас, из таб-порядка выпадает (нативный `disabled`) — существующее поведение, менять в этом шаге не нужно.
- Фокус-ринг: внешний `ring-2 ring-brand` из `.field` остаётся видимым — рамка `line-strong` под ним не перекрывает ринг и не сливается с ним по цвету.
- Контраст: текст `ink` (`#292c31`) и плейсхолдер `ink-placeholder` (`#6b7075`) на белой заливке контрастнее, чем было на `surface-muted` — регресса по тексту нет. Граница поля (`#c9c9c9` к `#f5f6f6`) остаётся ниже порога 3:1 для нетекстовых элементов, поэтому видимость поля обеспечивается связкой «рамка + белая заливка + видимый плейсхолдер», а не рамкой в одиночку. Вводить новый более тёмный line-токен ради формального 3:1 в этом шаге не нужно — это изменило бы палитру всего приложения.
- `opacity-60` у disabled применяется к элементу, у которого нет интерактивности и собственного текстового содержимого кроме плейсхолдера — потери читаемости значимой информации нет; смысл блокировки дублируется текстовой подсказкой под полем.

## Критерии визуальной приёмки

- [ ] Провайдер без ключа: поле различимо сразу при открытии «Настроек» — белая заливка + рамка `border-line-strong` на серой карточке, без hover и без фокуса.
- [ ] Плейсхолдер поля — ровно «Вставьте API-ключ», в том числе в режиме замены ключа.
- [ ] Класс инпута = `field min-w-0 flex-1 border border-line-strong bg-surface disabled:opacity-60`; отдельного `disabled:bg-surface-muted` не добавлено.
- [ ] `<li>` карточки провайдера сохранил `rounded border border-line bg-surface-muted px-3 py-2`.
- [ ] Строка формы использует `items-center`; поле и кнопки «Сохранить»/«Отмена» выровнены по вертикали без ступеньки.
- [ ] Env-managed и неизвестный провайдер: поле визуально выцветшее (серая заливка + пониженная непрозрачность + `cursor-not-allowed`), отличается от активного пустого поля с первого взгляда; подсказка под полем на месте.
- [ ] Во время сохранения поле выглядит как заблокированное, кнопка показывает «Сохранение…», раскладка карточки не прыгает.
- [ ] Фокус в поле даёт видимый brand-ринг поверх рамки; ринг не срезан краем карточки.
- [ ] Ошибка сохранения: красная строка под формой, поле остаётся активным и белым, введённое значение сохранено.
- [ ] `SetupKeyScreen`, `SkillSettingsModal`, комбобоксы и композер выглядят как до правки — блок `.field` в `index.css` не изменён ни на символ.
- [ ] Сабмит по Enter и по кнопке, «Отмена», Escape, автофокус при «Заменить ключ», возврат фокуса и `aria-describedby` работают как прежде.
- [ ] Новых CSS-классов, цветовых токенов и зависимостей не добавлено; диф ограничен `ProviderRow` в `SettingsPanel.tsx`.
