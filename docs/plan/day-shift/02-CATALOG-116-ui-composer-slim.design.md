# CATALOG-116 — Дизайн UI

- **Источник:** `docs/plan/day-shift/02-CATALOG-116-ui-composer-slim.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Композер перестаёт быть вертикальной «простынёй» из шести блоков и становится одной картой: полоса вложений сверху → поле ввода → тонкая панель действий (`+`, инструменты, таймаут). Высота карты фиксирована и не зависит от числа документов.

Путь пользователя (новая сессия):

1. Пользователь видит пустой чат, подсказку-заглушку и **одну строку** быстрых ответов над композером.
2. Жмёт `+` в панели действий → всплывает пикер документов (поиск + чекбоксы) над кнопкой.
3. Выбранные документы появляются **карточками в горизонтальной полосе**, приклеенной к верхней кромке композера. Полоса — единственное место, где документ виден.
4. Пишет текст и жмёт «отправить» (или Enter), либо кликает быстрый ответ — в обоих случаях уходит текущий выбор документов (`sendCurrent`), после чего выбор композера обнуляется.
5. Документы, уже вошедшие в сессию, остаются в той же полосе (но как «в сессии», не «к отправке») — их крестик снимает документ с сессии.
6. Скилл собирается кнопкой в **хедере чата**, а не из подвала композера.
7. Иконка инструментов в панели действий присутствует и кликается, но поповер появится в CATALOG-118 — сейчас это слот.

## Layout и состояния

### Хедер чата

- `shrink-0 border-b border-line px-4 py-2`, фон `.catalog-chat__header` (= `var(--header-bg)`, как общий хедер приложения).
- Внутри — `.catalog-chat__content flex items-center gap-2`, чтобы хедер жил в той же колонке 965px, что история и композер.
- Слева `p.min-w-0.flex-1.truncate.text-xs`: без редактирования — `Чат планировщика` (`text-ink-faint`); при `editingSkillName` — `Редактирование: <name>` (`text-brand-ink`).
- Справа `button.btn-secondary.shrink-0`. Подпись: `Подбираю варианты…` → `Собираю скилл…` → `Сохранить изменения` (если `editingSkillName`) → `Создать скилл`. `disabled = buildingSkill || proposingTracks || messages.length === 0`, `aria-busy` на время работы.

### Полоса вложений (ключ к стабильной высоте)

- Рендерится только при `attachmentDocs.length > 0`.
- `ul`: `flex gap-2 overflow-x-auto overscroll-contain rounded-t-card border border-b-0 border-line bg-surface-muted px-2.5 py-2`, без `mb-*` — полоса стыкуется с картой композера, у которой в этом состоянии срезаны верхние радиусы (`.catalog-composer--attached`). Визуально это одна деталь: приглушённая «шапка» + белое поле.
- `li` (карточка): `flex min-w-[9.5rem] max-w-[12rem] shrink-0 items-start gap-2 rounded-lg border bg-surface px-2.5 py-2`.
  - Рамка: `border-line-brand` для pending (ещё не отправленных), `border-line` для документов сессии.
  - Слева `FileTextIcon` в `text-ink-faint` (`mt-0.5`, `aria-hidden`).
  - Центр (`min-w-0 flex-1`): строка 1 — `p.truncate.text-xs.font-medium.text-ink` с `title`; строка 2 — `p.truncate.text-[11px].text-ink-faint` с META.
  - Справа — крестик `×`, `shrink-0`.
- **META** = `d.kind.toUpperCase()` (при пустом `kind` — `FILE`), плюс ` · к отправке` для pending. Размер не показываем: в `DocumentOut` (`id`, `title`, `kind`, `created_at`) поля размера нет, а тянуть его — расширение скоупа на backend. Формат `KIND · <суффикс>` из плана сохранён, слот «размер» займёт размер, когда API его отдаст.
- Ровно одна строка карточек, скролл по X, обе строки текста `truncate` → высота полосы одинакова при 1 и при 10 документах; при 0 полосы нет вовсе.

### Быстрые ответы

- `mb-2 flex gap-2 overflow-x-auto overscroll-contain pb-0.5`, каждый чип `chip shrink-0` (без `flex-wrap`, без обрезки списка — длинный список уезжает в горизонтальный скролл).
- Источник: `messages.length === 0` → `STARTER_SUGGESTIONS`, иначе `suggestions`; при `streaming` — пусто.
- `pb-0.5` — чтобы фокусное кольцо чипа не подрезалось скролл-контейнером.

### Карта композера

- `.catalog-composer` (рамка `--line`, радиус 20px, `shadow-card`) + модификатор `--attached`, когда есть вложения.
- Ряд ввода: `flex items-end gap-2`; `textarea.field.max-h-40.flex-1.resize-none` с авто-ростом до 160px; справа `btn-icon-brand` (↑) либо `btn-icon-danger` (■) при `streaming`.
- Панель действий: `mt-2 flex items-center gap-1.5`.
  - `+` — триггер пикера документов, `btn-icon-ghost`.
  - Иконка инструментов — `btn-icon-ghost` + бейдж-счётчик.
  - `Timeout: Ns · изменить` — `ml-auto text-[11px] text-ink-faint`, только при `sessionId` (перенос из подвала без изменения поведения).
- `buildError` — внутри карты, `mt-2 rounded-md border border-danger-line bg-danger-soft px-3 py-2 text-xs text-danger-ink`, с крестиком и опциональной ссылкой «Увеличить таймаут…».

### Матрица состояний

| Состояние | Что видно |
|-----------|-----------|
| empty (`messages.length === 0`) | Подсказка по центру истории, стартовые быстрые ответы, «Создать скилл» disabled |
| нет документов | Полосы вложений нет; у карты композера все четыре радиуса круглые |
| pending-документы | Карточки с `border-line-brand` и META `… · к отправке` |
| документы сессии | Карточки с `border-line`, META без суффикса |
| streaming | Быстрые ответы скрыты; textarea, `+`, инструменты и все крестики disabled; кнопка отправки заменена на стоп (`disabled` при `cancelling`) |
| closed / reconnecting | Строка статуса + «Переподключить» в истории (без изменений) |
| error (WS) | `Ошибка: …` в истории, `text-danger-ink` |
| buildError | Алерт внутри карты композера, `role="alert"` |
| инструменты: 0 прикреплено | Иконка есть, бейдж скрыт |
| инструменты: N > 0 | Бейдж-счётчик поверх иконки |
| нет сессии (`sessionId === null`) | Иконка инструментов disabled, блок таймаута скрыт |

Disabled везде — по style guide: `surface-muted` + `ink-faint` + `cursor-not-allowed` (даёт `.btn-*`/`.field`), у иконочных ghost-кнопок — поведение существующего примитива `.btn-icon-ghost`.

## Взаимодействия

**Отправка (сохранить CATALOG-90).** Единая функция:

- `sendCurrent(text)`: при `streaming` — no-op; при пустом `text` и пустом выборе — no-op; иначе `onSend(text, selectedDocIds.length ? selectedDocIds : undefined, selectedDocs.length ? selectedDocs : undefined)`, затем `setInput('')`, `setSelectedDocIds([])`, закрыть пикер.
- Кнопка отправки и Enter → `sendCurrent(input.trim())`.
- Клик по быстрому ответу → `sendCurrent(s)`: подсказка уносит текущий выбор документов. Второй клик по той же подсказке уходит уже без документов, потому что выбор обнулён первым вызовом.
- `canSubmit = !streaming && (input.trim().length > 0 || selectedDocIds.length > 0)` — отправить можно и «пустой» текст с документами.
- Repeat под сообщением пользователя: `onRepeat={(content) => onSend(content)}` — документы композера не подмешиваются и не сбрасываются.

**Клавиатура ввода (без изменений).** Enter отправляет; Shift/Ctrl/Meta/Alt+Enter — перевод строки; IME (`isComposing` / `keyCode === 229`) не перехватываем.

**Пикер документов.** `+` — это сам триггер `DocumentCombobox` (`multiple`, `placement="top"`, `listClassName="w-64"`, `triggerContent=<PlusIcon />`, `ariaLabel="Добавить документ"`, `disabled={streaming}`), поэтому открытие — **один клик**, а закрытие по Escape и по клику вне уже реализовано в компоненте. Список остаётся открытым при переключении чекбоксов (мультивыбор), выбранные документы сразу появляются в полосе вложений. Триггер — `btn-icon-ghost`, обёртка `relative` для абсолютного списка; список позиционируется вверх (`bottom-full`), чтобы не уезжать за нижнюю кромку окна.

**Удаление вложения.** Крестик pending-карточки убирает id из `selectedDocIds`; крестик карточки сессии зовёт `onRemoveDocument?.(d.id)`. При `streaming` оба disabled.

**Слот инструментов.** Клик → `onOpenTools?.()`. Кнопка отрисована всегда, `disabled = streaming || !sessionId`. В этом шаге поповера нет, поэтому `aria-expanded`/`aria-haspopup` **не** ставим (не заявляем несуществующий диалог) — их добавит CATALOG-118 вместе с `ToolsPopover`. Бейдж: `attachedSkillCount > 0` → `absolute -right-0.5 -top-0.5 flex h-4 min-w-4 items-center justify-center rounded-full bg-brand px-1 text-[10px] font-medium text-white`, `aria-hidden` (счёт продублирован в `aria-label` кнопки).

**Крайние случаи.**

- Смена `sessionId`: сбросить `selectedDocIds` и закрыть пикер.
- Документ выбран в пикере и параллельно попал в сессию → в полосе он показывается один раз, как документ сессии (`attachmentDocs` = документы сессии + `selectedDocIds`, из которых вычтены id, уже вошедшие в сессию). При этом в `onSend` уходит полный `selectedDocIds` — контракт CATALOG-90 не меняем.
- Длинное название документа/подсказки — `truncate` в карточке; чипсы подсказок не переносятся, уезжают в скролл.
- 10+ документов — полоса скроллится по X, высота композера та же.
- Одновременно вложения и `buildError` — карта растёт только на высоту алерта, полоса не двигается.
- `documents` пуст → в списке пикера «нет совпадений» (поведение `DocumentCombobox`).

## Стиль и токены

Только семантические утилиты из `docs/ui-style-guide.md`, сырые палитры Tailwind не используем.

- Поверхности: `bg-surface` (карточки вложений, карта композера), `bg-surface-muted` (полоса вложений), `hover:bg-surface-hover`.
- Рамки: `border-line` (полоса, карточки сессии, разделитель хедера), `border-line-brand` (pending-карточки), `border-danger-line` (алерт).
- Текст: `text-ink` (название документа), `text-ink-muted` (иконочные кнопки), `text-ink-faint` (META, таймаут, подпись хедера), `text-brand-ink` (режим редактирования), `text-danger-ink` (алерт).
- Акцент: `bg-brand` + `text-white` (бейдж счётчика), `.btn-icon-brand` (отправить), `.btn-icon-danger` (стоп).
- Примитивы: `.btn-secondary` (создать скилл, переподключить), `.btn-icon-ghost` (`+`, инструменты), `.field` (textarea, поиск в пикере), `.chip` (быстрые ответы), `rounded-card`/`rounded-t-card`, `shadow-card`.
- Типографика: `text-sm` — ввод; `text-xs` — названия, кнопки, хедер; `text-[11px]` — META и таймаут; `text-[10px]` — бейдж. Ритм отступов: `gap-2` между карточками и в ряде ввода, `gap-1.5` в панели действий, `mt-2`/`mb-2` между блоками, `px-2.5 py-2` внутри карточек.
- Ширина контента: `.catalog-chat__content` (965px, центрирование) — общая для хедера, истории и композерной группы, поэтому полоса вложений и карта совпадают по краям.
- Новых CSS-переменных не вводим; из `index.css` используем только существующий `--header-bg`.

## Доступность (a11y)

- Хедер: обычный `p` (не заголовок), чтобы не ломать структуру заголовков; кнопка скилла получает `aria-busy` во время сборки.
- Полоса вложений: `ul[role="list"]` с `aria-label="Документы в сессии"` и `aria-live="polite"` — добавление/удаление документа озвучивается; `li[role="listitem"]`.
- Крестик карточки: `aria-label="Убрать <title>"`; иконка типа — `aria-hidden`.
- `+`: доступное имя «Добавить документ»; `role="combobox"`, `aria-expanded`, `aria-controls` приходят из `DocumentCombobox`; Escape закрывает список и возвращает фокус на триггер.
- Инструменты: `aria-label` = `Инструменты` при нуле и `Инструменты, включено N` при `N > 0`; `title="Инструменты"`; бейдж `aria-hidden`.
- Быстрые ответы: контейнер `role="group"` + `aria-label="Быстрые ответы"`; фокус ходит по чипам стрелками/Tab, скролл-контейнер не отрезает кольцо (`pb-0.5`).
- Фокус: у всех интерактивных элементов `focus-visible:ring-2 ring-brand` (в примитивах уже есть); в ad-hoc крестиках — прописать явно.
- Порядок табуляции сверху вниз: хедер → регион истории (`tabIndex=0`) → быстрые ответы → карточки вложений → textarea → отправить → `+` → инструменты → «изменить» таймаут.
- Контраст: META и таймаут на `--ink-faint` (#5f6368) поверх `--surface`/`--surface-muted` — ≥ 4.5:1; белый бейдж на `--brand` — ≥ 4.5:1.
- Информация о состоянии документа передаётся не только рамкой: pending имеет текстовый суффикс «к отправке».
- `prefers-reduced-motion` учитывать не нужно: анимаций в шаге нет (только `transition-colors` из примитивов).

## Контракты данных

- `DocumentOut` (`frontend/src/api.ts`): `{ id, title, kind, created_at }` — размера нет, отсюда META = `KIND` (+ суффикс pending).
- Пропсы `Chat` не меняются, кроме двух опциональных для слота:
  - `attachedSkillCount?: number` (по умолчанию `0`) — значение бейджа;
  - `onOpenTools?: () => void` — обработчик клика.
  Именно эти имена ждёт CATALOG-118 (`docs/plan/day-shift/04-CATALOG-118-ui-tools-popover.md`), поэтому переименование недопустимо.
- `onSend(text, docIds?, docs?)` — сигнатура и семантика без изменений (CATALOG-90).
- Новых API/WS-вызовов шаг не добавляет; данные вложений — `documents` (пикер) и `sessionDocuments` (сессия).
