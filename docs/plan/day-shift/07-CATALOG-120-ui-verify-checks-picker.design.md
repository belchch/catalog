# CATALOG-120 — Дизайн UI

- **Источник:** `docs/plan/day-shift/07-CATALOG-120-ui-verify-checks-picker.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Заменить текстовое поле `verify_checks` в секции Meta панели артефактов на понятный выбор проверок: пользователь видит, какие проверки уже стоят (в том числе те, что предложила модель), и правит их руками — добавляет стандартные, добавляет свои AI-проверки, создаёт новую и прогоняет её на примере до сохранения.

Сценарий:

1. В секции **Meta** вместо инпута — строка «Проверки результата» со списком чипов выбранных проверок (или «Проверки не выбраны») и кнопкой открытия попапа.
2. Клик по кнопке → модалка «Проверки результата» с двумя секциями: **Стандартные** (девять встроенных человеческими словами) и **Мои проверки** (AI-судьи из workspace-БД).
3. Пользователь отмечает нужные. Для стандартных с параметрами (`min_length`, `max_length`, `regex_matches`, `has_section`, `has_field`) прямо под строкой раскрывается поле параметра — без него проверку нельзя применить.
4. Нужной проверки нет → **Новая проверка**: название, утверждение-промпт, пример текста, кнопка **Прогнать на примере** → вердикт PASS/FAIL от судьи. Устраивает — **Сохранить проверку**: она появляется в «Моих» и сразу отмечается.
5. **Готово** закрывает модалку и переносит выбор в черновик meta. Фактическая запись на бэкенд — прежней кнопкой **Сохранить meta** (модалка сама meta не сохраняет).

Границы среза: удаления проверок нет; редактирования уже созданной «моей» проверки нет; выбор проверок для шагов pipeline не трогаем.

## Layout и состояния

### Триггер в панели (всегда виден)

```
Проверки результата                    ← text-[11px] text-ink-faint (как соседние подписи)
[Не пустой ×?] [Есть раздел · Тезисы] [Соответствие ТЗ  AI]   ← .chip, flex-wrap gap-1.5
[ Выбрать проверки ]                   ← .btn-secondary, текст «Выбрать проверки» / «Проверки: N»
```

- Пусто → вместо чипов строка `text-[11px] text-ink-faint`: «Проверки не выбраны».
- Чипы — только отображение (без крестиков): всё редактирование внутри модалки, чтобы не дублировать логику параметров и валидации.
- Подпись чипа: стандартная — человеческое имя из `labels` + значение параметра через `·` (например «Есть раздел · Тезисы»); «моя» — имя + `.badge-accent` «AI»; недоступная — `.badge-danger` «нет в списке».
- `streaming` (`inputsDisabled`) → кнопка `disabled` (стили disabled из `.btn-secondary`: `surface-muted` + `ink-faint` + `cursor-not-allowed`), чипы остаются видимыми.

### Модалка

`.modal-overlay` → `.modal-card max-w-lg`; тело `max-h-[60vh] overflow-y-auto`, заголовок и футер вне скролла.

```
Проверки результата                                     ✕     ← h2 text-sm font-semibold text-ink
──────────────────────────────────────────────────────────────
СТАНДАРТНЫЕ                          ← text-[11px] uppercase tracking-wide text-ink-faint
 [✓] Не пустой            non_empty  ← имя text-xs text-ink · id text-[10px] text-ink-faint
 [ ] Минимальная длина    min_length
 [✓] Есть раздел          has_section
     ┌ heading ───────────────────┐  ← .field text-xs, появляется только у выбранной
МОИ ПРОВЕРКИ
 [✓] Соответствие ТЗ  AI      Скрыть ← .badge-accent + .btn-ghost text-[11px]
     утверждение…                    ← 1 строка, truncate, text-[11px] text-ink-faint
НЕДОСТУПНЫЕ (только если есть)
 [✓] custom:9f3c…  нет в списке      ← снять можно, поставить заново нельзя
──────────────────────────────────────────────────────────────
[ Новая проверка ]              [ Отмена ]  [ Готово ]
```

Состояния тела модалки:

| Состояние | Что показываем |
|-----------|----------------|
| loading | Вместо списков — `text-xs text-ink-muted` «Загружаю проверки…»; футер активен, «Готово» disabled |
| error (сеть / 409 без workspace) | Блок `rounded bg-danger-soft border border-danger-line text-danger-ink text-xs p-2` с текстом ошибки сервера + `.btn-secondary` «Повторить». Секция «Стандартные» показывается, если её запрос прошёл — секции грузятся независимо |
| empty (нет своих) | В секции «Мои проверки»: `text-[11px] text-ink-faint` «Пока пусто — создайте первую» |
| success | Обе секции со строками; выбранные подсвечены `bg-brand-soft` |
| invalid | У выбранной проверки не заполнен обязательный параметр: поле `bg-danger-soft border border-danger-line`, под ним `text-[10px] text-danger-ink` «Заполните параметр», «Готово» disabled |
| busy (создание/preview) | Кнопки формы disabled, у активной кнопки текст «Прогоняю…» / «Сохраняю…» |

Вид «Новая проверка» (в том же `.modal-card`, вместо списков):

```
Новая проверка
Название            [ .field                                 ]
Утверждение         [ .field textarea rows=3                 ]  ← placeholder: «Что должно быть верно про результат»
Пример результата   [ .field textarea rows=4                 ]
[ Прогнать на примере ]
┌ Вердикт ────────────────────────────────────────────────┐    ← success-soft / danger-soft
│ PASS — проверка прошла на примере                        │
└──────────────────────────────────────────────────────────┘
                          [ Назад ]  [ Сохранить проверку ]
```

Состояния вердикта: нет прогона → блока нет; PASS → `bg-success-soft text-success-ink`, текст «PASS — проверка прошла на примере»; FAIL → `bg-danger-soft text-danger-ink`, «FAIL — » + `failures.join('; ')`; ошибка запроса → тот же danger-блок с текстом ошибки.

## Взаимодействия

- **Открытие/закрытие.** Кнопка триггера открывает модалку и запускает загрузку каталогов (`GET /verify-checks` + `GET /custom-checks` параллельно, `Promise.allSettled`, чтобы одна ошибка не гасила вторую секцию). Esc и «Отмена» закрывают без применения (по паттерну `SessionTimeoutModal`: слушатель `keydown` на `window`, игнорируется при `busy`). «Готово» вызывает `onChange(draft)` и закрывает. Клик по подложке не закрывает (как в остальных модалках проекта).
- **Черновик внутри модалки.** Модалка работает с локальной копией `value`, инициализируемой при открытии. Это позволяет отменить правку параметров одним «Отмена» и не дёргать `dirtyMeta` панели на каждый чих.
- **Переключение проверки.** Клик по строке (вся строка — кликабельная область, `role="checkbox"`): выбрать → добавить `{ check: id }` в конец списка, снять → удалить. Порядок выбранных сохраняется по времени добавления; порядок отображения в списке — как пришёл с бэкенда (`builtin` в порядке реестра, свои — `created_at DESC`).
- **Параметры.** У выбранной стандартной проверки с обязательным параметром сразу под строкой появляется поле. Соответствие: `min_length → min` (число), `max_length → max` (число), `regex_matches → pattern`, `has_section → heading`, `has_field → key`. Дефолтов не подставляем — пустое поле честно блокирует «Готово», чтобы не сохранить фиктивный `heading: "Раздел"`. Числовые поля: `inputMode="numeric"`, значение хранится числом, нечисловой ввод считается незаполненным. Снятие галочки стирает параметры этой проверки.
- **Своя проверка.** Строка = имя + `.badge-accent` «AI» + усечённый промпт как вторая строка (полный текст в `title`). Клик по строке — выбор, как у стандартных.
- **Скрыть (не удаление).** У каждой «моей» проверки — `.btn-ghost` «Скрыть», по клику строка превращается в подтверждение: «Скрыть из списка? Она перестанет предлагаться, а скиллы, которые уже на неё ссылаются, не пройдут проверку.» + `.btn-danger` «Скрыть» / `.btn-secondary` «Отмена». Подтверждение → `POST /custom-checks/{id}/hide`, строка уходит из списка и снимается из черновика. Кнопки удаления в UI нет и не появляется.
- **Недоступные ссылки.** Если в `value` есть `custom:<id>`, которого нет в ответе `/custom-checks` (скрыт или из чужого workspace), он показывается отдельной группой «Недоступные» с `.badge-danger` «нет в списке» и подсказкой «проверка скрыта — verify упадёт, снимите её». Снять можно, вернуть — нет. Неизвестный стандартный id ведёт себя так же (подпись = сам id).
- **Новая проверка.** Кнопка «Новая проверка» переводит модалку в форму, фокус — на поле «Название». «Прогнать на примере» активна при непустых «Утверждение» и «Пример» → `POST /custom-checks/preview`, вердикт в блок под кнопкой. «Сохранить проверку» активна при непустых «Название» и «Утверждение» (прогон не обязателен) → `POST /custom-checks`, новая запись добавляется в начало «Моих», автоматически отмечается в черновике, модалка возвращается в список. «Назад» возвращает в список, сбрасывая поля формы и вердикт.
- **Крайние случаи.** Двойной клик по «Сохранить»/«Прогнать» гасится флагом `busy`. Ошибка создания (409 без workspace, 422 на пустых полях) остаётся в форме danger-блоком, введённое не теряется. Приход новой версии артефакта meta с сервера, пока модалка открыта, черновик модалки не перетирает (панель и так не трогает грязный `metaDraft`).

## Стиль и токены

- Только семантические утилиты из `docs/ui-style-guide.md`. Сырые палитры Tailwind (`slate-*`, `red-*`, …) не использовать.
- Примитивы: `.modal-overlay` + `.modal-card max-w-lg`, `.field`, `.btn-primary` («Готово», «Сохранить проверку»), `.btn-secondary` (триггер, «Отмена», «Назад», «Новая проверка», «Повторить»), `.btn-ghost` («Скрыть», крестик закрытия), `.btn-danger` (подтверждение скрытия), `.chip` (выбранные в панели), `.badge-accent` (AI), `.badge-danger` (недоступная), `.badge-success`/danger-блоки для вердикта.
- Типографика: заголовок модалки `text-sm font-semibold text-ink`; заголовки секций `text-[11px] uppercase tracking-wide text-ink-faint` (как «Steps»/«Prompt» в панели); строки списка `text-xs text-ink`; технический id и промпт `text-[10px]`/`text-[11px] text-ink-faint`; тексты в панели — `text-[11px]`, подсказки `text-[10px]`.
- Ритм: тело модалки `space-y-3`, строки списка `px-2 py-1.5 rounded`, поля параметров `mt-1 ml-6`, футер `flex justify-end gap-2` с «Новая проверка», отжатой влево (`mr-auto`).
- Выбранная строка: `bg-brand-soft text-ink`; hover невыбранной: `hover:bg-surface-hover`; disabled — `surface-muted` + `ink-faint` + `cursor-not-allowed`, не `opacity-50`.

## Доступность (a11y)

- Модалка: `role="dialog"` + `aria-modal="true"` + `aria-labelledby` на заголовок (id через `useId`), как в `RescanReportModal`.
- Фокус: при открытии — на первую строку списка (или на «Название» в форме создания); при закрытии — обратно на кнопку-триггер. Esc закрывает (кроме `busy`); в режиме подтверждения скрытия Esc сначала отменяет подтверждение. Ловушку фокуса не делаем — в проекте её нет ни в одной модалке.
- Строки-переключатели: `<button role="checkbox" aria-checked>` с доступным именем «человеческое имя + (id)»; секции — контейнеры `role="group"` с `aria-labelledby` на заголовок секции. Клавиатура: Tab между строками, Space/Enter переключают.
- Триггер: `aria-haspopup="dialog"` + `aria-expanded`; доступное имя включает количество («Проверки: 3»).
- Вердикт прогона — `role="status"` (вежливое объявление), блоки ошибок — `role="alert"`. Поле с незаполненным обязательным параметром — `aria-invalid` + `aria-describedby` на текст ошибки.
- Focus-visible везде — кольцо `ring-2 ring-brand` (наследуется из примитивов; у кастомных строк добавить `focus-visible:ring-2 focus-visible:ring-brand`).
- Цвет не единственный носитель смысла: «AI», «нет в списке», PASS/FAIL продублированы текстом.

## Контракты данных

Из code-плана `06-CATALOG-120` (`backend/catalog/api/checks.py`), добавить в `frontend/src/api.ts`:

```ts
export interface VerifyChecksCatalog { builtin: string[]; labels: Record<string, string> }
export interface CustomCheckOut { id: string; name: string; prompt: string; hidden: boolean; created_at: string }
export interface CustomCheckPreviewOut { passed: boolean; failures: string[] }

listVerifyCheckCatalog(): GET  /verify-checks
listCustomChecks():      GET  /custom-checks            // скрытые не приходят
createCustomCheck(body): POST /custom-checks            // { name, prompt } → CustomCheckOut
previewCustomCheck(b):   POST /custom-checks/preview    // { prompt, sample } → CustomCheckPreviewOut
hideCustomCheck(id):     POST /custom-checks/{id}/hide  // 204
```

Формат значения (`VerifyCheckDraft[]`, он же `verify_checks` в meta): стандартная — `{ check: "has_section", params: { heading: "Тезисы" } }`; своя — `{ check: "custom:<id>" }` (бэкенд принимает и `custom:<id>`, и `{ check: "custom", params: { id } }`; берём первый вариант). `SkillMetaPatch.verify_checks` расширяется до `{ check: string; params?: Record<string, unknown> }[]`.

Чтение существующей meta: `parseMetaContent` больше не склеивает id в строку, а возвращает массив с сохранением `params` — иначе правка любого другого поля meta затирала бы параметры уже настроенных проверок. Если в артефакте лежит старое CSV-подобное значение или строки вместо объектов, каждая непустая строка превращается в `{ check }`.

Девять человеческих подписей приходят с бэкенда (`labels`), в UI не хардкодятся; фолбэк для неизвестного id — сам id.

## Критерии визуальной приёмки

- [ ] В секции Meta нет текстового `input` для `verify_checks`; вместо него подпись, чипы выбранного (или «Проверки не выбраны») и кнопка открытия попапа; при `streaming` кнопка disabled в токенах `surface-muted`/`ink-faint`.
- [ ] Попап построен на `.modal-overlay` + `.modal-card max-w-lg`, имеет `role="dialog"`, `aria-modal`, заголовок «Проверки результата» и крестик закрытия.
- [ ] В попапе есть секции «Стандартные» (девять встроенных с человеческими подписями из `labels` и техническим id рядом) и «Мои проверки», а также кнопка «Новая проверка».
- [ ] Выбор — мультивыбор через строки `role="checkbox"` с `aria-checked`; выбранная строка `bg-brand-soft`; свои проверки помечены `.badge-accent` «AI».
- [ ] У выбранных `min_length`, `max_length`, `regex_matches`, `has_section`, `has_field` показывается поле параметра; при пустом параметре поле в danger-стилях и «Готово» заблокировано.
- [ ] Форма новой проверки содержит название, утверждение, пример и кнопку прогона; вердикт выводится блоком `success-soft` (PASS) или `danger-soft` (FAIL со списком причин) внутри `role="status"`.
- [ ] Сохранение новой проверки добавляет её в «Мои» и сразу отмечает выбранной, возвращая пользователя к спискам.
- [ ] Кнопок и пунктов удаления нет; действие «Скрыть» есть только у своих проверок, требует подтверждения и явно описано как «не удаление».
- [ ] Ссылки на недоступные (скрытые/неизвестные) проверки видны отдельной группой с пометкой и снимаются одним кликом.
- [ ] Esc и «Отмена» закрывают попап без изменения черновика meta; «Готово» переносит выбор в черновик, а запись на сервер по-прежнему делает кнопка «Сохранить meta».
- [ ] Фокус при открытии уходит внутрь попапа, при закрытии возвращается на кнопку-триггер.
- [ ] Во всех новых стилях только токены из `docs/ui-style-guide.md`; сырых палитр Tailwind нет.
