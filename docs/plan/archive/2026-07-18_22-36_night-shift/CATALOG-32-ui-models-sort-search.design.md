## Цель и пользовательский путь

Модель выбирается в двух местах: селектор в шапке приложения (`ModelSelector`) и модалка настройки скила (`SkillSettingsModal`). Сейчас в обоих — «сырой» `<select>`, порядок как пришёл из API, поиска нет. На длинном каталоге (OpenRouter — сотни моделей) выбор мучителен: приходится крутить весь список.

Целевой путь пользователя:
1. Кликает по полю выбора модели (триггер-кнопка вместо `<select>`).
2. Открывается дропдаун со **строкой поиска** сверху и **отсортированным** списком моделей.
3. Печатает часть имени или id (`gpt`, `claude`, `llama`) — список мгновенно фильтруется.
4. Выбирает модель кликом или клавиатурой — дропдаун закрывается, выбранная модель показана на триггере.

Результат: предсказуемый порядок + быстрый поиск в обоих местах, единый UX.

## Дерево компонентов и файлы

Переиспользуем уже существующий паттерн `DocumentCombobox.tsx` (кнопка-триггер + дропдаун с поиском, закрытие по клику вне/Escape, роли combobox/listbox/option). Не тянем новые зависимости.

- **`frontend/src/components/ModelCombobox.tsx`** — новый компонент. Single-select combobox по моделям: триггер + дропдаун с полем поиска и отфильтрованным/отсортированным списком. Аналог `DocumentCombobox`, но для `ModelOut` и с доменными бейджами (reasoning). Принимает уже отсортированный/отфильтрованный набор через общий helper.
- **`frontend/src/lib/models.ts`** (или `frontend/src/components/modelSort.ts`) — новый shared helper `sortAndFilterModels(models, query)`:
  - сортировка стабильная по `name` (fallback на `id`, если `name` пустое) через `localeCompare` с `{ sensitivity: 'base', numeric: true }`;
  - фильтр: `query` (trim + lowercase) матчится по `name` **и** `id` (substring, регистронезависимо);
  - пустой `query` → только сортировка, без фильтра.
  Helper переиспользуется обоими местами, чтобы порядок и правила поиска были идентичны.
- **`frontend/src/components/ModelSelector.tsx`** — заменить второй `<select>` (модель) на `ModelCombobox`. Провайдерный `<select>` не трогаем (список короткий). Компактный вариант триггера под шапку (мелкий шрифт, как сейчас `text-xs`).
- **`frontend/src/components/SkillSettingsModal.tsx`** — заменить `<select>` модели на `ModelCombobox`. При выборе модели сохранить текущий побочный эффект: сброс `reasoning` в `''` (см. `onChange` на строках 175–178).

Провайдер и режим рассуждений остаются `<select>` — их списки короткие, они вне скоупа задачи.

## Layout и состояния

Общая раскладка `ModelCombobox` (по мотивам `DocumentCombobox`):

- **Триггер** — `button role="combobox"` во всю ширину контейнера: слева обрезаемый (`truncate`) лейбл выбранной модели (или её id, если модель ещё не в списке), справа маркер `▾`. Рядом допускается бейдж reasoning (`🧠`) для выбранной модели.
- **Дропдаун** — абсолютный, `z-10`, `max-h-*` со скроллом, тёмная карточка (`border-slate-700 bg-slate-900`). Сверху — залипающая строка поиска, ниже — список опций.

Состояния:

- **loading** (модели ещё грузятся): в шапке уже есть текст «загрузка…» рядом с селекторами — сохранить. Триггер `ModelCombobox` в это время `disabled` (пониженная непрозрачность). В модалке при пустом списке показываем текущее значение как единственную «псевдо-опцию» (см. ниже про selected-not-in-list).
- **empty (нет моделей вообще)**: триггер `disabled`, на нём — текущее значение `model`/`preview.model` как текст (никогда не показываем пустое поле).
- **empty (поиск не дал совпадений)**: в дропдауне строка «нет совпадений» (`text-slate-500`, мелкий шрифт) — как в `DocumentCombobox`.
- **success**: отсортированный список; выбранная опция подсвечена (`bg-indigo-600/20 text-white`), остальные — `hover:bg-slate-800`.
- **selected-not-in-list**: если текущее `value` отсутствует в `models` (модель из другого провайдера/устаревшая) — на триггере всё равно показываем сам `value` (id), чтобы не терять выбор. Это повторяет текущую защиту `{models.length === 0 && <option value={model}>{model}</option>}`.
- **error**: загрузка моделей уже обрабатывается родителями (`SkillSettingsModal` держит `error`, шапка — свою логику). `ModelCombobox` собственный сетевой статус не рисует.

## Взаимодействия

- **Открытие/закрытие**: клик по триггеру — toggle; клик вне корня — закрыть и очистить фильтр; `Escape` — закрыть и вернуть фокус на триггер. Повторяем поведение `DocumentCombobox` (обработчики `mousedown` вне корня, `onBlur` вне корня).
- **Поиск**: `input type="search"`, `autoFocus` при открытии; ввод обновляет фильтр немедленно (без debounce — фильтрация локальная). При закрытии фильтр сбрасывается в `''`.
- **Выбор**: клик по опции → `onChange(model.id)` и закрытие. В `SkillSettingsModal` дополнительно сбрасывается `reasoning`.
- **Клавиатура (минимум для среза)**: `Escape` закрывает; поле поиска фокусируемо; опции достижимы (as в `DocumentCombobox`). Стрелочная навигация по опциям — не требуется в скоупе (в `DocumentCombobox` её тоже нет); не расширяем.
- **Крайние случаи**:
  - смена провайдера в шапке перезагружает список моделей → открытый дропдаун закрывается/список обновляется; фильтр сбрасывается.
  - очень длинный id/name → `truncate` на триггере и в опциях, без переноса и без ломки ширины.
  - `disabled` (loading/empty) → дропдаун не открывается, фильтр очищен.

## Стиль и токены

Tailwind v3, палитра slate/indigo — строго как в существующем UI:

- Триггер и поле поиска: `rounded bg-slate-800 px-2 py-1 text-slate-100`. Размер шрифта — по контексту: в шапке `text-xs` (как текущий `selectCls`), в модалке `text-xs` (как `fieldCls`). Допускается проп `triggerClassName`/размерный проп для консистентности с местом использования (паттерн уже есть в `DocumentCombobox`).
- Дропдаун: `absolute z-10 mt-1 max-h-48 w-full overflow-y-auto rounded border border-slate-700 bg-slate-900 shadow-xl`.
- Строка поиска-контейнер: `border-b border-slate-800 p-1`; input — `w-full rounded bg-slate-800 px-2 py-1 placeholder:text-slate-500`.
- Опция: `flex items-center gap-1.5 px-2 py-1`; выбранная — `bg-indigo-600/20 text-white`, обычная — `text-slate-300 hover:bg-slate-800`.
- Плейсхолдер/пустые состояния — `text-slate-500`.
- Бейдж reasoning `🧠` — как сейчас в `ModelSelector` (после имени, приглушённо). Держим его и в опциях, и опционально на триггере.

Никаких новых цветов/токенов не вводим.

## Доступность (a11y)

Наследуем от `DocumentCombobox`:
- Триггер: `role="combobox"`, `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls={listId}`, `aria-label` (в шапке — «Модель», в модалке — «Модель»), `aria-disabled` при disabled.
- Дропдаун: `role="listbox"`; опции: `role="option"` + `aria-selected`.
- `useId()` для связки `aria-controls`.
- Фокус: `autoFocus` на поле поиска при открытии; `Escape` возвращает фокус на триггер.
- Поиск — `input type="search"` с осмысленным `placeholder="Поиск…"`.
- Контраст текста на slate-фоне сохраняем существующий (уже используется в проекте).

## Контракты данных

Ничего нового с бэкенда не требуется (шаг чисто фронтовый, сортировка/фильтр — на клиенте).

- Тип `ModelOut` (`frontend/src/api.ts:83-89`): `id`, `name`, `context_length`, `supports_reasoning`, `reasoning_variants`. Для лейбла — `name`; для поиска — `name` + `id`; для сортировки — `name` с fallback на `id`.
- Источники данных не меняются: шапка получает `models`/`loading` из `useSettings`, модалка грузит `listModels()` в `useEffect`.
- `onChange(model: string)` совместим с текущими `onModelChange` (шапка) и `setModel` (модалка).

## Критерии визуальной приёмки

- [ ] В обоих местах (шапка и модалка скила) выбор модели — это combobox с полем поиска, а не «голый» `<select>`.
- [ ] Список моделей отсортирован предсказуемо (по имени, стабильно, регистронезависимо, с числовой сортировкой) — одинаково в обоих местах.
- [ ] Ввод в поле поиска фильтрует список по подстроке в `name` **или** `id`, регистронезависимо; пустой запрос показывает полный отсортированный список.
- [ ] При отсутствии совпадений в дропдауне видна строка «нет совпадений».
- [ ] Текущая выбранная модель всегда отображается на триггере, даже если её нет в загруженном списке (id как fallback) и во время загрузки.
- [ ] При выборе модели в модалке сбрасывается режим рассуждений (`reasoning` → пусто), как раньше.
- [ ] Дропдаун закрывается по клику вне и по `Escape`; при открытии фокус в поле поиска; фильтр сбрасывается при закрытии.
- [ ] Стиль (slate/indigo, размеры, отступы, бейдж 🧠) визуально консистентен с существующими `ModelSelector`/`DocumentCombobox`; длинные id/name обрезаются без ломки ширины.
- [ ] Провайдерный селектор и селектор режима рассуждений остаются `<select>` (вне скоупа).
