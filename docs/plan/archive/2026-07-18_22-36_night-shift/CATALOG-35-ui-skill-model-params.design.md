# CATALOG-35 — Дизайн UI

- **Источник:** docs/plan/night-shift/CATALOG-35-ui-skill-model-params.md
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Пользователь смотрит список скилов в правой панели (`SkillsPanel`). Для каждого скила он уже видит имя, теги, статус и описание. Теперь на карточке добавляется компактная строка метаданных модели: **провайдер · модель · рассуждения**. Это read-only информация — увидеть, с какими параметрами скилл будет исполняться, не открывая модалку настроек (`SkillSettingsModal`).

Сценарий:
1. Пользователь открывает список скилов.
2. Под описанием AI-скила видит одну строку с провайдером, моделью и (если задан) режимом рассуждений.
3. У script-скила (без модели) этой строки нет — карточка не засоряется пустыми полями.

Скоуп шага — только отображение. Никаких новых кликов/редактирования из этой строки; редактирование остаётся в модалке настроек (кнопка «Редактировать»).

## Дерево компонентов и файлы

- `frontend/src/api.ts` — **изменяется**: в интерфейс `SkillOut` добавить три nullable-поля:
  - `provider: string | null`
  - `model: string | null`
  - `reasoning: string | null`
  Значения приходят из code-плана `CATALOG-35-code-skill-model-params-api.md` (эндпоинт `GET /skills`).
- `frontend/src/components/SkillsPanel.tsx` — **изменяется**: рендер строки метаданных модели внутри карточки скила. Ключевую разметку допустимо вынести в маленький локальный подкомпонент/функцию (например, `SkillModelMeta`) в этом же файле для читаемости — новый файл создавать не обязательно.

Новых зависимостей не вводится. Используется тот же стек (React 19 + Vite + TS + Tailwind v3) и существующие паттерны панели.

## Layout и состояния

Место вставки — внутри `<li>` карточки скила, **после** блока описания (`{s.description && <p .../>}`, строки ~261–263) и **до** блока действий (`<div className="mt-2 flex flex-wrap ...">`, строка ~264).

Строка метаданных: один горизонтальный ряд с переносом (`flex flex-wrap`), состоящий из пар «лейбл + значение». Каждый элемент показывается **только если соответствующее значение непустое**.

Поля и их лейблы:
- `provider` → лейбл «Провайдер»
- `model` → лейбл «Модель»
- `reasoning` → лейбл «Рассуждения»

Состояния строки:
- **AI-скилл с моделью:** видны провайдер и модель; рассуждения — только если `reasoning` задан.
- **Только часть полей заполнена:** рендерятся лишь непустые поля, остальные не показываются (без «—» и без пустых лейблов).
- **script-скилл / все поля пустые (`null`/`''`):** строка метаданных **не рендерится вовсе** (карточка выглядит как раньше). Это реализация требования плана «не показывать пустые поля»; вариант с «—» намеренно не используется ради чистоты списка.
- Прочие состояния карточки (loading/error/empty списка скилов) не меняются — они уже обработаны в `SkillsPanel` и вне скоупа этого шага.

## Взаимодействия

- Строка метаданных **не интерактивна**: без кликов, ховер-меню и фокуса.
- Значение модели может быть длинным (например `z-ai/glm-4.6`, `anthropic/claude-3.5-sonnet`). Значение `model` обрезается по ширине (`truncate` внутри `max-w`-контейнера) и получает нативный тултип `title` с полным идентификатором. Провайдер и рассуждения короткие — не обрезаются.
- При очень узкой панели строка переносится по элементам (`flex-wrap`), лейбл и его значение не разрываются между собой.
- Крайние случаи: пустая строка `''` и `null` трактуются одинаково — поле скрыто. Пробельные значения тоже считаются пустыми (после `trim`).

## Стиль и токены

Консистентно с существующей типографикой карточки (описание — `text-[11px] text-slate-400`):

- Контейнер строки: `mt-1 flex flex-wrap items-center gap-x-3 gap-y-0.5 text-[11px]`.
- Пара «лейбл+значение»: `inline-flex items-center gap-1 min-w-0`.
- Лейбл: `text-slate-500` (приглушённый, вторичный).
- Значение: `text-slate-300` (основной читаемый тон, чуть ярче лейбла).
- Значение модели: добавить `truncate max-w-[12rem]` (в пределах ширины панели) + `title={model}`.
- Не использовать badge/uppercase-стиль тегов и статуса — модельные метаданные это справочная строка, а не капсулы; так они визуально отделены от тегов/статуса сверху.
- Разделители между полями обеспечиваются `gap-x-3` (без символьных «·»/«|»), чтобы разметка оставалась простой и корректно переносилась.

## Доступность (a11y)

- Строку оформить как список описаний: контейнер `role` не обязателен, достаточно семантики «лейбл: значение» через видимый текст лейбла. Каждый лейбл — обычный текст рядом со значением (визуальная и смысловая связь очевидна).
- Значение модели: `title` дублирует полный id для случая обрезки; при этом полный текст остаётся доступен как обычный текстовый узел (обрезка только визуальная через CSS, содержимое DOM не режется), поэтому скринридер прочитает id целиком.
- Контраст: `text-slate-300`/`text-slate-500` на фоне `bg-slate-900/60` соответствует уровню уже используемого в карточке текста — не ниже существующего описания.
- Строка не фокусируемая и не в tab-порядке (нет интерактивных элементов) — навигация с клавиатуры по кнопкам карточки не меняется.

## Контракты данных (если нужны)

- Источник данных — `GET /skills` → `SkillOut` (см. `frontend/src/api.ts`).
- Новые поля (из code-плана `CATALOG-35-code-skill-model-params-api.md`):
  - `provider: string | null`
  - `model: string | null`
  - `reasoning: string | null`
- UI дополнительных запросов не делает: `listModels()`/`listProviders()` для этой строки не нужны — показываем ровно то, что вернул бэкенд (сырые id/значения). Человекочитаемые имена моделей/провайдеров в скоуп этого шага не входят.

## Критерии визуальной приёмки

- [ ] В карточке AI-скила под описанием видна строка с провайдером и моделью; если задан `reasoning` — также «Рассуждения».
- [ ] Для script-скила (все три поля `null`/пустые) строка метаданных отсутствует; карточка выглядит как до изменения.
- [ ] Пустые/`null` поля не рендерят ни лейбл, ни «—»; показываются только заполненные поля.
- [ ] Длинный идентификатор модели не ломает верстку карточки: значение обрезается, полный id доступен по `title`/в DOM.
- [ ] Строка метаданных стилистически отделена от бейджей тегов/статуса (приглушённый текст, без uppercase-капсул) и согласована с типографикой описания (`text-[11px]`).
- [ ] На узкой панели строка корректно переносится, лейбл со значением не разрываются.
- [ ] Строка не интерактивна и не влияет на существующие кнопки/фокус карточки.
