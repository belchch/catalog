# CATALOG-29 — Дизайн UI

- **Источник:** docs/plan/night-shift/CATALOG-29-ui-multiline-chat.md
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Пользователь пишет планировщику многострочные сообщения, не отправляя их случайно на первом же `Enter`.

Сценарий:
1. Пользователь кликает в поле ввода composer и печатает текст.
2. Нажимает `Shift+Enter` → в поле появляется перевод строки, поле подрастает по высоте.
3. Нажимает `Enter` (без модификаторов) → сообщение уходит планировщику, поле очищается и возвращается к исходной высоте.
4. Либо жмёт кнопку «Отправить» — эффект тот же, что у `Enter`.

Изменение точечное: заменяем однострочный `<input>` на многострочный `<textarea>` и уточняем обработку клавиш. Вся остальная композиция composer (быстрые ответы, ряд выбора документов, кнопка «Создать скилл») и логика `submit`/`onSend`/`onCancel` сохраняются без изменений.

## Дерево компонентов и файлы

Изменяемые:
- `frontend/src/components/Chat.tsx` — единственный затрагиваемый файл.
  - Заменить `<input>` (текущие строки ~208–217) на `<textarea>`.
  - Обработчик `onKeyDown`: `Enter` без `Shift`/`Ctrl`/`Meta`/`Alt` → `preventDefault()` + `submit()`; `Shift+Enter` → поведение по умолчанию (перевод строки), submit НЕ вызывать.
  - Автоподстройка высоты (auto-resize) textarea по контенту в диапазоне min/max (см. «Layout и состояния»). Реализация — на усмотрение генератора (управление `rows` + пересчёт `scrollHeight` в эффекте по `input`, либо CSS `field-sizing`; при использовании эффекта — сброс высоты при очистке поля после submit).

Новые файлы, компоненты и зависимости не вводятся. `submit()`, `canSubmit`, кнопки «Отправить»/«Стоп» остаются как есть.

## Layout и состояния

Ряд ввода — существующий контейнер `flex gap-2` в футере composer. Выравнивание кнопки при многострочном поле: контейнер выравнивает элементы по нижнему краю (`items-end`), чтобы «Отправить»/«Стоп» оставались у нижней строки растущего textarea.

`<textarea>`:
- Стартовая высота — одна строка (`rows={1}`), визуально совпадает с прежним однострочным полем.
- Рост по контенту до потолка ~5–6 строк, далее внутренний скролл (`overflow-y-auto`); `resize-none` (высотой управляет auto-resize, не ручной drag).
- Перенос длинных строк — по умолчанию (`white-space` textarea), без горизонтального скролла.

Состояния:
- **Empty:** одна строка, placeholder «Сообщение планировщику…» (как сейчас). Кнопка «Отправить» задизейблена по текущему правилу `canSubmit` (нет текста и нет выбранных доков).
- **Одна строка текста:** как прежний `<input>`; `Enter` отправляет.
- **Многострочный ввод:** после `Shift+Enter` поле выросло; видны все строки до потолка, затем скролл. `Enter` отправляет всё содержимое (включая внутренние переносы).
- **Streaming:** textarea `disabled` (как сейчас у input); клавиатурная отправка недоступна, вместо «Отправить» показана «Стоп».
- **После submit:** поле очищается (`setInput('')`) и высота сбрасывается к одной строке.

## Взаимодействия

- **Enter (без модификаторов):** `preventDefault()` + `submit()`. Не вставляет перевод строки. При `streaming` submit заблокирован существующей проверкой внутри `submit()`.
- **Shift+Enter:** обычный перевод строки в textarea; submit не срабатывает.
- **Ctrl/Cmd/Alt+Enter:** трактуются как «не чистый Enter» → перевод строки/дефолт, submit не срабатывает (submit только по «голому» Enter и по кнопке). Это исключает случайную отправку.
- **Кнопка «Отправить»:** вызывает тот же `submit()` (без изменений).
- **Крайние случаи:**
  - Текст только из пробелов/переводов строк: `submit()` уже делает `input.trim()`; при пустом trim и отсутствии выбранных доков отправки нет (текущее правило `canSubmit`).
  - Автоперенос в IME/композиции: при активной композиции (`e.nativeEvent.isComposing` / `e.keyCode === 229`) `Enter` НЕ должен отправлять — учесть, чтобы не рвать ввод (кит/яп/кор и автозамену). 
  - Вставка (`paste`) многострочного текста работает как обычно; высота пересчитывается через тот же auto-resize.

## Стиль и токены

Строго текущая палитра и утилиты Tailwind v3, без новых цветов/зависимостей.

- `<textarea>` наследует классы прежнего `<input>`: `flex-1 rounded-md bg-slate-800 px-3 py-2 text-sm text-slate-100 outline-none placeholder:text-slate-500 disabled:opacity-50`.
- Добавить к textarea: `resize-none` и, при потолке высоты, `overflow-y-auto` (либо `max-h-*`, задающий потолок ~5–6 строк, напр. `max-h-40`). `leading-*` — по умолчанию текущей темы; не переопределять без нужды.
- Контейнер ряда: изменить `flex gap-2` → `flex items-end gap-2` (только выравнивание; отступы/gap прежние).
- Кнопки «Отправить»/«Стоп» — без изменений классов.

## Доступность (a11y)

- `<textarea>` — нативно `role="textbox"` с `aria-multiline="true"`; сохранить осмысленный `placeholder`. Отдельный видимый label не требуется (паттерн composer как сейчас), placeholder + контекст достаточны для среза.
- Клавиатура: `Enter` — отправка, `Shift+Enter` — новая строка (стандартное для чат-полей поведение); `Tab` уводит фокус из поля (не перехватываем `Tab`).
- Не блокировать перевод строки для пользователей, которым он нужен (`Shift+Enter` всегда работает), и не отправлять во время IME-композиции.
- Контраст текста/placeholder на `bg-slate-800` — как в текущем UI, не регрессирует.

## Контракты данных

Контракты не меняются. Отправка идёт через существующий `onSend(text, docIds?)`; многострочный текст передаётся как обычная строка с `\n`. WS/REST не затрагиваются (см. `CATALOG-29-ui-multiline-chat.md`).

## Критерии визуальной приёмки

- [ ] Поле ввода — `<textarea>`, стартует в одну строку и визуально совпадает с прежним однострочным полем.
- [ ] `Shift+Enter` добавляет перевод строки и не отправляет сообщение.
- [ ] `Enter` без модификаторов отправляет сообщение (через тот же `submit()`), перевод строки при этом не вставляется.
- [ ] Многострочный текст (с внутренними `\n`) целиком уходит в `onSend`/planner.
- [ ] Поле растёт по контенту до потолка (~5–6 строк), далее появляется внутренний вертикальный скролл; ручной resize отключён (`resize-none`).
- [ ] После отправки поле очищается и высота сбрасывается к одной строке.
- [ ] Кнопка «Отправить»/«Стоп» выровнена по нижнему краю растущего поля; поведение кнопок и `canSubmit` не изменилось.
- [ ] Во время `streaming` поле задизейблено, отправка по `Enter` недоступна.
- [ ] Отправка не срабатывает во время IME-композиции.
- [ ] Стиль поля совпадает с текущими токенами composer (slate, `rounded-md`, `text-sm`); новых цветов/зависимостей нет.
