# CATALOG-22 — Названия файлов при загрузке (UUID вместо имени)

- **Plane:** CATALOG-22 (модуль: Баги) — [Todo → In Progress]
- **Тип шага:** code
- **Симптом:** После загрузки файл сохраняется на диск под именем-«кодировкой» (UUID), например `9db0e2ee0bff436d977d5062c31acedb.md`, вместо читаемого названия. Замечено на русскоязычных именах (тестировалось на них).

## Корневая причина (воспроизводимо)

`backend/app/documents/ingest.py:36-37`:
```python
doc_id = uuid.uuid4().hex
rel_path = f"documents/{doc_id}{ext}"
```
Имя файла на диске **всегда** формируется из сгенерированного `doc_id`, оригинальное имя не используется вовсе. Это сделано осознанно (привязка файла к id строки), но пользователь ожидает видеть читаемое название в `workspace/documents/`.

Важные нюансы:
- В БД `title` корректен — это оригинальное имя: `title = os.path.splitext(filename)[0]`, `ingest.py:44`. `DocumentOut` отдаёт `title`, фронт (`DocumentList.tsx:70`) показывает `d.title`. То есть **в UI имя отображается правильно**; проблема только в имени файла на диске.
- Проблема не специфична для кириллицы (UUID подставляется всегда), но пользователь заметил её именно на русских названиях, когда открыл папку.

> «Кодировка» в формулировке бага — это UUID-хеш; реальные проблемы с кодировкой UTF-8 при multipart-загрузке не выявлены (`file.filename` доходит корректно, `title` сохраняется верно).

## Решение

Сохранять файл под читаемым, файлсистем-безопасным именем, сохраняя уникальность и связь с `id`. Подход:

1. Получить «слаг» из оригинального имени (без расширения): транслитерация кириллицы → латиница, замена пробелов/небезопасных символов на `-`, нижний регистр, обрезка длины.
2. Имя файла: `documents/{slug}-{doc_id[:8]}{ext}` — слаг даёт читаемость, короткий суффикс `doc_id` гарантирует уникальность и связь со строкой (которая хранит полный `doc_id`).
3. `title` в БД оставить **оригинальным** (как есть) — не портить пользовательское имя транслитерацией.
4. `path` в строке документа и реальный файл на диске остаются согласованы (один источник истины в `ingest_file`).

### Транслитерация кириллицы
- Без новых зависимостей: небольшая таблица `А→A … я→ya` в `app/documents/ingest.py` (или отдельный `slugify`-хелпер). На крайний случай — `unicodedata.normalize('NFKD', ...)` для латиницы + явная таблица для кириллицы (NFKD кириллицу не разлагает).
- Имя только с пробелами/пустое → fallback на `doc_id` полностью.

## Порядок задач
1. **`backend/app/documents/ingest.py`:**
   - Добавить `slugify(name: str) -> str` (транслитерация + sanitize + обрезка до ~60 символов + trim `-`).
   - В `ingest_file` формировать `rel_path = f"documents/{slug}-{doc_id[:8]}{ext}"` (fallback на `doc_id` при пустом слаге).
   - `title` не менять.
2. **Тесты:** добавить/расширить unit-тесты (pytest) в `backend/tests/` на `ingest_file`:
   - русское имя → корректный слаг + суффикс + расширение;
   - имя с пробелами/спецсимволами;
   - пустое/только-пробелы имя → fallback;
   - согласованность `row.id` (префикс) и `row.path`;
   - `.docx` проходит валидацию расширения (`kind_for_filename`).
3. **Регресс:** `read_document`/`extract.extract_text` читают по `row.path` из БД — не ломаются (путь хранится полностью).

## Критерий приёмки
- [ ] Загрузка файла с русским названием сохраняет его на диск под читаемым транслитерированным именем (`<slug>-<id8><ext>`), не UUID-хешом.
- [ ] `row.title` остаётся оригинальным русским названием; в UI (`/documents`, DocumentList) имя отображается корректно.
- [ ] `row.path` согласован с реальным файлом; `read_document`/применение скиллов по-прежнему читают содержимое.
- [ ] Имена с пробелами/спецсимволами/пустые не падают (sanitize/fallback).
- [ ] `ruff check` и `pytest` зелёные.
- [ ] Существующие документы (если есть в `workspace/documents/`) не трогаются — фикс применяется к новым загрузкам (миграция не требуется).

## Риски / заметки
- Не вводить зависимость `python-slugify` и т.п. — своя компактная таблица транслитерации.
- Уникальность: суффикс `doc_id[:8]` (16^8 ≈ 4 млрд) достаточен для среза; при коллизии (крайне редко) — использовать полный `doc_id`. Решение: принять короткий суффикс.
- Кириллица через `unicodedata` не разлагается — нужна явная таблица.
- На Windows имя файла всё равно ограничено кодировкой ФС; для MVP (dev, macOS/Linux) sanitize достаточно.
