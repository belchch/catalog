# CATALOG-84 — Дизайн UI

- **Источник:** `docs/plan/2-shift/04-CATALOG-84-ui-pipeline-steps.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Пользователь должен увидеть pipeline как **структуру шагов** в двух местах: в черновике скилла (что будет собрано) и в ленте прогона (что уже выполнилось на каком шаге).

Сценарий:

1. В чате пользователь описывает многоэтапную задачу. Планировщик вызывает `set_skill_meta(kind=pipeline)` и `save_skill_steps`.
2. Сводка черновика (`ArtifactSummaryCard`) получает четвёртую строку **Шаги** с количеством шагов — пользователь видит, что структура появилась, не открывая редактор.
3. Пользователь открывает черновик (`ArtifactsPanel`): в Meta выбран `kind = pipeline`, ниже — readonly-секция **Steps** со списком шагов (порядок, id, тип, источник входа, раскрываемые детали: код / промпт / модель / инструменты).
4. Секции Prompt и Script остаются рабочими: для pipeline они подставляются в первый шаг без собственного кода/промпта (см. «Контракты данных»). Пользователь понимает это по подсказке под заголовком секции, а не по погашенному виду.
5. Пользователь применяет скилл. В `RunView` лента разбита на группы «шаг N · {id}»; внутри группы — обычные события (script/llm/tool/verify/reasoning). Для agent- и script-скилов лента остаётся плоской, как раньше.

Вне scope: редактирование шагов из панели, модалка настроек модели на шаге, drag-and-drop порядка. Редактирование шагов — через чат-планировщик; в UI это сказано явным текстом.

## Layout и состояния

### 1. Сводка черновика — `ArtifactSummaryCard`

Строки списка формируются динамически: базовые `meta`, `prompt`, `script` + `steps`, если артефакт `steps` присутствует в `artifacts` (независимо от валидности). Порядок: **Настройки → Шаги → Промпт → Скрипт** (шаги — структура, они выше кусков наполнения). Метка строки: `Шаги`.

- Счётчик в описании считает от числа видимых строк: `Готово {ready} из {visible.length}` (было жёстко «из 3»).
- Готовность строки `steps`: артефакт есть, `is_valid !== false`, распарсенных шагов ≥ 1.
- Правый слот вместо слова «готово» для steps показывает `{n} шагов` (`{n} шаг` / `{n} шага` / `{n} шагов` — простое склонение), классом `artifact-summary__ready`.
- Если артефакт `steps` есть, но невалиден или шагов 0 — маркер `—`, правый слот пуст.
- Остальные состояния карточки (`streaming`, `loading`, `error`) не меняются.

### 2. Панель черновика — `ArtifactsPanel`

Порядок секций: **Meta → Steps → Prompt → Script**.

Секция **Steps** видна, когда выполняется хотя бы одно: артефакт `steps` есть в списке **или** `metaDraft.kind === 'pipeline'`. Для agent/script без артефакта секция не рендерится вовсе (нулевая регрессия по вертикальному месту).

Состояния секции Steps:

| Состояние | Условие | Что показываем |
|---|---|---|
| Пусто (ожидание) | `kind = pipeline`, артефакта нет | Муть-текст: «Шагов пока нет — планировщик добавит их инструментом `save_skill_steps`.» |
| Пустой список | артефакт есть, `steps.length === 0` | Тот же муть-текст + `statusRow` артефакта |
| Список | `steps.length > 0` | `<ol>` шагов (структура ниже) |
| Невалидный | `is_valid === false` | Рамка `border-danger-line` (через существующий `sectionShell`), текст ошибки `artifact.error` под списком, список рендерим, если распарсился |
| Не парсится | JSON битый | Текст ошибки + `<details>` «сырой JSON» с `<pre>` содержимого |

Строка шага (`<li>`):

```
[1]  extract_sections   [SCRIPT]  вход: документы
     ▸ подробнее
[2]  summarize          [LLM]     вход: предыдущий · model: (из скила)
     ▸ подробнее
```

- Порядковый номер — из индекса массива, моноширинный, `text-ink-faint`.
- `id` — моно, `text-ink`.
- Тип: `badge-info` для `script`, `badge-accent` для `llm` (текст в бейдже читаемый, не только цвет).
- Вход: `badge-neutral` с текстом `документы` / `предыдущий`.
- `<details>` «подробнее» (закрыт по умолчанию):
  - `script`: `<pre>` с `code` (моно, `bg-surface-muted`, `max-h-40 overflow-auto`); если `code` пуст и это **первый** script-шаг без кода — подсказка «код возьмётся из артефакта Script при сборке»; если пуст и не первый — предупреждение `text-warning-ink` «код не задан».
  - `llm`: `<pre>` с `system_prompt` (или та же логика подстановки из артефакта Prompt для первого llm-шага без промпта), затем строка `model / provider / reasoning` (пустые значения → `по умолчанию скила`), затем `allowed_tools` списком через запятую или `—`.
- Кнопки «Сохранить» у секции нет — секция readonly. Под заголовком секции постоянная муть-подсказка: «Только просмотр — шаги меняются в чате».

Секции Prompt / Script — изменение правил приглушения:

- `opacity-70` (нерелевантно) ставим только так: Prompt — при `hasMeta && kind === 'script'`; Script — при `hasMeta && kind === 'agent'`. При `kind === 'pipeline'` **ничего не гасим**.
- При `kind === 'pipeline'` под заголовком Prompt показываем нейтральную подсказку: «pipeline: подставится в первый llm-шаг без своего промпта»; под Script — «pipeline: подставится в первый script-шаг без своего кода». Стиль подсказки — тот же `text-[10px] text-ink-faint`, что у текущих «нужен только для kind=agent».

Секция Meta:

- `KIND_OPTIONS` = `agent | script | pipeline`; радиогруппа и стрелочная навигация работают без изменений (цикл по трём).
- `allowed_tools` disabled при `kind !== 'agent'`; подпись под полем: `не используется для script` для script и `задаётся на шагах` для pipeline.
- `metaToPatch`: `allowed_tools: draft.kind === 'agent' ? tools : []` (сейчас пустой список только для script) — совпадает с поведением backend.
- `parseMetaContent`: `kind` берём из `SKILL_KINDS`-подобной проверки (`'script' | 'pipeline'` иначе `'agent'`).

### 3. Лента прогона — `RunView` / `TraceSteps`

Модель отображения: лента остаётся **одним хронологическим потоком**, но соседние события с одинаковым непустым `stepId` схлопываются в группу. События без `stepId` рендерятся как раньше — плоскими `<li>` на своём месте в потоке. Это даёт нулевую регрессию для agent/script и корректно показывает финальный `verify` пайплайна (у него `step_id` нет).

Сегментация: один проход по `steps`, накопление сегментов `{ kind: 'flat', item } | { kind: 'group', stepId, items }`. Новая группа открывается при смене `stepId`; повторное появление того же `stepId` позже (теоретически) даёт новую группу — нумерация групп сквозная по порядку появления.

Группа:

```
▾ шаг 1 · extract_sections            ✓  ·  3 события
   › Скрипт: запуск
   › Скрипт: готово · 0.412s ✓
```

- Обёртка — `<details open>` (нативная клавиатура и раскрытие, как у остальных `<details>` в трейсе).
- `<summary>`: `шаг {n} · {stepId}` моно `text-[11px] text-ink-muted`, справа статус-глиф и счётчик событий `text-ink-faint`.
- Статус группы: `✗` `text-danger-ink`, если внутри есть событие `script` со `stage === 'error'` или `verify` с `passed === false`; иначе `…` `text-ink-faint`, если это последняя группа и `running === true`; иначе `✓` `text-success-ink`.
- Содержимое — вложенный `<ol>` с теми же `<li>`, что и сейчас, с отступом `pl-3` и левой линией `border-l border-line` для визуальной привязки.
- Пустых групп не бывает (группа создаётся первым событием).

Заголовок панели ленты в `RunView`: `Лента шагов` + справа, когда групп ≥ 1, муть-счётчик `шагов: {N}`. Блок `run.meta` не меняется (там уже печатается `kind: pipeline`).

Прочие состояния `TraceSteps`: пустой список — существующий текст «Шаги появятся здесь…»; ошибка и «Соединение закрыто» — как сейчас, вне группировки.

## Взаимодействия

- **Раскрытие шага в панели**: клик/Enter/Space по `<summary>` «подробнее». Состояние раскрытия локальное для DOM, при обновлении артефакта (новый `session_artifacts`) React перерисовывает список; ключ элемента — `step.id || index`, чтобы раскрытие не «прыгало» между шагами.
- **Раскрытие группы в ленте**: клик по `<summary>`. Все группы открыты по умолчанию; закрытая группа не открывается заново сама при приходе новых событий этого шага (ключ группы — `stepId`+порядковый номер, стабилен во время прогона).
- **Автопрокрутка** ленты не вводится (её нет сейчас) — поведение не меняем.
- **Подсветка ошибок сборки**: `highlightFromDetail` возвращает `'steps'`, если в detail встречается `steps` (проверка **до** `script`/`prompt`, т.к. сообщения бэкенда — `steps artifact is missing`, `steps are invalid`). В `ArtifactsPanel` для `highlightType === 'steps'` скроллим секцию Steps и ставим фокус на её контейнер (`tabIndex={-1}`), т.к. фокусируемого поля в секции нет. Ring `ring-2 ring-danger-line` даёт существующий `sectionShell`. Снятие подсветки: `onClearHighlight` вызываем при blur/клике по секции — либо (проще и достаточно) подсветка снимается штатно при следующей сборке; отдельного обработчика ввода тут нет, потому что секция readonly.
- **Стриминг планировщика** (`streaming = true`): секция Steps не имеет полей ввода, поэтому не блокируется; остальные секции — как сейчас.
- Крайние случаи: очень длинный `code`/`system_prompt` — `<pre>` c `max-h-40 overflow-auto whitespace-pre-wrap break-words`; очень длинный `stepId` — `truncate` в заголовке группы/строке шага; шаг с пустым `id` (артефакт невалиден) — показываем `(без id)` `text-warning-ink`, номер сохраняется.

## Стиль и токены

Только существующие утилиты и компонентные классы из `src/index.css` — новых CSS-классов и зависимостей не добавляем.

- Секция Steps использует тот же `sectionShell`: `rounded-md border border-line bg-surface p-3`; заголовок `text-[11px] uppercase tracking-wide text-ink-faint`; `statusRow` — существующий (`source · updated_at`).
- Список шагов: `flex flex-col gap-1.5`; строка — `flex flex-wrap items-center gap-2 text-[11px]`; номер и id — `font-mono`.
- Бейджи: `badge-info` (script), `badge-accent` (llm), `badge-neutral` (вход). Никакого нового цветового языка.
- Блоки кода/промпта: `mt-1 overflow-auto max-h-40 whitespace-pre-wrap break-words rounded bg-surface-muted p-1.5 font-mono text-[11px] text-ink-muted` — тот же приём, что в `TraceSteps` и секции Script.
- Подсказки: `text-[10px] text-ink-faint`; предупреждения — `text-warning-ink`; ошибки — `text-[11px] text-danger-ink`.
- Группы ленты: `rounded border border-line bg-surface p-1.5` для группы, вложенный список `mt-1 flex flex-col gap-1.5 border-l border-line pl-3`. Шрифт — `font-mono text-[11px]`, как весь трейс.
- Отступы между сегментами ленты — существующий `gap-1.5` внешнего `<ol>`.

## Доступность (a11y)

- Секция Steps: контейнер `role="group"` + `aria-labelledby` на заголовок `h3` (id генерим через `useId`), `tabIndex={-1}` для программного фокуса при подсветке; при `is_valid === false` — `aria-invalid` на контейнере и `aria-describedby` на элемент с текстом ошибки.
- Список шагов — семантический `<ol>` / `<li>`: порядок озвучивается скринридером, номер шага дублируется текстом, а не только визуально.
- Тип и источник входа шага — текстовые бейджи; цвет не единственный носитель смысла.
- Раскрытия — нативные `<details>/<summary>`: клавиатура и `aria-expanded` бесплатно. Фокус-кольцо у `summary` не подавляем.
- Группы ленты: `<summary>` содержит текст `шаг {n} {stepId}, {статус}` — статус дублируется словом в `sr-only`-спане (`ок` / `ошибка` / `выполняется`), чтобы глиф `✓`/`✗` не был единственным сигналом. Декоративные глифы — `aria-hidden="true"`.
- Kind-радиогруппа: третий вариант не ломает существующую `role="radiogroup"` + стрелочную навигацию; `tabIndex` по-прежнему только у активного варианта.
- Контраст: используются уже принятые токены `text-ink-muted` / `text-ink-faint` на `bg-surface` / `bg-surface-muted`, новых пар не вводим.

## Контракты данных

- **Артефакт `steps`** (`GET/WS session_artifacts`, `PATCH /sessions/{id}/artifacts/steps`): `content` — JSON `{"steps": [PipelineStep, ...]}`. Поле шага: `id: string`, `type: 'script' | 'llm'`, `input: 'documents' | 'previous'`, `code: string`, `system_prompt: string`, `allowed_tools: string[]`, `model: string`, `provider: string`, `reasoning: string` (backend всегда сериализует все поля; пустая строка = «не задано»). Парсер UI обязан переживать битый JSON и лишние/недостающие поля без исключения.
- **Meta**: `kind ∈ {agent, script, pipeline}`; для non-agent backend принудительно обнуляет `allowed_tools` (`sessions.py`), UI шлёт то же самое.
- **Подстановка при сборке** (`POST /sessions/{id}/skills`): первый `script`-шаг с пустым `code` берёт содержимое артефакта `script`, первый `llm`-шаг с пустым `system_prompt` — артефакта `prompt`. Именно это правило объясняет подсказки в секциях Prompt/Script и в раскрытии шага.
- **События прогона** (`WS /runs/{id}/stream`): опциональное поле `step_id` у кадров `step`, `token`, `tool_call`, `tool_result`, `verify`, `script`, `reasoning`. Для agent/script-скилов поля нет — группировка не включается.
- Кадр `meta` шагов не содержит: число шагов в ленте берём из фактических групп, а не из конфига.

## Критерии визуальной приёмки

- [ ] После `save_skill_steps` в сводке черновика появляется строка **Шаги** с числом шагов, счётчик в описании считает «из 4»; для agent/script скилов строки нет и счётчик остаётся «из 3».
- [ ] В Meta доступен третий вариант kind — `pipeline`; он выбирается мышью и стрелками, сохраняется и восстанавливается из артефакта.
- [ ] При `kind = pipeline` поле `allowed_tools` заблокировано с подписью «задаётся на шагах», а в сохранённом meta `allowed_tools` пуст.
- [ ] Секция **Steps** идёт сразу после Meta, доступна только для чтения (нет кнопки сохранения, есть подпись «Только просмотр — шаги меняются в чате») и показывает для каждого шага номер, id, бейдж типа (`SCRIPT`/`LLM`) и бейдж входа (`документы`/`предыдущий`).
- [ ] Раскрытие «подробнее» показывает код для script-шага и промпт + model/provider/reasoning + allowed_tools для llm-шага; для пустых code/system_prompt первого подходящего шага видна подсказка про подстановку из артефакта Script/Prompt.
- [ ] Невалидный или неразбираемый артефакт `steps` даёт красную рамку секции, текст ошибки и раскрытие с сырым JSON; приложение не падает.
- [ ] При `kind = pipeline` секции Prompt и Script не приглушены (`opacity-70` отсутствует) и содержат подсказку про подстановку в первый шаг.
- [ ] Прогон pipeline: лента разбита на группы `шаг N · {id}`, события шага вложены внутрь группы с левой линией; финальный `verify` без `step_id` показан вне групп.
- [ ] Статус группы отражает исход: `✓` для завершённого, `✗` при ошибке скрипта/проваленном verify, `…` для текущей выполняющейся; в каждом случае есть текстовый дубль для скринридера.
- [ ] Заголовок панели ленты показывает `шагов: N`, когда группы есть, и ничего не показывает для плоской ленты.
- [ ] Прогон agent- и script-скила выглядит ровно как до изменения: плоский список без групп и без счётчика шагов.
- [ ] Ошибка сборки с упоминанием `steps` подсвечивает секцию Steps (ring) и прокручивает панель к ней.
