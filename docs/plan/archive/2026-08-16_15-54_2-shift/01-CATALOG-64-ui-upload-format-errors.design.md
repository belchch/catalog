# CATALOG-64 — Дизайн UI

- **Источник:** `docs/plan/2-shift/01-CATALOG-64-ui-upload-format-errors.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Экран: левый сайдбар, секция «Документы» (`CollapsibleSection` → `DocumentList`). Ширина колонки узкая, текст мелкий (`text-xs`).

Сценарий «неподдерживаемый формат»:
1. Пользователь жмёт плашку «+ Загрузить документ» → открывается системный файловый пикер.
2. В пикере **виден и выбираем** файл `.xls` / `.ods` / `.tsv` (раньше был серым/невидимым — пользователь не понимал, почему).
3. Пользователь выбирает такой файл → плашка переходит в «Загрузка…», сама плашка и input disabled.
4. Бэкенд отвечает 400 с человекочитаемым `detail` (см. предусловие `00-CATALOG-64-code-*`), например: «Формат .xls не поддерживается — пересохраните файл как .xlsx».
5. Под плашкой появляется красная строка ровно с этим текстом — без префикса `400 Bad Request`, без JSON, без `{"detail": ...}`. Пользователь понимает, что делать дальше.
6. Пользователь пересохраняет файл, жмёт плашку снова → при старте новой загрузки прежняя ошибка исчезает; при успехе документ появляется первым в списке.

Сценарий «битый файл»: тот же путь, но текст `detail` сообщает, что файл повреждён/не читается. UI-обработка идентична — отдельной ветки в компоненте нет.

Сценарий «валидный формат»: без изменений относительно текущего поведения (регрессий быть не должно).

## Дерево компонентов и файлы

Новых компонентов **нет**. Единственный изменяемый файл:

- `frontend/src/components/DocumentList.tsx`
  - `<label>` с плашкой загрузки → атрибут `accept` у вложенного `<input type="file">` расширяется.
  - `catch` в `onFile` → текст ошибки формируется через `extractApiDetail` из `../api.ts` (импорт добавляется; сейчас файл импортирует из `api.ts` только тип `DocumentOut`).
  - Строка ошибки `{err && <p className="text-xs text-danger-ink">{err}</p>}` → остаётся на месте, получает семантику алерта и перенос длинного текста (см. ниже).

Не трогаем: `useDocuments.ts` (`upload` пробрасывает ошибку наверх — это правильное разделение), `api.ts` (`extractApiDetail` уже даёт нужный контракт), `App.tsx`, разметку списка документов, `uploadDisabled`/`uploading` логику.

## Layout и состояния

Порядок блоков в `DocumentList` сохраняется: плашка загрузки → ошибка загрузки (`err`) → ошибка списка (`docs.error`) → `<ul>` документов. Ошибки не сливаются в один блок: у них разные источники и разное время жизни.

| Состояние | Что видно |
|---|---|
| idle | Плашка «+ Загрузить документ», пунктирная рамка, `text-ink-faint`; строки ошибки нет |
| uploading | Плашка «Загрузка…», `cursor-not-allowed`, `opacity-60`; строка ошибки скрыта (сброшена в начале попытки) |
| error | Плашка снова в idle; под ней одна строка `text-xs text-danger-ink` с текстом `detail` |
| success | Строки ошибки нет; новый документ первым в `<ul>`, значение `input` сброшено |
| disabled (нет воркспейса) | Плашка приглушена, input `disabled`; загрузка не стартует, ошибка не появляется |

Ключевые требования к блоку ошибки:
- Текст `detail` может быть длинным (полтора-два предложения с подсказкой) и содержать длинные токены вроде `.xlsx`. В узком сайдбаре он обязан переноситься и не расширять колонку: к существующим классам добавить перенос по словам (`break-words`).
- Блок остаётся однострочным `<p>` — никаких карточек, рамок, иконок и кнопки «закрыть». Плашка ошибки уже существует, дизайн её не переизобретает.

## Взаимодействия

- **Клик по плашке** (и `Space`/`Enter` при фокусе на input) → системный пикер.
- **`accept`** = `".md,.docx,.pdf,.csv,.xlsx,.xls,.ods,.tsv"`. Порядок: сначала поддерживаемые форматы, затем три «объяснимо отвергаемых» — так список в пикере читается как «что вообще имеет смысл нести сюда».
- `accept` — только фильтр-подсказка ОС; пользователь всё равно может выбрать любой файл через «All files». Поэтому текст ошибки — основной, а не запасной механизм объяснения. Клиентской валидации расширения перед отправкой **не добавляем**: единственный источник правды о поддерживаемых форматах — бэкенд.
- **Повторная попытка** сразу после ошибки: `input.value` сбрасывается в `finally`, поэтому выбор того же файла повторно триггерит `change`; `setErr(null)` в начале `onFile` гарантирует, что пользователь не смотрит на старый текст во время новой загрузки.
- **Отмена пикера** → `onFile(undefined)` → ничего не меняется, прежняя ошибка остаётся видимой (осознанно: пользователь ещё не начал новую попытку).
- **Крайние случаи текста:** если ошибка не сетевая/не `ApiError` (например, `TypeError: Failed to fetch`), `extractApiDetail` вернёт `message` — это допустимо, отдельной обработки не проектируем.

## Стиль и токены

- Никаких новых токенов и зависимостей. Используем существующие: `text-xs`, `text-danger-ink` (`--danger-ink: #a63838`), `flex flex-col gap-2` контейнера.
- Плашка загрузки: классы не меняются (`rounded-md border border-dashed border-line-strong px-3 py-2 text-center text-xs`, состояния через `cursor-*`/`opacity-60`/`hover:border-line-brand`).
- Ошибка: `text-xs text-danger-ink break-words`. Фон/рамку (`bg-danger-soft`, `border-danger-line`) **не добавляем** — в сайдбаре такие плашки нигде не используются (сравнить `SkillsPanel`, `SessionsPanel`: там тоже голый `p.text-xs.text-danger-ink`). Насыщенный вариант с рамкой в проекте зарезервирован за модалками и чатом (`Chat.tsx`, `WorkspacePicker.tsx`).
- Тональность текста задаёт бэкенд; UI не приписывает свои префиксы вида «Ошибка:» — `detail` уже самодостаточен.

## Доступность (a11y)

Обязательно:
- Строке ошибки загрузки дать `role="alert"` — сообщение появляется как результат действия пользователя и должно озвучиваться немедленно. Паттерн уже есть в проекте (`SetupKeyScreen.tsx:146`, `SettingsPanel.tsx:363`).
- Контраст: `text-danger-ink` на `--surface` — уже используемая в проекте пара, дополнительных проверок не требуется.
- Ошибка не должна перехватывать фокус: фокус остаётся там же, где был (на плашке/input).

Рекомендуется, но **не является критерием приёмки** (можно сделать, если не тянет за собой правок раскладки): сейчас `<input type="file">` скрыт классом `hidden` (`display: none`), из-за чего он не фокусируется с клавиатуры и объявленный на `<label>` `focus-within:ring-2` никогда не срабатывает — плашка недоступна без мыши. Замена `hidden` на `sr-only` чинит это без визуальных последствий.

## Контракты данных

- `POST /documents` (`uploadDocument` в `api.ts`) при отказе бросает `ApiError`, у которого `detail` — уже распарсенный человекочитаемый текст (`api.ts:57-67`).
- `extractApiDetail(e)` (`api.ts:104-116`) — единственный разрешённый способ получить текст для показа: для `ApiError` берёт `e.detail`, для прочих ошибок деградирует до `message`. Прямое использование `e.message` в `DocumentList` запрещено.
- Тексты `detail` для `.xls` / `.ods` / `.tsv` и битых файлов приходят из шага `docs/plan/2-shift/00-CATALOG-64-code-upload-content-validation.md`. Фронтенд их **не дублирует и не хардкодит**.
