# CATALOG-39 — Дизайн UI

- **Источник:** `docs/plan/night-shift/CATALOG-39-ui-skill-param-doc-select.md`
- **Статус дизайна:** Ready

> **Важно для генератора/ревьюера:** первичный фикс `DocumentCombobox` (удаление `onBlur` на root div, проп `placement`) уже выполнен в шаге CATALOG-28 (коммит `aaee19e`) и слит в текущую ветку — проверено: в `frontend/src/components/DocumentCombobox.tsx` обработчика `onBlur` на корневом `<div>` **нет**, outside-listener на `mousedown` (`:39-49`) и Escape на триггере (`:116-121`) и listbox (`:137-143`) на месте. Этот шаг CATALOG-39 — **regression-чек** по трём вариантам слотов параметров скила в `SkillsPanel`. Если в regression-проверке всплывёт необходимость дополнительной правки — её описание минимально и сосредоточено в разделе «Взаимодействия → Граничные случаи».

## Цель и пользовательский путь

Сценарий — пользователь в `SkillsPanel` выбирает документы для запуска скила с разными `input_arity`. После выбора должны активироваться кнопки «В док» / «На экран», а выбранные значения — корректно отображаться в слотах. Три варианта параметров скила:

- **`input_arity=1`** — один слот, single-выбор (`SkillsPanel.tsx:367-377`). Юзер раскрывает список → кликает документ → слот заполняется, кнопка применения активируется, listbox закрывается (стандартное single-поведение).
- **`input_arity=2`** — два независимых single-слота «Документ 1» и «Документ 2» (`SkillsPanel.tsx:379-408`). Юзер заполняет оба; валидность требует, чтобы слоты **различались** (`isSelectionValid`, `SkillsPanel.tsx:46-52`). До выполнения условия под слотами показывается amber-подсказка.
- **`input_arity=null`** — multi-слот, чекбоксы (`SkillsPanel.tsx:410-421`). Юзер кликает несколько пунктов → чекбоксы обновляются, listbox остаётся открытым, счётчик `(${docIds.length})` на кнопках отражает количество.

Регрессионный сценарий — `composer` чата (CATALOG-28): выбор документов для контекста сообщения продолжает работать после правок этого шага.

Шаги пользователя (каждый вариант) расписаны в разделе «Взаимодействия».

## Дерево компонентов и файлы

Новых компонентов нет. Изменения в коде **не планируются** (фикс уже на месте); компоненты перечислены ниже как контракты для regression-тестирования.

- `frontend/src/components/SkillsPanel.tsx` — **не меняется**. Три блока отрисовки слотов уже корректны:
  - `arity === 1` — `<DocumentCombobox value/onChange>` single-режим, control через `setSlots(s.id, 1, [id])` (`:370-376`).
  - `arity === 2` — два `<DocumentCombobox value/onChange>` single-режима, control через `setSlots(s.id, 2, [id, slots[1] ?? null])` и `[slots[0] ?? null, id]` (`:383-404`).
  - `arity === null` — один `<DocumentCombobox multiple values/onChange>`, control через `setSlots(s.id, null, ids)` (`:413-420`).
  - Валидность: `isSelectionValid(arity, slots)` (`:44-55`); hint для `arity=2`: `mode2Hint(slots)` (`:102-108`).
- `frontend/src/components/DocumentCombobox.tsx` — **не меняется**. Фикс CATALOG-28 уже слит (`onBlur` удалён, `placement` добавлен, default `'bottom'`). Все вызовы из `SkillsPanel` берут дефолтный `placement='bottom'` — раскрываются вниз, как раньше.
- `frontend/src/components/Chat.tsx` — **не меняется**. Composer использует `placement="top"` (фикс CATALOG-28). Регрессия: выбор документов в multiple-режиме продолжает работать.

> Если regression-проверка вскроет необходимость правки — она ограничивается `DocumentCombobox.tsx` и не должна касаться `SkillsPanel.tsx` (логика слотов верная, ломается только сам комбо, как в CATALOG-28).

## Layout и состояния

Структура карточки скила в `SkillsPanel` (не меняется, контекст для regression-чеков):

```
<li>  карточка скила
  ├─ заголовок (имя / rename-input) + теги + статус
  ├─ description (optional)
  ├─ SkillModelMeta (optional)
  └─ action row:
       [Редактировать] [Коммит (если draft)] [Удалить/confirm]
       └─ если status === 'committed':
            ├─ "нет документов"              ← documents.length === 0
            ├─ arity=1: блок "Документ"      ← DocumentCombobox single
            ├─ arity=2: блок "Документ 1" + "Документ 2" + optional hint
            └─ arity=null: блок "Документы"  ← DocumentCombobox multiple
            ↓
            [В док (N)]  [На экран (N)]      ← disabled, пока !valid
```

Состояния `DocumentCombobox` (для каждого из трёх вариантов слотов):

- **closed, value=null** — триггер показывает `placeholder` («Выберите документ» / «Выберите документы»). Цвет подписи `text-slate-500`.
- **closed, value выбран** — single: триггер показывает `title` выбранного документа. Multiple: подпись `${values.length} выбрано`. Кнопки применения активируются, если `isSelectionValid` проходит.
- **open, has results** — listbox под триггером (`placement='bottom'`): инпут поиска сверху, под ним опции (single: `<div role="option" onClick>`; multiple: `<label>` с `<input type="checkbox">`). Выбранная опция подсвечена: single — `bg-indigo-600/20 text-white`; multiple — `checked` + `aria-selected="true"`.
- **open, empty filter** — под инпутом поиска: текст `нет совпадений` (`px-2 py-1 text-[11px] text-slate-500`).
- **disabled** — триггер `disabled`, `aria-disabled`, opacity-50. В `SkillsPanel` комбобокс не передаёт `disabled` (отключается только кнопка применения через `disabled={!valid || documents.length===0}`).

Состояния валидности и UI-эффект:

- **`arity=1`** — валидно, когда `slots[0] != null`. До выбора: кнопки «В док» / «На экран» disabled. После: активны.
- **`arity=2`** — валидно, когда `slots.length===2 && slots[0] && slots[1] && slots[0] !== slots[1]`. Под слотами может быть hint:
  - оба null/один null → `Выберите два разных документа` (`text-[10px] text-amber-400`, `:105-106`).
  - равные id → `Документы должны отличаться` (`:106`).
  - разные id → hint не показывается, кнопки активируются.
- **`arity=null`** — валидно, когда выбран ≥1 документ. Подписи кнопок: `В док (N)` / `На экран (N)`, где N = `docIds.length` (`:429-430, 437-438`).

Loading-состояние не нужно — `documents: DocumentOut[]` приходит синхронно как проп. Error-состояние уровня карточки отсутствует (ошибки `skills.error` рисуются выше списка, `:182`).

## Взаимодействия

Базовые механизмы (все уже реализованы в `DocumentCombobox`, фикс CATALOG-28 на месте):

- **Клик по триггеру** — toggle `open`. При открытии поле поиска получает `autoFocus`.
- **Клик по option single** — `onChange(d.id)` + `close()`. Listbox закрывается после выбора (стандартное single-поведение).
- **Клик по option multiple (label или checkbox)** — `toggleMulti(d.id)` → `onChange(nextIds)`. Listbox остаётся открытым.
- **Ввод в поиск** — `setFilter(value)`, фильтрация по `title.toLowerCase().includes(q)`.
- **Escape** (на триггере или внутри listbox) — `close()` + возврат фокуса на триггер.
- **Клик вне rootRef** — outside-listener на `mousedown` → `close()`.

Regression-сценарии (это и есть основной скоуп шага):

### Сценарий A — `input_arity=1`

1. В `SkillsPanel` найти скил со `status='committed'` и `input_arity=1`. Убедиться, что отрисован ровно один блок «Документ» с single-`DocumentCombobox`.
2. Раскрыть список → кликнуть любой документ → listbox закрывается, триггер показывает `title` документа.
3. Кнопки «В док» / «На экран» активируются (без суффикса-счётчика, N=1).
4. Раскрыть список снова → кликнуть другой документ → значение в слоте заменяется, триггер обновляется, listbox закрывается. Старый выбор не «прилипает».
5. С фильтром: ввести подстроку → кликнуть по отфильтрованному пункту → выбор записывается корректно.

**Приёмка:** после шага 3 кнопки активны; после шага 4 слот содержит новое значение, валидность сохраняется.

### Сценарий B — `input_arity=2`

1. Найти скил с `input_arity=2`. Отрисованы два независимых блока: «Документ 1» и «Документ 2», каждый со своим single-`DocumentCombobox`. Под ними — hint «Выберите два разных документа», кнопки применения disabled.
2. Раскрыть «Документ 1» → выбрать документ A → слот 0 = A. Hint остаётся, кнопки disabled (слот 1 пуст).
3. Раскрыть «Документ 2» → выбрать документ B (B ≠ A) → слот 1 = B. Hint исчезает, кнопки «В док» / «На экран» активируются (без суффикса N=1, т.к. `docIds.length` для arity=2 на кнопке не показывается — см. `:430, 438`).
4. Граничный: выбрать в «Документ 2» тот же документ A → hint «Документы должны отличаться», кнопки снова disabled.
5. Сменить выбор в любом слоте на другой документ → валидность восстанавливается.
6. С фильтром в каждом слоте: выбор после фильтрации работает.

**Приёмка:** шаг 3 → кнопки активны и hint убран; шаг 4 → hint обновляется и блокирует запуск; шаг 5 → валидность восстанавливается без перезагрузки страницы.

### Сценарий C — `input_arity=null` (multi)

1. Найти скил с `input_arity=null`. Отрисован один блок «Документы» с `<DocumentCombobox multiple>`.
2. Раскрыть список → кликнуть (по чекбоксу **или** по тексту `<label>`) документ A → чекбокс A отмечается, listbox остаётся открытым, триггер показывает `1 выбрано`, кнопки «В док (1)» / «На экран (1)» активируются.
3. Кликнуть документ B → счётчик `2 выбрано`, подписи кнопок `В док (2)` / `На экран (2)`.
4. Кликнуть A повторно → галка снимается, счётчик декрементируется до `1 выбрано`, подписи кнопок `В док (1)` / `На экран (1)`.
5. Снять последний → счётчик `0 выбрано`, триггер показывает placeholder, кнопки снова disabled.
6. С фильтром: ввести подстроку → клики по отфильтрованным пунктам корректно переключают выбор.

**Приёмка:** шаги 2-4 — счётчик и состояние чекбоксов синхронны с выбором; шаг 5 — валидность корректно откатывается; шаг 6 — фильтр не ломает выбор.

### Сценарий D — регрессия по composer'у (CATALOG-28)

1. Открыть чат сессии → в composer внизу раскрыть `+ документ` (multiple, `placement="top"`).
2. Кликнуть 2 документа → появляются чипы над текстерой, подпись триггера `2 выбрано`.
3. Снять выбор через клик по пункту и через `×` на чипе — оба пути работают.

**Приёмка:** поведение composer идентично состоянию после CATALOG-28.

### Граничные случаи

- **`documents.length === 0`** — в карточке `committed`-скила показывается текст «нет документов» (`:364-366`), слоты не отрисовываются, кнопки применения hidden/disabled. Проверить для всех трёх `input_arity`.
- **Документ пропал из списка между выборами** — `filterValidSlots` (`:40-42`) и `slotsFor` (`:127-141`) фильтруют невалидные id при следующем рендере. Проверить, что при удалении документа выбранный слот корректно очищается (или валидность перепадает).
- **`defaultDocId` предзаполнен** (`arity=1`, `defaultSlots`, `:33-34`) — при первом рендере слот уже заполнен, кнопки активны. Проверить, что пользователь может сменить выбор.
- **Быстрое переключение фокуса между двумя слотами `arity=2`** — оба listbox могут быть открыты одновременно (они независимы). Закрытие одного не должно ломать другой.
- **Поиск, не возвращающий результатов** — список показывает «нет совпадений», кликов нет, выбор не меняется.

> Если в regression-проверке всплывёт новый баг, требующий правки кода, скоуп ограничивается `DocumentCombobox.tsx` и должен быть **минимальным** (как в CATALOG-28). Правки `SkillsPanel.tsx` в этом шаге не предусматриваются — логика слотов верная.

## Стиль и токены

Стек — Tailwind v3 (ADR-0011). Новых зависимостей и токенов нет. Изменений визуала не планируется — все регрессионные чеки сверяются с **уже существующим** визуальным языком `SkillsPanel` + `DocumentCombobox`.

Контрольные классы (для UI-ревьюера, что должно остаться как есть):

- Карточка скила: `rounded-md border border-slate-800 bg-slate-900/60 p-2`.
- Подписи слотов: `mb-0.5 text-[11px] text-slate-400` («Документ» / «Документ 1» / «Документ 2» / «Документы»).
- Hint для `arity=2`: `text-[10px] text-amber-400`.
- Триггер `DocumentCombobox` (default): `flex w-full items-center justify-between rounded bg-slate-800 px-2 py-1 text-left text-[11px] text-slate-100 disabled:opacity-50`.
- Listbox: `absolute z-10 max-h-48 w-full overflow-y-auto rounded border border-slate-700 bg-slate-900 shadow-xl mt-1` (`placement='bottom'`).
- Кнопки применения: `rounded bg-indigo-600 px-2 py-1 text-[11px] text-white disabled:opacity-50` («В док») и `rounded bg-slate-700 px-2 py-1 text-[11px] text-slate-200 disabled:opacity-50` («На экран»).

Консистентность с существующим UI: те же `slate-800/900`, `border-slate-700/800`, `text-[11px]`, `indigo-600` для primary-действия. Отклонений нет.

## Доступность (a11y)

Минимум для среза — без расширения относительно текущего кода. Все перечисленное уже реализовано в `DocumentCombobox` и `SkillsPanel`, регрессия не должна его ломать:

- Триггер `<button type="button" role="combobox" aria-haspopup="listbox" aria-expanded={open} aria-controls={listId} aria-label={ariaLabel}>`.
- Listbox: `<div role="listbox" aria-multiselectable={multiple || undefined}>`.
- Опции: single — `<div role="option" aria-selected={selected}>`; multiple — `<label role="option" aria-selected={selected}>` с вложенным `<input type="checkbox">`.
- **Клавиатура:**
  - Escape — закрывает listbox и возвращает фокус на триггер.
  - Tab — естественный порядок: триггер → поиск (autoFocus) → чекбоксы (multiple) / опции (single).
  - Стрелки/Enter-on-option **не предусмотрены** (так и в текущем коде, вне скоупа).
- **Фокус после закрытия** — на триггер (возвращает `rootRef.current?.querySelector('button')?.focus()`).
- **Контраст** — без новых пар; все используемые `slate-100/200/300` на `slate-800/900` уже прошли визуальный приём.
- Дежурное: `aria-disabled={disabled || undefined}` на триггере.

## Контракты данных (если нужны)

Без изменений. Перечислено как контракт для regression-тестирования:

- `SkillsPanel` получает `documents: DocumentOut[]`, `defaultDocId: string | null`, колбэки `onApply(skillId, docIds, mode)`, `onEdit`, `onDelete`, `onRename`.
- `input_arity` на `SkillOut` (`frontend/src/api.ts:21,77`) определяет отрисовку слотов: `1` → single, `2` → two single, `null` (или иное) → multi (`skillArity`, `SkillsPanel.tsx:23-26`).
- `DocumentCombobox` общий компонент: single-вариант — `value: string | null, onChange: (id: string | null) => void`; multiple — `values: string[], onChange: (ids: string[]) => void`. Никаких новых пропсов не вводится.
- Кнопка применения шлёт `onApply(s.id, docIds, 'persist' | 'preview')`, где `docIds = applyDocIds(arity, slots)` (`:94-100`).

Дизайн **не вводит** новых типов, эндпоинтов или WS-контрактов. Весь UI-контракт остётся как в CATALOG-28 + существующая `SkillsPanel`.

## Критерии визуальной приёмки

- [ ] **`input_arity=1`**: клик по документу в single-слоте записывает значение, триггер показывает `title`, listbox закрывается; кнопки «В док» / «На экран» активируются.
- [ ] **`input_arity=1`**: повторный выбор другого документа заменяет значение в слоте (не накапливается).
