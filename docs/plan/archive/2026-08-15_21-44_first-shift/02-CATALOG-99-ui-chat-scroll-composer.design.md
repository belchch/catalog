# CATALOG-99 — Дизайн UI

- **Источник:** `docs/plan/first-shift/02-CATALOG-99-ui-chat-scroll-composer.md`
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Экран — главный экран планировщика: `header` → `.catalog-layout` (сайдбар + `main`) → колонка чата (`Chat.tsx`) и колонка черновика.

Целевой контракт один и тот же во всех сценариях: **окно не скроллится никогда**, скроллятся только внутренние области (лента чата, сайдбар, тело черновика), композер всегда виден внизу колонки чата.

Сценарии:

1. **Новая сессия.** Пользователь жмёт «Новый чат». Колонка чата занимает всю высоту `main`: сверху пустая лента с empty-state («Опишите задачу для документа…»), внизу — карточка композера. Пустого белого блока под композером нет, композер не всплывает к верхнему краю.
2. **Сессия с историей.** Пользователь открывает сессию из сайдбара — лента сразу показана прокрученной **в самый низ** (последнее сообщение видно без действий), композер под ней. Прокрутка колёсиком двигает только ленту; шапка, сайдбар и композер стоят на месте.
3. **Отправка и стриминг.** Пользователь отправляет сообщение — пузырь появляется внизу ленты, лента доскроллена до низа, индикатор «●●● планировщик думает…» виден. Пока идут чанки, лента продолжает держаться низа; ни окно, ни `main` при этом не смещаются.
4. **Рост композера.** Пользователь набирает многострочный текст (или в композере появляются чипы документов сессии, быстрые ответы, блок ошибки сборки) — композер растёт вверх, лента ужимается, кнопка «Отправить» остаётся в кадре. Textarea перестаёт расти на `max-h-40` и дальше скроллится сама.
5. **Ниже `lg`.** Чат и черновик — табы. Активный таб занимает ту же полную высоту `main`, композер прижат к низу.

## Дерево компонентов и файлы

Новых компонентов, классов-обёрток и зависимостей нет. Меняется только цепочка высот в существующей разметке и логика автоскролла.

- `frontend/src/components/Chat.tsx`
  - Заменить `bottomRef` (sentinel-div в конце ленты) на `scrollRef` — ref **на сам контейнер** `.catalog-chat__scroll`. Sentinel `<div ref={bottomRef} />` (`Chat.tsx:162`) удалить: он больше не нужен и его наличие провоцирует возврат к `scrollIntoView`.
  - Эффект автоскролла: guard на `messages.length === 0`, затем `el.scrollTop = el.scrollHeight` (или `el.scrollTo({ top: el.scrollHeight })`). Никаких `scrollIntoView`, никакого `behavior: 'smooth'`.
  - Классы высот: корень `.catalog-chat` — `flex h-full min-h-0 flex-col`; лента — `flex-1 min-h-0 overflow-y-auto`; баннер «Редактирование: …» и `.catalog-composer-area` — `shrink-0`.
- `frontend/src/App.tsx` — только добавление `min-h-0` в цепочке (перечислено в «Layout и состояния»); структура узлов, роли табов и условные классы `flex`/`hidden` не меняются.
- `frontend/src/index.css` — `.catalog-layout` получает ограничение строки грида (см. ниже). Остальные правила (`.catalog-composer-area`, `.catalog-composer`, ширины `.catalog-chat__content`) не трогать.

## Layout и состояния

### Контракт высот (сверху вниз)

Единственный источник высоты — `h-screen` на `.catalog-shell`; всё ниже только распределяет её и обязано уметь сжиматься.

| Узел | Требование |
| --- | --- |
| `.catalog-shell` (`App.tsx:582`) | без изменений: `flex h-screen flex-col` |
| `header`, `.catalog-notice` | `shrink-0` (у header уже есть; нотис не должен растягиваться) |
| `.catalog-layout` (`App.tsx:623`) | `flex-1 overflow-hidden` + в `index.css`: `min-height: 0; grid-template-rows: minmax(0, 1fr);` |
| `.catalog-main` (`App.tsx:741`) | добавить `min-h-0` (и `h-full`, если строка грида не даёт определённой высоты) |
| обёртка табов+колонок (`App.tsx:770`) | добавить `min-h-0` к `flex h-full flex-col overflow-hidden` |
| ряд колонок (`App.tsx:805`) | уже `flex min-h-0 flex-1 overflow-hidden` — оставить |
| панель чата (`App.tsx:806-814`) | добавить `min-h-0` к `min-w-0 flex-1 overflow-hidden` |
| внутренняя обёртка чата (`App.tsx:815`) | добавить `min-h-0` к `flex h-full w-full flex-col overflow-hidden` |
| `.catalog-chat` (`Chat.tsx:115`) | добавить `min-h-0` |
| `.catalog-chat__scroll` (`Chat.tsx:121`) | добавить `min-h-0`, оставить `flex-1 overflow-y-auto` |
| `.catalog-composer-area` (`Chat.tsx:165`) | добавить `shrink-0` |
| колонка черновика (`App.tsx:846`) | добавить `min-h-0`; внутреннее содержимое (`h-full`) не менять |

Ключевой пункт — `grid-template-rows: minmax(0, 1fr)` у `.catalog-layout`. Одного `min-height: 0` мало: неявная строка грида имеет размер `auto` и растёт под контент `main`, поэтому `h-full` внутри резолвится в высоту **контента**, а не viewport — это и есть третья гипотеза плана. `minmax(0, 1fr)` жёстко приравнивает строку к высоте контейнера, после чего `h-full` у детей `main` становится осмысленным. `min-h-0` в остальных узлах снимает автоматический минимальный размер flex/grid-детей, чтобы лента могла сжиматься, а не распирать предка.

Порядок сжатия при нехватке высоты: сначала ужимается **лента** (`min-h-0`, вплоть до нуля), композер не сжимается и не уезжает за экран никогда. Рост composer-области ограничен собственным `max-h-40` у textarea; дополнительных `max-height` на `.catalog-composer` не вводить.

### Состояния колонки чата

- **Пусто (`messages.length === 0`)** — лента занимает всё свободное место, в ней текст empty-state (`mt-16 text-center`), композер внизу. Автоскролл **не выполняется**: эффект выходит по guard, `scrollTop` ленты и всех предков остаётся `0`.
- **История загружена** — лента прокручена в конец **мгновенно**, без видимой анимации проезда сверху вниз.
- **Стриминг** — лента держится низа на каждом обновлении `messages`; индикатор «думает…» — последний элемент ленты и виден целиком.
- **Ошибка / закрытое соединение** — блоки статуса и ошибки живут внутри ленты, участвуют в автоскролле, отдельного позиционирования не получают.
- **Загрузка приложения / нет воркспейса** — экраны-заглушки (`App.tsx:753`, `catalog-shell` при `setup.status === 'unknown'`) визуально не меняются, но так же не должны давать прокрутку окна.

Визуальных изменений (цвета, отступы, размеры карточек, ширина `min(100%, 965px)`) шаг не вносит: экран после фикса должен отличаться от текущего только положением композера и отсутствием прокрутки окна.

## Взаимодействия

- **Автоскролл** — единственный триггер: изменение `messages` (новое сообщение, чанк стриминга, смена сессии, гидрация истории). Скролл **только** контейнера `.catalog-chat__scroll` через `scrollTop`; ни один предок и `document.scrollingElement` не должны менять `scrollTop`.
- **Мгновенно, без `smooth`** — на стриминге эффект срабатывает десятки раз, плавная анимация не успевает завершиться и даёт дёрганье; мгновенный скролл детерминирован и снимает вопрос `prefers-reduced-motion`.
- **Ручная прокрутка вверх** — пользователь может уехать в историю; следующий приход `messages` вернёт ленту вниз. «Липкий низ» с эвристикой «скроллить только если пользователь у низа» — **вне скоупа шага**, не реализовывать.
- **Прокрутка колёсиком/тачпадом над лентой** — двигает ленту; при достижении границы прокрутка **не** передаётся окну (окно и так не имеет overflow).
- **Ввод в textarea** — авто-рост до `max-h-40`, дальше скролл внутри textarea; при росте композера лента ужимается, а не выталкивается.
- **Переключение табов ниже `lg`** — активная панель получает полную высоту `main`; скрытая (`hidden`) высоту не занимает и на скролл не влияет.
- **Переключение сессий / F5** — лента открывается внизу; композер сразу на своём месте, без кадра, где он вверху экрана.
- **Крайние случаи:** очень низкий viewport (лента почти нулевая) — композер целиком виден, лента прокручиваема; одно очень длинное сообщение — прокручивается только лента; блок ошибки сборки внутри композера появляется без выталкивания композера за экран.

## Стиль и токены

Tailwind v3 + существующие компонентные классы. Новых утилит, цветов и CSS-классов не вводить.

- Все правки — служебные утилиты раскладки: `min-h-0`, `shrink-0`, `h-full`, `flex-1`, `overflow-hidden`, `overflow-y-auto`. Ничего из визуального слоя (`px-*`, `py-*`, `text-*`, `bg-*`, `border-*`, `shadow-*`) не меняется.
- Единственное правило в `index.css` — `grid-template-rows: minmax(0, 1fr)` рядом с существующим `min-height: 0` у `.catalog-layout` (`index.css:211`). Альтернатива утилитой `lg:grid-rows-[minmax(0,1fr)]` в разметке допустима, но правило в CSS предпочтительнее: там уже живёт `min-height: 0` того же узла, и правило действует одинаково на обоих брейкпоинтах.
- `.catalog-composer-area` сохраняет `background: var(--composer-fade)` и `padding-bottom: 20px` — визуальный «подпор» композера снизу остаётся прежним.
- `h-screen` (100vh) сохраняется. Переход на `100dvh` ради мобильной адресной строки — **вне скоупа**.

## Доступность (a11y)

- Лента становится единственной областью прокрутки, поэтому она обязана быть достижима с клавиатуры: `.catalog-chat__scroll` получает `tabIndex={0}` и `aria-label="История сообщений"` (с `role="region"`, чтобы фокусируемый контейнер имел роль). Без этого пользователь клавиатуры теряет доступ к истории — раньше её «спасала» ошибочная прокрутка документа.
- `aria-live` на ленте **не** ставить: стриминг зачитывался бы посимвольно. Живые объявления остаются на существующих узлах — статус соединения (`role="status" aria-live="polite"`) и блок ошибки сборки (`role="alert"`).
- Автоскролл не должен перемещать фокус: после отправки фокус остаётся в textarea, программный скролл контейнера фокус не трогает.
- Порядок табуляции не меняется: лента добавляется как один стоп перед элементами композера, порядок «лента → чипы/комбобокс → textarea → отправить → создать скилл» соответствует визуальному.
- Видимый фокус на ленте — существующая связка `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand`, как у остальных интерактивных узлов.
- Контраст и токены не затрагиваются.

## Контракты данных

API/WS не участвуют. Единственный вход UI — проп `messages: PlannerMessage[]` (`usePlannerSession`): его изменение (новый элемент или мутация последнего при стриминге) служит триггером автоскролла. Сигнатуры пропсов `Chat` не меняются.

DOM-контракт, на который опирается ручная и автоматическая проверка:

- `.catalog-chat__scroll` — единственный элемент колонки чата с ненулевым `scrollTop`.
- `document.scrollingElement.scrollTop === 0`, `.catalog-layout.scrollTop === 0`, `.catalog-main.scrollTop === 0` в любой момент.
- `.catalog-chat` и `.catalog-main` имеют вычисленную высоту, равную доступной высоте `main` / строки грида, а не высоте контента.
