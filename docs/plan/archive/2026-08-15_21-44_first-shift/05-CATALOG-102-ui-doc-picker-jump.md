# CATALOG-102 — Дропдаун документов «прыгает» при выборе нескольких документов подряд

- **Задача Plane:** [CATALOG-102](https://app.plane.so/belchch/projects/catalog-app/work-items/102) (id: `4f6debdc-13a3-445a-87d9-afca8127fe01`, state: In Progress)
- **Статус плана:** Analyzed
- **Тип шага:** ui
- **Очередь:** 05 · независимый
- **Цель:** Пока пикер документов открыт, панель не едет за чипами: чекбоксы остаются под курсором, composer не скачет по высоте при выборе и при появлении «Документы в сессии».

## Постановка задачи (актуальное ТЗ)
_(источник: описание задачи — комментариев не было)_

Открытая панель «+ документ» после каждого чекбокса смещается; смещение копится с числом выбранных. Ожидание: положение панели относительно viewport стабильно, 5 документов подряд без перенаведения, панель не обрезается, рост «Документы в сессии» и повторный refresh списка после send не дёргают composer.

Гипотезы: чипы и триггер в одном `flex-wrap`; панель `absolute` + `bottom-full` без portal; секция сессии монтируется с нуля; подпись триггера `+ документ` → `N выбрано`; двойной апдейт `sessionDocuments` (WS + finish GET).

## Контекст
Чипы и пикер в одной wrap-строке — каждый чип двигает триггер:

```190:218:frontend/src/components/Chat.tsx
        <div className="mb-2 flex flex-wrap items-center gap-1.5">
          {selectedDocs.map((d) => (
            <span key={d.id} className="chip-brand">...</span>
          ))}
          <div className="w-44 max-w-[12rem]">
            <DocumentCombobox ... placement="top" />
          </div>
        </div>
```

Панель привязана к `relative` корню триггера, не к viewport:

```97:136:frontend/src/components/DocumentCombobox.tsx
    <div ref={rootRef} className="relative">
      ...
        <div className={
            'absolute z-10 max-h-48 w-full ... ' +
            (placement === 'top' ? 'bottom-full mb-1' : 'mt-1')
          }
```

Подпись триггера (`:76-79`) меняет ширину. «Документы в сессии» (`Chat.tsx:163`) рендерится только при `length > 0` — первый документ даёт скачок (для выбора в композере это ещё не session docs, но после send — да). Двойной set в `usePlannerSession.ts:185-212` (`session_docs` + GET на `finish`) перестраивает ту же секцию дважды. Связано с CATALOG-90, но здесь цель — стабильность раскладки, не гонка списка.

`DocumentCombobox` ещё используется вне Chat (скиллы и т.п.) — portal/fixed не должны ломать `placement="bottom"` и single-select.

## Затрагиваемые файлы
- `frontend/src/components/Chat.tsx` — вынести триггер из wrap-потока чипов (отдельная строка / `shrink-0` якорь); не монтировать секцию сессии скачком (резерв высоты или всегда рендерить обёртку).
- `frontend/src/components/DocumentCombobox.tsx` — пока `open`, фиксировать позицию панели (portal + координаты на момент открытия, или не двигать при смене `values`); стабильная ширина триггера (`min-w` / не менять label пока открыт).
- `frontend/src/hooks/usePlannerSession.ts` — только если после UI-якоря останется двойной скачок секции: не вызывать finish-GET, если список уже равен ответу `session_docs`. Не раздувать хук без необходимости.

## План действий
1. Отвязать якорь пикера от wrap чипов: чипы в своём ряду, триггер `+ документ` на стабильном месте (первая колонка / отдельная строка). Пока панель открыта, рост чипов не двигает `rootRef`.
2. В `DocumentCombobox` при `open`: либо portal/`position: fixed` от `getBoundingClientRect()` триггера на open (обновлять только при scroll/resize, не при `values`), либо оставить absolute, но якорь из п. 1 достаточен — проверить оба, взять меньший дифф. Клик-outside (`:39-49`) должен учитывать portal-узел.
3. Пока `open && multiple`, не менять ширину триггера: оставить «+ документ» или зарезервировать `min-w` под «N выбрано».
4. Секция «Документы в сессии»: не давать нулевой→полный скачок (постоянный слот / `min-height` / рендер заголовка всегда). После send — один визуальный апдейт списка (сравнить id до `setSessionDocuments` на `finish`).
5. Ручная проверка: 0 / 1 / 5 / 10+ чипов; 5 чекбоксов подряд без движения мыши; панель в пределах окна; send не дёргает composer дважды. Single-select / `placement="bottom"` в других местах не регрессируют.

## Критерии приёмки (Definition of Done)
- [ ] Открытая панель не смещается при выборе — проверено на 0, 1, 5 и 10+ чипах.
- [ ] Пять документов подряд отмечаются без перенаведения курсора.
- [ ] Панель не обрезается и не выходит за окно при любом числе чипов.
- [ ] Появление и рост «Документы в сессии» не дают видимого скачка composer.
- [ ] После одной отправки список сессии обновляется без повторных перестроений раскладки.
- [ ] Single-select и `placement="bottom"` у того же combobox работают как раньше.
