# CATALOG-45 — Дизайн UI

- **Источник:** docs/plan/night-shift/CATALOG-45-ui-skill-modal-defaults.md
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Пользователь уже выбрал в шапке (`ModelSelector`) провайдера и модель — это его «рабочий» выбор. Когда он открывает модалку настройки скилла для нового/несконфигурированного скилла, поля «Провайдер» и «Модель» должны быть уже заполнены этим глобальным выбором, а не пустыми. Для старого скилла с явно заданными значениями приоритет остаётся за значениями скилла.

Сценарий:
1. В шапке выбраны, например, `openrouter` + модель `X`.
2. Пользователь создаёт скилл через planner и открывает модалку настройки.
3. Модалка открывается: «Провайдер» = `openrouter`, «Модель» = `X` — заполнены сразу, без ручного выбора.
4. Пользователь при желании меняет значения и жмёт «Сохранить»; либо сразу сохраняет предзаполненные.
5. Открытие старого скилла с сохранёнными `preview.provider`/`preview.model` показывает именно значения скилла.

Это чисто визуально-инициализирующее изменение: раскладка, набор полей и поведение сохранения не меняются — меняется только источник начальных значений двух полей.

## Дерево компонентов и файлы

- `frontend/src/components/SkillSettingsModal.tsx` (изменяемый) — модалка настройки скилла. Добавляются два props `defaultProvider: string`, `defaultModel: string`; они участвуют только в инициализации `useState` полей «Провайдер» и «Модель». Разметка не меняется.
- `frontend/src/App.tsx` (изменяемый) — место рендера модалки. Прокидывает `defaultProvider={settingsHook.provider}` и `defaultModel={settingsHook.model}`.
- `frontend/src/components/ModelCombobox.tsx` (без изменений) — используется как есть для поля «Модель».

Новых компонентов и зависимостей нет.

## Layout и состояния

Layout модалки без изменений: заголовок «Настройка скила» + кнопка закрытия, поля «Имя», «Вход» (radiogroup), «Провайдер» (`select`), «Модель» (`ModelCombobox`), «Режим рассуждений» (`select`), блок ошибки, кнопки «Отмена»/«Сохранить». Меняется только начальное значение двух полей.

Состояния поля «Провайдер»/«Модель» при открытии:
- **preview задан** (`preview.provider`/`preview.model` непустые) → поле показывает значение скилла (как сейчас). `defaultProvider`/`defaultModel` игнорируются.
- **preview пуст, глобальный выбор задан** → поле предзаполнено `defaultProvider`/`defaultModel`.
- **preview пуст и глобальный выбор пуст** (бэкенд ещё не ответил / нет провайдеров) → поле пустое, как раньше; «Провайдер» показывает опцию `(по умолчанию)`, комбобокс «Модель» — пустой/`disabled` до загрузки списков.
- **loading списков** (`listModels`/`listProviders` ещё грузятся) → значения полей уже проставлены из preview/defaults; сами списки опций подтягиваются асинхронно (поведение как сейчас). Предзаполненное значение показывается даже если элемент ещё не найден в списке.
- **error** загрузки списков → существующий блок ошибки под полями (`text-red-400`), без изменений.

Важно: глобальный выбор читается один раз при монтировании модалки (инициализация `useState`). Если пользователь меняет шапку, пока модалка открыта, поля не обновляются в реальном времени — это осознанное упрощение из плана (реактивный `useEffect` затирал бы ручной выбор пользователя). Новые значения подхватятся при следующем открытии модалки.

## Взаимодействия

- Открытие модалки: поля «Провайдер»/«Модель» инициализируются по правилу `preview.X || defaultX`.
- Ручное изменение «Провайдер»/«Модель»: работает как сейчас; смена модели сбрасывает «Режим рассуждений» (`setReasoning('')`).
- «Сохранить»: отправляет выбранные значения через `configureSkill` — контракт вызова не меняется (в т.ч. когда значения пришли из defaults, а не из preview).
- «Отмена»/закрытие: без изменений.
- Крайний случай: если предзаполненный `defaultModel` отсутствует в загруженном списке моделей (например, глобальный выбор относится к другому провайдеру, чем список в модалке) — комбобокс показывает сырое значение id, пользователь может переопределить. Это не регресс относительно текущего поведения и вне скоупа шага (смежная проблема несинхронного списка моделей отмечена в плане, не фиксится здесь).

## Стиль и токены

Изменений в стилях нет — переиспользуются существующие Tailwind-утилиты модалки:
- поля: `fieldCls = 'w-full rounded bg-slate-800 px-2 py-1 text-xs text-slate-100'`;
- подписи полей: `text-[11px] text-slate-400`;
- акцент/активные элементы: `bg-indigo-600 text-white`.

Консистентность с текущим UI сохраняется полностью, т.к. новых элементов не добавляется.

## Доступность (a11y)

Без регрессий; изменение чисто инициализирующее:
- существующие `aria-label` («Модель»), `role="radiogroup"`/`role="radio"` и `aria-checked` сохраняются;
- предзаполненные значения не меняют порядок фокуса и клавиатурную навигацию;
- контраст текста на полях (`text-slate-100` на `bg-slate-800`) не затрагивается.

## Контракты данных (если нужны)

- `settingsHook` (`useSettings`) в `App.tsx`: используем `settingsHook.provider` и `settingsHook.model` как источник дефолтов (см. план, App.tsx стр. 46). Оба — `string`, могут быть пустыми до загрузки бэкенда.
- `SkillPreview.provider` / `SkillPreview.model` — приоритетный источник, если непусты.
- `configureSkill(skillId, { model, provider, reasoning, input_arity, name })` — контракт сохранения без изменений.

## Критерии визуальной приёмки

- [ ] При открытии модалки для скилла с пустыми `preview.provider`/`preview.model` поля «Провайдер» и «Модель» показывают значения из глобальной шапки (`settingsHook.provider`/`settingsHook.model`).
- [ ] Для скилла с непустыми `preview.provider`/`preview.model` поля показывают значения скилла, а не шапки.
- [ ] Если и preview, и глобальный выбор пусты — поля пустые (`Провайдер` = `(по умолчанию)`, `Модель` пустая), без ошибок.
- [ ] Смена значения в шапке и повторное открытие модалки нового скилла → поля предзаполнены обновлённым выбором.
- [ ] Раскладка, набор полей, стили и кнопки модалки визуально идентичны текущим (изменены только начальные значения двух полей).
- [ ] Кнопка «Сохранить» отправляет предзаполненные значения без дополнительных действий пользователя.
