## Контекст

### Что сейчас

В существующем результате `backend/workspace/results/ea6cf3908d974e42b8b76485e86d2ca4.md` уже есть линки:
- `[[Экономия токенов]]`, `[[Стратегии оптимизации]]`, `[[Инструменты анализа]]`.

Эти линки сгенерированы LLM в результате skills. Obsidian их не разрешает, потому что физические имена файлов другие (`results/<uuid>.md`, `documents/<slug>-<id8>.md` или какой-то корневой документ).

### Где формируется результат

`backend/app/skills/apply.py`:

- Шаг формирования пользовательского промпта (стр. 225, 229): `Обработай документ {doc_id} ({docs[0].title})` — LLM получает `title` документа.
- Шаг персиста (стр. 296-315): `write_text(last_text or "")` — текст пишется **как есть**, без какой-либо пост-обработки линов.

Также аналогично в `backend/app/api/runs.py:118-126` (`save_run_result_endpoint`) — `write_text(run["result_text"])` без пост-обработки.

### Известные имена файлов для подмены

У нас есть `DocumentRow` с полями `id`, `title`, `path`, `kind`. `path` — это относительный путь внутри workspace, например `documents/cover-letter-spiiran-ntbvt-java-ea411722.md` или `results/56dfe0e9476248bf8d962e95ea2f0f81.md`. Stem = последняя компонента без расширения (`Path(path).stem`).

Для **входных документов** skills (`docs` в `apply.py`) мы их знаем сразу. Для **других документов, на которые LLM решит сослаться** — мы не знаем, что именно она имела в виду; помогает только эвристика: поиск по title среди всех документов.

### Подход

Гибрид:

1. **Передать в промпт инструкции** — указать LLM, что Obsidian-линки должны содержать **имя файла** (stem), и дать список `{title} → {stem}` для известных документов.
2. **Пост-обработка** — после генерации, перед `write_text`, пройтись по тексту и заменить `[[{title}]]` на `[[{stem}]]` для всех документов в workspace (не только входных). Это гарантия даже если LLM ошибётся.

Пост-обработка надёжнее — это детерминированный слой. Промпт лишь уменьшает количество замен.

## План действий

1. **Хелпер для подмены** — новый модуль `backend/app/documents/obsidian.py`:
   - `build_title_to_stem_map(db: Database) -> dict[str, str]` — для всех документов в `document` строит mapping `title → Path(path).stem`.
   - `rewrite_wiki_links(text: str, mapping: dict[str, str]) -> str` — заменяет `[[title]]` → `[[stem]]` для известных title. Использует regex `\[\[([^\]]+)\]\]`, аккуратно с alias-синтаксисом Obsidian (`[[file|alias]]`, `[[file#heading]]`) — обрабатывать только первый сегмент до `|` или `#`.
   - Если `title` в тексте не найден в mapping — оставить как есть (LLM могла сослаться на документ, которого нет в БД, но который физически существует в workspace; в первой итерации не лечим).
2. **Применить в `apply.py`** (`apply.py:296-315`):
   - После формирования `last_text`, до `write_text` — `last_text = rewrite_wiki_links(last_text, build_title_to_stem_map(db))`.
   - Записывать уже переписанный текст.
3. **Применить в `runs.py`** (`runs.py:118-126`):
   - В `save_run_result_endpoint` — `run["result_text"]` перечитать, переписать линки, сохранить в файл. **Не перезаписывать** `run["result_text"]` в БД (это оригинальный «displayed» текст) — переписывать только для файлового вывода.
4. **Прокачать промпт в `apply.py`** (стр. 225, 229): добавить в формулировку «если ссылаешься на документы Obsidian-линком `[[...]]`, используй **имя файла** (stem), а не title». Для контекста можно рядом передать mapping, но это уже на усмотрение исполнителя — основная гарантия через пост-обработку.
5. **Edge cases**:
   - Title дубликаты — если два документа имеют одинаковый title (редко, но возможно), mapping выбирает любой; это допустимо для первой итерации.
   - Title со спецсимволами `[`, `]` — regex должен корректно среагировать; покрыть тестом.
   - Уже корректный линк `[[stem]]` — не должен ломаться: mapping не содержит такого ключа → останется как есть.
   - Линки на заголовки `[[file#section]]` — обрабатывать только `file`, `#section` сохранять.
6. **Тесты**:
   - Создать документ с `title="Экономия токенов"`, `path="documents/ekonomiya-tokov-abc12345.md"`.
   - Вызвать `rewrite_wiki_links("[[Экономия токенов]] abc", mapping)` → ожидать `[[ekonomiya-tokov-abc12345]] abc`.
   - Тест alias-синтаксиса: `[[Экономия токенов|раздел]]` → `[[ekonomiya-tokov-abc12345|раздел]]`.
   - Тест `[[unknown]]` → `[[unknown]]` (без изменений).
   - В `test_apply.py`: после `apply_skill(persist=True)` проверить, что результат содержит `[[stem]]`, а не `[[title]]`.
