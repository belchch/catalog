# CATALOG-42 — Дизайн UI

- **Источник:** docs/plan/night-shift/CATALOG-42-ui-session-docs-controls.md
- **Статус дизайна:** Ready

## Цель и пользовательский путь

Пользователь работает в чате планировщика (`Chat.tsx`) и должен полностью управлять составом документов сессии прямо из composer-панели (низ чата), не открывая модалок и не покидая экран.

Сценарий:
1. Пользователь видит секцию «Документы в сессии» над строкой ввода — актуальный состав, доступный агенту.
2. Под заголовком есть короткая подпись «Агент видит только эти документы» — пользователь понимает, что сессия работает в scoped-режиме (агент не видит всю библиотеку, только этот список).
3. Пользователь наводит на пилюлю документа и нажимает `×` → документ мгновенно исчезает из списка (оптимистично), сетевой detach уходит в фоне.
4. Если detach упал — пилюля возвращается на место, показывается инлайн-сообщение об ошибке.
5. Когда агент/скилл создаёт новый документ в рамках сессии, он сам появляется в списке (через WS-кадр `session_docs`) без перезагрузки.
6. Если агент просит «добавьте документ X» (scoped-режим, документа нет в сессии) — пользователь добавляет его через уже существующий `DocumentCombobox` в той же панели; при отправке сообщения документ прикрепляется к сессии.
7. После переоткрытия сессии состав восстанавливается из `GET /sessions/{id}/documents`.

## Layout и состояния

Секция «Документы в сессии» остаётся на текущем месте — внутри composer-панели (`border-t`, `p-3`), над блоком suggestions и строкой ввода. Порядок сверху вниз внутри панели:

1. Заголовок секции + micro-copy.
2. Список пилюль документов сессии.
3. (существующее) suggestions.
4. (существующее) selectedDocs + `DocumentCombobox`.
5. (существующее) textarea + кнопка отправки/стоп.

Структура секции:

```
Документы в сессии            ← h2, uppercase, text-slate-500 (как сейчас)
Агент видит только эти документы   ← micro-copy, ещё тусклее заголовка
[ KIND  Название  × ] [ KIND  Название  × ] …   ← пилюли с кнопкой detach
```

Состояния:

- **empty (список пуст):** вся секция «Документы в сессии» не рендерится (условие `sessionDocuments.length > 0` сохраняется). Значит и заголовок, и micro-copy показываются только когда есть хотя бы один документ. Пустого плейсхолдера не добавляем — скоуп шага этого не требует.
- **default (есть документы):** пилюли со стилем текущих session-пилюль (нейтральный slate), у каждой — кнопка `×`.
- **removing (оптимистичное удаление):** пилюля убирается из списка немедленно, отдельного skeleton/спиннера на пилюле НЕТ (документ уже исчез). Отдельного «loading» состояния секции не вводим.
- **streaming:** кнопки `×` во всех session-пилюлях `disabled` (визуально `opacity-50`, `cursor` по умолчанию для disabled), клики игнорируются. Список при этом виден.
- **error (detach упал):** удалённая пилюля возвращается в список (rollback через re-fetch/setSessionDocuments в хуке), ошибка показывается в существующем инлайн-слоте ошибок чата (`error` из `usePlannerSession`, рендерится строкой `text-red-400` в области сообщений, стр. 142). Отдельный snackbar не вводим — консистентно с текущей обработкой ошибок.
- **success (автодобавление):** новый документ появляется как обычная пилюля при получении кадра `session_docs`; спец-подсветку «нового» документа не делаем (вне скоупа).

## Взаимодействия

- **Клик по `×` в session-пилюле:**
  - Немедленно вызывает `onRemoveDocument(d.id)`.
  - Хук оптимистично убирает документ из `sessionDocuments`.
  - Фоновый `removeSessionDocument`; при ошибке — rollback (re-fetch `getSessionDocuments`) и `setError`.
  - Подтверждения (confirm/модалки) НЕТ — detach не деструктивен (документ остаётся в глобальной библиотеке).
- **Наведение (hover):** цвет `×` усиливается (`text-slate-400 → hover:text-slate-100`), как у `×` в `selectedDocs`.
- **Во время `streaming`:** `×` disabled; сам список читаем, но неинтерактивен (по detach). Комбобокс добавления тоже уже disabled при streaming — поведение симметрично.
- **Добавление документа:** без изменений — через `DocumentCombobox` (draft-выбор `selectedDocs`), attach происходит при отправке сообщения (`doc_ids` в payload). Дизайн шага это не меняет, только опирается на существующее.
- **Крайние случаи:**
  - Двойной клик по `×`: после первого клика пилюля исчезает, повторный клик невозможен (элемента нет).
  - Detach документа, которого уже нет на бэке (404): бэкенд отдаёт 404 «document not attached» → трактуем как успех (пилюля и так убрана), ошибку не показываем.
  - Гонка «detach во время прихода `session_docs`»: источник истины — последний `session_docs`/re-fetch; оптимистичное состояние перетирается серверным списком.

## Стиль и токены

Переиспользуем существующие Tailwind-утилиты чата; новых цветов/зависимостей не вводим.

- **Пилюля session-документа (без изменений базы):** `inline-flex items-center gap-1 rounded-full border border-slate-700 bg-slate-800/60 px-2.5 py-1 text-xs text-slate-300`.
- **KIND-бейдж внутри пилюли (без изменений):** `rounded bg-slate-700/60 px-1 text-[10px] uppercase text-slate-400`.
- **Кнопка `×` (новая, копия паттерна из `selectedDocs`, стр. 191–200):** `ml-0.5 text-slate-400 hover:text-slate-100 disabled:opacity-50`, `type="button"`.
- **Micro-copy про scoped-режим:** отдельная строка под `h2`, тусклее заголовка и не доминирует: `mb-1 text-[11px] text-slate-600` (на тон тусклее, чем `text-slate-500` заголовка). Заголовок и подпись группируются, список идёт следом.
- **Отступы:** сохранить текущие (`mb-1` у заголовка, `gap-1.5` у списка, `mb-2` у секции). Micro-copy не должна раздувать высоту панели — одна строка, без переноса на нормальной ширине.

Консистентность: session-пилюли остаются нейтральными (slate), draft-пилюли выбора (`selectedDocs`) — акцентные (indigo). Это визуально разделяет «уже в сессии» и «черновой выбор для отправки» — сохраняем текущее различие.

## Доступность (a11y)

- Кнопка `×` detach: `type="button"`, `aria-label="Убрать {title} из сессии"` (осмысленно и уникально по документу; отличается от draft-варианта `Убрать {title}`, чтобы screen reader различал контексты).
- Кнопка `×` фокусируема с клавиатуры и активируется Enter/Space (нативная `<button>`), в DOM-порядке идёт после названия документа внутри пилюли.
- `disabled` при `streaming` корректно снимает элемент из tab-порядка (нативный `disabled`).
- Секция сохраняет `aria-label="Документы в сессии"`; список — `role="list"`, элементы — `role="listitem"` (как сейчас).
- Micro-copy — обычный текст (не отдельная aria-роль); достаточно того, что она визуально и в потоке чтения следует за заголовком секции.
- Контраст: `text-slate-600` на тёмном фоне — вспомогательный текст; допустимо для non-essential подписи, но она дублирует смысл, уже понятный из UI (не является единственным носителем критичной информации).

## Контракты данных (если нужны)

- **DELETE** `/sessions/{sessionId}/documents/{docId}` → `204` (успех) / `404` «document not attached» (трактуем как успех). Клиент: `removeSessionDocument(sessionId, docId)` в `api.ts` (см. план, п. 1).
- **GET** `/sessions/{id}/documents` → `DocumentOut[]` — источник восстановления состава и rollback-re-fetch (уже есть: `getSessionDocuments`).
- **WS-кадр** `session_docs` → `{ documents: DocumentOut[] }` — источник актуализации при автодобавлении и (по согласованию с code-планом) после detach. Уже обрабатывается в `usePlannerSession` (стр. 158–160). Fallback, если бэкенд не шлёт кадр после detach: оптимистичное локальное состояние + re-fetch при ошибке (см. план, п. 2, 4).
- **Тип:** `DocumentOut { id, title, kind, created_at }` (`api.ts`).
