## Цель и пользовательский путь

Пользователь в чате хочет подключить скилл как инструмент планировщика и заранее понимать его цену.

1. В композере жмёт кнопку с гаечным ключом. Если кнопка серая — наведение показывает **почему** (нет сессии / идёт генерация), а не пустую подсказку «Инструменты».
2. Открывается поповер «Инструменты». В каждой строке скилла третья строка описания говорит о типе и цене: `script · без LLM`, `agent · до 4 LLM-вызовов`, `pipeline · до 6 LLM-вызовов`.
3. Пользователь щёлкает свич у любого скилла — script, agent и pipeline одинаково включаемы. Единственный момент, когда свич заблокирован, — пока запрос на прикрепление/открепление в полёте (`pending`).
4. Поповер больше нигде не сообщает, что «инструментом может стать только script-скилл» — этого ограничения нет.

Скоуп — ровно это. Ни новых экранов, ни новых элементов управления, ни фильтра/сортировки по цене.

### `costLine` — контракт

Переименование `guaranteeLine` осознанное: функции теперь нужен весь скилл, а не только `kind` (план, п. 4 — строка про гарантию и цену).

```
costLine(skill: SkillOut): string
  kind === 'script'                      → 'script · без LLM'
  estimated_llm_calls > 0                → `${kind} · до ${n} LLM-${n === 1 ? 'вызова' : 'вызовов'}`
  иначе (n <= 0 у не-script)             → kind
```

- Формулу расчёта (`max_iterations × (max_retries + 1)`, `len(steps) × max_iterations`) во фронте **не** дублируем — берём готовое число.
- Разделитель — ` · ` (как в текущей строке), не тире и не скобки.
- Форма единственного числа обязательна: «до 1 LLM-вызова» — реальный кейс для agent с `max_iterations=1, max_retries=0`.

## Layout и состояния

Строка скилла (`SkillRow`) сохраняет ту же трёхстрочную сетку — новых строк и сдвига высоты нет:

```
[ Название  (badge python) (badge ai) ]   [ › ] [ ⬤— ]
[ Описание / «Без описания»           ]
[ script · без LLM                    ]     ← та же <p class="text-[11px] text-ink-faint">
```

Состояния поповера (без изменений): `loading` → «Загрузка…»; пустой список → «Скиллов пока нет…»; пустой поиск → «Ничего не найдено» + «Сбросить»; `error` → алерт в шапке поверх списка.

Состояния строки:

| Состояние | Вид |
|-----------|-----|
| Доступен (любой kind) | Свич активен, серый `bg-surface-muted`, третья строка с ценой. |
| Включён | Свич `bg-brand`, ручка сдвинута, цена показывается так же. |
| `pending` | Свич `disabled` + `cursor-not-allowed`, `aria-busy` на `<li>`, подсказка «Применяем…». Внешний вид свича не гасим (`disabled:opacity-100` остаётся). |

Состояния кнопки инструментов в `Chat.tsx`:

| Условие | `title` | Кнопка |
|---------|---------|--------|
| `streaming` | `Идёт генерация` | disabled |
| `!sessionId` (и не streaming) | `Отправьте сообщение, чтобы начать сессию` | disabled |
| Иначе | `Инструменты` | активна |

Порядок веток важен: `streaming` проверяем первым. Во время ответа на самое первое сообщение `sessionId` может ещё отсутствовать, и подсказка «Отправьте сообщение» была бы прямой ложью.

## Взаимодействия

- **Свич**: клик → `onToggle(skill.id, !enabled)` для всех трёх `kind`. Пока строка `pending`, клики не проходят (нативный `disabled`), повторные запросы не шлём.
- **Шеврон**: как было — закрывает поповер и открывает карточку скилла.
- **Кнопка инструментов**: поведение не меняется (`onOpenTools`), меняется только подсказка. Когда `streaming` включается при открытом поповере, он закрывается — существующий эффект, трогать не нужно.
- **Крайние случаи**:
  - `estimated_llm_calls` отсутствует/`0` у agent или pipeline (старый бэкенд, кэш) → показываем только `kind`, без «до 0 LLM-вызовов».
  - Неизвестный `kind` → та же ветка: `kind` плюс цена, если она пришла. Никаких «unknown» и заглушек.
  - Цена не влияет на возможность включения: блокирует только `pending`.

## Стиль и токены

- Только утилиты из `docs/ui-style-guide.md`. Никаких сырых палитр (`slate-*`, `amber-*` и т. п.).
- Строка цены: тот же `text-[11px] text-ink-faint`, что и текущая строка гарантии. Цену **не** красим в warning/danger — это нейтральная справка, а не предупреждение, и подсветка сломала бы визуальную иерархию строки (имя → описание → мета).
- Бейдж под цену не заводим: `.badge-*` в этой строке заняты тегами `python`/`ai`, второй ряд бейджей утяжелит плотный список.
- Disabled-свич остаётся на `bg-surface-muted` + `cursor-not-allowed` (правило style guide «disabled — не `opacity-50`»).

## Доступность (a11y)

- Свич сохраняет `role="switch"` + `aria-checked` + `aria-label` (`Включить {name} как инструмент` / `Отключить {name}`). Тексты меток не меняем — на них завязаны тесты и мышечная память.
- `aria-description`/`title` свича: `Применяем…` при `pending`, `undefined` в остальных случаях. Дублировать цену в `title` не нужно — она уже видимый текст строки и читается скринридером в составе `<li>`.
- `<li>` с `aria-busy="true"` при `pending` — как сейчас.
- Кнопка инструментов: `aria-label` остаётся счётчиком (`Инструменты, включено N`), причина блокировки идёт в `title` и в `aria-description` — последний ставим только когда кнопка `disabled`. Нативный `title` показывается и на disabled-кнопке, так что подсказка мышью работает.
- Фокус-кольца `ring-2 ring-brand` не трогаем.

## Контракты данных

- `GET /skills`, `GET /sessions/{id}/tools`, `POST /sessions/{id}/tools` возвращают `SkillOut` с `estimated_llm_calls: int` (см. `backend/catalog/api/schemas.py:69`, `estimate_skill_llm_calls` в `backend/catalog/skills/budget.py:95`).
- Семантика числа: **верхняя оценка** LLM-вызовов на один запуск скилла; `0` — LLM не используется. Отсюда формулировка «до N».
- Поле объявляем обязательным (`number`, не `number | undefined`) — так typecheck сам укажет все фикстуры, которые надо дополнить.

## Критерии визуальной приёмки

- [ ] У agent-скилла в строке видно `agent · до N LLM-вызовов`, у pipeline — `pipeline · до N LLM-вызовов`, у script — `script · без LLM`.
- [ ] При `estimated_llm_calls === 1` текст «до 1 LLM-вызова» (единственное число).
- [ ] У не-script скилла с `estimated_llm_calls === 0` строка содержит только `kind`, без «до 0».
- [ ] Свичи у script, agent и pipeline кликабельны и вызывают `onToggle`; ни у одного нет `disabled` вне `pending`.
- [ ] Текста «Инструментом может стать только script-скилл» нет ни в разметке, ни в `title`, ни в `aria-description`.
- [ ] Строка в состоянии `pending`: свич `disabled`, `title` = «Применяем…», `aria-busy="true"` на `<li>`.
- [ ] Кнопка инструментов без сессии: `disabled` + `title` «Отправьте сообщение, чтобы начать сессию».
- [ ] Кнопка инструментов при `streaming` (в т. ч. когда `sessionId` уже есть): `disabled` + `title` «Идёт генерация».
- [ ] Кнопка инструментов в рабочем состоянии: активна, `title` «Инструменты», `aria-description` отсутствует.
- [ ] Высота строки скилла не изменилась: те же три текстовые строки, цена занимает место прежней строки гарантии.
- [ ] В диффе `frontend/src` нет сырых палитр Tailwind и новых кастомных цветов — только токены style guide.
