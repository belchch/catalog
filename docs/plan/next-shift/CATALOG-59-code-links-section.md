_(источник: описание задачи)_

Ссылки должны сохраняться в специальный раздел или просто внизу документа. Сейчас модель пытается выдумать место, куда влепить эти ссылки. Ссылки семантически — это просто связь между документами. Возможно, ссылки должны вставляться в frontmatter.

## Контекст

SoT продукта (CATALOG-49): связь = wiki-link в vault, не таблица в БД. Детерминированный ensure уже есть:

- `ensure_parent_wikilinks` — `backend/app/documents/obsidian.py:72–100`: дописывает в конец `Источник: [[stem]]` / список `Источники:`, но **только отсутствующие** stems; если LLM уже вставила `[[stem]]` mid-body — блок не добавляется (`idempotent_when_present`, тесты `test_obsidian_links.py:87–90`).
- Вызовы: persist apply (`skills/apply.py` ~349–358), `POST /runs/{id}/save` (`api/runs.py` ~151–160).
- Agent prompt hint (`apply.py:246–264`) говорит использовать stem, **не** запрещает вставлять links в narrative и не указывает «только внизу».

Frontmatter у workspace-документов сейчас нет (сырой markdown). Предложение ТЗ про frontmatter — опция; для Obsidian graph достаточно `[[stem]]` в теле. **Рекомендуемый канон (без YAML):** явный хвостовой раздел, например `## Ссылки` / унифицированный блок `Источник(и):`, плюс нормализация при persist/save. Frontmatter (`related:`) — только если явно нужен Obsidian Properties; иначе out of scope этого шага (больше парсинга, миграций, без выигрыша для graph).

Смежный план (архив): `docs/plan/archive/2026-07-20_10-54_next-shift/CATALOG-49-code-ensure-parent-wikilinks.md`.

UI Catalog wiki-links не рендерит (`MarkdownView` без `[[...]]`) — отдельная панель Related **не** входит в этот шаг.

## План действий

1. Зафиксировать формат канон-блока (предпочтение: markdown-секция внизу, напр. `## Ссылки` с bullet `[[stem]]`, либо стабилизировать текущие `Источник:` / `Источники:` как единственный канон — выбрать один вариант и не смешивать).
2. Расширить `ensure_parent_wikilinks` (или заменить на `ensure_links_section`): всегда гарантировать хвостовой раздел со всеми parent stems; политика mid-body: либо оставить narrative `[[...]]` как цитаты + дублировать в разделе, либо вычищать из тела только parent-provenance links при persist (осторожно с ложными срабатываниями на осмысленные mid-body ссылки в контенте скилла — по умолчанию **не вычищать** narrative, только гарантировать раздел).
3. Обновить agent `link_hint` в `apply.py`: связи с входными документами не размещать в тексте ответа произвольно — они появятся в разделе ссылок при сохранении; для прочих wiki-links — stem, не title.
4. Пройти persist + save пути: один и тот же helper.
5. Тесты: пустое тело → только раздел; тело с mid-body parent link → раздел всё равно содержит parent; несколько родителей; идемпотентный повтор ensure; rewrite title→stem по-прежнему перед ensure.
6. Frontmatter не внедрять в этом шаге, если не всплывёт жёсткое требование Obsidian Properties (ТЗ допускает «возможно» — канон «внизу» закрывает формулировку).
