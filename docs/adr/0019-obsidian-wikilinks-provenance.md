# ADR 0019: Связь «результат ↔ источник» — Obsidian-wikilinks в тексте

- **Date:** 2026-07-24
- **Status:** Accepted
- **Revises:** ADR-0006 (даёт provenance до появления графа), ADR-0010 (частично снимает non-goal «граф Obsidian»)

## Context

ADR-0006 обещал: результат станет полноправным узлом графа, «когда появятся
provenance/граф»; ADR-0010 отложил и граф, и рёбра происхождения. При этом
уже сейчас у результата есть ровно одна связь, без которой он бесполезен, —
**из каких документов он получен**. `skill_run.input_doc_ids` эту связь
хранит, но она невидима в самом файле: открыв `workspace/results/*.md` в
редакторе, происхождение не восстановить.

Дополнительно модель, если её не остановить, вставляет ссылки на входы
самостоятельно — по **title** документа, а не по имени файла, из-за чего
ссылка в Obsidian никуда не ведёт (файл на диске называется
`{slug}-{doc_id[:8]}.md`).

## Decision

Связи живут **в тексте результата**, в формате Obsidian-wikilinks, и
проставляются приложением при сохранении — не моделью.

1. **Каноникализация ссылок.** `rewrite_wiki_links`
   (`backend/app/documents/obsidian.py:40`) переписывает `[[Title]]` →
   `[[stem]]` по карте «title → имя файла», построенной из индекса
   документов. Поддержаны `[[target|alias]]` и `[[target#heading]]`;
   **неоднозначные** title (два документа с одинаковым названием) из карты
   исключаются и остаются нетронутыми — молча привязать ссылку не к тому
   файлу хуже, чем оставить её неразрешённой.

2. **Секция источников.** `ensure_parent_wikilinks`
   (`backend/app/documents/obsidian.py:106`) дописывает в конец результата
   секцию `## Ссылки` со списком `- [[stem]]` по всем входам прогона.
   Предыдущие варианты этой секции (в т.ч. написанные моделью «Источник:» /
   «Источники:») срезаются, чтобы при повторном сохранении не накапливались
   дубли.

3. **Модели запрещено делать это самой:** стартовое сообщение агента содержит
   явную инструкцию не вставлять ссылки на входные документы (система
   добавит секцию сама) и использовать stem, а не title, для прочих ссылок
   (`backend/app/skills/apply.py`).

4. **Оба пути сохранения** проходят через эту пару функций: авто-persist в
   `_apply_core` и отложенный `POST /runs/{id}/save` (ADR-0017).

5. **Никаких рёбер в SQLite.** Provenance — это содержимое файла; БД остаётся
   выводимым индексом (ADR-0005).

## Consequences

**Плюсы:** каталог `workspace/` открывается в Obsidian и даёт граф связей
без единой строки графового кода; связь переживает экспорт/копирование папки
(она в тексте, а не в БД); ссылки всегда указывают на реальные файлы.

**Минусы / риски:** обратный запрос («какие результаты произошли от X») —
только парсингом текстов, индекса нет; ссылка привязана к имени файла, то
есть переименование файла на диске её сломает (сейчас `path` неизменяем, а
осиротевшие строки чистит reconcile — ADR-0005); секция `## Ссылки`
формируется по входам **прогона**, а не по фактически использованным
моделью документам — если агент прочитал что-то ещё через `read_document`,
в секции этого не будет.

## Alternatives considered

- **Таблица provenance-рёбер в SQLite** — отложено: ADR-0005 требует, чтобы
  БД была выводима из ФС; рёбра в БД пришлось бы уметь восстанавливать —
  проще сразу писать их в текст.
- **Ссылка только через `skill_run.output_doc_id`/`input_doc_ids`** —
  отклонено: невидима в файле, теряется при выгрузке результатов наружу.
- **Front-matter YAML вместо секции `## Ссылки`** — отклонено: секция
  читается человеком в любом редакторе и не требует парсера.
