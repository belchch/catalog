# ADR 0021: Двухфазная сборка — выбор операции (tracks) + анти-доменные правила

- **Date:** 2026-07-24
- **Status:** Accepted
- **Revises:** ADR-0015 (уточняет, когда build идёт мимо упаковки артефактов)

## Context

Сборщик скилла читает историю планировочной сессии, в которой перемешаны две
разные вещи: **операция**, которую пользователь хочет автоматизировать
(«сравнить два документа по темам»), и **домен** обсуждаемых документов
(«код на Go и Dart»). LLM устойчиво путала одно с другим и выдавала скилл
«ревью Go-кода» вместо «сравнение документов по темам» — то есть скилл,
непереиспользуемый ни на чём, кроме исходной пары файлов.

Вторая часть проблемы: в истории сессии сообщения ассистента (пересказ
содержимого документов) объёмнее пользовательских, и модель-сборщик
принимала их за постановку задачи.

## Decision

Сборка разделена на две фазы, а намерение пользователя делается явным и
приоритетным.

### Фаза A — предложить операции (tracks)

- `POST /sessions/{id}/skill-tracks` (`backend/app/api/skills.py:815`)
  запрашивает у модели **1–3 варианта операции** через tool
  `propose_skill_tracks`; каждый трек — `{name, description, operation,
  rationale, input_arity}`, где `input_arity ∈ {1, 2, null}` (ADR-0017).
- Фаза A **пропускается** (`skipped=true`) для edit-сессий
  (`session.skill_id`) и когда операция уже выбрана: редактирование
  существующего скилла не начинается с переизобретения его назначения.
- Любой сбой — таймаут, ошибка провайдера, невалидный ответ после
  `MAX_BUILD_ATTEMPTS` — деградирует в `fallback=true`, и UI строит скилл
  без треков. Фаза A **не должна** быть способна заблокировать сборку.
- `POST /sessions/{id}/skill-tracks/select` дописывает в историю **обычное
  user-сообщение** с префиксом `Собери скилл по этой операции:` и телом
  трека. Идемпотентно: если такое сообщение уже есть, оно возвращается, а
  второе не создаётся.

Выбор хранится как сообщение в чате, а не как колонка: история сессии
остаётся единственным входом сборщика, и выбор виден пользователю в ленте.

### Фаза B — сборка с приоритетом намерения

- Наличие track-intent сообщения включает `force_llm`
  (`backend/app/api/skills.py:654`): build **пропускает упаковку артефактов**
  (ADR-0015) и идёт LLM-путём, потому что артефакты черновика были
  материализованы до выбора операции и её не учитывают.
- История размечается по ролям перед подачей в сборщик: user-сообщения —
  `[USER INTENT — authoritative instruction…]`, assistant-сообщения —
  `[ASSISTANT RESEARCH JOURNAL — topical notes…]`.
- `BUILD_SKILL_SYSTEM_PROMPT` содержит явные **анти-доменные правила**:
  скилл описывает операцию, а не тему/язык/продукт из содержимого; языки,
  продукты и предметные области не попадают в `name`/`description`/
  `system_prompt`/`code` без прямого требования пользователя; приоритет —
  за track-intent сообщением. Правило подкреплено few-shot примером
  (Go + Dart → «сравнение документов по темам», а не «ревью Go»).

## Consequences

**Плюсы:** пользователь выбирает операцию явно, до сборки, а не вычитывает
её из готового скилла; скиллы получаются переиспользуемыми (операция, а не
домен); ошибка фазы A не ломает основной поток.

**Минусы / риски:** прямое натяжение с ADR-0015 — «build мгновенный и без
LLM» верно только для сессий **без** выбранного трека; при выбранном треке
build снова стоит LLM-вызов и снова подвержен таймауту, а ручные правки
артефактов на этом пути игнорируются; фаза A добавляет отдельный LLM-вызов
до сборки; анти-доменные правила — промпт, а не гарантия.

## Alternatives considered

- **Чинить только промпт сборщика, без фазы A** — отклонено: модель всё
  равно угадывает намерение; выбор из 1–3 треков делает его явным.
- **Хранить выбранный трек отдельной колонкой/артефактом** — отклонено:
  сборщик читает историю сессии, и трек в виде сообщения не требует второго
  канала подачи; заодно виден в UI.
- **Учитывать трек при упаковке артефактов (без LLM)** — отклонено пока:
  артефакты `prompt`/`script` пишутся планировщиком до выбора операции;
  корректный «перепак» под другой трек — это и есть повторная сборка.
  Устранение этого натяжения — открытый шаг (перегенерация артефактов сразу
  после выбора трека, тогда build вернётся на pack-путь).
