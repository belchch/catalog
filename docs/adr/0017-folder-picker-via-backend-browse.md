# ADR 0017: Folder-picker — серверный обзор ФС, не системный диалог

- **Date:** 2026-08-14
- **Status:** Accepted
- **Refines:** ADR-0016 (пункт 3 — «пользователь выбирает папку»: здесь фиксируется, чем именно выбирает)

## Context

ADR-0016 сделал folder-picker end-user функцией: пользователь сам указывает папку, которая станет воркспейсом. Каким UI он это делает — не оговаривалось.

Ограничение задаёт форма доставки (ADR-0016, нативный запуск): Catalog — это localhost-приложение, uvicorn + React в обычной вкладке браузера, а не Electron/Tauri. Выбранную папку обрабатывает бэкенд: `POST /workspaces/open` создаёт `.catalog/index.db` и индексирует файлы, значит ему нужен **абсолютный путь в ФС хоста**.

Браузерные механизмы выбора папки этого не дают. `showDirectoryPicker` (File System Access API) возвращает handle и намеренно скрывает путь; `<input webkitdirectory>` загружает содержимое папки в страницу, а не сообщает её расположение. Оба смотрят на диск с точки зрения браузера и ничего не сообщают Python-процессу.

## Decision

1. **Пикер рисует своё дерево.** `WorkspacePicker` навигирует по ответам `GET /fs/browse?path=` — бэкенд отдаёт список подпапок (`FsEntry { name, path, has_catalog }`). Системный диалог ОС не используется.

2. **Корень обзора — `APP_FS_ROOT`**, по умолчанию `Path.home()`. Выход за корень запрещён: путь резолвится и проверяется через `relative_to(root)` — это отсекает и `..`, и абсолютный путь снаружи, и симлинк наружу (симлинк-цель проверяется отдельно, по `resolve()`).

3. **Скрытые папки не показываются** (имена с ведущей точкой отфильтрованы), файлы — тоже: пикер выбирает только каталоги.

4. **`has_catalog`** (наличие `.catalog/index.db`) отдаётся вместе с записью, чтобы UI помечал уже существующие воркспейсы бейджем до открытия.

5. **Недавние воркспейсы** из глобального реестра (`GET /workspaces`) — первый способ выбора; обход дерева нужен только для новой папки.

6. **Инвариант доставки: серверный процесс запущен пользователем на его же машине и слушает loopback.** Пикер показывает ФС того процесса, который отвечает на `/fs/browse`, и открывает папку его правами, поэтому нативный запуск (ADR-0016) — не предпочтительный способ, а условие работоспособности. Отсюда же `cli.py` сводит `--host 0.0.0.0`/`::` к `127.0.0.1`: у `/fs/browse` и `/workspaces/open` нет аутентификации, и единственная защита обзора home и записи `.catalog` — недоступность порта извне.

7. **Доставка в контейнер или на удалённый хост несовместима с пикером** и не поддерживается для работы с документами: в контейнере `Path.home()` и всё дерево — это ФС контейнера (`docker-compose.yml` монтирует только том `catalog-data:/data`, не home пользователя), на сервере — чужой диск плюс нарушение loopback-инварианта.

8. **Нативный диалог возвращается вместе с оболочкой.** Если доставка станет Electron/Tauri (или появится локальный хелпер, отдающий путь), пересматривается этот ADR; модель воркспейса из ADR-0016 при этом не меняется.

## Consequences

**Плюсы:**
- Бэкенд получает путь, который может открыть, — без прослойки «handle → путь», которой в браузере нет.
- Обзор ограничен одним корнем: страница не может заставить сервер листать произвольные каталоги хоста.
- В списке видно то, чего нативный диалог не знает: где уже есть воркспейс (`has_catalog`), какие папки открывались раньше.
- Открытие сразу разветвляется на три исхода API (`ok` / `needs_init` / `needs_confirm`) внутри той же модалки.

**Минусы / риски:**
- UI непривычен: это не Finder/Explorer — нет поиска, избранного, ввода пути руками, боковой панели дисков.
- Папку вне `APP_FS_ROOT` через UI не открыть; нужен env-override и перезапуск.
- Листинг чужих каталогов делает серверный процесс — граница безопасности держится на одной проверке `relative_to`, поэтому она покрыта тестами (`backend/tests/test_workspaces.py`: escape через `..`, абсолютный путь, симлинк).
- Способ запуска перестаёт быть свободным выбором: Docker и удалённый хост ломают не только «где лежат файлы», но и сам выбор папки. Docker-артефакты в репозитории остаются заделом под серверный деплой без пользовательского пикера.
- Открытый не на loopback порт превращает `/fs/browse` в листалку домашнего каталога для сети; при появлении сценария «Catalog на общей машине» потребуются аутентификация и пересмотр пункта 6.
- Обход глубокого дерева — это запрос на каждый уровень; «недавние» существуют в том числе чтобы им не пользоваться.

## Alternatives considered

- **`showDirectoryPicker` (File System Access API)** — отклонён: отдаёт handle без пути (это его дизайн-цель, приватность), бэкенд по нему ничего не откроет; плюс не поддержан вне Chromium.
- **`<input type="file" webkitdirectory>`** — отклонён: это загрузка содержимого в страницу, а не выбор расположения; ломает модель «документы остаются лежать там, где лежат» (ADR-0016).
- **Текстовое поле «введи абсолютный путь»** — отклонён как единственный способ: опечатки и ноль подсказок про существующие воркспейсы. Может быть добавлен как ускоритель поверх дерева.
- **Обернуть в Electron/Tauri ради нативного диалога** — отложено: меняет всю доставку ради одного диалога, вне скоупа первого среза (ADR-0010).
- **Обзор без ограничения корнем (вся ФС)** — отклонён: локальный сервер превращается в листалку всего диска; `$HOME` покрывает сценарий и оставляет env-выход.
