# ADR 0020: LLM-судья как отдельный тип пользовательской проверки

- **Date:** 2026-08-16
- **Status:** Accepted
- **Extends:** ADR-0007
- **Related:** ADR-0019, CATALOG-114, CATALOG-120

## Context

Реестр детерминированных проверок (ADR-0007) не оценивает семантику.
Пользователь хочет сохранять критерии вроде «резюме содержит опыт Python ≥ 3 лет»
и выбирать их в `verify_checks` рядом со стандартными.

ADR-0007 отклонил «верификацию только LLM» как единственный механизм; LLM-судья
был отложен как отдельный слой. Подмешивать его в `registered_checks()` нельзя:
ломается контракт «все проверки — код, не LLM».

## Decision

1. Пользовательские проверки хранятся в workspace-таблице `custom_check`
   (`id`, `name`, `prompt`, `hidden`, timestamps). Удаления нет — только
   `hidden=1`, чтобы не ломать ссылки в уже сохранённых скиллах.
2. В `verify_checks` допускается второй тип: `{ check: "custom:<id>" }` или
   `{ check: "custom", params: { id } }`. Это не часть детерминированного
   реестра и не попадает в `registered_checks()`.
3. `run_verify` сначала гоняет детерминированные проверки (CATALOG-114).
   LLM-судья вызывается только если они все зелёные. Verify до 3 раз
   (ADR-0007 retry) — каждый судья умножается на это.
4. Судья получает текст результата и критерий пользователя. System prompt
   исполнителя скилла судье не передаётся.
5. Fail-closed: неизвестный или скрытый custom id валит verify без вызова
   модели. Нет провайдера / модели при наличии custom — тоже fail.
6. REST для UI: список стандартных и видимых пользовательских, создание,
   скрытие, preview на примере (без записи в таблицу).

## Consequences

**Плюсы:** семантика без ломки ADR-0007; стоимость контролируется порядком;
скрытые проверки не пропадают из истории скиллов.

**Минусы:** LLM-судья дороже и недетерминирован; нужна модель/провайдер
на момент verify; скрытая, но процитированная проверка ломает прогон
(это намеренно).

## Alternatives considered

- **Подмешать в детерминированный реестр** — отклонено: ломает контракт
  ADR-0007 и `docs/verification-checks.md`.
- **Script-скилл как validator** — отложено; промпт покрывает основной кейс.
- **Жёсткое удаление проверок** — отклонено: ломает существующие скиллы
  без явного fail-closed сигнала.
- **Верификация только LLM** — по-прежнему отклонено ADR-0007.
