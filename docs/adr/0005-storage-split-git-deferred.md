# ADR 0005: ФС для контента, SQLite для системных данных; git отложен

- **Date:** 2026-07-12
- **Status:** Accepted

## Context
Нужно дешёвое переносимое хранение. Разделение ФС+Git+SQLite согласовано (opus), но git добавляет механизмы версионирования, не нужные для того, чтобы «почувствовать продукт».

## Decision
**Первый срез:** документы и результаты лежат файлами в `workspace/` (без версионирования); **SQLite хранит системные данные** — сессии, сообщения чата, трейсы прогонов, конфиги скиллов, индекс документов, контекст модели. Git (а с ним версии/diff) — **после среза**. SQLite остаётся пересобираемым индексом над ФС.

## Consequences
**Плюсы:** минимальная нагрузка, быстрота; пока нет проблем с бинарными diff/Git LFS.
**Минусы:** нет истории версий/diff до появления git (надо добавить до того, как демо «переиспользование на новой версии» станет осмысленным); конфиги скиллов в SQLite (позже переедут в ФС+git).

## Alternatives considered
- Git с первого дня — отклонено для среза (лишняя поверхность).
- SQLite как источник истины для контента — отклонено (контент живёт в ФС).
