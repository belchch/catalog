# ADR 0005: ФС для контента, SQLite для системных данных; git отложен

- **Date:** 2026-07-12
- **Status:** Accepted
- **Revised by:** ADR-0012 (data-root + git-репозитории), ADR-0017 (preview-результат живёт только в SQLite до сохранения), ADR-0022 (git больше не отложен — реальные коммиты)

## Context
Нужно дешёвое переносимое хранение. Разделение ФС+Git+SQLite согласовано (opus), но git добавляет механизмы версионирования, не нужные для того, чтобы «почувствовать продукт».

## Decision
**Первый срез:** документы и результаты лежат файлами в `workspace/` (без версионирования); **SQLite хранит системные данные** — сессии, сообщения чата, трейсы прогонов, конфиги скиллов, индекс документов, контекст модели. Git (а с ним версии/diff) — **после среза**. SQLite остаётся пересобираемым индексом над ФС.

## Consequences
**Плюсы:** минимальная нагрузка, быстрота; пока нет проблем с бинарными diff/Git LFS.
**Минусы:** нет истории версий/diff до появления git (надо добавить до того, как демо «переиспользование на новой версии» станет осмысленным); конфиги скиллов в SQLite (позже переедут в ФС+git).

## Alternatives considered
- Git с первого дня — отклонено для среза (лишняя поверхность).
- SQLite как источник истины для контента — отклонено (контент живёт в ФС).

## Как инвариант «SQLite выводим из ФС» держится в коде (2026-07-24)

Инвариант поддерживается **односторонней сверкой** `reconcile_orphans`
(`backend/app/storage/repo_document.py:150`): строки `document`, под которыми
нет файла в workspace, удаляются вместе со ссылками на них (`session_document`,
поля `skill_run`). Обратного направления **нет**: файл, положенный в
`workspace/documents/` мимо приложения, в индекс не попадёт — путь и id
связаны схемой имени (`{slug}-{doc_id[:8]}{ext}`), поэтому «усыновить»
произвольный файл нельзя.

Сверка вызывается лениво, без watcher'а: на старте приложения, в
`GET /documents`, в инструменте `list_documents` и по явному
`POST /documents/reconcile`.

**Что из этого ADR ещё не закрыто:**

- **preview-прогоны** (`persist=false`, ADR-0017) держат результат только в
  `skill_run.result_text` — до сохранения этот артефакт из ФС не выводим (не
  коммитится: коммитить нечего, пока нет файла).

## Git больше не отложен (2026-07-24, ADR-0022)

Два предыдущих пункта долга закрыты: git-коммиты теперь реально пишутся
(`POST /kb/commit`, `POST /skills/{id}/commit` — см. ADR-0022), и конфиги
скиллов материализуются в `skills/` вместо того чтобы жить только в
`skill.config_json`. Инвариант этого ADR не отменяется, а **усиливается**:
«SQLite — пересобираемый индекс над ФС» теперь читается как «...над
подключённым git-репозиторием» — `scan_repo`/`scan_skills` восстанавливают
индекс сканированием рабочего дерева, включая случай пустой SQLite (fresh
clone).
