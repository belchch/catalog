# ADR 0010: Скоуп первого среза и non-goals

- **Date:** 2026-07-12
- **Status:** Accepted; срез пройден — часть non-goals снята (см. «Ревизия non-goals»)
- **Revised by:** ADR-0012 (git), ADR-0014 (sandbox, script-скиллы), ADR-0017 (мульти-вход), ADR-0019 (ссылки Obsidian), ADR-0020 (pdf/csv/xlsx), ADR-0022 (KB-репозиторий, реальные git-коммиты)

## Context
Нужен один сквозной вертикальный срез, чтобы «почувствовать продукт» при минимальной нагрузке, но с архитектурой, честно готовой к расширению.

## Decision
**Скоуп среза:**
- UI: чат-планировщик; загрузка/выбор документа (`.md`, `.docx`); кнопка «Создать скилл» (собрать конфиг + применить, со стримингом шагов); «Коммит»; список скиллов; «Применить» к другому документу; просмотр результата.
- Инструменты (tool layer): `list_documents`, `read_document`.
- Проверки: минимальный реестр (`docs/verification-checks.md`).
- Схема SQLite закладывается «на вырост»: поддержка мульти-входа и лога сообщений, даже если срез пока использует один вход.

**Non-goals (явно не делаем в срезе):**
- git/версии/diff;
- FTS (системный скилл — следом);
- pdf/xlsx;
- граф Obsidian;
- ArchiMate;
- MCP;
- LLM-судья;
- sandbox (только cap + timeout + валидация аргументов);
- мультипользователь/RBAC;
- произвольная кодогенерация `.py`.

## Consequences
**Плюсы:** быстро доносит ключевое «ощущение» продукта; дёшево расширяется.
**Минусы:** ряд пробелов fable отложен намеренно (мульти-вход, diff, граф) — отслеживаются как ближайшие шаги.

## Alternatives considered
Более широкий срез (включая FTS/граф/MCP) — отклонено: риск для сроков «почувствовать продукт».

## Ближайшие шаги после среза (порядок)
1. FTS как системный скилл (`search_documents`, FTS5).
2. Git + версии документов/скиллов + diff результатов.
3. pdf/xlsx ingest (+ нормальный table→markdown для xlsx).
4. Provenance-рёбра + Obsidian-рендер графа.
5. Sandbox под будущую произвольную кодогенерацию.
6. MCP (скиллы как tools).
7. ArchiMate-экспорт с `archimate_well_formed` как verify-кейсом.

## Ревизия non-goals (2026-07-24, сверено с кодом)

| Non-goal среза | Сейчас | Чем снят |
|---|---|---|
| git / версии / diff | **снят (коммиты)**: подключаемый KB-репозиторий, реальные git-коммиты из UI (документы+скиллы, точечный commit скилла); версии документа/diff по-прежнему нет | ADR-0012, ADR-0022 |
| FTS | **в силе**: `search_documents` не реализован | ADR-0008 (долг) |
| pdf / xlsx | **снят**: ингест `md, docx, pdf, csv, xlsx`, ленивое извлечение текста | ADR-0020 |
| граф Obsidian | **частично снят**: wikilinks и секция `## Ссылки` в результатах; рендера графа и рёбер в БД нет | ADR-0019 |
| ArchiMate | **в силе** (идентификатор `archimate_well_formed` зарезервирован в реестре проверок) | — |
| MCP | **в силе** | — |
| LLM-судья | **в силе**: verify — детерминированный реестр из 9 проверок | ADR-0007 |
| sandbox («только cap + timeout + валидация») | **снят**: AST-валидация + ограниченный namespace + SIGALRM-таймаут; лимит памяти отложен до subprocess-изоляции | ADR-0014 |
| мультипользователь / RBAC | **в силе**; изоляция контекста решается сессией, а не правами | ADR-0016 |
| произвольная кодогенерация `.py` | **частично снят**: LLM генерирует код скилла на build, но исполняется он только sandbox-раннером; произвольного импорта/рантайма нет | ADR-0014 |
| «срез использует один вход» | **снят**: `input_arity` 1 / 2 / список, проверка на apply и в ядре | ADR-0017 |

**Скоуп среза** тоже разошёлся с текстом: кнопка «Создать скилл» больше не
«собрать конфиг + применить» (build → configure → commit → apply —
ADR-0018), а реестр инструментов агента остался прежним
(`list_documents`, `read_document`) — расширились только инструменты
планировщика (артефакты черновика, ADR-0015; выбор операции, ADR-0021).

**Порядок «ближайших шагов» фактически сложился другим:** сделаны 3 (ingest),
5 (sandbox), 2 (data-root + реальные git-коммиты, ADR-0022) и частично 4
(ссылки без графа); открыты 1 (FTS), версии документа/diff из 2, 6 (MCP) и 7
(ArchiMate).
