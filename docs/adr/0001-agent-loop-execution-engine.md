# ADR 0001: Один function-calling агент-луп как движок исполнения

- **Date:** 2026-07-12
- **Status:** Accepted

## Context
Нужен движок, который (а) позволяет пользователю планировать задачу в чате с системным ИИ и (б) исполняет зафиксированный «скилл» над документом. Две архитектуры-кандидата:
1. **Один function-calling агент-луп**, общий для планирования и исполнения: модель сама решает порядок вызовов инструментов в рантайме.
2. **Декларативный исполнитель рецептов** поверх фиксированных шагов `code|llm|verify`, где отдельный skill-builder раскладывает задачу в жёсткую последовательность.

## Decision
Принять **один function-calling агент-луп**. Один и тот же драйвер работает в режиме планировщика (пользователь в цикле) и в режиме исполнения скилла (автономно). Скилл — это замороженная конфигурация, подаваемая в этот движок. Поверх результата — `verify` + `retry`.

## Consequences
**Плюсы:** один движок — меньше кода и концепций; обходит самую сложную часть (декомпозицию задачи на шаги — skill-builder просто замораживает конфиг); гибко переносится на документы разной структуры; новые инструменты (в т.ч. будущий FTS) сразу доступны всем скиллам.
**Минусы:** не бит-воспроизводим (сглаживается `temperature=0` + pin провайдера + `verify`); нужны ограничители (`max_iterations`, `max_retries`, timeout) и валидация аргументов tool-call; стоимость/латентность прогона зависят от модели.

## Alternatives considered
Декларативные рецепты шагов (модель opus) — строже воспроизводимы и прозрачнее, но требуют хрупкой декомпозиции («дистилляция», fable G4). Отклонены для первого среза; могут вернуться позже как эволюция «заморозить удачный трейс → детерминированный рецепт».
