# ADR 0004: Скилл строится в момент согласия (без дистилляции)

- **Date:** 2026-07-12
- **Status:** Superseded в части потока (см. «Что отменено» ниже)
- **Superseded by:** ADR-0018 (жизненный цикл draft → configure → commit → apply)
- **Revised by:** ADR-0015 (build = упаковка артефактов, а не синтез из чата), ADR-0021 (двухфазная сборка с выбором операции)

## Context
Исходный поток «фиксируем скилл в конце сессии» + дистилляция fable — самая сложная и неопределённая задача проекта (G4). Заказчик переформулировал поток: *план в диалоге → система показывает финальное задание → пользователь согласен → модель формирует скилл и применяет → ревью → коммит/итерация*.

## Decision
Скилл конструируется **в момент согласия** одним LLM-вызовом со structured output (вся сессия → `SkillConfig`), после чего **немедленно исполняется**. Исполнение на исходном документе — это и есть реплей-тест; повторное применение на другом документе — реальная проверка воспроизводимости. Отдельной фазы дистилляции нет.

## Consequences
**Плюсы:** растворяет проблему дистилляции; пользователь видит результат до коммита; итерация = разморозить конфиг, поправить план, заморозить заново.
**Минусы:** шаг сборки должен выдать валидный конфиг (проверяется против реестров инструментов и проверок; при невалидности — retry эмита).

## Alternatives considered
- Дистилляция из лога сессии постфактум — отклонено (см. ADR-0002).
- Ручная сборка скилла пользователем — отклонено (визуального редактора нет; non-goal).

## Что отменено (2026-07-24, сверено с кодом)

**Остаётся в силе:** отдельной фазы дистилляции нет; скилл возникает в момент
согласия пользователя; итерация — это правка плана и повторная сборка, а не
ручное редактирование конфига.

**Отменено:**

| Формулировка 2026-07-12 | Как в коде сейчас | Где записано |
|---|---|---|
| «одним LLM-вызовом со structured output (вся сессия → SkillConfig)» | основной путь — упаковка `session_artifact` (prompt/script/meta) **без LLM**; LLM-путь остался как fallback для сессий без артефактов и как принудительный при выбранном треке | ADR-0015, ADR-0021 |
| «после чего **немедленно исполняется**» | build создаёт скилл в `draft` и возвращает preview; между сборкой и первым прогоном — `configure` и `commit`; `apply` требует `committed` (иначе 409) | ADR-0018 |
| «исполнение на исходном документе — это и есть реплей-тест» | автоматического прогона нет; первый запуск инициирует пользователь | ADR-0018 |
| «итерация = разморозить конфиг» | итерация = edit-сессия (`POST /skills/{id}/edit`), которая засевает артефакты из конфига и возвращает скилл в `draft` | ADR-0018 |

**Ручная правка появилась, но не как визуальный редактор конфига:**
пользователь правит артефакты черновика (`PATCH /sessions/{id}/artifacts/…`,
`PATCH /sessions/{id}/skill-meta`) — то есть prompt/script/meta до сборки, а
не поля собранного скилла (ADR-0015).
