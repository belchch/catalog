# ADR 0007: verify = детерминированный реестр проверок + retry

- **Date:** 2026-07-12
- **Status:** Accepted

## Context
Проверка не должна быть «ещё одним промптом» — она обязана быть надёжной и дешёвой. Но чистый код не оценивает семантику/качество.

## Decision
`verify` — это набор **детерминированных** проверок, выбираемых из реестра (`docs/verification-checks.md`: `non_empty`, `markdown_well_formed`, `has_section`, `table_parses`, …). При провале список ошибок возвращается в агент, и он повторяет (до `max_retries`). LLM-судья — будущий отдельный механизм, **не** часть этого реестра.

## Consequences
**Плюсы:** надёжно, дёшево, инспектируемо; стабилизирует недетерминированный вывод LLM.
**Минусы:** не может судить «смысл/качество» до добавления LLM-судьи (приемлемо для среза).

## Alternatives considered
- Верификация только LLM — отклонено: ненадёжно.
- Без верификации — отклонено: ломает доверие к переиспользованию.
