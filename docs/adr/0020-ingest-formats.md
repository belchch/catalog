# ADR 0020: Форматы ингеста — md, docx, pdf, csv, xlsx; текст извлекается лениво

- **Date:** 2026-07-24
- **Status:** Accepted
- **Revises:** ADR-0010 (снимает non-goal «pdf/xlsx»)

## Context

Срез (ADR-0010) поддерживал `.md` и `.docx`, а `pdf/xlsx` были явным
non-goal и шли третьим пунктом в списке «после среза». Реальные входные
данные пользователя — выгрузки таблиц и присланные PDF; без них скиллы
сравнения и сведения применять не к чему.

Вопрос, который надо было решить вместе с форматами: **когда** превращать
файл в текст — при загрузке или при чтении.

## Decision

1. **Реестр форматов — одна карта расширений** `_EXT_TO_KIND`
   (`backend/app/documents/ingest.py:11`): `.md → md`, `.docx → docx`,
   `.pdf → pdf`, `.csv → csv`, `.xlsx → xlsx`. Неизвестное расширение →
   `ValueError` → 400 на `POST /documents`. UI ограничивает выбор тем же
   списком (`accept=".md,.docx,.pdf,.csv,.xlsx"`).

2. **Байты хранятся verbatim**, извлечение текста — **ленивое**, в
   `extract_text(path, kind)` (`backend/app/documents/extract.py:6`), на
   каждом чтении (`read_document`, старт прогона). Исходник не портится
   парсером, а улучшение экстрактора применяется задним числом ко всему
   ранее загруженному без реингеста.

3. **Правила извлечения по видам:**
   - `md` / `result_md` — файл как есть (utf-8);
   - `docx` — абзацы через python-docx;
   - `csv` — сырой текст с каскадом декодирования
     `utf-8-sig → cp1251 → latin-1` (последний — с заменой битых байт):
     выгрузки из корп-систем в кириллице чаще всего не utf-8;
   - `xlsx` — **все непустые листы** рендерятся в markdown-таблицы с
     заголовком `## Sheet: …`; хвостовые пустые строки срезаются, `|` в
     ячейках экранируется. То есть таблица приходит в модель уже в том виде,
     который проверяет `table_parses` (ADR-0007);
   - `pdf` — постранично через pypdf с явными маркерами `--- page N ---`;
     если текстового слоя нет ни на одной странице, возвращается **явное
     предупреждение** о скане вместо пустой строки.

4. **`kind` — это формат источника, а не результата.** Результат скилла
   по-прежнему единственного вида `result_md` (ADR-0006): вход разнороден,
   выход нормализован в markdown.

## Consequences

**Плюсы:** реальные пользовательские файлы загружаются без конвертации на
стороне пользователя; xlsx приходит в модель нормализованным markdown, а не
как «прочитай бинарь»; скан-PDF отличим от пустого документа (модель видит
причину, а не молчание).

**Минусы / риски:** OCR не поддерживается — скан остаётся нечитаемым;
извлечение повторяется на каждом чтении (кэша нет — приемлемо на текущих
объёмах); xlsx-рендер теряет формулы, форматирование и объединённые ячейки
(берутся вычисленные значения, `data_only=True`); `extract_text` — общий
шов, через который проходит любой вход, поэтому его отказ (битый файл)
валит прогон целиком.

## Alternatives considered

- **Извлекать текст при загрузке и хранить .md** — отклонено: теряется
  оригинал, улучшение экстрактора требует реингеста, а `kind` перестаёт
  описывать источник.
- **Внешний конвертер (pandoc / markitdown)** — отклонено для self-hosted:
  host-зависимость, ровно та же причина, по которой ADR-0012 выбрал dulwich
  вместо системного `git`.
- **OCR для скан-PDF** — отложено: тяжёлая зависимость ради редкого случая;
  сейчас честное предупреждение вместо тихой пустоты.
