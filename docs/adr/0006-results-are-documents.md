# ADR 0006: Результаты скилла — полноправные Documents

- **Date:** 2026-07-12
- **Status:** Accepted (с оговоркой о режиме предпросмотра)
- **Revised by:** ADR-0017 (при `persist=false` результат становится Document только по решению пользователя), ADR-0019 (связь с источниками — wikilinks в тексте)

## Context
fable G3: результат был лишь `output_path` у прогона — без версий, аннотаций, участия в графе и поиске.

## Decision
Результат скилла регистрируется как `Document(kind=result_md)` (позже — другие `result_*`). Он участвует в списке, может быть входом другого скилла, а когда появятся provenance/граф — будет там полноправным узлом.

## Consequences
**Плюсы:** единая модель артефакта; позже проще diff/аннотирование/экспорт (один путь); результаты доступны для поиска и переиспользования.
**Минусы:** чуть больше учёта сейчас (строка `Document` + файл).

## Alternatives considered
Результат как непрозрачный вывод прогона — отклонено: фрагментарно и затрудняет будущие фичи.

## Оговорка (2026-07-24)

Решение в силе для успешного прогона в режиме «в документ»: создаётся
`Document(kind="result_md")` + файл в `workspace/results/`, документ
привязывается к сессии (ADR-0016) и получает секцию `## Ссылки` на источники
(ADR-0019). Единственный вид результата — `result_md`; других `result_*` пока нет.

В режиме «на экран» (`persist=false`, ADR-0017) документ **не** создаётся:
текст хранится в `skill_run.result_text` и становится Document только после
`POST /runs/{id}/save`. То есть «результат — полноправный документ» теперь
верно с момента сохранения, а не с момента прогона.
