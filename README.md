# Catalog — ИИ-агент для аналитика/архитектора

Платформа-оболочка: пользователь в чате составляет план обработки документа, превращает его в переиспользуемый **скилл** и применяет к документам. MVP («первый срез») — один сквозной цикл, чтобы «почувствовать продукт».

> Этот README — точка быстрого погружения для **новой сессии ИИ-агента**. См. раздел «Новому ИИ-агенту» внизу.

## Стек
| Слой | Технология |
|------|-----------|
| Backend | Python 3.11+ · FastAPI (+WebSocket) · httpx · pydantic |
| LLM | Фабрика OpenAI-совместимых провайдеров: OpenRouter, z.ai (GLM); selector моделей, pin провайдера, streaming |
| Хранилище | Подключаемый git-репозиторий базы знаний (`APP_KB_REPO`) — контент; SQLite — системные данные и пересобираемый индекс |
| Frontend | React (Vite) + TypeScript + Tailwind CSS |
| Движок скиллов | один function-calling агент-луп |

## Архитектура (кратко)
- **Движок** — один function-calling агент-луп; планировщик (чат) и выполнение скилла используют один и тот же цикл.
- **Скилл** = замороженный конфиг (`system_prompt`, `allowed_tools`, `model`, `temperature=0`, `verify_checks`) двух видов: `kind="agent"` (LLM-луп) и `kind="script"` (детерминированный Python в sandbox).
- **Поток**: план в чате → планировщик пишет артефакты черновика (prompt/script/meta) → выбор операции → сборка (`draft`) → настройка модели → `commit` → `apply`.
- **Хранилище**: подключаемый git-репозиторий базы знаний (`documents/`, `results/`, `skills/` — одна история на всё) — источник контента; SQLite — состояние (сессии, сообщения, скиллы, трейсы) и пересобираемый индекс поверх репозитория. Коммит — явной кнопкой в UI (ADR-0022).
- **Документы** видны агенту только через сессию (привязка `session_document`); результат прогона привязывается автоматически.
- **Проверки** — детерминированный реестр (`docs/verification-checks.md`).

Полный список решений — в `docs/adr/` (ADR-0001…0022); открытые долги — в конце `docs/adr/README.md`.

## Быстрый старт (после инициализации)
```bash
# env (backend): скопируй шаблон и впиши ключи
cd backend
cp .env.example .env
#   OPENROUTER_API_KEY=...        # обязательный ключ OpenRouter
#   OPENROUTER_DEFAULT_MODEL=...   # tool-capable модель (см. ниже)
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
uvicorn app.main:app --reload      # http://localhost:8000/health

# frontend
cd frontend
pnpm install
pnpm run dev                       # http://localhost:5173
```

> `OPENROUTER_DEFAULT_MODEL` должна уметь в function-calling (tool use) — иначе агент не сможет вызывать инструменты. Для работы с дефолтной модели нужен tool-capable вариант; fallback-модель зашита в `app/config.py`.

## База знаний (ADR-0022)

При первом запуске без явной настройки приложение создаёт/открывает
git-репозиторий по умолчанию под `<data-root>/kb` (`APP_KB_REPO` — переопределить
путь; legacy `APP_WORKSPACE` по-прежнему работает для существующих
инсталлов). В UI (секция «База знаний») можно подключить свой путь — выбор
персистентен и переживает рестарт. Работает офлайн; push на remote —
опциональная функция бэкапа, выключенная по умолчанию.

```
<repo_root>/
  documents/   # входные документы (md/docx/pdf/csv/xlsx)
  results/     # result_md прогонов скиллов
  skills/      # материализованные конфиги закоммиченных скиллов
  .git/
```

Изменения на диске подхватываются кнопкой **Rescan**; накопленные изменения
коммитятся кнопкой **Commit** (документы+скиллы вместе). У «Commit skill»
своя отдельная точечная git-операция — коммитит только файл этого скилла.

## Ключевые принципы (не нарушать)
- ФС — источник контента; SQLite — только системные данные/индекс (пересобираемый).
- Новый инструмент/проверка → регистрируем в реестре + запись в `docs/verification-checks.md`.
- Значимое архитектурное решение → новый ADR + строка в `docs/adr/README.md`.
- Код скилла (`kind="script"`) исполняется только sandbox-раннером (AST-валидация + ограниченный namespace + таймаут); произвольного импорта/рантайма нет — ADR-0014.
- Ключи провайдеров (`OPENROUTER_API_KEY`, `ZAI_API_KEY`) — только в `.env` (в `.gitignore`), никогда в коде/коммитах.

## Новому ИИ-агенту (onboarding)
1. Прочитай этот README целиком.
2. Прочитай `docs/adr/README.md` (индекс решений). Ключевые: **ADR-0001** (агент-луп), **ADR-0002** (скилл=конфиг) + **ADR-0014** (script-скиллы), **ADR-0018** (жизненный цикл скилла; отменяет поток ADR-0004), **ADR-0015** (артефакты сессии), **ADR-0016** (видимость документов через сессию), **ADR-0017** (контракт apply), **ADR-0005**/**ADR-0012**/**ADR-0022** (хранилище, data-root и подключаемый KB-репозиторий), **ADR-0010** (скоуп среза и что из non-goals уже снято), **ADR-0011** (фронтенд-стек).
3. Открой `docs/plan/` — текущий шаг и статус работы.
4. При необходимости — `docs/pre-design/` (исходные транскрипты) и `docs/verification-checks.md`.
5. Окружение: Python 3.13, node 23, pnpm 9, git. Менеджеры Python — `venv`+`pip` (uv не установлен).
