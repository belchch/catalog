## Порядок задач

### 1. [CRITICAL] Исправить `stream_complete` на настоящее стриминг-API
Файл: `backend/app/llm/openrouter.py` (метод `stream_complete`, ~стр. 185–240).

Заменить буферизующий вызов:
```python
resp = await self._client.post(url, headers=..., json=body)
if resp.status_code == 401: ...
resp.raise_for_status()
async for line in resp.aiter_lines(): ...
```
на контекстный менеджер стриминга:
```python
async with self._client.stream("POST", url, headers=self._auth_headers(), json=body) as resp:
    if resp.status_code == 401:
        raise ValueError("Invalid OpenRouter API key — check OPENROUTER_API_KEY in .env")
    if resp.status_code == 429:
        raise RuntimeError("Rate limit exceeded")
    if resp.status_code >= 400:
        err_body = (await resp.aread()).decode(errors="replace")
        logger.warning("stream_complete HTTP %d body: %s", resp.status_code, err_body[:1000])
        resp.raise_for_status()
    async for line in resp.aiter_lines():
        ...  # существующий SSE-парсинг без изменений
```
- yield-ы остаются **внутри** `async with` — контекст держится между yield'ами и корректно закрывается при `break`/исключении через `aclose`.
- Причина фикса: `client.post` полностью вычитывает тело в буфер до возврата; настоящий стриминг даёт только `client.stream(...)`.

### 2. Привести логирование к плану (event_hooks) — замечание #2
Файл: `backend/app/llm/openrouter.py`.

- Добавить модульную функцию:
  ```python
  async def _log_request(request: httpx.Request) -> None:
      body_preview = ""
      if request.content:
          body_preview = request.content.decode(errors="replace")[:1000]
      logger.debug("HTTP %s %s body=%s", request.method, request.url, body_preview)

  def build_debug_hooks() -> dict:
      return {"request": [_log_request]}
  ```
- Удалить инлайн `logger.debug("complete request body: ...")` в `complete` (теперь дублируется request-hook'ом).
- INFO-логи ответа в `complete` **оставить** (несут семантику, недоступную из сырого HTTP: model, finish_reason, tool_calls, usage).
- Обоснование решения: response-body через event_hooks конфликтует со стримингом (нельзя вычитать поток), поэтому hook только на request — ровно «оба слоя сосуществуют» из хэндовера планирования.

### 8. Добавить smoke-проверку стриминга
Файл: `backend/scripts/smoke_llm.py` — 4-я проверка `check_stream`:
```python
async def check_stream(provider, model):
    print(f"\n=== Test 4: stream_complete (model={model}) ===")
    chunks = []
    async for chunk in provider.stream_complete(
        model=model,
        messages=[Message(role="user", content="Count from 1 to 3, numbers only.")],
    ):
        chunks.append(chunk)
    text = "".join(chunks)
    print(f"  chunks={len(chunks)} text={text!r}")
    assert chunks, "no chunks streamed"
    assert len(chunks) >= 2, "expected multiple chunks (true streaming)"
```
Вызвать после `check_complete`. Эта проверка реально прогоняет фиксированный стриминг-API против живого API и ловит регрессию «буферизации».

## Риски
- **`async with` + yield в async-генераторе:** стандартный паттерн; корректно закрывается при раннем `break` через `aclose`. Регрессию ловит новый `check_stream` (assert `len(chunks) >= 2`).
- **event_hooks на MockTransport:** хуки стреляют при любом транспорте, тесты не ассертят логи — влияния нет.
