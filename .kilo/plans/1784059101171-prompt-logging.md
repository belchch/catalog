# Plan: Логирование промптов LLM

## Цель

Сохранять сырые промпты (полный request + response + метаданные) для каждого
LLM-вызова на диск, чтобы потом анализировать файлы и повышать качество ответов.
Включается env-переключателем, путь задаётся env-параметром.

## Контекст кодовой базы

- `LLMProvider` Protocol (`backend/app/llm/base.py:46`) с методами
  `complete`/`stream_complete` — единое горлышко всех LLM-вызовов (цикл агента в
  `backend/app/agent/runner.py` и `build_skill` в `backend/app/api/skills.py`).
- Реализация — `OpenRouterProvider` в `backend/app/llm/openrouter.py`
  (`complete` ~`openrouter.py:160-265`, `stream_complete` ~`:267-330`).
- Конфиг env — `backend/app/config.py` (модульные константы + frozen `Settings`).
- API-слой, где известны `session_id`/`run_id`:
  - `backend/app/api/sessions.py` (planner-сессия, `run_agent` ~`:94`).
  - `backend/app/api/skills.py` (`build_skill_from_session` ~`:112`, цикл `complete` ~`:134`).
- `.gitignore` уже исключает `workspace/*` (дефолтный путь логов под ним).

## Зафиксированные решения

1. **Точка перехвата:** внутри `OpenRouterProvider.complete` и `.stream_complete`.
   Покрывает цикл агента, `build_skill` и оба режима (stream / non-stream).
2. **Привязка к сессии:** через `contextvars` — отдельный модуль, без изменения
   `LLMProvider` Protocol. API-слой выставляет контекст перед вызовом; `runner`
   проставляет номер итерации.
3. **Формат:** отдельный JSON-файл на запрос, путь
   `${PROMPT_LOG_DIR}/YYYY-MM-DD/<HHMMSSffffff>_<request_id>.json`.
4. **ENV:** `PROMPT_LOG_ENABLED` (default `false`), `PROMPT_LOG_DIR`
   (default `workspace/prompt_logs`).

## Состав JSON-файла лога (schema_version=1)

```jsonc
{
  "schema_version": 1,
  "request_id": "<uuid4-prefix>",
  "timestamp": "<ISO8601 UTC>",
  "provider": "openrouter",
  "context": { "session_id": null, "run_id": null, "iteration": null,
               "purpose": "planner|build_skill|unknown" },
  "request": {
    "model": "...", "temperature": 0.0, "tool_choice": "auto", "stream": false,
    "tools": [ { "name": "...", "description": "...", "parameters": {...} } ],
    "messages": [ { "role": "...", "content": "...", "tool_calls": [...],
                    "tool_call_id": "...", "name": "..." } ]
  },
  "response": {
    "content": "...", "tool_calls": [...], "finish_reason": "...",
    "usage": {...}, "assembled_text": "..." // только для stream
  },
  "meta": { "latency_ms": 0, "ok": true, "error": null }
}
```

- Логируется **только body** (messages/tools/model/temperature) и response.
  HTTP-заголовки (включая `Authorization: Bearer ...`) **не пишутся**.
- Ошибка провайдера/таймаут логируется с `"ok": false`, `"error": "..."`.

## Пошаговые задачи

### 1. Конфиг (`backend/app/config.py`)

- Добавить модульные константы:
  ```python
  _TRUTHY = {"1", "true", "yes", "on"}
  PROMPT_LOG_ENABLED = os.getenv("PROMPT_LOG_ENABLED", "").strip().lower() in _TRUTHY
  PROMPT_LOG_DIR = os.getenv("PROMPT_LOG_DIR", os.path.join(APP_WORKSPACE, "prompt_logs"))
  ```
- Добавить поля в `Settings` (frozen):
  `prompt_log_enabled: bool = PROMPT_LOG_ENABLED`, `prompt_log_dir: str = PROMPT_LOG_DIR`.

### 2. Контекст логирования (`backend/app/llm/log_context.py`, новый)

- `ContextVar`-ы (все `default=None`): `session_id`, `run_id`, `iteration`,
  `purpose`.
- Контекст-менеджер:
  ```python
  @contextmanager
  def prompt_log_context(*, session_id=None, run_id=None, purpose=None):
      tokens = [cv.set(v) for cv, v in (
          (current_session_id, session_id),
          (current_run_id, run_id),
          (current_purpose, purpose),
      ) if v is not None]
      try:
          yield
      finally:
          for cv, tok in reversed(tokens):
              cv.reset(tok)
  ```
- `def collect_context() -> dict` — снимок текущих значений для meta.

### 3. Модуль записи (`backend/app/llm/prompt_log.py`, новый)

- `def is_enabled() -> bool` — читает `PROMPT_LOG_ENABLED` из config.
- `async def write_prompt_log(*, provider, model, messages, tools, temperature,
  tool_choice, stream, response, error, latency_ms)`:
  - Early-return, если `not is_enabled()`.
  - Собирает dict по схеме выше; `messages`/`tools` сериализуются через
    существующие `_message_to_dict`/`_tools_to_dicts` из `openrouter.py`
    (вынести их переиспользуемыми хелперами или дублировать минимально — см. риск).
  - `request_id = uuid4().hex[:12]`, `timestamp = datetime.now(timezone.utc)`.
  - День = `timestamp.strftime("%Y-%m-%d")`, имя файла =
    `<HHMMSSffffff>_<request_id>.json`.
  - Запись — `await asyncio.to_thread(_write_atomic, path, payload)`:
    `os.makedirs(dir, exist_ok=True)` → пишем во `path.tmp` → `os.replace(tmp, path)`.
  - Любое исключение оборачивать в `logger.warning("prompt log write failed: %s", exc)`
    и **не пробрасывать** — логирование не должно валить LLM-вызов.

### 4. Интеграция в провайдер (`backend/app/llm/openrouter.py`)

- В `complete`:
  - `t0 = time.monotonic()` перед `_post_with_retry`.
  - После разбора `CompletionResult`: в `try/except` вызвать
    `await write_prompt_log(provider="openrouter", model=model, messages=messages,
    tools=tools, temperature=temperature, tool_choice=tool_choice, stream=False,
    response={...content/tool_calls/finish_reason/usage...}, error=None,
    latency_ms=round((time.monotonic()-t0)*1000))`.
  - В случае исключения из `_post_with_retry` — вызвать `write_prompt_log` с
    `response=None`, `error=str(exc)`, затем re-raise исходное исключение.
- В `stream_complete`:
  - `t0 = time.monotonic()`, накапливать `text` из дельт.
  - После нормального завершения итератора — `write_prompt_log(..., stream=True,
    response={"assembled_text": text, "usage": {}, "finish_reason": "stop"})`.
  - При исключении во время стрима — лог с `error=...`, затем re-raise.

### 5. Простановка контекста (contextvars)

- `backend/app/agent/runner.py`: внутри `_run_agent_core`, перед каждым вызовом
  `provider.complete` / `provider.stream_complete` обновлять
  `current_iteration.set(i)` (использовать `current_iteration`, не менеджер —
  session_id/run_id/purpose ставит API-слой).
- `backend/app/api/sessions.py`: обернуть `async for event in run_agent(...)` в
  `with prompt_log_context(session_id=session_id, purpose="planner")`.
- `backend/app/api/skills.py`: в `build_skill_from_session` обернуть цикл
  `for _attempt in range(MAX_BUILD_ATTEMPTS)` в
  `with prompt_log_context(session_id=session_id, run_id=None, purpose="build_skill")`.

### 6. Документация env

- В `backend/.env.example` добавить блок:

  PROMPT_LOG_ENABLED=false

## Риски и заметки

- **Объём:** `messages` содержат полный текст документов (`read_document`) —
  логи могут быть большими. Для цели анализа это ожидаемо. Ротация/чистка —
  out of scope.
- **Stream без usage/tool_calls:** в текущем slice `stream_complete` не парсит
  `tool_calls` и не возвращает `usage` — лог stream-режима будет содержать
  только `assembled_text` (отмечено в схеме).
- **Дублирование сериализации messages/tools:** `_message_to_dict`/`_tools_to_dicts`
  сейчас приватные в `openrouter.py`. Варианты: (а) вынести в общий хелпер в
  `app/llm/base.py`/новом модуле; (б) импортировать приватные. Рекомендация —
  вынести в `app/llm/base.py` как `message_to_dict`/`tool_specs_to_dicts`,
  использовать и в провайдере, и в логгере.
- **Секреты в content:** если документы содержат чувствительные данные, они
  попадут в лог. Redaction/masking — out of scope (решается на этапе анализа или
  отдельной задачей).
