# Step 02 — LLM-провайдер (OpenRouter): план реализации

## Цель
Рабочая интеграция с OpenRouter: `list_models`, `complete` (с tool-calling), `stream_complete`. Доказать, что function-calling поверх OpenRouter работает (главный технический риск среза). Без агент-лупа, инструментов документов, БД.

## Решённые дизайнерские вопросы
- **Lifecycle `httpx.AsyncClient`: DI.** Провайдер принимает готовый клиент в конструкторе, не создаёт и не закрывает его. Caller управляет lifecycle. Это нужно для FastAPI lifespan (шаг 06) и для моков в тестах.
- **Логирование:** все запросы/ответы LLM логируются через `logging.getLogger("app.llm")`. Запрос: model, messages (roles + content, без tool_calls дампим компактно), tools, temperature. Ответ: content (первые 200 символов), tool_calls (имена), finish_reason, usage. Уровень: INFO для запросов/ответов, DEBUG для полных bodies. Реализуется через httpx `event_hooks` на клиенте — так логируются и сырые HTTP-запросы, и провайдер не размазывается логикой логирования. Smoke-скрипт включает `logging.basicConfig(level=DEBUG)` чтобы видеть лог.
- **Модель по умолчанию:** `openrouter/free` (бесплатная). Fallback: `google/gemini-2.5-flash`. В `config.py`: `OPENROUTER_DEFAULT_MODEL = env или "openrouter/free"`.
- **API-ключ:** хранится в `backend/.env` (в `.gitignore`), через `python-dotenv`.

## Исходное состояние

## Порядок задач

### 1. Обновить `app/config.py` — добавить fallback-модель
Файл: `backend/app/config.py`

```
OPENROUTER_DEFAULT_MODEL = os.getenv("OPENROUTER_DEFAULT_MODEL", "openrouter/free")
OPENROUTER_FALLBACK_MODEL = "google/gemini-2.5-flash"
```

### 2. Создать `app/llm/base.py` — типы и протокол
Файл: `backend/app/llm/base.py`

Dataclass'ы и Protocol по контракту из `docs/plan/step-02-llm-provider.md`:
- `ToolSpec(name, description, parameters)` — parameters: dict (JSON Schema)
- `ToolCall(id, name, arguments)` — arguments: dict
- `Message(role, content?, tool_calls?, tool_call_id?, name?)` — role: str (system|user|assistant|tool)
- `ModelInfo(id, name, context_length?)`
- `CompletionResult(content, tool_calls, finish_reason, usage)`
- `LLMProvider(Protocol)`: `list_models()`, `complete(model, messages, tools?, temperature?, tool_choice?)`, `stream_complete(model, messages, tools?, temperature?) -> AsyncIterator[str]`

### 3. Создать `app/llm/openrouter.py` — реализация провайдера
Файл: `backend/app/llm/openrouter.py`

- Класс `OpenRouterProvider` реализует `LLMProvider`.
- Конструктор: `__init__(self, client: httpx.AsyncClient, api_key: str, base_url: str)`.
- Логгер: `logger = logging.getLogger("app.llm")`.
- `list_models()`: `GET {base_url}/models` → парсинг → `list[ModelInfo]`. Лог: INFO с числом моделей.
- `complete(model, messages, tools, temperature, tool_choice)`:
  - Формирование OpenAI-совместимого body (mapping Message→dict, ToolSpec→OpenAI tool format).
  - `POST {base_url}/chat/completions`, заголовки `Authorization: Bearer {api_key}`, `Content-Type: application/json`.
  - Парсинг response → `CompletionResult`.
  - Лог: INFO (model, finish_reason, usage, tool_call names if any; content preview 200 chars).
- `stream_complete(model, messages, tools, temperature)`:
  - `POST {base_url}/chat/completions` с `stream: true`.
  - SSE parsing: строка `data: {json}` → yield delta content; `data: [DONE]` → стоп; пустые строки → пропустить.
  - Лог: DEBUG на каждый чанк.
- Обработка ошибок:
  - 401 → `ValueError("Invalid OpenRouter API key")` (с подсказкой проверить .env)
  - 429 → `RuntimeError("Rate limit exceeded")`
  - Таймаут/сетевая → пробрасывание `httpx.TimeoutException` / `httpx.ConnectError`
  - Другие HTTP ошибки → лог тела ответа + пробрасывание

### 4. Обновить `app/llm/__init__.py` — публичные импорты
```python
from app.llm.base import CompletionResult, LLMProvider, Message, ModelInfo, ToolCall, ToolSpec
from app.llm.openrouter import OpenRouterProvider
```

### 5. Создать `scripts/smoke_llm.py` — smoke-тест
Файл: `backend/scripts/smoke_llm.py`

`asyncio.run(main())`. В `main()`:
1. Создаёт `httpx.AsyncClient(timeout=30)`.
2. Читает `config` (OPENROUTER_API_KEY, DEFAULT_MODEL, BASE_URL).
3. Проверка отсутствия ключа → понятная ошибка и `sys.exit(1)`.
4. `logging.basicConfig(level=DEBUG)`.
5. Три проверки:
   - `list_models()` → напечатать общее число и 3 slug'а.
   - `complete(model, [system, user("скажи привет")])` → напечатать текст ответа.
   - **Tool-call proof:** tool `current_time()` (schema без параметров); user «сколько сейчас времени?»; assert `result.tool_calls[0].name == "current_time"`; напечатать.
6. Если tool-call proof не прошёл с `openrouter/free` — автоматически повторить с fallback-моделью (`google/gemini-2.5-flash`), залогировать «free model failed tool-calling, retrying with fallback».
7. Все проверки passed → «All smoke tests passed».
8. Клиент закрывается в `finally`.

### 6. Создать `tests/test_llm.py` — юнит-тесты (без ключа, мок httpx)
Файл: `backend/tests/test_llm.py`

Используем `httpx.MockTransport` — передаём mock-клиент через DI, не нужно патчить.
- Тест `test_list_models`: мок GET /models → проверка парсинга и количества `ModelInfo`.
- Тест `test_complete_text`: мок POST /chat/completions без tool_calls → проверка `CompletionResult.content`.
- Тест `test_complete_with_tool_calls`: мок с tool_calls в ответе → проверка парсинга `ToolCall`.
- Тест `test_stream_complete`: мок SSE-строки → проверка yield текстовых чанков и остановки на `[DONE]`.
- Тест `test_auth_error`: мок 401 → проверка `ValueError` с текстом про ключ.
- Тест `test_rate_limit_error`: мок 429 → проверка `RuntimeError`.

### 7. Запустить валидацию
- `ruff check backend/app/llm/ backend/tests/test_llm.py backend/scripts/smoke_llm.py`
- `cd backend && python -m pytest tests/test_llm.py -v`
- `cd backend && python scripts/smoke_llm.py`

## Критерий приёмки

- [ ] Без ключа — понятная ошибка, а не трейс.
- [ ] `from app.llm import OpenRouterProvider, Message, ToolSpec` импортируется чисто.
- [ ] Юнит-тесты с моками проходят (`pytest tests/test_llm.py`).
- [ ] `ruff check` без ошибок.
- [ ] В логе smoke видно: отправленные messages (roles + content preview), ответ (content, tool_calls, usage).

## Чего НЕ делаем
- Агент-луп (шаг 03).
- Реестр инструментов документов.
- SQLite.
- FastAPI-эндпоинты (кроме `/health`).
- UI.
- Pin провайдера (ADR-0009) — готовим поле в запросе, но не используем.
- Stripping tool_calls из stream — `stream_complete` отдаёт только текстовые чанки.

## Зависимости
Только уже установленные: `httpx`, `pydantic`, `python-dotenv`. Новых зависимостей нет.

## Риски
1. **`openrouter/free` не поддерживает tool-calling** — mitigated: smoke автоматически пробует fallback-модель.
2. **OpenRouter tool-calling формат** — проверяем на реальном вызове в smoke.
3. **SSE parsing** — формат прост (text/event-stream), но нужно обработать edge cases (пустые строки, пробелы).
